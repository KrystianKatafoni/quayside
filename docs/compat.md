# Kompatybilność z Claude Code

Quayside steruje supervisorem sesji Claude Code (Agent View, research preview). Ten plik aktualizuje skill `/compat-check` (co tydzień w GitHub Actions) albo człowiek po ręcznym teście.

| Pozycja | Wartość |
| --- | --- |
| Minimalna wersja (Agent View, `claude agents`) | 2.1.139 |
| Wersja, na której oparto dokumentację | 2.1.290 (dokumentacja Agent View, październik 2026) |
| Ostatnio przetestowana ręcznie | 2.1.322 (2026-11-10, macOS; pliki sesji na dysku i `claude --bg --resume`, pomiar AM-311); wcześniej 2.1.302 (2026-10-18, Linux; tylko `claude agents --json [--all]` z sesją interaktywną, bez sesji w tle) |
| Ostatni automatyczny przegląd | — |

Zaobserwowane w 2.1.302 (sesja interaktywna): `pid`, `cwd`, `kind`, `startedAt` (epoch millis), `sessionId`, `name`, `status`; brak `id`, `state`, `waitingFor`. Pola sesji w tle wciąż niezweryfikowane nagraniem (fixtures: `feature/agent-runtime/impl/src/test/resources/fixtures/agents-json/`) |
| `claude --bg`, `--name`, `--agent`, `--model`, `--permission-mode`, `--resume` | `agent-runtime:impl` (`ClaudeCliAdapter`) | zmiany flag; adapter parsuje linię `backgrounded · <id> · <name>` ze stdout (potwierdzone nagraniem 2.1.302; baner `Starting background service…` idzie na stderr). W niezaufanym katalogu `--bg` kończy się kodem 1 i `Workspace not trusted…`. `--permission-mode` w 2.1.302 przyjmuje `acceptEdits`, `auto`, `bypassPermissions`, `manual`, `dontAsk`, `plan` — dla `DEFAULT` flaga jest pomijana. Prompt idzie po `--`. `--resume <uuid>` (pomiar AM-311, 2.1.322, nagrania `2.1.322-bg-resume-*`): rozmowa jest znajdowana po UUID z dowolnego zaufanego katalogu (R1–R3), transkrypt jest dopisywany do istniejącego pliku, a `id` zadania to pierwsze 8 znaków UUID. Rozmowa otwarta w interaktywnym `claude` (R4) albo zadanie już w supervisorze, wznowione z flagą (`--model`, R5), daje kopię z nowym UUID i uwagą `note: …` na stderr, kod 0. Sam prompt bez flag budzi to samo zadanie. Nieistniejący UUID: kod 0 i `backgrounded`, dopiero potem zadanie przechodzi w `failed` (błąd nie jest w wyjściu polecenia). `ClaudeCliAdapter.resume` (AM-313) woła dokładnie `claude --bg --resume <uuid>` w katalogu startu rozmowy, bez promptu i bez innych flag (R5); sprawdzenie pliku i katalogu robi `sessions:impl` przed wywołaniem; tekst `note: …` ze stderr nie trafia do logów ani błędów |
| `claude attach / logs / stop / respawn / rm` | `agent-runtime:impl`, `terminal` | zmiany zachowania, nowe potwierdzenia. 2.1.302: `attach`/`logs` przyjmują `<id\|name>`, `stop`/`rm` `<id>`, `respawn` `<id>\|--all`; `rm` usuwa też worktree i może odmówić (`kept <id>` → `CommandFailed`). Nieznane id (nagranie 2.1.302): kod 1 i stderr `No job matching '<id>'` (dla `attach`, `logs`, `stop` z dopiskiem `. Run 'claude agents' to list running sessions.`) — adapter i tak sprawdza listę ponownie. `stop` sesji `done` zostawia stan `done`, `logs` zwraca surowy zrzut TUI z ANSI. Nagrania: `feature/agent-runtime/impl/src/test/resources/fixtures/cli/` |
| `claude -p --model <m> --output-format json --settings {"disableAllHooks":true} --no-session-persistence --tools "" --strict-mcp-config --disable-slash-commands -- <prompt>` | `agent-runtime:impl` (`ClaudePrintAdapter`, `PrintResultParser`; streszczenia Haiku, ADR 0019) | **Do potwierdzenia na claude 2.1.139+** (`/compat-check`; `claude --help` 2.1.316 zawiera te flagi): nazwy flag (`--tools ""`, `--strict-mcp-config` i `--disable-slash-commands` odbierają modelowi narzędzia, MCP i komendy wobec niezaufanego promptu), to, że `--settings` z `disableAllHooks` wyłącza hooki (inaczej `Stop` streszczenia wywoła pętlę), oraz pola JSON `result` (string) i `is_error`. Adapter czyta tylko `result` i `is_error`; kod wyjścia ≠ 0 daje `CommandFailed` z oczyszczonym stderr, bez promptu. Prompt idzie po `--` w argv |
| Hooki HTTP: `Notification`, `Stop`, `StopFailure`, `SessionStart`, `SessionEnd` | `agent-runtime:impl` (`HookPayloadParser`, `KtorHookServer`), `sessions:impl` | nazwy pól (`session_id`, `cwd`, `hook_event_name`, `last_assistant_message`, `notification_type`, `message`, `reason`), typy powiadomień. Parser czyta błąd `StopFailure` z `error_type` albo `error` (nazwa pola niezweryfikowana nagraniem) i nazwę narzędzia z tekstu `… permission to use <Tool>`. Wszystko oparte na docs/03, nie na nagraniu prawdziwego hooka |
| `claude --version` | `agent-runtime:impl` (`health()`, `ClaudeVersion`) | 2.1.302 wypisuje `2.1.302 (Claude Code)`, kod 0. Adapter czyta `x.y.z` z początku pierwszej niepustej linii (sufiks ignorowany) i porównuje z 2.1.139; wersja starsza albo nieczytelna kończy sprawdzanie |
| `claude daemon status` | `agent-runtime:impl` (`health()`, `DaemonStatus`; tylko informacyjnie) | 2.1.302: demon nie działa → kod 1, pierwsza linia `not running`; działa → kod 0 i linie `pid:     698`, `version: 2.1.302`, `uptime: …`, `origin: …`, sekcja `bg sessions:` z `control.sock: reachable`. Adapter uznaje demona za działającego tylko przy kodzie 0 i linii `pid: <cyfry>`. Flagi `--json` CLI nie zna (ignoruje z ostrzeżeniem), więc jej nie podajemy. Demon startuje na żądanie, więc „nie działa” nie jest problemem. Od której wersji istnieje podkomenda — niezweryfikowane |
| `~/.claude.json` → `projects[<ścieżka>].hasTrustDialogAccepted` (boolean); przy `CLAUDE_CONFIG_DIR`: `<CLAUDE_CONFIG_DIR>/.claude.json`. `claude --bg` w niezaufanym katalogu: kod 1 i stderr `Workspace not trusted…` | `agent-runtime:impl` (`ClaudeJsonTrust`, `TrustJson`, `BgOutput.untrusted`; ADR 0031) | Zależność od nieudokumentowanego formatu pliku: nazwa pola, struktura `projects`, klucz = ścieżka po `toRealPath` (nie potwierdzone nagraniem dla katalogu z dowiązaniem, np. `/var` vs `/private/var`), pierwsze słowa komunikatu. Po aktualizacji Claude Code sprawdź ręcznie: (1) w katalogu tymczasowym z `CLAUDE_CONFIG_DIR=$(mktemp -d)` ustaw wpis `false`, uruchom `claude --bg` (spodziewane `Workspace not trusted`), zmień na `true` (spodziewane `backgrounded · <id>`); (2) dla katalogu pod `/var/folders/...` sprawdź, czy klucz wpisu to ścieżka z `/private/var/...`; (3) w oknie „Nowy agent” zaufaj świeżemu katalogowi i potwierdź, że start się udaje. Zaufanie działa też na podkatalogi: Claude Code przy sprawdzaniu idzie w górę po katalogach nadrzędnych (własny klucz Claude Code to raczej korzeń repozytorium git, nasz klucz `toRealPath` działa dzięki przeszukiwaniu w górę); gdy mimo zapisu odmawia, okno pokazuje `TrustIneffective`. Cofnięcie: ustaw `false` albo usuń wpis. Gdy format się zmieni, `TrustJson` zwraca `CONFIG_INVALID` i nic nie zapisuje, a start nadal kończy się instrukcją ręczną (ADR 0031) |
| `disableAgentView`, `CLAUDE_CODE_DISABLE_AGENT_VIEW` | `agent-runtime:impl` (`health()`, `AgentViewProbe` na `claude agents --json`) | 2.1.302: kod 1, stderr `'claude agents --json' is disabled by CLAUDE_CODE_DISABLE_AGENT_VIEW.` albo `… is disabled by the 'disableAgentView' setting.` → `AgentViewDisabled`. Wykrywanie po treści komunikatu: inny tekst da `CommandFailed` zamiast `AgentViewDisabled` |
| `<claudeHome>/projects/<dirNameOf(cwd)>/<uuid>.jsonl` (pola `sessionId`, `cwd`, `timestamp`, `type`, `isSidechain`, `isMeta`, `message.content` jako tekst albo części `text`/`tool_use`/`tool_result`/`thinking`; wpis `custom-title` z `customTitle`) | `agent-runtime:impl` (`SessionFiles`, `SessionFileReader`, `FileSessionHistory`, `BackwardLines`, `ConversationEntries`, AM-311, AM-312, AM-315) i `sessions:impl` (`TranscriptTail`, AM-818; stare sesje na liście tylko przez port `SessionHistory`, AM-312) | format nieudokumentowany; zmiana formatu daje pustą listę starych sesji, nie błąd okna; kodowanie nazwy katalogu jest stratne (`/a/b-c` i `/a/b/c` dają to samo) i obcina nazwy powyżej 200 znaków; w jednym pliku może być wiele `cwd` (wznowienie z innego katalogu dopisuje wpisy z nowym `cwd`); pliki mają do 163 MB, więc lista czyta tylko początek i koniec, a historia (AM-315) czyta od końca porcjami po 64 KiB i nigdy całość; wpis `custom-title` albo części `message.content` w innym kształcie dają brak nazwy lub pustą historię, nie błąd; treść to dane użytkownika (ENG-C8). ## Pliki sesji na dysku (pomiar AM-311)

Pomiar na Macu, Claude Code 2.1.322, 2026-11-10: 104 katalogi projektów, 132 pliki `.jsonl`, 113 podkatalogów i 2 inne pliki w katalogach projektów (do pominięcia). Wyniki M1–M8 to agregaty z `SessionFilesOnDiskMeasurement` (raport bez ścieżek, UUID i tekstu). M3 dla znaków spoza ASCII i długich ścieżek oraz M9 zmierzono na sesjach testowych w osobnych katalogach, bo prawdziwe dane takich ścieżek nie miały. Żaden fragment prawdziwego pliku sesji nie jest w repozytorium; fixtures w `fixtures/session-files/synthetic/` są napisane ręcznie.

### Rekomendacje

- **AM-312 (lista starych sesji).** Parser zostaje w `agent-runtime:impl` (wariant A, decyzja człowieka 2026-11-10); AM-312 dodaje port w `agent-runtime:api` (np. `SessionHistory`) i dopisuje ten moduł do swojej listy, po osobnym pytaniu do człowieka o zmianę `api`, bo `sessions:impl` nie widzi `internal` z `agent-runtime:impl`. `startCwd` = pierwszy wpis z bezwzględnym `cwd` w głowie 64 KiB; ogon 64 KiB daje `lastActivityAt` i dolne ograniczenie `cwdChanged`. Filtr wieku po `mtime` przed odczytem. Wpisy `custom-title` jako możliwy tytuł. Przypisanie do projektu po `startCwd` w `Project.dir`.
- **AM-313 (Wznów).** Rozdzielić dwa przypadki. Sesja będąca w supervisorze (zadanie `stopped`/`done`): istniejący Respawn (`claude respawn <id>`) wraca to samo zadanie bez nowego UUID. Sesja spoza supervisora: osobna akcja „Wznów” = `claude --bg --resume <uuid>` (bez promptu i flag) w katalogu `startCwd`, bo UUID rozmowy zostaje, a lista nie dubluje sesji (deduplikacja po UUID). Przed startem sprawdzić, że plik sesji istnieje (nieistniejący UUID daje kod 0 i dopiero potem `failed`), a po starcie czytać stan zadania. Gdy rozmowa ma zadanie w supervisorze, użyć Respawn, nie `--resume` (z flagą `--model` powstaje kopia z nowym UUID). Nie wznawiać rozmowy otwartej w interaktywnym `claude`: powstaje kopia z nowym UUID. Przy kopii (R4/R5) adapter bierze nowe `id` z linii `backgrounded · <id>`, nie z UUID rozmowy. Akcja „Wznów” nie wymaga promptu. Wznowienie dopisuje do transkryptu, więc `cwd` w pliku może się zmienić; `startCwd` zostaje pierwszym.
- **AM-314 (ręczne przypisanie).** Potrzebne tylko dla sesji z `cwdChanged`; ze zmierzonych 132 plików dotyczy to 5.
- **Rozjazd z AM-818 (do `/triage`, osobne zadanie).** `FileSessionMetaSource` koduje nazwę regexem Javy `[^A-Za-z0-9]`, który działa na punktach kodowych, więc emoji daje jeden `-` zamiast dwóch, i nie zna obcinania powyżej 200 znaków z hashem. Dla zwykłych ścieżek wynik jest taki sam.
