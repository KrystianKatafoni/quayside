# AM-1002 · Feature `accounts` (api/impl)

Issue: #144 · Wymagania: FR-L1, FR-L2, FR-L9 (też NFR-5) · ENG-M2–M5, ENG-I1–I8, ENG-C2, ENG-C5, ENG-C8, ENG-T1–T6 · ADR 0024, 0029, nowy 0035 (proponowana) · Zależy: AM-1001 (PR #198, częściowy)

Status: **zrealizowany** (kod i testy w PR; plan poprawiony po review do stanu kodu). Jeden PR (decyzja człowieka). ADR 0035 ma status „proponowana”: zatwierdza go człowiek przy review PR.

**Decyzje człowieka:**

- **1a.** Dowiązanie `projects/` domyślnie włączone (`NewAccount.shareProjects = true`), z ostrzeżeniem w KDoc i w ADR 0035. Brakujący pomiar (dwie sesje na dwóch kontach, `memory/`) jest warunkiem AM-1007.
- **2a.** `AccountId` w `core:domain/Ids.kt`, obok `ProjectId` i `SessionId`.
- **3a.** Kopia do istniejącego konta scala po ścieżce względnej; kopia zapasowa tylko dla nadpisywanych plików o innej treści; pliki spoza konta domyślnego zostają.

## Zakres

1. Nowe moduły `feature:accounts:api` i `feature:accounts:impl`, bez `ui`.
2. **Model:** `Account`, `AccountStatus` (dostępne, limit od–do albo do ręcznego odblokowania, wylogowane, nieznane), `AccountsState` (kolejność automatu, chłodzenie domyślnie 5 h, zakres 1–24 h); `AccountId` w `core:domain`.
3. **`accounts.json`** (ADR 0035): `AccountsRepo` ze `StateFlow` i `update`, zapis tylko odstępstw, niezmienniki w czystym `AccountRules`.
4. **Czysty `AccountSelector.choose`** i `AccountRules.cooldownLimit`.
5. **`AccountSetup`:** nowe konto w `~/.claude-quayside/<id>/` z dowiązaniem `projects/` i jednorazową kopią z `~/.claude`; wskazanie istniejącego katalogu (bez zapisu); kopia do istniejącego konta z kopią zapasową.
6. **`app`:** `accountsModule(…)` obok `storedSettings`, pole `SettingsDeps.accounts` i właściwość `AppModules.accounts` dla AM-1003/1005. UI bez zmian.

**Nie robimy:** okna „Konta” i logowania (AM-1005), `claude auth status`, `CLAUDE_CONFIG_DIR` w wywołaniach (AM-1003), pól `current` i `proposeSwitch` (AM-1010, AM-1006), przywracania z kopii zapasowej, zmian w `agent-runtime` i `sessions`.

## Zmiany API

Stan zgodny z kodem; pełne KDoc w plikach `api`. Najważniejsze punkty:

```kotlin
// core:domain/Ids.kt
/** Slug `[a-z0-9-]{1,32}`; [DEFAULT] is `~/.claude`; `auto` is reserved (ADR 0035).
 *  @throws IllegalArgumentException when not a slug (programmer error). */
@JvmInline public value class AccountId(public val value: String) {
    public companion object { public val DEFAULT: AccountId = AccountId("default") }
}

public object AccountRules { // DEFAULT_COOLDOWN = 5.hours, COOLDOWN_RANGE = 1.hours..24.hours, MAX_ID = 32
    public fun slug(label: String): AccountId?   // null when empty, `default` or `auto`
    public fun isValidId(value: String): Boolean // slug pattern only
    /** First broken invariant, or null. A non-default account with id `auto` is [AccountProblem.RESERVED_ID]. */
    public fun validate(state: AccountsState, home: Path): AccountProblem?
    public fun cooldownLimit(now: Instant, cooldown: Duration): AccountStatus.Limited
}
public enum class AccountProblem { DEFAULT_MISSING, DEFAULT_DIR_CHANGED, DUPLICATE_ID, RESERVED_ID,
    DUPLICATE_DIR, RELATIVE_DIR, BLANK_LABEL, COOLDOWN_OUT_OF_RANGE }

public object AccountSelector {
    /** [preferred] when enabled and not blocked: [AccountStatus.LoggedOut] and a [AccountStatus.Limited] whose
     *  `until` is null or after [now] block it; [AccountStatus.Unknown] or no entry does NOT block the user's own
     *  choice (until AM-1005/1006 every account is Unknown), and `inAutomation` is not required. Else the first
     *  enabled, in-automation account that is Available or has an over limit (`until <= now`), then the first
     *  Unknown (missing = Unknown); null when none. */
    public fun choose(accounts: List<Account>, statuses: Map<AccountId, AccountStatus>,
                      preferred: AccountId?, now: Instant): AccountId?
}
```

**Zastrzeżone id `auto`** odrzuca wyłącznie `AccountRules.validate` (`AccountProblem.RESERVED_ID`, prywatna stała `AUTO`). To jedyne źródło reguły dla `JsonAccountsRepo.update`, `FakeAccounts` i odczytu pliku (`AccountsSerializer` woła `validate`); `AccountEntryJson` sprawdza tylko `isValidId`, osobnego warunku `it != "auto"` nie ma. Pozostałe typy (`Account`, `AccountStatus`, `AccountsState`, `AccountsRepo`, `AccountsError`, `AccountSetup`, `NewAccount`, `CopyItem`, `CopyReport`, `AccountSetupError`, `SetupStage`, `AccountsApi`, `AccountPaths`) bez zmian względem kodu. Fabryka: `suspend fun accountsModule(storage, paths, clock, io, logger): AccountsApi` (5 parametrów). Logi tylko z kategorią i `id`.

## Ryzyka i pytania

**Pytania blokujące:** brak (decyzje 1a, 2a, 3a powyżej). ADR 0035 zatwierdza człowiek przy review PR.

**Świadome luki z review (do decyzji człowieka albo do AM-1005; nie poprawiamy w tym PR):**

- **Brak testu `NonCancellable`** w `FileAccountSetup` i `JsonAccountsRepo`: test anulowania w trakcie operacji wymaga haka (zawieszenie w kroku IO) w `impl`. Do decyzji: hak testowy albo zostawić na review kodu.
- **Względne dowiązania wskazujące poza kopiowane drzewo** (np. `skills/x -> ../../inne`) kopiujemy dosłownie; na nowym koncie mogą wskazywać nieistniejący cel. Do AM-1005 (ostrzeżenie w oknie „Konta”).
- **Częściowe scalenie przy błędzie COPY:** gdy zapis nie uda się w połowie, część plików jest już nadpisana; stare wersje są w `accounts-backup/`, ale nic ich nie przywraca. Do AM-1005 (NFR-5: pokazanie ścieżki kopii, przywracanie).
- **Kolizja nazwy kopii zapasowej** `<epochMillis>-<id>` przy dwóch kopiach tego samego konta w tej samej milisekundzie. Do decyzji: sufiks licznika albo blokada per konto.

**Ryzyka:**

- **Usunięcie złego katalogu przy sprzątaniu:** usuwamy tylko katalog utworzony przez `create` (`createDirectory`), bez podążania za dowiązaniami (`NOFOLLOW_LINKS`); test `cleanup never deletes through the projects link`.
- **Wspólne `projects/` (1a):** zapisy równoległe na dwóch kontach niepotwierdzone (AM-1001, p. 7); pomiar przed AM-1007, w razie złego wyniku `shareProjects = false`.
- **Dane użytkownika (ENG-C8):** nazwy i ścieżki nie trafiają do logów, `toString` ani komunikatów błędów.
- **Rozmiar PR** ok. 2,9× limitu ENG-C10, jeden PR z decyzji człowieka.
