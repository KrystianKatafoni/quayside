# AM-102 · core:domain (ID, Outcome, Clock, Logger, ShellCommand)

Issue: #10 · Wymagania: ENG-M6, ENG-I3, ENG-I4 · Etap: M1

## Zakres

Moduł `core:domain` z typami bazowymi współdzielonymi przez wszystkie moduły:

- `ProjectId`, `SessionId` — `value class`, puste wartości odrzucane.
- `Outcome<T, E>` (`Ok` / `Err`) z operacjami `map`, `mapError`, `flatMap`, `fold`, `getOrElse`, `getOrNull`, `errorOrNull`, `isOk` oraz `catching` dla adapterów (mapuje wyjątki na błąd domenowy, przepuszcza `CancellationException`).
- `Clock` (`fun interface`) i `SystemClock`.
- `Logger` z poziomami, polami strukturalnymi, skrótami `debug/info/warn/error` i `NoOpLogger`.
- `AppDispatchers` (main/io/default) — instancję produkcyjną buduje `app` (AM-108).
- `ShellCommand` — opis procesu; `toString()` ukrywa wartości zmiennych środowiskowych (ENG-C8).

Nie robimy: `TestClock` i buildery (AM-103), uruchamianie procesów (AM-106), adapter SLF4J (AM-108).

## Moduły

`core:domain` (nowy), `settings.gradle.kts`.

Moduł używa convention pluginu `am.feature.api`: daje explicit API i `testFixtures`, czyli dokładnie to, czego potrzebuje kontrakt współdzielony. Osobny plugin `am.core` nie wnosi dziś nic nowego.

## Zmiany API

Nowe typy publiczne w pakiecie `dev.quayside.core.domain` (jak wyżej, zgodne ze szkicem z `docs/11-koncepcja-techniczna.md` §4). Zależność `api`: `kotlinx-coroutines-core` (tylko dla `CoroutineDispatcher`).

## Ryzyka i pytania

- `Clock` zwraca `java.time.Instant` (stabilne, bez opt-in), a nie `kotlin.time.Instant`.
- Reguły Konsist dla `core:domain` (zakaz `java.io`, `java.net`, Compose) dojdą w AM-104.
