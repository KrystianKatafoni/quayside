# AM-103 · core:testing (TestClock, TestDispatchers, buildery)

Issue: #11 · Wymagania: ENG-T6 · Etap: M1

## Zakres

Moduł `core:testing` z narzędziami używanymi w testach wszystkich modułów:

- `TestClock` + stała `T0` — czas przesuwany ręcznie (`advanceBy`, `setTo`), nie cofa się.
- `testDispatchers(scheduler)` i `TestScope.testDispatchers()` — `AppDispatchers` na jednym `TestCoroutineScheduler`, więc wirtualny czas `runTest` obejmuje main/io/default.
- `RecordingLogger` + `LogEntry` — logger zapamiętujący wpisy do asercji.
- Buildery `aProjectId()`, `aSessionId()`, `aShellCommand()`. Buildery typów z feature (`aSession`, `aProject`) dojdą razem z tymi typami.

Nie robimy: Turbine (dojdzie z pierwszym ViewModelem), zmian w `core:domain`.

## Moduły

`core:testing` (nowy), `settings.gradle.kts`. Plugin `am.feature.api` (explicit API). Zależności `api`: `core:domain`, `kotlinx-coroutines-test`. Moduł jest dołączany wyłącznie jako zależność testowa (`testImplementation` / `testFixturesApi`).

## Zmiany API

Nowe typy w `dev.quayside.core.testing` (jak wyżej). Brak zmian w istniejących modułach.

## Testy

- [x] jednostkowe: `TestClockTest` (3), `TestDispatchersTest` (1), `RecordingLoggerTest` (1), `BuildersTest` (1)

## Ryzyka i pytania

- `runCurrent`/`advanceTimeBy` wymagają opt-in `ExperimentalCoroutinesApi`; na razie `@file:OptIn` w testach. Jeśli będzie się powtarzać, przeniesiemy opt-in do `am.kotlin` dla zbiorów testowych.
