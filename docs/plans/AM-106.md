# AM-106 · core:process: LoginShellProcessRunner (timeouty, ucinanie wyjścia)

Issue: #14 · Wymagania: ENG-M9 · Etap: M1

## Zakres

Moduł `core:process` — jedyne miejsce w aplikacji, które uruchamia procesy systemowe:

- port `ProcessRunner` (`suspend fun run(command, options): Outcome<ProcessResult, ProcessError>`),
- `RunOptions` (timeout, domyślnie 30 s; limit wyjścia, domyślnie 1 MiB osobno dla stdout i stderr),
- `ProcessResult` (kod wyjścia, stdout, stderr, flagi ucięcia) i `ProcessError` (`NotFound`, `Timeout`, `StartFailed`, `IoFailed`),
- `LoginShellProcessRunner`: uruchamia `<shell> -l -c 'exec "$@"' agent-manager <argv>`, więc ładuje profil użytkownika (`.zprofile`), a argumenty nie są ponownie interpretowane przez powłokę. Po timeoucie lub anulowaniu korutyny zabija proces razem z potomkami. Wyjście ponad limit jest czytane i odrzucane, żeby proces nie zablokował się na pełnym potoku.
- `FakeProcessRunner` w `testFixtures` (ENG-I7): zapisuje wywołania, wynik ze skryptu.

Nie robimy: wejścia stdin, strumieniowania wyjścia na żywo, PTY (to `terminal:impl`), mapowania na `RuntimeError` (AM-203).

## Moduły

`core:process` (nowy), `settings.gradle.kts`.

Zależności: `api(core:domain)`, `testImplementation(core:testing)`. Plugin `am.feature.api` (explicit API, `testFixtures`) wystarcza — obie zależności są dozwolone dla modułów `core`.

## Zmiany API

Nowe typy publiczne w pakiecie `dev.agentmanager.core.process`:

```kotlin
interface ProcessRunner {
    suspend fun run(command: ShellCommand, options: RunOptions = RunOptions()): Outcome<ProcessResult, ProcessError>
}
data class RunOptions(val timeout: Duration = 30.seconds, val maxOutputBytes: Int = 1024 * 1024)
data class ProcessResult(val exitCode: Int, val stdout: String, val stderr: String,
                         val stdoutTruncated: Boolean = false, val stderrTruncated: Boolean = false) { val isSuccess: Boolean }
sealed interface ProcessError { NotFound(program); Timeout(after); StartFailed(reason); IoFailed(reason) }
class LoginShellProcessRunner(io: CoroutineDispatcher, shell: Path = defaultShell(), logger: Logger = NoOpLogger)
```

Niezerowy kod wyjścia to `Ok(ProcessResult)` — interpretacja należy do adaptera. `NotFound` = kod 127 i linia stderr z „not found” oraz nazwą programu (błąd w `.zprofile` się nie liczy). Ścieżka do nieistniejącego pliku wraca świadomie jako `Ok` z kodem 127. Timeout musi wynosić co najmniej 1 ms.

## Testy

- [x] jednostkowe: `ProcessRunnerTypesTest` (2), `FakeProcessRunnerTest` (2), `OutputCaptureTest` (tablicowy test ucinania: puste wejście, dokładnie limit, limit + 1, duże wejście, znak UTF-8 na granicy; rozpoznawanie `NotFound`)
- [x] integracyjne na prawdziwych procesach przez `/bin/sh -l` (`LoginShellProcessRunnerTest`, 12): stdout/stderr/kod wyjścia, argumenty bez interpretacji powłoki, katalog roboczy i środowisko, profil logowania (`.profile`; `.zprofile` gdy jest zsh), ucięcie dużego wyjścia, zabicie drzewa procesów po timeoucie, zabicie po anulowaniu, brak programu → `NotFound`, brak katalogu → `StartFailed`, wartości środowiska nie trafiają do logów, `defaultShell()`
- kontraktowe: **odstępstwo od ENG-T2 do zatwierdzenia w PR** — `FakeProcessRunner` jest skryptowany i nie ma zachowania wspólnego z prawdziwym runnerem poza sygnaturą, więc wspólny kontrakt niczego by nie sprawdzał
- funkcjonalne: nie dotyczy (brak UI)

Testy integracyjne leżą w `src/test`, bo convention plugins nie mają jeszcze zestawu `integrationTest`. Są hermetyczne: `HOME` i `ZDOTDIR` wskazują katalog tymczasowy, więc prawdziwy profil dewelopera ani runnera CI nie jest czytany. Używają prawdziwego czasu (krótkie timeouty) — to test zasobu systemowego, nie logiki czasu.

## Ryzyka i pytania

- Proces w tle, który przeżyje proces główny (np. demon), nie jest zabijany, a to, co wypisze po wyjściu procesu głównego, przepada (JDK po wyjściu procesu przepisuje resztę potoku i zamyka deskryptor, więc odczyt nie wisi). Do AM-203: test regresji z `sh -c "sleep 30 &"` przy `claude --bg`.
- `docs/11` §9 pokazuje `LoginShellProcessRunner()` bez argumentów; konstruktor wymaga `io` — do uwzględnienia w AM-108.
- `NotFound` opiera się na kodzie 127 i tekście „not found” (bash, zsh, dash) — program, który sam zwraca 127 z takim tekstem, zostanie potraktowany jak brakujący.
- Dekodowanie UTF-8 po ucięciu może zostawić znak zastępczy na granicy limitu.
