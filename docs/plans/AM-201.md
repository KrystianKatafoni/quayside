# AM-201 · agent-runtime:api + kontrakt AgentRuntime w testFixtures

Issue: #17 · Wymagania: ENG-I1–I8, ENG-T2, docs/11 §4, ADR 0002, ADR 0004 · Etap: M2

## Zakres

Nowy moduł `feature:agent-runtime:api`: port do supervisora Claude Code bez żadnej implementacji.

- Typy i interfejsy ze szkicu docs/11 §4 (`AgentRuntime`, `AgentEventSource`, `HookInstaller`) z KDoc (ENG-I1). Szkic doprecyzowany o brakujące typy (`StartSpec`, `RuntimeHealth`, `HookScope`, `HookStatus`, `BackupRef`, `HookError`) i o kilka zmian opisanych niżej.
- `testFixtures`: abstrakcyjne kontrakty `AgentRuntimeContract`, `AgentRuntimeHealthContract`, `HookInstallerContract` i `AgentEventSourceContract` (ENG-T2: kontrakt dla każdego interfejsu `api`), opis stanu świata `RuntimeWorld`, fake'i `FakeAgentRuntime` (skryptowalny, spełnia oba kontrakty runtime), `FakeAgentEventSource` i `FakeHookInstaller` (ENG-I7).
- Wpis `include(":feature:agent-runtime:api")` w `settings.gradle.kts`.

Nie robimy: `agent-runtime:impl` (parser, `ClaudeCliAdapter`, health: AM-202–204), serwera hooków (AM-601), prawdziwego instalatora hooków (AM-602), zmian w `core:*`. Kontrakty `HookInstallerContract` i `AgentEventSourceContract` powstają tutaj; AM-601 i AM-602 uruchamiają je na swoich implementacjach.

## Moduły

`feature:agent-runtime:api` (nowy), `settings.gradle.kts`. Opcjonalnie `docs/11-koncepcja-techniczna.md` §4: tylko dopasowanie szkicu do ostatecznego API.

`build.gradle.kts`: plugin `am.feature.api`; `api(project(":core:domain"))` (daje też `kotlinx-coroutines-core` dla `Flow`); `testFixturesApi(project(":core:testing"))` (`TestClock`, buildery); `testFixturesImplementation` JUnit BOM, `junit-jupiter`, `kotest-assertions`, `kotlinx-coroutines-test`, tak jak w `core:storage`. Wszystkie zależności projektowe są w `ModuleRules.allowedForApi`. Nowych bibliotek nie ma, więc ADR nie jest potrzebny.

Pakiet `dev.agentmanager.agentruntime.api`, bo tego wymaga reguła Konsist `package follows the module path` (z `feature/agent-runtime/api` robi `agentruntime.api`).

**`java.nio.file.Path` w `api`:** wolno. Konsist w `*:api` zabrania importów zaczynających się od `java.io.`, `java.net.`, `java.lang.ProcessBuilder` i `androidx.compose.`. `java.nio.file.Path` i `java.time.Instant` nie pasują do żadnego prefiksu i są typami JDK, a nie bibliotek (ENG-I8). `core:domain` używa ich już w `ShellCommand` i `Clock`. Reguła sprawdza tylko `src/main`, a w `src/testFixtures` i tak nie potrzebujemy `java.io`. Ten moduł jako pierwszy uruchomi reguły Konsist dla `feature api modules` i `package follows the module path` (dotąd były pominięte).

## Zmiany API

Wszystkie metody `suspend` są bezpieczne do wywołania z dowolnego dispatchera (implementacja sama przełącza się na IO), nie blokują wątku (ENG-I5) i nie rzucają wyjątków poza `CancellationException` (ENG-I4). Każdy typ jest niemutowalny (ENG-I3).

```kotlin
/** Claude Code conversation UUID (hook `session_id`, `sessionId` in `agents --json`); joins hooks with polling. */
@JvmInline value class ConversationId(val value: String)          // init: not blank

interface AgentRuntime {
    /** Sessions whose `cwd` equals [under] or lies below it (Path-wise, `/p/ab` is not under `/p/a`); null = all. */
    suspend fun listSessions(under: Path? = null): Outcome<List<RuntimeSession>, RuntimeError>
    /** Starts a background agent (`claude --bg`); returns the supervisor's short id. */
    suspend fun start(spec: StartSpec): Outcome<SessionId, RuntimeError>
    suspend fun stop(id: SessionId): Outcome<Unit, RuntimeError>
    suspend fun respawn(id: SessionId): Outcome<Unit, RuntimeError>
    /** Removes the session from the supervisor list; never deletes project files. */
    suspend fun remove(id: SessionId): Outcome<Unit, RuntimeError>
    /** Tail of the session output (`claude logs`), already truncated by the implementation. */
    suspend fun recentOutput(id: SessionId): Outcome<String, RuntimeError>
    /** Pure: the command a terminal runs in a PTY to attach. Does not check that [id] exists. */
    fun attachCommand(id: SessionId): ShellCommand
    /** Never fails: every problem is reported inside [RuntimeHealth]. */
    suspend fun health(): RuntimeHealth
}

data class RuntimeSession(
    val id: SessionId, val conversationId: ConversationId?, val name: String, val cwd: Path,
    val phase: RuntimePhase, val waitingFor: WaitingFor?, val startedAt: Instant, val pid: Long?,
)
enum class RuntimePhase { WORKING, BLOCKED, DONE, FAILED, STOPPED }
sealed interface WaitingFor { data object Permission; data object Input; data class Other(val raw: String) }

/** Minimum supported Claude Code version (NFR-9); single source for impl and contracts. */
object RuntimeRequirements { const val MIN_CLAUDE_VERSION = "2.1.139" }

/** FR-S3. `toString` hides [prompt] (ENG-C8). init: prompt and optional texts not blank. */
data class StartSpec(
    val cwd: Path, val prompt: String, val name: String? = null, val agent: String? = null,
    val model: String? = null, val permissionMode: PermissionMode? = null,
)
enum class PermissionMode { DEFAULT, ACCEPT_EDITS, PLAN, BYPASS_PERMISSIONS }

/** [version] is the raw CLI version, null when not installed; [isReady] = problems.isEmpty(). */
data class RuntimeHealth(
    val version: String?, val agentViewEnabled: Boolean, val supervisorRunning: Boolean,
    val problems: List<RuntimeError>,
) { val isReady: Boolean }

sealed interface RuntimeError {
    data object NotInstalled
    data class UnsupportedVersion(val found: String, val required: String)
    data object AgentViewDisabled
    data class UnknownSession(val id: SessionId)                    // new vs docs/11
    data class CommandFailed(val exitCode: Int, val stderrTail: String)
    data class Unparseable(val detail: String)                       // fixed reason category, never input text
    data object Timeout
}

/** Hot stream of hook events; no replay, events with no collector are lost (polling corrects state, ADR 0004). */
interface AgentEventSource { val events: Flow<AgentEvent> }
data class EventMeta(val conversationId: ConversationId, val cwd: Path, val at: Instant)
sealed interface AgentEvent { val meta: EventMeta  /* NeedsInput, PermissionRequested, TurnEnded, Failed, SessionEnded as in docs/11 */ }

interface HookInstaller {
    suspend fun status(scope: HookScope): HookStatus
    /** Always backs up the settings file first; idempotent (a second install changes nothing but still returns a backup). */
    suspend fun install(scope: HookScope): Outcome<BackupRef, HookError>
    /** Removes only our hooks; with [backup] restores that copy instead. */
    suspend fun uninstall(scope: HookScope, backup: BackupRef?): Outcome<Unit, HookError>
}
sealed interface HookScope { data object Global; data class Project(val dir: Path) }   // ~/.claude/settings.json | .claude/settings.local.json
enum class HookKind { NOTIFICATION, STOP, STOP_FAILURE, SESSION_START, SESSION_END }
sealed interface HookStatus {
    data object NotInstalled; data object Installed
    data class Partial(val missing: Set<HookKind>)
    data class Unreadable(val reason: String)                        // fixed category
}
/** Opaque handle to a backup kept by the implementation (`hooks-backup/*.json`). */
@JvmInline value class BackupRef(val value: String)                // init: not blank
sealed interface HookError {
    data class SettingsUnreadable(val file: Path, val reason: String)
    data class WriteFailed(val file: Path, val reason: String)
    data class BackupNotFound(val ref: BackupRef)
}
```

Zmiany względem szkicu docs/11: `ConversationId` zamiast `String` (ENG-I3), nowy `RuntimeError.UnknownSession`, a semantyka `under` i idempotencja `install` są opisane w KDoc.

testFixtures:

`FakeAgentRuntime` nadaje identyfikatory deterministycznie (`fake0001`, …), `startedAt` bierze z `clock`, a stan trzyma jako niemutowalną migawkę w `AtomicReference` aktualizowaną przez compare-and-set (bez `Mutex`, więc metody nie muszą być `suspend`, a `calls` i `hasSession` działają synchronicznie). Gdy świat ma `installed = false`, każda operacja `suspend` zwraca `NotInstalled`.

## Ryzyka i pytania

Pytania do człowieka (niczego nie blokują, plan przyjmuje rekomendację):

1. **Kontrakty `AgentEventSource` i `HookInstaller`** (ENG-T2, ENG-I7): zrobione w AM-201 po review. `HookInstallerContract`, `AgentEventSourceContract` i `FakeHookInstaller` są w `testFixtures`; AM-601 i AM-602 tylko uruchamiają kontrakty na swoich implementacjach.
2. **`RuntimeError.UnknownSession`** nie ma w docs/11. Bez tego wariantu stop/rm nieistniejącej sesji wraca jako `CommandFailed`, a sesje nie odróżnią sesji, która zniknęła, od awarii CLI. Rekomendacja: dodać i dopasować docs/11 §4.
3. **`ConversationId` jako `value class`** w `agent-runtime:api`, a nie w `core:domain` (żeby nie zmieniać `core:domain`). Jeśli `sessions:api` (AM-401) też będzie go potrzebować, ma do niego dostęp przez `agent-runtime:api`. Rekomendacja: zostawić tutaj.
4. **`PermissionMode` jako `enum`**: Claude Code może dodać tryby, a każdy nowy oznacza zmianę łamiącą (ENG-I6). Alternatywa: `value class PermissionMode(val cliValue: String)` ze stałymi. Rekomendacja: `enum`, bo UI potrzebuje zamkniętej listy.

Ryzyka:

- Kontrakt opisuje świat (`RuntimeWorld`), a AM-203 musi go odwzorować fałszywym `claude` ze stanem w pliku (start → lista, stop → `STOPPED`). Jeśli prawdziwy supervisor zachowuje się inaczej (np. `respawn` sesji `WORKING`), kontrakt sprawdza tylko przypadki opisane wyżej.
- Kontrakt zdrowia jest osobną klasą, bo health powstaje w AM-204, a `ClaudeCliAdapter` z AM-203 i tak musi przejść `AgentRuntimeContract`.
- Semantyka `--cwd` w `claude agents` (dokładne dopasowanie czy również podkatalogi) jest nieznana. Jeśli CLI zachowuje się inaczej niż KDoc, adapter filtruje po stronie klienta.
- `HookScope.Project` + `Global` zostawia otwartą kwestię z docs/09 (gdzie instalować hooki) do decyzji w AM-602 bez zmiany `api`.
- Treść z hooków (`question`, `lastMessage`) i `recentOutput` jest wrażliwa (ENG-C8). KDoc oznacza ją jako „tylko DEBUG”; `toString` ukrywa je w `StartSpec`, `NeedsInput` i `TurnEnded`.
