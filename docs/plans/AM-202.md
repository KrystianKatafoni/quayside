# AM-202 · Parser `claude agents --json` + nagrane fixtures

Issue: #18 · Wymagania: FR-S2, NFR-8, ENG-C5, ENG-T1, ENG-C8 · docs/05 „Stany sesji”, docs/12 (fixtures), ADR 0002 · Etap: M2

## Zakres

Nowy moduł `feature:agent-runtime:impl` z jedną czystą funkcją: tekst stdout `claude agents --json [--all]` → lista `RuntimeSession` (ENG-C5, bez IO) oraz fixtures z nagraniami i przypadkami syntetycznymi.

Nie robimy: `ClaudeCliAdapter`, `ProcessRunner`, fałszywego `claude` na `PATH`, filtra `under` (AM-203); health (AM-204); fabryki `agentRuntimeModule()` i wpięcia w `app` (powstaną razem z adapterem w AM-203, bo fabryka bez `AgentRuntime` nie ma czego zwrócić); zmian w `agent-runtime:api`.

## Moduły

`feature:agent-runtime:impl` (nowy), `settings.gradle.kts` (`include(":feature:agent-runtime:impl")`), `docs/compat.md` (wiersz `agents --json` i „Ostatnio przetestowana ręcznie”: 2.1.302, tylko sesja interaktywna).

Szkielet według `/new-module agent-runtime impl` (`.claude/skills/new-module/templates.md`), ale bez pliku `AgentRuntimeModule.kt` (patrz Zakres). `build.gradle.kts`: plugin `am.feature.impl`; `implementation(project(":feature:agent-runtime:api"))`, `implementation(project(":core:domain"))`, `implementation(libs.kotlinx.serialization.json)`; `testImplementation(testFixtures(project(":feature:agent-runtime:api")))` (buildery `aRuntimeSession`). JUnit, Kotest i coroutines-test daje `am.kotlin`. Parsujemy drzewo (`Json.parseToJsonElement`), więc nie trzeba pluginu `kotlinx-serialization`. Biblioteka jest już w katalogu wersji i w `core:storage`, więc ADR nie jest potrzebny. Pakiet `dev.quayside.agentruntime.impl`. Moduł jako pierwszy uruchomi regułę Konsist `impl exposes only its module factory`. Wszystkie deklaracje są `internal`, a `JsonElement` nie wychodzi poza plik parsera (ENG-I8).

## Zmiany API

Brak zmian w `api`. Kontrakt wewnętrzny modułu (`internal`, KDoc po angielsku):

```kotlin
/** Pure parser of `claude agents --json`; tolerant to new fields and values (NFR-8). Never throws. */
internal object AgentsJsonParser {
    /** Upper bound of accepted stdout; larger input is rejected before parsing. */
    const val MAX_INPUT_CHARS: Int = 4 * 1024 * 1024

    /**
     * [observedAt] replaces a missing or unreadable `startedAt` (the parser has no clock).
     * Err only when the whole document is unusable; a bad entry is skipped and reported in [AgentsListing.notices].
     */
    fun parse(stdout: String, observedAt: Instant): Outcome<AgentsListing, RuntimeError.Unparseable>
}

/** Parsed sessions in input order plus everything that was tolerated, for DEBUG logs and `/compat-check`. */
internal data class AgentsListing(val sessions: List<RuntimeSession>, val notices: List<ParseNotice>)

/** Something the parser tolerated. Never carries input text except [token]s that passed [SafeToken]. */
internal sealed class ParseNotice {  // sealed class: Konsist requires `internal` on nested types, which an interface cannot carry
    data class EntrySkipped(val index: Int, val reason: SkipReason) : ParseNotice
    data class UnknownPhase(val id: SessionId, val token: String?) : ParseNotice      // null = no state/status
    data class StartedAtMissing(val id: SessionId) : ParseNotice
}
internal enum class SkipReason { NOT_AN_OBJECT, INTERACTIVE, MISSING_ID, INVALID_CWD, DUPLICATE_ID }

/** Fixed categories of [RuntimeError.Unparseable.detail]; the only values the parser ever puts there. */
internal object UnparseableReason {
    const val EMPTY = "agents-json:empty"
    const val TOO_LARGE = "agents-json:too-large"
    const val MALFORMED = "agents-json:malformed"
    const val NOT_AN_ARRAY = "agents-json:not-an-array"
}
```

`SafeToken`: wartość `state`/`status` trafia do `ParseNotice.UnknownPhase.token` tylko wtedy, gdy pasuje do `^[A-Za-z][A-Za-z0-9_ -]{0,31}$`; w przeciwnym razie `token = "<redacted>"`. Wyjątki kotlinx.serialization (`SerializationException`, `IllegalArgumentException`) łapiemy wewnątrz `parse` i zamieniamy na `MALFORMED` bez `message` i `cause` (lekcja z CLAUDE.md).

### Dokument i wpisy

| Wejście | Wynik |
| --- | --- |
| pusty lub sam whitespace | `Err(Unparseable(EMPTY))`; adapter rozstrzygnie w AM-203 (pytanie 4) |
| `length > MAX_INPUT_CHARS` | `Err(Unparseable(TOO_LARGE))` |
| niepoprawny JSON | `Err(Unparseable(MALFORMED))` |
| poprawny JSON, ale nie tablica | `Err(Unparseable(NOT_AN_ARRAY))` |
| `[]` | `Ok(sessions = [], notices = [])` |
| element nie jest obiektem | pominięty, `EntrySkipped(i, NOT_AN_OBJECT)` |
| nieznane pola (np. `kind`, `model`, `worktree`) | ignorowane, bez notice |

### Pola → `RuntimeSession`

| Pole JSON | Pole | Reguła |
| --- | --- | --- |
| `kind` | (filtr) | `"interactive"` → pominięty `INTERACTIVE`; brak lub inna wartość → dalej |
| `id` | `id` | string niepusty → `SessionId`; brak, pusty lub nie-string → pominięty `MISSING_ID`; powtórzony → `DUPLICATE_ID` (zostaje pierwszy) |
| `sessionId` | `conversationId` | string niepusty → `ConversationId`, inaczej `null` |
| `name` | `name` | string niepusty, inaczej `id.value` |
| `cwd` | `cwd` | ścieżka absolutna (`Path.of`, `InvalidPathException` złapany) → `normalize()`; brak, względna lub zła → pominięty `INVALID_CWD` |
| `state` ?: `status` | `phase` | tabela niżej; `state` ma pierwszeństwo, bo opisuje sesję w tle (docs/05), `status` znamy z nagrania 2.1.302 |
| `waitingFor` | `waitingFor` | tabela niżej; ustawiane tylko dla `BLOCKED`, w innych fazach `null` |
| `startedAt` | `startedAt` | liczba `≥ 1e11` → epoch millis (nagranie 2.1.302); liczba `< 1e11` → epoch sekundy; string → `Instant.parse` (ISO-8601); inaczej `observedAt` + `StartedAtMissing` |
| `pid` | `pid` | liczba całkowita `> 0` → `Long`, inaczej `null`; dla `STOPPED` zawsze `null` (KDoc: „null when not running”) |

Fazy (porównanie po `trim().lowercase()`, `-` i spacja traktowane jak `_`):

| `state`/`status` | `RuntimePhase` |
| --- | --- |
| `working`, `busy`, `running`, `active` | `WORKING` |
| `blocked`, `waiting`, `needs_input` | `BLOCKED` |
| `done`, `idle`, `completed`, `finished` | `DONE` |
| `failed`, `error`, `errored`, `crashed` | `FAILED` |
| `stopped`, `exited`, `killed`, `terminated` | `STOPPED` |
| nieznana lub brak, ale `waitingFor` jest niepuste | `BLOCKED` + `UnknownPhase` |
| nieznana lub brak, bez `waitingFor` | `WORKING` + `UnknownPhase` |

Uzasadnienie nieznanej fazy: `WORKING` niczego nie ogłasza (nie wyzwala powiadomień „czeka/błąd”) i nie chowa sesji, a polling i hooki (ADR 0004) poprawią stan w następnym cyklu. `BLOCKED` przy obecnym `waitingFor` jest bezpieczniejsze, bo użytkownik nie przegapi prośby.

| `waitingFor` (znormalizowane) | `WaitingFor` |
| --- | --- |
| `permission`, `permission_prompt` | `Permission` |
| `input`, `input_needed`, `idle_prompt`, `agent_needs_input` | `Input` |
| inny niepusty string | `Other(raw)`, gdzie `raw` jest przycięte do 64 znaków (trafia do UI, nie do logów) |
| brak, pusty, nie-string | `null` (także dla `BLOCKED`; reducer AM-402 i hooki rozstrzygną powód) |

**Sesje interaktywne są odfiltrowane.** ADR 0002: aplikacja steruje supervisorem sesji w tle; `attach/stop/respawn/rm` działają na krótkim `id` supervisora, którego sesja interaktywna nie ma (nagranie 2.1.302: brak `id`, `state`, `waitingFor`). `RuntimeSession.id` jest wymagane, a FR-S1/FR-S2 (docs/05) opisują stany i akcje sesji agentów, którymi aplikacja zarządza. Pokazanie sesji z terminala wymagałoby zmiany `api` (opcjonalne `id`), więc to osobna decyzja (pytanie 1). Filtr działa podwójnie: `kind == "interactive"` albo brak `id`.

## Fixtures

`feature/agent-runtime/impl/src/test/resources/fixtures/agents-json/` (ścieżka z docs/12):

- `synthetic/` — ręcznie napisane według docs/compat.md i docs/05: `background-all-phases.json` (po jednej sesji na fazę, `blocked` z `permission prompt` i `input needed`), `mixed-interactive-and-background.json`, `unknown-fields-and-values.json` (nowe pola, `state: "hibernating"`, `waitingFor: "oauth"`), `partial-entries.json` (brak `id`, względny `cwd`, nie-obiekt, duplikat `id`, `startedAt` jako ISO, sekundy i śmieć), `empty.json` (`[]`), `not-an-array.json`, `malformed.txt`.
- `README.md` — tabela: plik · źródło (`recorded`/`synthetic`) · polecenie · wersja `claude` · data · system · uwagi. Nagrania 2.1.302: 2026-10-18, Linux (kontener sesji Claude Code w chmurze).

## Ryzyka i pytania

Pytania do człowieka (niczego nie blokują, plan przyjmuje rekomendację):

1. **Sesje interaktywne** (`kind: "interactive"`) są pomijane. Gdyby Mission Control miało pokazywać też sesje z terminala (tylko podgląd, bez akcji), potrzebna jest zmiana `agent-runtime:api` (`id: SessionId?` albo `RuntimeSession.kind`) i nowe zadanie. Rekomendacja: pominąć w MVP.
2. **Nieznana faza → `WORKING`** zamiast nowej `RuntimePhase.UNKNOWN`. `UNKNOWN` byłoby uczciwsze w UI, ale to zmiana łamiąca `api` (ENG-I6) i reducera AM-402. Rekomendacja: `WORKING` + notice, wrócić do tematu, jeśli `/compat-check` zobaczy nowe wartości.
3. **Brak nagrania sesji w tle.** Nazwy pól i wartości sesji w tle (`id`, `state`, `waitingFor`, wartość `kind`) pochodzą z docs/compat.md i docs/05, nie z nagrania. Rekomendacja: przed scaleniem AM-203 człowiek nagrywa na macOS `claude --bg …` i `claude agents --json --all` w fazach working/blocked/done/stopped; parser i tabele poprawia wtedy mały PR.
4. **Puste stdout** → `Err(EMPTY)`, a nie pusta lista, żeby nie maskować awarii supervisora. AM-203 może to zmapować inaczej, gdy kod wyjścia jest 0.

Ryzyka:

- Heurystyka sekund i milisekund w `startedAt` pomyli się dla dat przed 1973; to nie dotyczy prawdziwych sesji.
- Szerokie tabele synonimów (`busy`, `idle`, `exited`…) to zgadywanie przyszłych wartości. Każdy synonim ma przypadek testowy, więc ewentualne usunięcie jest tanie.
- `Other(raw)` niesie tekst supervisora do UI. Jest przycięty i nie trafia do logów ani do `Unparseable` (ENG-C8).
- PR: kod mieści się w limicie ENG-C10 (< 400 linii bez testów i fixtures).
