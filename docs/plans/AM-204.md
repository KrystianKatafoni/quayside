# AM-204 · Health check: wersja ≥ 2.1.139, Agent View, supervisor

Issue: #20 · Wymagania: NFR-9, ENG-C8, ENG-I2, ENG-T2, ENG-T3 · docs/11 §4 (`RuntimeHealth`), docs/12 (fałszywy `claude`), ADR 0002 · Etap: M2 · Zależy: AM-203

## Zakres

`ClaudeCliAdapter.health()` zastępuje zaślepkę `Unparseable("health:not-checked")` prawdziwym sprawdzeniem instalacji: wersja z `claude --version`, stan supervisora z `claude daemon status` (tylko informacyjnie), Agent View z `claude agents --json`. Adapter przechodzi `AgentRuntimeHealthContract` na fałszywym `claude`.

Nie robimy: banera w UI ani wywołania przy starcie aplikacji (konsument `health()`, `sessions:impl`/`app`), cache'owania wyniku, uruchamiania demona, nowych pól ani błędów w `api`.

Fakty z claude 2.1.302 (Linux, 2026-10-18), na których opiera się plan:

- `claude --version` wypisuje na stdout `2.1.302 (Claude Code)` i kończy się kodem 0.
- Gdy Agent View jest wyłączony, `claude agents --json` kończy się kodem 1, a stderr zawiera `'claude agents --json' is disabled by CLAUDE_CODE_DISABLE_AGENT_VIEW.` albo `… is disabled by the 'disableAgentView' setting.`
- `claude daemon status`: gdy demon nie działa, kod 1 i pierwsza linia `not running`. Gdy działa, kod 0 i linie `pid:     698`, `version: 2.1.302`, `uptime: …`, `origin: …`, a w sekcji `bg sessions:` linia `control.sock: reachable`. Flagi `--json` CLI nie zna (ignoruje ją z ostrzeżeniem), więc jej nie podajemy.
- Instalacja usługi jest wyłączona: demon startuje na żądanie (`claude agents`, `claude --bg`) i kończy pracę po rozłączeniu ostatniego klienta.

## Moduły

- `feature:agent-runtime:impl`: `ClaudeCliAdapter.health()`, nowe czyste funkcje, `ClaudeCommands` (+3 polecenia), fałszywy `claude` (`src/test/resources/fake-claude/fake-claude.sh`, `FakeClaude.kt`), testy. Nowych zależności nie ma, więc ADR nie jest potrzebny.
- `docs/compat.md`: wiersze `--version`, `daemon status` i komunikaty o wyłączonym Agent View. `docs/ROADMAP.md`: `[~]` AM-204.
- `feature:agent-runtime:api`: **bez zmian** (ani `src/main`, ani `testFixtures`).

## Zmiany API

Brak. Wszystko poniżej to typy `internal` w `impl` (KDoc po angielsku):

```kotlin
/** Dotted numeric Claude Code version `major.minor.patch`; [toString] gives `2.1.302`. */
internal data class ClaudeVersion(val major: Int, val minor: Int, val patch: Int) : Comparable<ClaudeVersion> {
    override fun compareTo(other: ClaudeVersion): Int   // numeric, part by part
    companion object {
        /** Version at the start of the first non-blank line of `claude --version` stdout; null when there is none. */
        fun parse(stdout: String): ClaudeVersion?
        /** [RuntimeRequirements.MIN_CLAUDE_VERSION] parsed; a unit test guards that it parses. */
        val MINIMUM: ClaudeVersion
    }
}
internal object DaemonStatus {
    /** True only for exit code 0 and a `pid: <digits>` line; any other answer means "not running". */
    fun isRunning(exitCode: Int, stdout: String): Boolean
}
internal object AgentViewProbe {
    /** True when stderr or stdout says `… is disabled by` CLAUDE_CODE_DISABLE_AGENT_VIEW or 'disableAgentView'. */
    fun isDisabledMessage(stderr: String, stdout: String): Boolean
}
// ClaudeCommands: version(exe) = [exe, "--version"]; daemonStatus(exe) = [exe, "daemon", "status"];
// agentViewProbe(exe) = [exe, "agents", "--json"]   (bez --all: wystarczy kod wyjścia)
```

`ClaudeVersion.parse`: regex `^(\d+)\.(\d+)\.(\d+)(?![\d.])` na pierwszej niepustej linii po `trim()`. Każda część przez `toIntOrNull()`, więc przepełnienie daje `null`. Sufiks (`(Claude Code)` po spacji, `-beta.1`, `+build`) jest ignorowany.

### Zachowanie `health()` (decyzje)

Kroki idą po kolei, każdy z `config.commandTimeout`, `workDir = homeDir`. Najgorszy przypadek to 3 × `commandTimeout` (30 s przy domyślnym 10 s).

| Krok | Wynik | `RuntimeHealth` |
| --- | --- | --- |
| 1. `--version` | `NotFound` | `version=null`, `problems=[NotInstalled]`, **koniec** |
| | `Timeout` / `StartFailed` / `IoFailed` | `[Timeout]` / `[CommandFailed(-1, "process:…")]`, koniec |
| | kod ≠ 0 | `[CommandFailed(code, StderrTail)]`, koniec |
| | kod 0, `parse` = null | `version=null`, `[Unparseable("version:unparseable")]`, koniec |
| | wersja < `MINIMUM` | `version="x.y.z"`, `[UnsupportedVersion(found="x.y.z", required=MIN_CLAUDE_VERSION)]`, koniec |
| 2. `daemon status` | dowolny | `supervisorRunning = DaemonStatus.isRunning(…)`; błąd procesu daje `false`. **Nigdy nie dodaje problemu** |
| 3. `agents --json` | kod 0 | `agentViewEnabled=true` |
| | kod ≠ 0 i `isDisabledMessage` | `agentViewEnabled=false`, `[AgentViewDisabled]` |
| | inny błąd | `agentViewEnabled=false`, zmapowany błąd (`Timeout`, `CommandFailed` z `StderrTail`, `NotInstalled`) |

Uzasadnienie:

- **`version` to sparsowane `x.y.z`, a nie surowe wyjście.** Kontrakt oczekuje `"2.1.290"`, a skrypt wypisuje `2.1.290 (Claude Code)`. Do `RuntimeHealth` ani do błędu nie trafia żaden fragment nieparsowalnego wejścia (ENG-C8): używamy stałej kategorii `version:unparseable`.
- **Za stara albo nieznana wersja kończy sprawdzanie.** Dla wersji < 2.1.139 podkomenda `agents` (a tym bardziej `daemon`) może nie istnieć. Starsze CLI potraktowałoby wtedy `daemon status` jako **prompt** i uruchomiło sesję interaktywną: wisiałaby do timeoutu albo zużyła tokeny. Wynik mógłby też fałszywie wskazać `AgentViewDisabled`. Użytkownik dostaje jeden problem, który da się naprawić („zaktualizuj Claude Code”). Fake z `testFixtures` w tym przypadku wylicza też AV, ale kontrakt sprawdza tylko `shouldContain`, więc oba zachowania są z nim zgodne.
- **`supervisorRunning` jest informacyjne.** Od 2.1.302 demon działa na żądanie, więc „nie działa” to normalny stan spoczynku, a nie usterka. `problems` zawiera tylko to, co blokuje pracę, zgodnie z KDoc `RuntimeHealth.problems`.
- **`daemon status` idzie przed `agents`,** bo `agents` może sam uruchomić demona. Pole pokazuje więc stan zastany, a kolejność jest deterministyczna w testach (bez `async`).
- Wykrywanie AV opiera się na treści komunikatu, a nie na samym kodzie 1, żeby awaria `agents` z innego powodu nie wyglądała na wyłączony Agent View.
- Logi: jeden wpis INFO `claude health` z polami `version`, `agentViewEnabled`, `supervisorRunning` i kategoriami problemów (nazwa klasy, bez treści). Błąd `daemon status` trafia tylko do DEBUG jako kategoria.

## Fałszywy `claude`

Nowe pliki stanu: `agent-view` (`enabled` | `env` | `setting`) i `daemon` (`running` | `stopped` | `absent`). `FakeClaude.install` zapisuje `agent-view = env`, gdy `world.agentViewEnabled == false`, a `daemon = running` domyślnie. Dochodzą metody `setAgentView(…)`, `setDaemon(…)` i `setVersion(…)`, a KDoc `install` przestaje mówić „not modelled yet”.

| Wywołanie | Zachowanie |
| --- | --- |
| `agents …` przy `agent-view ≠ enabled` | stderr z jednym z dwóch komunikatów 2.1.302, kod 1 |
| `daemon status` | `running`: kod 0, linie `pid:`/`version:`/`uptime:`/`origin:`/`bg sessions:`/`control.sock: reachable`; `stopped`: `not running`, kod 1; `absent`: `fake-claude: unknown command daemon`, kod 2 |
| `--version` | bez zmian (`<version> (Claude Code)`); tryby `garbage`/`hang`/`fail` działają jak dotąd |

## Ryzyka i pytania

Pytania do człowieka (nie blokują, plan przyjmuje rekomendację):

1. **`supervisorRunning` tylko informacyjne** (decyzja wyżej). Alternatywa: dodawać problem, gdy demon nie działa. Zablokowałoby to jednak gotowość w normalnym stanie spoczynku 2.1.302 i wymagałoby nowego `RuntimeError`, czyli zmiany `api`. Rekomendacja: przyjąć.
2. **KDoc `RuntimeHealth.version` mówi „raw `claude --version` result”**, a zwracamy sparsowane `x.y.z` (tego wymaga kontrakt). Rekomendacja: poprawić sam KDoc w osobnym PR `docs(agent-runtime)` albo przy najbliższej zmianie `api`. Sygnatura się nie zmienia, ale to plik `api`, więc nie robimy tego tutaj.
3. **Od której wersji istnieje `claude daemon status`, nie wiadomo.** Wołamy je tylko dla wersji ≥ 2.1.139. Jeśli 2.1.139–2.1.2xx potraktuje `daemon status` jako prompt, wywołanie zakończy się timeoutem (`supervisorRunning=false`) albo, w najgorszym razie, uruchomi sesję. Rekomendacja: sprawdzić `claude daemon --help` na najstarszej dostępnej wersji ≥ 2.1.139 i, jeśli trzeba, dodać w `impl` stałą `DAEMON_STATUS_SINCE` (bez zmiany `api`). Wynik wpisać do `docs/compat.md`.

Ryzyka:

- Pełne sprawdzenie trwa w najgorszym razie 3 × `commandTimeout`. Wywołujący (`sessions:impl`/`app`) nie może blokować na nim startu UI. Osobny `healthTimeout` wymagałby nowego parametru fabryki, więc na razie go nie dodajemy.
- `claude agents --json` w sprawdzeniu może sam uruchomić demona (efekt uboczny akceptowalny: robi to też `listSessions`) i pokazać dialog zaufania katalogu (AM-203, ryzyko 3). Uruchamiamy go w `homeDir`.
- Wykrywanie AV zależy od treści komunikatu 2.1.302. Jeśli CLI zmieni tekst, wyłączony AV pokaże się jako `CommandFailed` (nadal `isReady=false`, tylko mniej trafny komunikat). `/compat-check` śledzi to w `docs/compat.md`.
- Sufiks prerelease jest ignorowany, więc `2.1.139-beta` liczy się jako wspierana wersja. Świadome uproszczenie: CLI nie publikuje dziś prerelease'ów.
- PR: kod produkcyjny ok. 120 linii, poniżej limitu ENG-C10.
