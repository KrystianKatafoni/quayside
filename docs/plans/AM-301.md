## Zmiany API

Metody `suspend` można wołać z dowolnego dispatchera, nie blokują wątku (ENG-I5) i nie rzucają wyjątków poza `CancellationException` (ENG-I4). Typy są niemutowalne (ENG-I3).

```kotlin
/** A directory registered in Agent Manager. [dir] is absolute and normalized; log [id], [dir] only at DEBUG (ENG-C8). */
data class Project(val id: ProjectId, val dir: Path, val displayName: String)

/**
 * Registered projects (FR-P1, FR-P3, FR-P6). Never touches project files: it only keeps the list.
 * [projects] keeps the order in which projects were added; it is updated before a command returns.
 */
interface ProjectsApi {
    val projects: StateFlow<List<Project>>
    /** [displayName] null = last segment of [dir]. Errors: NotAbsolute, NotFound, NotADirectory, AlreadyAdded, InvalidDisplayName, StorageFailed. */
    suspend fun add(dir: Path, displayName: String? = null): Outcome<Project, ProjectError>
    /** Removes the project from the list only; files, transcripts and worktrees stay on disk. Running sessions are not touched. */
    suspend fun remove(id: ProjectId): Outcome<Unit, ProjectError>
    /** Keeps id, dir and position in the list. */
    suspend fun rename(id: ProjectId, displayName: String): Outcome<Unit, ProjectError>
}

/** Paths are user data: UI may show them, logs only at DEBUG. [reason] is a fixed category, never an exception message. */
sealed interface ProjectError {
    data class NotAbsolute(val dir: Path) : ProjectError
    data class NotFound(val dir: Path) : ProjectError
    data class NotADirectory(val dir: Path) : ProjectError
    data class AlreadyAdded(val existing: ProjectId) : ProjectError
    data class UnknownProject(val id: ProjectId) : ProjectError
    data class InvalidDisplayName(val reason: NameProblem) : ProjectError
    data class StorageFailed(val reason: String) : ProjectError
}
enum class NameProblem { BLANK, TOO_LONG, CONTROL_CHARACTERS }

/** Pure input rules shared by every implementation (ENG-C5, ENG-C9). No IO: symlinks are resolved by impl. */
object ProjectInputRules {
    const val MAX_DISPLAY_NAME_LENGTH = 80
    /** Absolute → `normalize()`d path; relative → NotAbsolute. */
    fun normalizeDir(dir: Path): Outcome<Path, ProjectError.NotAbsolute>
    /** Trims; null → `dir.fileName` (or `dir` for the root); blank, too long or control chars → InvalidDisplayName. */
    fun displayName(raw: String?, dir: Path): Outcome<String, ProjectError.InvalidDisplayName>
}

/** Read-only check of a directory before adding it (FR-P2). Never modifies the directory. */
interface ProjectInspector {
    /** Errors: NotAbsolute, NotFound, NotADirectory. Problems with git/runtime/hooks land in the report, not as Err. */
    suspend fun inspect(dir: Path): Outcome<DirectoryReport, ProjectError>
}
data class DirectoryReport(
    val dir: Path, val git: GitInfo?, val hasClaudeMd: Boolean,
    val sessionCount: Int?,                     // null = runtime unavailable
    val hooks: HooksPresence, val alreadyAdded: ProjectId?,
)
/** [branch] null = detached HEAD. */
data class GitInfo(val branch: String?)
/** Our hooks in `.claude/settings*.json` of the directory. */
enum class HooksPresence { NONE, PARTIAL, INSTALLED, UNREADABLE }
```

Zmiany względem szkicu docs/11: `inspect` przeniesione z `ProjectsApi` do osobnego `ProjectInspector` (ENG-I2; `DirectoryReport` nie istnieje w docs/11) i zwraca `Outcome`, bo katalog może nie istnieć; doszły `Project`, `ProjectError`, `ProjectInputRules`.

## Ryzyka i pytania

Pytania do człowieka (niczego nie blokują, plan przyjmuje rekomendację):

1. **`inspect` jako osobny `ProjectInspector`, nie metoda `ProjectsApi`** (rozbieżność z docs/11 §4). Powody: ENG-I2, `JsonProjectStore` (AM-302) nie musi implementować inspekcji, a AM-303 dostarcza osobną klasę. Rekomendacja: rozdzielić i dopasować docs/11.
2. **`ProjectsApi` łączy odczyt (`projects`) i komendy.** Zostawiamy tak jak w docs/11 i `AgentRuntime` (interfejs ma 4 elementy). Alternatywa zgodna z literą ENG-I2: `ProjectCatalog` + `ProjectCommands`. Rekomendacja: zostawić jeden.
3. **`inspect` zwraca `Outcome`**, a nie samo `DirectoryReport` z docs/11, bo nieistniejący katalog to błąd użytkownika, a nie pole raportu. Rekomendacja: `Outcome`.
4. **Limit nazwy 80 znaków** i odrzucanie znaków sterujących to propozycja (sidebar i tak przycina). Rekomendacja: przyjąć.
5. **`ProjectId` nadaje `impl`** (nieprzezroczysty, stabilny między uruchomieniami); kontrakt wymaga tylko unikalności. Ścieżka nie jest identyfikatorem, bo wtedy przeniesienie katalogu w przyszłości zmieniałoby id.

Ryzyka:

- Symlinki (`/tmp` → `/private/tmp` na macOS): `ProjectInputRules` normalizuje tylko składniowo, a `toRealPath()` robi implementacja. Zmienione w review: kontrakty sprawdzają to na prawdziwych symlinkach w `tempDir` (patrz „Decyzje z implementacji i review”), więc `JsonProjectStore` (AM-302) i `DirectoryInspector` (AM-303) dostają te przypadki za darmo.
- Unicode NFC/NFD (znane ryzyko, poza zakresem): APFS zachowuje postać nazwy, a użytkownik może wpisać ją w innej. `é` jako jeden code point i jako `e` + akcent to dwie różne nazwy wyświetlane i dwie różne długości. Ścieżek to nie dotyczy, bo porównujemy `toRealPath()`. Wrócimy do tego, jeśli pojawi się zgłoszenie.
- `InspectionWorld` musi dać się odtworzyć w AM-303 (`git init`, fałszywy `AgentRuntime`, pliki ustawień). Jeśli `git` nie jest dostępny w CI, przypadki z git przechodzą do testu integracyjnego z tagiem.
- ENG-C8: ścieżki zawierają nazwę użytkownika. KDoc `Project` i `ProjectError` zabrania logowania ich poza DEBUG; pola strukturalne to `projectId`.
- `HooksPresence` powiela część `HookStatus` z `agent-runtime:api`. To świadoma cena reguły „`api` → tylko `core:domain`” (ENG-M5); mapowanie żyje w jednym miejscu w `projects:impl`.

## Decyzje z implementacji i review

Odstępstwa od szkicu API powyżej. Kod jest źródłem prawdy, szkic zostaje jako zapis planu.

1. **Kanoniczna ścieżka.** `Project.dir` i `DirectoryReport.dir` to ścieżka rzeczywista (`toRealPath()`, symlinki rozwiązane), bo `AgentRuntime.listSessions(under)` porównuje po komponentach z cwd sesji, a cwd jest ścieżką rzeczywistą (`/private/tmp/...`). Dwie ścieżki do tego samego katalogu, także przez symlink albo przez symlink do rodzica, to ten sam projekt. Zepsuty symlink → `NotFound`, symlink do pliku → `NotADirectory`. Ścieżka w błędzie to ścieżka podana przez wołającego po `normalizeDir`, nie rzeczywista. `ProjectInputRules.normalizeDir` zostaje czystym krokiem składniowym; to, że `normalize()` działa przed `toRealPath()`, świadomie zmienia semantykę `link/..` (daje rodzica `link`, a nie rodzica celu symlinku). Ścieżka, której nie da się rozwiązać (brak, zepsuty symlink, pętla symlinków, brak uprawnień), to `NotFound`. Opisane w KDoc `Project.dir`, `ProjectsApi.add`, `ProjectInspector.inspect`, `DirectoryReport.dir`.
2. **Fake'i bez IO, z wstrzykiwanym resolverem.** `FakeProjectsApi` i `FakeProjectInspector` mają `pathKind: (Path) -> PathKind` (od początku implementacji, w szkicu planu miał go tylko `FakeProjectsApi`) i `realPath: (Path) -> Path?` (domyślnie `{ it }`). Typ `Path?` zamiast proponowanego w review `(Path) -> Path`: null = nic tam nie ma → `NotFound`, bo fake nie może rzucać. W `*ContractTest` przekazujemy `PathKind.onDisk` i `PathKind.realPathOnDisk` (`toRealPath()`, każdy `FileSystemException`, w tym pętla symlinków i `AccessDeniedException` → null). `PathKind.onDisk` podąża za symlinkami i łapie te same wyjątki, więc zepsuty symlink i pętla to `MISSING`, a nie `FILE`.
3. **Nazwa zastępcza nigdy nie daje błędu.** `displayName(null, dir)` zawsze zwraca `Ok`: znaki sterujące (te same co w nazwie jawnej, patrz niżej) → spacja, `trim`, przycięcie do `MAX_DISPLAY_NAME_LENGTH` z „…” wliczonym w limit, cięcie po granicy code pointa. Pusto po `trim` → pełna ścieżka przycięta tak samo, a w ostateczności `/`. Nazwa jawna (`add` z nazwą, `rename`) nadal jest walidowana ostro. `InvalidDisplayName` z `add` tylko dla nazwy różnej od null.
4. **Długość w code pointach** (`String.codePointCount`), nie w jednostkach UTF-16: emoji spoza BMP liczy się jako 1 i nigdy nie jest rozcinane. Sekwencje łączone liczą się osobno (patrz ryzyko NFC/NFD). Reguła zastępcza ma wewnętrzny wariant na napisach (`fallbackName(lastSegment, fullPath)`), bo `Path.of` z emoji rzuca wyjątek przy kodowaniu ścieżek innym niż UTF-8 (`sun.jnu.encoding`, np. kontener bez locale); test surogatów nie zależy więc od locale maszyny.
5. **`StorageFailed(problem: StorageProblem)`** zamiast `reason: String` (ENG-C8: nie da się wstawić `e.message`). `StorageProblem { READ_FAILED, WRITE_FAILED, NEWER_SCHEMA }` odpowiada błędom `JsonStore` z `core:storage` (`IoFailed` przy odczycie/zapisie, `NewerSchema`). Nieparsowalny plik nie jest błędem: `JsonStore` odkłada go jako `*.broken` i lista startuje pusta.
6. **Atomowość i start.** KDoc `ProjectsApi`: po każdym `Err`, także `StorageFailed`, lista się nie zmienia. Nieczytelny plik albo plik z nowszej wersji przy starcie: `projects` puste, każda komenda zwraca `StorageFailed` (`READ_FAILED` / `NEWER_SCHEMA`), plik nie jest nadpisywany. **`storageIssue: StateFlow<StorageIssue?>`** (review, runda 2): docs/11 §8 wymaga komunikatu w UI o odłożeniu uszkodzonego pliku, a bez kanału UI nie odróżni pustej listy od błędu odczytu. `StorageIssue { RECOVERED_FROM_BROKEN_FILE, READ_FAILED, NEWER_SCHEMA }` to stała kategoria bez ścieżki (ENG-C8); wartość jest ustalona, zanim `projects` pokaże załadowaną listę, a zamknięcie komunikatu to stan UI. `FakeProjectsApi(storageIssue = …)` przy `READ_FAILED` / `NEWER_SCHEMA` zwraca `StorageFailed` na każdą komendę, spójnie z KDoc.
7. **`toString` błędów ze ścieżką** (`NotAbsolute`, `NotFound`, `NotADirectory`) pokazuje `dir=***`, jak `StartSpec` w `agent-runtime:api`; równość nadal porównuje ścieżkę (ENG-C8).
8. **KDoc `DirectoryReport` pod AM-303:** `git` non-null także w podkatalogu repo i w worktree z plikiem `.git`; null = nie repo albo git niedostępny (nie rozróżniamy, żeby nie zmieniać kształtu API; UI pokazuje „brak repozytorium”). `hasClaudeMd` = `CLAUDE.md` albo `.claude/CLAUDE.md`. `sessionCount` = semantyka `listSessions(under = dir)`, tylko aktywne sesje. `HooksPresence` łączy `settings.json` i `settings.local.json` (hook obecny w którymkolwiek), `UNREADABLE` ma pierwszeństwo. Inspekcja nie modyfikuje katalogu: git z `--no-optional-locks`.
9. **Dodatkowe testy** ponad listę z planu. Kontrakt `ProjectsApiContract`: `added directory is stored normalized`, `add without a name of a long directory name succeeds`, `add with a too long name returns TOO_LONG and adds nothing`, `rename with a too long name returns TOO_LONG`, `concurrent adds of the same directory give exactly one project` (na `Dispatchers.Default`), symlinki: `adding a directory through a symlink returns AlreadyAdded when its target is added`, `adding the target of an added symlink returns AlreadyAdded`, `adding through a symlink stores the real path`, `directory under a symlinked parent is stored by its real path`, `broken symlink returns NotFound`, `symlink to a file returns NotADirectory`. Kontrakt `ProjectInspectorContract`: `report names the normalized directory`, `report names the real path of a symlinked directory`, `broken symlink returns NotFound`, `relative path returns NotAbsolute`. Jednostkowe: `ProjectErrorTest` (`toString` bez ścieżki), `PathKindTest`, w `FakeProjectsApiTest` `pathKind decides what is at a path`, `realPath decides the stored directory`, `unresolvable path returns NotFound with the normalized path`, w `FakeProjectInspectorTest` `report and alreadyAdded use the real path`, `unresolvable path returns NotFound`, a w `ProjectInputRulesTest` wiersze dla katalogu 81 i 255 znaków, `a\nb`, `"   "`, emoji na granicy cięcia i długości w code pointach. Przypadki z symlinkami wymagają systemu plików z dowiązaniami (macOS, Linux).
10. **Znaki sterujące w nazwie** (review, runda 2): poza `isISOControl` odrzucamy (w nazwie jawnej `CONTROL_CHARACTERS`, w zastępczej spacja) kategorie `Character.getType` `FORMAT` (Cf, np. bidi U+202E, U+200B, U+FEFF), `LINE_SEPARATOR` (U+2028), `PARAGRAPH_SEPARATOR` (U+2029) i `SURROGATE` (samotny surogat). Sprawdzamy po code pointach, więc poprawna para surogatów (emoji) przechodzi. Wyjątek: U+200D (ZWJ) jest dozwolony, bo tworzy sekwencje emoji (np. rodzina, flagi).
11. **Podział kontraktu i `alreadyAdded`** (review, runda 2): przypadki ścieżek (normalizacja, symlinki, w tym pętla, brakujące ścieżki) przeniesione do `ProjectsApiPathContract`, z którego dziedziczy `ProjectsApiContract`; implementacje nadal rozszerzają tylko `ProjectsApiContract` (limit 400 linii na plik). Test współbieżnego `add` startuje wszystkie wywołania z bramki `CompletableDeferred`. `InspectionWorld.registered: List<Project>` (zamiast proponowanego `List<Path>`, żeby kontrakt sprawdzał dokładne id) pokrywa `alreadyAdded` w `ProjectInspectorContract`, także przez symlink; `FakeProjectInspector` bierze zarejestrowane projekty z `projects`, a gdy go nie ma, z `world.registered`.
