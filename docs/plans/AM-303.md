# AM-303 · DirectoryInspector (git, CLAUDE.md, sesje, hooki)

Issue: #23 · Wymagania: FR-P2, ENG-C6, ENG-C8, ENG-I4, ENG-I5, ENG-M9, ENG-T2, ENG-T3 · docs/11 §4, §6, ADR 0004, ADR 0010 (proponowana) · Etap: M3

## Zakres

`DirectoryInspector` (`internal`) w `feature:projects:impl` implementuje `ProjectInspector` i przechodzi `ProjectInspectorContract` na prawdziwym `git` i prawdziwych plikach w `@TempDir`. Publiczna jest nowa, osobna fabryka `projectInspectorModule(...)` (zapowiedź z AM-302, pyt. 4).

Nie robimy: zmian `projects:api` (KDoc z AM-301, decyzja 8, jest specyfikacją), wpięcia w `app`, UI (AM-304), instalacji hooków (AM-602), rozróżniania „brak repo” od „git niedostępny”.

## Moduły

- `feature:projects:impl` (kod, testy). `docs/adr/0010-rozpoznawanie-hookow-am.md` (szkic).
- `build.gradle.kts`: `implementation` `:feature:agent-runtime:api` (`AgentRuntime`, `HookKind`, `RuntimePhase`), `:core:process` (`ProcessRunner`); `testImplementation` `testFixtures(:feature:agent-runtime:api)` (`FakeAgentRuntime`, `aRuntimeSession`), `testFixtures(:core:process)` (`FakeProcessRunner`). Reguła zależności nr 2 z docs/11 (`impl` → `api` innych feature, `core:*`) i `ModuleRules` (zabronione tylko `impl`/`ui`) na to pozwalają. Bez nowych bibliotek: JSON przez `kotlinx-serialization-json`, który `core:storage` już daje jako `api`.

## Zmiany API

`projects:api`, `agent-runtime:api`: brak. Publiczna fabryka (druga funkcja publiczna w `impl`; Konsist sprawdza tylko klasy, interfejsy i obiekty):

```kotlin
/**
 * Creates the read-only [ProjectInspector] (FR-P2). Thread-safe and stateless; [projects] is read on every
 * call, so `alreadyAdded` follows the current list. git, the runtime and both settings files are probed
 * in parallel; [gitTimeout] limits each git call, the runtime applies its own timeout.
 * The long parameter list is deliberate: `impl` may expose only factories, so no public settings type.
 *
 * @param io dispatcher for `toRealPath()` and file reads, usually `AppDispatchers.io`.
 * @param logger gets fixed categories only, never paths, branch names or process output (ENG-C8).
 * @param gitExecutable `git` on the login-shell PATH, or an absolute path (tests).
 */
@Suppress("LongParameterList")
public fun projectInspectorModule(
    projects: ProjectsApi, runtime: AgentRuntime, process: ProcessRunner, io: CoroutineDispatcher, logger: Logger,
    gitExecutable: String = "git", gitTimeout: Duration = 5.seconds,
): ProjectInspector
```

Wewnętrzne (KDoc po angielsku; hierarchie `sealed` jako `sealed class`, Konsist):

```kotlin
internal class DirectoryInspector(projects: ProjectsApi, runtime: AgentRuntime, git: GitProbe,
                                  io: CoroutineDispatcher, logger: Logger) : ProjectInspector
internal class GitProbe(process: ProcessRunner, executable: String, timeout: Duration, logger: Logger) {
    suspend fun info(dir: Path): GitInfo?                       // adapter: the only place that runs git
}
internal object GitCommands {                                  // pure argv builders
    fun isInsideWorkTree(exe: String): List<String>            // [exe, "--no-optional-locks", "-c", "core.fsmonitor=false", "rev-parse", "--is-inside-work-tree"]
    fun branch(exe: String): List<String>                      // [exe, "--no-optional-locks", "-c", "core.fsmonitor=false", "symbolic-ref", "--quiet", "--short", "HEAD"]
}
internal object GitOutput { fun isWorkTree(r: ProcessResult): Boolean; fun branch(r: ProcessResult): String? }   // pure
internal sealed class SettingsRead { object Missing; data class Text(val text: String); data class Unreadable(val reason: String) }
internal object SettingsFiles { const val MAX_BYTES = 1 shl 20; suspend fun read(file: Path, io: CoroutineDispatcher): SettingsRead }
internal object OurHooks {                                     // pure, ADR 0010
    fun kinds(settingsText: String): Outcome<Set<HookKind>, String>   // Err = fixed category
    fun presence(reads: List<SettingsRead>): HooksPresence
}
internal object ActiveSessions { fun count(listed: Outcome<List<RuntimeSession>, RuntimeError>): Int? }  // pure
internal object ClaudeMd { suspend fun present(dir: Path, io: CoroutineDispatcher): Boolean }
```

### Decyzje

1. **Przebieg `inspect`**: `ProjectInputRules.normalizeDir` → `RealPaths.resolve` (z AM-302, ten sam wynik co `add`). Błąd → `Err`, bez git i runtime. Potem `coroutineScope` z czterema `async` (git, sesje, `ClaudeMd`, dwa pliki ustawień) i `alreadyAdded = projects.projects.value.firstOrNull { it.dir == real }?.id`. Bez wstrzykiwanego `CoroutineScope` (structured concurrency, ENG-C6). Najgorszy przypadek to około `max(2 × gitTimeout, timeout runtime)`, czyli ok. 10 s.
2. **git**: dwa wywołania w `workDir = real`, każde z `RunOptions(timeout = gitTimeout, maxOutputBytes = 4 KiB)`. `rev-parse --is-inside-work-tree` daje `true` w katalogu głównym, podkatalogu i worktree z plikiem `.git`, a `false` w `.git` i w repo bare (→ `null`). `symbolic-ref --quiet --short HEAD` działa też na gałęzi bez commitów (świeży `git init`). Przy detached HEAD zwraca kod 1 bez wyjścia, co daje `GitInfo(null)`. `--no-optional-locks` (KDoc `ProjectInspector`) i `-c core.fsmonitor=false`: obce repo nie może uruchomić skonfigurowanego w nim polecenia. Każdy `ProcessError` (`NotFound`, `Timeout`, `StartFailed`, `IoFailed`), kod ≠ 0 z pierwszego wywołania (też `dubious ownership`) → `null`. Drugie wywołanie zakończone błędem procesu → `null` (wynik niepewny, nie zgadujemy).
3. **Sesje**: `runtime.listSessions(under = real)`. `Err` (dowolny `RuntimeError`) → `null`. Liczymy tylko `WORKING` i `BLOCKED`; `DONE`, `FAILED`, `STOPPED` to sesje zakończone, bo `claude agents` bez `--all` je ukrywa (AM-203; pyt. 2).
4. **`hasClaudeMd`**: `Files.isRegularFile` (podąża za symlinkiem) dla `real/CLAUDE.md` lub `real/.claude/CLAUDE.md`, na `io`. Katalog o tej nazwie się nie liczy. `SecurityException` → `false`.
5. **Hooki: czytamy pliki sami, nie przez `HookInstaller`** (ADR 0010). `HookInstaller.status(HookScope.Project(dir))` opisuje tylko `settings.local.json`, a FR-P2 i KDoc `HooksPresence` wymagają też `settings.json` (wspólne ustawienia z repo). Implementacji `HookInstaller` jeszcze nie ma (AM-602), więc `app` nie miałby czego wstrzyknąć. Rozszerzenie `HookScope` byłoby zmianą `agent-runtime:api`. Reguła rozpoznawania „naszego” hooka trafia do ADR 0010, który AM-602 ma stosować. Ze `agent-runtime:api` bierzemy tylko `HookKind`, więc lista zdarzeń jest jedna.
6. **Ustawienia** (`SettingsFiles.read`, na `io`): brak pliku → `Missing`; nie zwykły plik, `IOException`, `SecurityException`, rozmiar > 1 MiB, niepoprawny UTF-8 → `Unreadable(kategoria)`. Odczyt tylko `newInputStream`/`readAllBytes`, bez blokad i zapisu. `OurHooks.kinds`: niepoprawny JSON, korzeń nie jest obiektem, `hooks` nie jest obiektem → `Err(kategoria)`; głębsze odstępstwa od kształtu (zdarzenie nie jest tablicą, handler nie jest obiektem) są pomijane. `presence`: dowolne `Unreadable`/`Err` → `UNREADABLE`; w przeciwnym razie suma rodzajów z obu plików: pusta → `NONE`, wszystkie `HookKind.entries` → `INSTALLED`, inaczej `PARTIAL`.
7. **Logowanie** (ENG-C8): tylko DEBUG i stałe kategorie: `inspect git unavailable` (`process:not-found|timeout|start-failed|io-failed`, `git:exit`), `inspect runtime unavailable` (nazwa typu `RuntimeError`), `inspect settings unreadable` (kategoria, `shared|local`). Nigdy nie logujemy ścieżki, nazwy gałęzi, stdout/stderr git, treści ustawień ani komunikatów wyjątków (kotlinx.serialization cytuje wejście, patrz Lekcje).

## Decyzje z implementacji

1. **`OurHooks` ma dwie dodatkowe funkcje**: `kindsOf(read: SettingsRead)` (`Missing` → pusty zbiór, `Unreadable` → `Err(kategoria)`, `Text` → `kinds`) i `presenceOf(results)`. `presence(reads)` z planu zostaje i składa się z nich. Dzięki temu `DirectoryInspector` parsuje każdy plik raz i loguje kategorię z informacją `shared|local`.
2. **Stałe kategorie**: pliki `file:not-regular`, `file:too-large`, `file:invalid-utf8`, `file:io`, `file:security`; JSON `json:invalid`, `json:root-not-object`, `json:hooks-not-object`. Logi: `inspect git unavailable` (`reason`), `inspect runtime unavailable` (`error` = nazwa typu `RuntimeError`), `inspect settings unreadable` (`reason`, `file`). Wszystkie na DEBUG, bez `cause`.
3. **`SettingsFiles.read`**: `Files.readAttributes` (podąża za symlinkiem), `NoSuchFileException` → `Missing` (także zerwany symlink), potem `newInputStream().readNBytes(MAX_BYTES + 1)`, więc plik rosnący w trakcie odczytu też daje `file:too-large`. UTF-8 dekodowany ściśle (`CodingErrorAction.REPORT`). Wyjątki mapuje `catching` z `core:domain`, komunikaty są odrzucane.
4. **Reguła URL (ADR 0010)**: `java.net.URI`; schemat `http` i host porównywane bez wielkości liter (RFC 3986), ścieżka dokładnie `/hooks`, port i query dowolne; niepoprawny URL to nie nasz hook. `type` musi być dokładnie `"http"`. `"hooks": null` traktujemy jak „`hooks` nie jest obiektem” (`Err`).
5. **Log `git:exit`** tylko dla kodu ≠ 0 z pierwszego wywołania; `rev-parse` z kodem 0 i `false` (katalog `.git`, repo bare) nie jest błędem i nie jest logowany.
6. **`DiskWorld` (test)**: `"s%07d".format(Locale.ROOT, it)` zamiast formatu z domyślną lokalizacją. Detekt (`ImplicitDefaultLocale`) blokował bramkę; wynik jest ten sam, zachowanie testu się nie zmienia.
7. **git w neutralnym katalogu (review S1, zmienia decyzję 2)**: oba wywołania mają `workDir = /`, a sprawdzany katalog podaje `git -C <realPath>` (`GitCommands.isInsideWorkTree(exe, dir)`, `branch(exe, dir)`). Gdy PATH powłoki logowania ma `.` albo pusty element, powłoka szukałaby `git` w katalogu roboczym, czyli w niezaufanym katalogu użytkownika. Wybrany `/`, nie katalog domowy: zawsze istnieje, należy do roota i nie wymaga nowego parametru fabryki (`agentRuntimeModule` ma `homeDir` bez wartości domyślnej, więc „spójna” wartość domyślna nie istnieje); `~` bywa zapisywalny przez dowolny proces użytkownika. Ścieżka jest absolutna (`/…`), więc nie da się jej pomylić z opcją. Test integracyjny `git planted in the inspected dir is never run` ustawia `HOME` na `tempDir` z `.profile` dodającym `.` na początek PATH, sprawdza, że pułapka działa (polecenie z `workDir` = katalog uruchamia podłożony `git`), a potem, że inspekcja go nie uruchamia. Przy starym `workDir` test jest czerwony (sprawdzone mutacją).
8. **`GitOutput.branch` przy `stdoutTruncated` → null (review S2)**: ucięta odpowiedź to niepewny wynik, nie zgadujemy nazwy gałęzi.
9. **`-c core.hooksPath=/dev/null` (review S6)** w bezpiecznych opcjach obok `core.fsmonitor=false`: obecne polecenia nie uruchamiają hooków, ale opcja zamyka tę drogę, gdyby lista poleceń się zmieniła. Pilnuje jej `GitCommandsTest`.

## Ryzyka i pytania

Pytania blokujące: brak. Pytania do człowieka (niczego nie blokują, plan przyjmuje rekomendację):

1. **ADR 0010: reguła „nasz hook”** (handler `type: "http"`, URL `http`, host `127.0.0.1` lub `localhost`, ścieżka `/hooks`, dowolny port, nagłówek `X-AM-Token` bez względu na wielkość liter; zdarzenia jak `HookKind`). Wiąże AM-602, który zapisuje hooki dokładnie w tym kształcie (docs/03). Rekomendacja: przyjąć. Alternatywa: wspólna czysta funkcja w `agent-runtime:api` (`HookKind.eventName`, znacznik nagłówka) to zmiana `api` innego feature, więc osobne zadanie przed AM-602.
2. **Co jest „aktywną” sesją.** Rekomendacja: `WORKING` + `BLOCKED`, bo to samo pokazuje `claude agents` bez `--all`. Alternatywa: także `DONE` (sesja czeka na kolejny prompt).
3. **Wpięcie w `app`.** Rekomendacja jak w AM-302 pyt. 2: AM-304 (albo zadanie wpinające `agent-runtime:impl`) dodaje `ProcessRunner` i `AgentRuntime` do `CoreDeps` i woła fabrykę.

Ryzyka:

- macOS bez Xcode CLT: `/usr/bin/git` to nakładka, która może pokazać systemowy dialog instalacji i zakończyć się kodem ≠ 0. Wynik to `git = null` (zgodnie z KDoc), ale dialog jest widoczny dla użytkownika. Sprawdzenie ręczne na Macu przed scaleniem; ewentualna poprawka to osobne zadanie (`xcode-select -p` przed wywołaniem git).
- Każde wywołanie git startuje powłokę logowania (`LoginShellProcessRunner`), co kosztuje ok. 100–300 ms. Trzy procesy na inspekcję wystarczą dla dialogu dodawania; UI (AM-304) pokazuje stan „sprawdzanie”.
- APFS bez rozróżniania wielkości liter: `claude.md` liczy się jak `CLAUDE.md` na macOS, ale nie na Linuksie. Testy używają dokładnej nazwy.
- Snapshot kontraktu porównuje mtime, nie atime; odczyt ustawień zmienia tylko atime.
- Hooki w `~/.claude/settings.json` (zakres globalny) nie są częścią raportu (KDoc `HooksPresence`); UI nie może z `NONE` wnioskować, że zdarzeń nie będzie.
- PR: kod produkcyjny ok. 250 linii, poniżej limitu ENG-C10.
- `LoginShellProcessRunner` loguje `workDir` na DEBUG (review S3). Inspektor podaje teraz `/`, ale ścieżka trafia do argv, a inne wywołania mogą podać katalog projektu. Przy wpinaniu w `app` (AM-304) logger runnera nie może zapisywać ścieżek albo DEBUG musi być wyłączony.
- git w testach inspektora (kontraktowych i integracyjnych) dziedziczy środowisko procesu testów (`GIT_*`, `~/.gitconfig`) — izolowany jest tylko `TestGit` (przygotowanie repozytoriów). Znane ograniczenie (review S4): nietypowa konfiguracja dewelopera może zmienić wynik testu.
