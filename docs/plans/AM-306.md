# AM-306 · Grupy projektów z podfolderami

Issue: #119 · Wymagania: FR-P7 (FR-P8 robi AM-307), FR-S9, FR-K1, ENG-I1–I8, ENG-C2, ENG-C8 · docs/11 §3, §10 · ADR 0009, 0024, 0026 · Zależy: AM-305, AM-816

Pojęcia (jedno słowo = jedna rzecz): **grupa** = projekt z co najmniej jednym podfolderem; **podfolder** = bezpośredni podkatalog katalogu projektu wybrany jako pozycja grupy (np. `soft` w `plant-puls/`); **katalog główny** = sam katalog projektu.

## Zakres

1. Podfoldery projektu zapisane w `projects.json` (schemat 2, ADR 0026). Edycja: menu ⋯ wiersza i paleta „Podfoldery projektu…” otwierają dialog z listą bezpośrednich podkatalogów z dysku (bez ukrytych i symlinków) do zaznaczenia (rozstrzygnięcie 3).
2. Sidebar: wiersz grupy ze strzałką zwijania (niefokusowalna, `Role.Button`, etykieta „Zwiń/Rozwiń grupę”), pod nim wiersze podfolderów z wcięciem, ikoną folderu i licznikami czekających i pracujących (`AmCounter`). Podfoldery posortowane bez wielkości liter. Wiersz projektu nadrzędnego liczy wszystkie sesje projektu (jak dziś).
3. Klik w podfolder: Mission Control pokazuje tylko sesje, których `cwd` leży w podfolderze; nagłówek „plant-puls / soft”, pigułka ścieżki podfolderu, liczba sesji i kafelki liczników z podfolderu; segmenty Wszystkie/Aktywne/Zakończone działają w obrębie podfolderu. Okruszki i pasek stanu pokazują „plant-puls / soft”.
4. Paleta: „Przejdź do: plant-puls / soft” dla każdego podfolderu i „Podfoldery projektu…”.

Nie robimy: przeglądu grupy z kafelkami podprojektów (AM-307), zmian `sessions:api` (`Session.project` dalej wybiera najgłębszy projekt), zapisu stanu zwinięcia (pytanie 6), podfolderów zagnieżdżonych głębiej niż jeden poziom, automatycznego odświeżania listy podfolderów przy zmianach na dysku.

Pod AM-307: `Project.subfolders` i czysta `ProjectGroups.subfolderOf(project, cwd)` w `projects:api` wystarczą, by `mission-control:ui` policzył czekających per podfolder z migawki bez zmian `api`.

## Zmiany API

Według rozstrzygnięć 1–2. `projects:api`:

```kotlin
/** @property subfolders positions of the group in the sidebar (FR-P7): names of direct subdirectories of [dir],
 *  distinct, sorted ignoring case, then by code point; empty = not a group. User data (ENG-C8). */
public data class Project(val id: ProjectId, val dir: Path, val displayName: String,
    val subfolders: List<SubfolderName> = emptyList())

/** Name of one direct subdirectory of a project, e.g. `soft`; valid only from [ProjectInputRules.subfolderName]
 *  or [ProjectInspector.subfolders]. `toString` hides the value (ENG-C8). */
@JvmInline public value class SubfolderName(public val value: String)

/** What the sidebar has selected: [project], and [subfolder] when a subfolder row is selected (FR-P7). */
public data class ProjectFocus(val project: ProjectId, val subfolder: SubfolderName? = null)

/** Pure rules of groups, no IO (ENG-C9). */
public object ProjectGroups {
    /** `project.dir.resolve(name.value)`. */
    public fun dirOf(project: Project, name: SubfolderName): Path
    /** The subfolder of [project] that equals or contains [cwd] by path components (`soft` does not contain
     *  `software`); null for the project directory itself, outside every subfolder, outside the project or a
     *  relative [cwd]. [cwd] is normalized purely, like `SessionRules.projectFor`. */
    public fun subfolderOf(project: Project, cwd: Path): SubfolderName?
}

// ProjectInputRules
/** Rejects blank, `.`, `..`, a `/`, a leading dot, control characters and > MAX_DISPLAY_NAME_LENGTH code points. */
public fun subfolderName(text: String): Outcome<SubfolderName, ProjectError>

// ProjectsApi
/** Replaces the subfolders of [id]; keeps id, dir, name and position. Duplicates are dropped, the list is sorted
 *  (see [Project.subfolders]); empty = no group. Each name must pass [ProjectInputRules.subfolderName] and be a real
 *  directory directly under [Project.dir], not a symlink (checked on the io dispatcher outside the lock); at most
 *  [ProjectInputRules.MAX_SUBFOLDERS] (64). Atomic like the other commands.
 *  Errors: UnknownProject, InvalidSubfolder, StorageFailed. */
public suspend fun setSubfolders(id: ProjectId, subfolders: List<SubfolderName>): Outcome<Unit, ProjectError>

// ProjectInspector
/** Direct subdirectories of [dir] that can be subfolders: not hidden, not symlinks, readable; sorted like
 *  [Project.subfolders]; at most MAX_SUBFOLDERS (the rest is cut). Read-only.
 *  Errors: NotAbsolute, NotFound, NotADirectory. */
public suspend fun subfolders(dir: Path): Outcome<List<SubfolderName>, ProjectError>

// ProjectError
/** [name] was rejected for [reason]; `toString` hides the name. */
public data class InvalidSubfolder(val name: SubfolderName, val reason: SubfolderProblem) : ProjectError
public enum class SubfolderProblem { NOT_A_NAME, HIDDEN, MISSING, NOT_A_DIRECTORY, SYMLINK, TOO_MANY }
```

`projects:ui` (widzi `app`): `ProjectsController.focus: StateFlow<ProjectFocus?>` obok `selection` (bez zmian, `focus?.project`); `ProjectsIntent.Select(id, subfolder: SubfolderName? = null)`; `ProjectsIntent.EditSubfoldersRequested`; `ProjectsMenuState.canEditSubfolders`. `mission-control:ui`: konstruktor `MissionControlController(sessions, projects, selected: StateFlow<ProjectFocus?>, clock, scope, logger, tick)` zamiast `selectedProject` (liczba parametrów bez zmian).

## Ryzyka i pytania

Pytania blokujące: brak.

Rozstrzygnięte przez człowieka (2026-11-07, wszystkie warianty rekomendowane):

1. **Zmiana `projects:api`: (a)** pole `Project.subfolders` + `setSubfolders` + `ProjectInspector.subfolders` + `ProjectFocus` (jak wyżej). Odrzucone: osobny `ProjectGroupsApi` z plikiem `groups.json` (dane jednego projektu w dwóch plikach) i wariant bez zmian `api` (wyklucza wybór ręczny i zapis).
2. **Format `projects.json`: (a)** schemat 2, klucz `subfolders` zapisywany tylko, gdy niepusty (ADR 0024), migracja 1→2 bez zmiany danych, ADR 0026 (przyjęta). Odrzucony schemat 1 z nowym kluczem, bo starsza wersja aplikacji po cichu kasowałaby podfoldery przy zapisie.
3. **Wybór podfolderów: (b)** ręcznie w dialogu z listy bezpośrednich podkatalogów z dysku, zapis zaznaczonych. Odrzucone: wybór automatyczny (zaśmieca sidebar katalogami typu `node_modules`, `build`) i mieszany (zapis wykluczeń i samoczynnie pojawiające się pozycje).
4. **Zagnieżdżone projekty: (a)** sesja trafia do najgłębszego projektu (`SessionRules.projectFor`, bez zmian); podfolder, który jest osobnym projektem, jest w dialogu wyłączony z dopiskiem „jest osobnym projektem”. Odrzucone: pierwszeństwo grupy (zmiana `sessions:api`) i blokada dodania projektu w grupie (zmiana kontraktu `add`).
5. **Sesje w katalogu głównym lub w niezaznaczonym podkatalogu: (a)** liczą się tylko w wierszu projektu nadrzędnego, który pokazuje wszystkie sesje projektu; `subfolderOf` zwraca null, więc AM-307 może pokazać „Pozostałe” bez zmian `api`. Odrzucona dodatkowa pozycja „Katalog główny” w grupie.

Decyzje przyjęte w planie (do potwierdzenia przez człowieka):

- **6.** Stan zwinięcia grupy: tylko w pamięci, grupy rozwinięte po starcie. Zapis wymagałby nowego klucza w `projects.json` albo `window.json`.
- **7.** Podfolder usunięty z dysku: zostaje na liście (bez IO przy starcie), w dialogu jest zaznaczony z dopiskiem „brak na dysku”, można go odznaczyć.

Ryzyka: wielkość liter na APFS (`Soft` i `soft` to ten sam katalog) — nazwy biorę z listingu dysku i porównuję po ścieżce rzeczywistej; `cwd` sesji w symlinkowanym podfolderze nie trafi do grupy (podfolder-symlink jest odrzucany, więc to nie powstanie); kolejność emisji `focus` i `SelectSession` (Lekcja o `ProjectsIntent.Select`) — test okna z popupu; `stateIn` o krok w tyle przy szybkim kliku w strzałkę i wiersz — `update` czyta bieżące `ui.value`.

## Odstępstwa i decyzje z implementacji (2026-11-07)

- **Wielkość liter na APFS (rozstrzygnięcie).** Reguły czyste (`ProjectGroups.subfolderOf`, serializer) porównują składniki ścieżki dokładnie, więc `Soft` ≠ `soft`; testy i plan są spójne, bo ścieżkę rzeczywistą sprawdza dopiero `SubfolderChecks.resolve` (impl, na `io`): nazwa wpisana inaczej niż na dysku jest zamieniana na pisownię z listingu katalogu (`Files.newDirectoryStream` + `isSameFile`), a nazwy oznaczające ten sam katalog zlewają się w jedną (test `a name spelled with other case gives the name the disk lists`, `case-insensitive APFS duplicate is stored once`). Serializer odrzuca tylko dokładne duplikaty, bo do pliku trafiają wyłącznie nazwy po `resolve` (ADR 0026, punkt 4). Pozostałe ryzyko: plik edytowany ręcznie z `Soft` i `soft` naraz zostaje przyjęty jako dwa podfoldery (to dwa wiersze jednego katalogu); nie psuje to danych, a wystarczy raz zapisać listę w dialogu.
- **Sortowanie w UI.** Wiersze podfolderów sidebaru sortuje `SUBFOLDER_ORDER` także w UI (test podaje `bob, Anna` w nieposortowanym polu), kontrakt `api` nadal gwarantuje kolejność.
- **Podział kontrolera.** `ProjectsController` dostał `SubfolderFlow` (lista i zapis) oraz `RemoveFlow` (dotychczasowy przepływ usuwania); `onEvent` kieruje do nich przez `handle(event, dialog): Boolean`. Wiersz projektu dostaje `RowState` i `RowActions` (ENG-C2, `GroupRows.kt`).
- **Strzałka bez ikony.** Design system nie ma ikony szewronu, więc strzałka to glif `▸`/`▾` w `AmText` w `GroupRows.kt` (`projects:ui`); `core:design-system` bez zmian.
- **Semantyka `selected` wiersza sesji (Mission Control).** Testy okna sprawdzają `assertIsSelected` na wierszu sesji; wiersz nie miał takiej semantyki (zaznaczenie było tylko tłem), więc dodano `semantics { selected = row.selected }` w `SessionRows.kt`.
- **Zmienione testy (z uzasadnieniem).** `RecordingInspector.subfolders` czeka teraz na bramkę `gated` jak `inspect` (test `listing shows a waiting state until the disk answers` wymaga stanu `LISTING` do `release()`); `ProjectsControllerTest` i `ProjectsControllerRenameTest` oczekują `canEditSubfolders = true` przy zaznaczonym projekcie bez dialogu (test `menu allows editing subfolders only with a selection and no dialog`).
- **Identyfikatory komend palety bez nazw podfolderów (review).** Paleta loguje `commandId` na INFO, więc komenda podfolderu ma id `projects.goto.<id>.sub<i>` (pozycja na posortowanej liście), a nie `...<nazwa>` (ENG-C8). Test `no command id holds the name of a subfolder`.
- **Jedna kolejność podfolderów.** `ProjectGroups.order` w `projects:api` zastępuje trzy kopie komparatora (impl, UI, fake'i). `SessionScope.visible`, `SessionActions.target` i `SessionPreview.key` nie mają już domyślnej pustej listy projektów (cichy pusty wynik); zawężanie do podfolderu to jedno `Session.isIn` w `GlobalView.kt`.
- **Pisownia z dysku.** `SubfolderChecks` sprawdza reguły nazwy jeszcze raz dla pisowni z dysku (NFC/NFD na APFS mogą zmienić długość) i przy szukaniu tego samego katalogu pomija symlinki.
- **Dialog.** Fokus wraca na „Anuluj” tylko po pojawieniu się błędu zapisu, nie po jego wyczyszczeniu przełączeniem wiersza; komunikat `MISSING` podpowiada odznaczenie pozycji „brak na dysku”.
- **Nowe testy z review:** `JsonProjectStoreSubfoldersTest` (projekt usunięty w trakcie sprawdzania dysku), `ProjectsReducerGroupTest` (strzałka pod dialogiem, pamięć zwiniętych grup), test zaznaczonego podfolderu, który stał się osobnym projektem, test symlinku przy dopasowaniu pisowni.
