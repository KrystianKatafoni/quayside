# AM-307 · Przegląd grupy projektu

Issue: #121 · Wymagania: FR-P8, FR-S9, FR-K1, NFR-6, ENG-I1–I8, ENG-C2 · docs/11 §1, §3 · ADR 0026 · Zależy: AM-306, AM-816

Pojęcia jak w AM-306: **grupa** = projekt z podfolderami; **podfolder** = pozycja grupy (w roadmapie „podprojekt”, w UI i w kodzie zawsze „podfolder”); **pozostałe** = sesje grupy w katalogu głównym albo w niezaznaczonym podkatalogu (`ProjectGroups.subfolderOf` = null); **przegląd** = nowa sekcja strony grupy.

## Zakres

1. Strona grupy w Mission Control (wybrany wiersz projektu, bez podfolderu) dostaje pod kafelkami liczników sekcję **„Podfoldery”**: karta z wierszem dla każdego podfolderu: ikona folderu, nazwa, liczniki `AmCounter` czekających (WARN), z błędem (ERR) i pracujących (WORK), zera ukryte; wiersz bez takich sesji pokazuje „brak agentów”. Pod listą sesji grupy bez zmian.
2. Kolejność: najpierw wiersze z czekającymi, potem z błędem, potem z pracującymi, potem reszta; w obrębie poziomu `ProjectGroups.order` (bez wielkości liter). Liczba nie zmienia kolejności w poziomie, więc wiersze nie skaczą przy każdej migawce.
3. Wiersz „Pozostałe” na końcu, tylko gdy pozostałe sesje mają czekających, błędy lub pracujących; nieklikalny (patrz decyzja 3).
4. Klik w wiersz podfolderu: `app` wysyła `ProjectsIntent.Select(id, subfolder)`; sidebar zaznacza wiersz podfolderu (zwinięta grupa się rozwija), Mission Control przez `focus` → `Selection.onFocus` pokazuje stronę podfolderu (AM-306). Jedna droga jak klik w sidebarze, bez osobnej zmiany `Selection` w MC.
5. Liczby z `SessionMonitor.snapshot` (wszystkie stany, `Session.project == grupa`), niezależne od segmentów Wszystkie/Aktywne/Zakończone. Podczas wczytywania przeglądu nie ma; przy migawce nieaktualnej jest, z banerem.

Nie robimy: zmian `sessions:api` i `projects:api`, nowych skrótów i komend palety (dojście klawiaturą daje istniejąca komenda „Przejdź do: projekt / podfolder”, FR-K1), przeglądu w trybie terminala, klikalnego „Pozostałe”, zapisu stanu przeglądu.

## Zmiany API

`sessions:api`, `projects:api`: brak. `mission-control:ui` (publiczne tylko dla `app`):

```kotlin
public class MissionControlHandlers(
    public val onAttach: () -> Unit = {},
    public val onReply: () -> Unit = {},
    public val keyCaps: SessionKeyCaps? = null,
    /** A click on a subfolder row of the group overview (FR-P8); `app` selects that focus in the sidebar,
     *  Mission Control follows through `selected`. Never called for the "Pozostałe" row. */
    public val onOpenSubfolder: (ProjectFocus) -> Unit = {},
)
```

Wewnętrzne:

```kotlin
/** One subfolder row: [stats] count the sessions of the group whose directory is in [name] (FR-P8). */
internal data class SubfolderStats(val name: SubfolderName, val stats: SessionStats)

/** The overview of group [project]: [rows] in display order; [rest] = sessions outside every subfolder,
 *  null when none of them waits, works or failed. */
internal data class GroupOverview(val project: ProjectId, val rows: List<SubfolderStats>, val rest: SessionStats?)

internal object GroupOverviews {
    /** Null when [project] has no subfolders. Counts only sessions with `project == project.id` (a nested project
     *  keeps its own); tiers: waiting > 0, failed > 0, working > 0, the rest; inside a tier [ProjectGroups.order]. */
    fun of(project: Project, sessions: List<Session>): GroupOverview?
}

// MissionControlEvent: a click on a subfolder row; MissionControl hands it to handlers.onOpenSubfolder.
data class OpenSubfolder(val focus: ProjectFocus) : MissionControlEvent
// Screen.Project: + val overview: GroupOverview? = null  (only with selection.subfolder == null and not loading)
```

Composable: `GroupOverviewView(overview: GroupOverview, onEvent: (MissionControlEvent) -> Unit)`; wiersz rozbity na `OverviewRow` i `OverviewCells` jak `SubfolderRow` (LongMethod 30, ENG-C2 ≤ 5). Karta na `panel` z ramką `border`, wysokość `heightIn(max = 168.dp)` z `verticalScroll`; wiersz: `focusProperties { canFocus = false }` + `selectable`/`clickable` z `Role.Button`, semantyka scalona z tekstem nazwy; liczniki z opisem z odmianą („1 czeka”, „2 czekają”, „5 czeka”; „{0} z błędem”; „1 pracuje”, „2 pracują”). Rysowane pary: text/panel, muted/panel (oba w `ContrastAudit`), `AmCounter` (kolory z `core:design-system`). Bez tła hover i bez `raised` (muted/raised nie jest audytowane).

## Ryzyka i pytania

Pytania blokujące: brak (bez zmian `api`; zakres rozstrzygnął człowiek 2026-11-07).

Decyzje przyjęte w planie (do potwierdzenia przez człowieka):

1. **Kiedy pokazać przegląd.** Wybrane: (a) sekcja nad listą sesji na stronie grupy, zawsze po wybraniu grupy. Odrzucone: (b) przegląd zamiast listy sesji (traci widok wszystkich sesji grupy), (c) przełącznik „Przegląd/Lista” (dodatkowy stan i skrót bez potrzeby).
2. **Wiersze, nie kafelki.** Do 64 podfolderów; wiersz jest niski i zgodny z sidebarem, kafelki `AmStatCard` dublowałyby kafelki liczników strony. Karta ograniczona do ok. 4,5 wiersza z przewijaniem, czekające są na górze.
3. **„Pozostałe” nieklikalne.** Klik wymagałby fokusu „poza podfolderami”, czyli nowego wariantu `ProjectFocus` w `projects:api`; lista pod przeglądem i tak pokazuje te sesje. Gdy człowiek chce klikalne „Pozostałe” → osobne zadanie ze zmianą `api`.
4. **Sortowanie poziomami** (czeka > błąd > pracuje > reszta), remis i wnętrze poziomu: `ProjectGroups.order`. Odrzucone sortowanie po liczbie (wiersze skaczą pod kursorem).
5. **Grupa bez sesji:** wszystkie wiersze z „brak agentów”, bez „Pozostałe”; przegląd zostaje, by dało się kliknąć podfolder.
6. **Klawiatura:** wiersze nigdy nie biorą fokusu (Space i ⏎ zostają skrótami okna); dojście bez myszy przez paletę „Przejdź do: projekt / podfolder”. Bez nowych skrótów.
7. **Zwinięta grupa** rozwija się przy wyborze jej podfolderu (także z palety), bo inaczej sidebar nie pokazuje zaznaczenia.

8. **Odmiana liczebnika.** Opis licznika zgadza czasownik z liczbą (1 czeka, 2–4 czekają, 5+ i 12–14 czeka; tak samo pracuje/pracują) przez `MissionControlStrings.plural(klucz, liczba)` z kluczami `.one`/`.few`/`.many` (`overview.waiting`, `overview.working`); „z błędem” nie odmienia się. Testy miały „2 czeka” i „3 pracuje” (błąd) — poprawione w `GroupOverviewMessagesTest` (przypadki 1, 2, 4, 5, 12, 14, 21, 22, 112), `GroupOverviewScreenTest`, `GroupOverviewLookScreenTest`, `GroupOverviewHost`, `GroupOverviewWindowTest`. `countText` paska stanu (AM-816, `StatusBar.kt`, ten sam moduł; `.one` albo liczba mnoga) i `countText` szyny w `projects:ui` zostały bez zmian. Ujednolicenie odmiany (jeden helper dla paska stanu, szyny i przeglądu) to osobne zadanie, nie ten PR.
9. **Test kolorów liczników z tolerancją.** `counters use the warn err and work tones` porównywał piksele dokładnie; krawędzie koła różnią się o 1–2 poziomy kanału, gdy licznik leży w innym miejscu niż wzorzec (zaokrąglenia float w Skia przy dużym przesunięciu), więc test pada bez względu na ton. Porównanie ma teraz tolerancję 2 poziomów na kanał (karta ma `clip(shape.card)` jak `AmPanel`, żeby przewinięta treść nie wystawała poza zaokrąglony róg; test z `clip` przechodzi z tą tolerancją); zły ton nadal pada (różnica rzędu 100).
10. **Test dodany po mutacjach:** przypadek „błąd poza podfolderami tworzy Pozostałe” w `GroupOverviewsTest` (mutacja „Pozostałe tylko dla czekających i pracujących” przeżywała).

Ryzyka: `verticalScroll` może dodać fokusowalny kontener — test Tab; kolejność emisji `focus` → `onFocus` po kliku (Lekcja o `ProjectsIntent.Select`) — test okna; kolory `AmCounter` nie są widoczne w czystej funkcji — test pikselowy z referencją; nazwa podfolderu jest danymi użytkownika — nie trafia do logów ani `commandId` (nie dodajemy komend).
