# AM-308 · Nowy agent w podfolderze grupy projektu

Issue: #139 · Wymagania: FR-S3, FR-P7, NFR-6, ENG-I1–I8, ENG-C2, ENG-C8 · docs/11 §4 · Zależy: AM-306, AM-608

**Status planu: zatwierdzony.** Człowiek potwierdził: zmianę `sessions:api` (wariant A), dopisanie `projects:ui` do modułów oraz test z fałszywym `claude` tylko w `agent-runtime:impl`. Zmiana `sessions:api` jest konieczna: `SessionCommands.start(project, spec)` bierze katalog wyłącznie z `Project.dir`, a `NewSessionSpec` nie ma pola katalogu. Obejście z `mission-control:ui` (np. `AgentRuntime.start` z `cwd` podfolderu) łamie granice modułów i omija nakładkę migawki, więc go nie projektujemy.

Pojęcia jak w AM-306/307: **grupa** = projekt z `Project.subfolders`; **podfolder** = jedna z tych nazw; **katalog projektu** = start bez podfolderu (dzisiejsze zachowanie).

## Zakres

1. Okno „Nowy agent”: pod listą projektów druga lista `AmDropdown` „Podfolder”, widoczna tylko, gdy wybrany projekt jest grupą. Pozycje: „Katalog projektu” (start w `Project.dir`), potem podfoldery w `ProjectGroups.order`. Kolejność Tab: projekt, podfolder, prompt, … Fokus startowy bez zmian (prompt).
2. Domyślnie zaznaczony fokus sidebaru (`ProjectsController.focus`): podfolder, gdy należy do projektu z listy; inaczej katalog projektu. Zmiana projektu na liście czyści podfolder.
3. `sessions:impl` sprawdza podfolder przed `claude --bg`: nazwa musi być dokładnie (z wielkością liter) jedną z `Project.subfolders`, a `dirOf` musi być katalogiem na dysku i nie dowiązaniem (jak `ProjectInspector.subfolders`). Błąd → `Outcome.Err(SessionError.SubfolderUnavailable)`, runtime nie jest wołany.
4. Sesja startuje z `cwd` = `Project.dir/<podfolder>`; nakładka migawki ma ten sam `cwd`, więc sesja od razu trafia do filtra i liczników podfolderu (`ProjectGroups.subfolderOf`, AM-306/307).
5. Po starcie `app` zaznacza w sidebarze ten podfolder (`ProjectsIntent.Select(id, subfolder)`), potem `MissionControlIntent.SelectSession(project, id, subfolder)`; MC pokazuje stronę podfolderu z zaznaczoną sesją.

Nie robimy: wyboru dowolnego katalogu, sprawdzania istnienia `Project.dir`, nowych komend palety ani skrótów, zmian `projects:api`, zmiany zachowania innych wywołań `SelectSession` (Attach, paleta sesji).

## Zmiany API

`sessions:api` (zgoda człowieka, wariant A). `sessions:api` zależy tylko od `core:domain`, więc nazwa to `String`, nie `SubfolderName`:

```kotlin
/** ...existing KDoc...
 * @property subfolder name of one of the project's subfolders (`Project.subfolders`, FR-P7) to start in;
 *  null = the project directory. Not blank. User data: [toString] shows it as `***` (ENG-C8). */
public data class NewSessionSpec(
    val prompt: String, val name: String? = null, val agent: String? = null, val model: String? = null,
    val permissionMode: SessionPermissionMode? = null,
    val subfolder: String? = null,
)

// SessionCommands.start KDoc: "in the directory of [project], or in its [NewSessionSpec.subfolder]" +
// Errors: [SessionError.UnknownProject], [SessionError.SubfolderUnavailable], [SessionError.Runtime].

/** The subfolder of a start cannot be used; never carries its name (ENG-C8). */
public data class SubfolderUnavailable(val project: ProjectId, val problem: SubfolderProblem) : SessionError

public enum class SubfolderProblem {
    /** Not one of the project's subfolders (also a path such as `../x` or a different letter case). */
    NOT_IN_PROJECT,
    /** One of them, but not a directory on disk (missing, a file or a symlink). */
    MISSING,
}
```

`sessions:impl` (wewnętrzne):

```kotlin
/** Where a start runs (AM-308). [isDirectory] = `Files.isDirectory(p, NOFOLLOW_LINKS)` on `io`. */
internal class StartDirs(private val projects: ProjectsApi, private val isDirectory: suspend (Path) -> Boolean) {
    fun has(project: ProjectId): Boolean
    /** Project dir for null; else checks membership, then the disk. The root dir is never checked. */
    suspend fun resolve(project: ProjectId, subfolder: String?): Outcome<Path, SessionError>
}
```

Stan po wdrożeniu: martwa `NewAgentRules.defaultProject` jest usunięta (`open` używa `defaultFocus`, a jej przypadki pokrywa tabela `defaultFocus`); `PollingHarness` składa moduł ręcznie (szew dysku `missing` bez zmiany fabryki).

`sessionsModule`: `io == null` → `isDirectory = { true }` (KDoc: brakujący katalog zgłosi wtedy runtime jako `COMMAND_FAILED`); bez nowego parametru fabryki.

`mission-control:ui` (publiczne tylko dla `app`): `NewAgentController.open(focus: ProjectFocus?)`, `onStarted: (ProjectFocus, SessionId) -> Unit`, `MissionControlIntent.SelectSession(project, id, subfolder: SubfolderName? = null)`. Wewnętrzne: `NewAgentForm.subfolder: SubfolderName? = null` (ukryte w `toString`), `NewAgentRules.defaultFocus(selected: ProjectFocus?, projects): Pair<ProjectId?, SubfolderName?>`, `NewAgentRules.withProject(form, id): NewAgentForm`, `failureOf` z kluczami `newAgent.failure.subfolder.notInProject` / `.missing`.

## Ryzyka i pytania

Pytania blokujące: brak. Odpowiedzi człowieka: (1) wariant A zmiany `sessions:api`; (2) `projects:ui` w modułach zadania; (3) test z fałszywym `claude` tylko w `agent-runtime:impl` (pełny test end-to-end w `app` wymagałby przeniesienia `FakeClaude` do `testFixtures` — osobne zadanie). Odrzucone warianty zmiany API: B — `start(project, spec, subfolder)` (parametr domyślny w interfejsie), C — dowolny `cwd: Path` (bez walidacji), D — `SubfolderName` w `core:domain` (zmiana `projects:api`).

Decyzje przyjęte domyślnie, do potwierdzenia w review PR:

1. Druga lista `AmDropdown`, nie wiersze pod projektem: spójne z polami okna, ukryta dla zwykłych projektów (bez zmian UI dla nich).
2. Walidacja w `sessions:impl` (źródło prawdy); UI nie sprawdza dysku, a lista projektów w oknie jest migawką z otwarcia.
3. Wielkość liter rozróżniana; dowiązanie to `MISSING` (zgodnie z `ProjectInspector.subfolders`, a `cwd` dowiązania nie pasowałby do `subfolderOf`).
4. `NOT_IN_PROJECT` czyści podfolder w formie (jak `UnknownProject` czyści projekt); `MISSING` zostawia formę.

Ryzyka:

- Podfolder zarejestrowany też jako osobny projekt: sesja należy do projektu zagnieżdżonego (`SessionRules.projectFor`), więc nie trafi do filtra grupy, a `app` zaznaczy podfolder grupy. Przypadek opisać w KDoc `start`; test kontraktowy `` `start in a subfolder that is a nested project belongs to that project` `` (fake ustala projekt przez `SessionRules.projectFor`, jak impl). Skutek w UI: `selectStartedSession` zaznaczy wtedy projekt zagnieżdżony (jego katalog), nie podfolder grupy. Naprawa poza zakresem.
- APFS bez rozróżniania wielkości liter: zapisana nazwa `Marketing` przy katalogu `marketing` przejdzie `isDirectory`, a `cwd` (realna ścieżka) nie trafi do `subfolderOf`, więc sesja nie pojawi się w filtrze podfolderu.
- Kolizja nazwy `SubfolderProblem` w `sessions.api` i `projects.api`: przy wspólnym imporcie w jednym pliku potrzebny alias (`import ... as ...`).
- Zaufanie workspace Claude Code dla podkatalogu: jeśli `claude --bg` uzna podfolder za niezaufany, start kończy się `COMMAND_FAILED` z istniejącym tekstem; do sprawdzenia ręcznie na macOS.
- `ProjectsController.focus` czytane przy otwarciu może być o krok w tyle po kliku w sidebar (Lekcja o `stateIn`) — test okna klikiem i od razu ⌘N.
- Nazwa podfolderu to dane użytkownika: nie w logach, `SessionError` ani ID komend palety.
