# AM-309 · Zaufanie katalogu z okna „Nowy agent”

Issue: #157 · Wymagania: FR-S3, NFR-5 (duch), NFR-6, ENG-C2, ENG-C8, ENG-I1–I8 · [ADR 0031](../adr/0031-zaufanie-katalogu-w-claude-json.md) (proponowana) · Zależy: AM-608

## Zakres

Gdy `claude --bg` kończy się `Workspace not trusted`, okno „Nowy agent” nie pokazuje ogólnego `COMMAND_FAILED`, tylko krok zgody „Zaufać katalogowi <ścieżka>?” w tym samym oknie (formularz i prompt zostają w stanie). Po zgodzie `WorkspaceTrust` ustawia `hasTrustDialogAccepted: true` dla dokładnie tego katalogu w `~/.claude.json` (reguły w ADR 0031, punkty 3–9) i kontroler ponawia start z tym samym formularzem.

Nie robimy: zaufania z innych miejsc (respawn, terminal), cofania zaufania w UI, blokady pliku Claude Code (nie wiadomo, czy istnieje; ADR 0031, ryzyka), `CLAUDE_CONFIG_DIR` per konto (AM-1003), kopii zapasowej (ADR 0031, punkt 7).

## Zmiany API (wymagają zgody człowieka, patrz pytania 1–3)

```kotlin
// agent-runtime:api, AgentRuntime.kt, w RuntimeError
/** `claude --bg` refused the workspace: it is not trusted in Claude Code (ADR 0031). Carries no path (ENG-C8). */
public data object WorkspaceNotTrusted : RuntimeError

// agent-runtime:api, WorkspaceTrust.kt
/**
 * Trusts one workspace directory in Claude Code's user config (`.claude.json`, ADR 0031) so that `claude --bg` may
 * start there. Call only after the user agreed. May be called from any dispatcher; never blocks the calling thread and
 * never throws except cancellation.
 */
public fun interface WorkspaceTrust {
    /**
     * Sets `hasTrustDialogAccepted` to true for the real path of [dir] (`toRealPath`) only, never for its parents, and
     * keeps every other value of the file. `Ok` without writing when it is already true. Never writes when the file
     * is missing, unreadable or not in the expected shape; the write is atomic and retried on a concurrent change.
     */
    public suspend fun trust(dir: Path): Outcome<Unit, TrustError>
}

/** Why [WorkspaceTrust.trust] wrote nothing. Fixed categories, never paths or file content (ENG-C8). */
public enum class TrustError {
    /** [dir] does not exist or is not a directory. */ DIRECTORY_MISSING,
    /** The config file does not exist; Claude Code has never run for this user. */ CONFIG_MISSING,
    /** The config file is a symbolic link or larger than 16 MiB. */ CONFIG_UNSUPPORTED,
    /** The config file could not be read. */ CONFIG_UNREADABLE,
    /** Not UTF-8 JSON in the expected shape (root, `projects`, entry objects; boolean flag). */ CONFIG_INVALID,
    /** Another process changed the file on every attempt. */ CONCURRENT_CHANGE,
    /** The temporary file or the atomic move failed. */ WRITE_FAILED,
}

// agent-runtime:impl (public fabryka); configHome = katalog z `.claude.json` (dziś katalog domowy)
public fun workspaceTrustModule(configHome: Path, io: CoroutineDispatcher, logger: Logger): WorkspaceTrust

// sessions:api, SessionError.kt, w RuntimeProblem
/** Claude Code refused to start in a directory it does not trust. */
WORKSPACE_NOT_TRUSTED,

// mission-control:ui (publiczne, woła je app); ENG-C2: porty w jednym typie zamiast 6. parametru
public data class NewAgentPorts(val commands: SessionCommands, val projects: ProjectsApi, val trust: WorkspaceTrust)
public class NewAgentController(ports: NewAgentPorts, scope: CoroutineScope, logger: Logger,
    onStarted: (ProjectId, SessionId) -> Unit)
```

Typy wewnętrzne `mission-control:ui`: `NewAgentState.trust: TrustStep?` (`TrustStep(dir: Path, saving: Boolean)`; non-null = krok zgody zamiast pól), `NewAgentState.trustTried: Boolean`, zdarzenia `TrustAccept`, `TrustDecline`, problemy `NotTrusted(dir)`, `TrustFailed(dir)`, `TrustIneffective(dir)`. Wpływ na `when`: `toProblem` w `sessions:impl` (wyczerpujący), `NewAgentRules.runtimeKey` (wyczerpujący); `HaikuSummaryRefiner` ma `else`; fake'i bez zmian (`failNext` przyjmuje nowe wartości).

## Reguły

1. **Rozpoznanie** (`BgOutput.untrusted(stderr)`): kod ≠ 0 i linia po `TerminalText.clean` + `trim` zaczyna się od `Workspace not trusted` (wielkość liter ma znaczenie). Sprawdzane na surowym stderr przed `StderrTail`, nigdzie nie logowane. Kod 0 z ID wygrywa (sukces).
2. **Merge** (`TrustJson.withTrust(text, key): Outcome<String?, TrustError>`, `null` = bez zmian): brak `projects` → dopisany na końcu; brak wpisu → `{"hasTrustDialogAccepted":true}`; wpis bez pola → pole dopisane na końcu wpisu. Ścisłe typy (`isString` przy booleanie, lekcja). Wyjście: `prettyPrint`, wcięcie 2 spacje (`@OptIn(ExperimentalSerializationApi::class)`), końcowy `\n` jak w wejściu.
3. **IO** (`ClaudeJsonTrust`, `Mutex`, `withContext(io)`): `toRealPath` katalogu → kontrola pliku (istnieje, nie dowiązanie, ≤ 16 MiB) → odczyt bajtów A i uprawnień → merge → plik tymczasowy w tym samym katalogu z uprawnieniami oryginału → odczyt B; `B ≠ A` → nowa próba (≤ 3) → `ATOMIC_MOVE` bez obejścia → `finally` usuwa plik tymczasowy. Wąskie gardła IO (`maxBytes`, `beforeCommit`, `move`) w `internal class TrustTuning`, czwartym parametrze konstruktora (domyślny `move` = `ATOMIC_MOVE`), tylko dla testów. Liczby w wyjściu zapisują się dosłownie przez `JsonUnquotedLiteral` (domyślny enkoder zamienia `1e3` na `1000.0`). Wyjątki łapane w adapterze, komunikaty nie trafiają do logów.
4. **Kontroler.** `Err(Runtime(WORKSPACE_NOT_TRUSTED))` przy `trustTried == false` i projekcie z listy → `trust = TrustStep(project.dir)`, bez problemu. Przy `trustTried == true` → `TrustIneffective`. `TrustAccept` (ignorowany przy `saving`) → `saving = true`, `trust.trust(dir)`; `Ok` → `trustTried = true`, start z bieżącym formularzem (ta sama ścieżka co `Submit`, `busy` jak w AM-608); `Err` → krok znika, `TrustFailed`, log `warn` z kategorią (`TrustError.name`). `Submit` w kroku zgody jest ignorowany (⌘⏎ nic nie robi). `TrustDecline` i `Cancel` w kroku zgody → krok znika, `NotTrusted` (okno zostaje otwarte). Każdy `Submit` użytkownika zeruje `trustTried`. `Edit` w kroku zgody ignorowany.
5. **Widok kroku zgody** (`NewAgentTrust.kt`): tytuł „Zaufać katalogowi?”, ścieżka w osobnej linii (`{0}`, String), ostrzeżenie (ton WARN): Claude Code uruchomi wtedy ustawienia, hooki i serwery MCP z tego katalogu; zapis w `~/.claude.json`. Przyciski `DialogButton` „Anuluj” i „Zaufaj i uruchom” (oba z `amFocusFrame`, oba fokusowalne Tabem). Fokus startowy na „Anuluj” (`LaunchedEffect(trust)`); ⌘⏎ w kroku zgody nic nie robi; Escape = `TrustDecline`. Po zniknięciu kroku fokus wraca na prompt (istniejący efekt na `problem`). Kolory z `AmTheme` przez `Tone`/`mutedColor()` jak reszta okna (audyt katalogu motywów pokrywa NFR-6).
6. **Teksty** (ścieżka zawsze parametrem `{0}`): `NotTrusted` i `TrustFailed` → instrukcja ręczna z AM-608 (⌘T, `claude`, akceptacja); `TrustIneffective` → „Zapisano zaufanie, ale Claude Code nadal odmawia; może używać innego pliku konfiguracji (`CLAUDE_CONFIG_DIR`)” + ta sama instrukcja. `COMMAND_FAILED` traci zdanie o zaufaniu.
7. **Logi**: kontroler — `project`, kategoria; adapter — `changed`, kategoria. Nigdy ścieżka, treść pliku, stderr.

## Ryzyka i pytania

Pytania blokujące (zmiany `api`; rekomendacja w nawiasie):

1. `agent-runtime:api`: dodać `RuntimeError.WorkspaceNotTrusted` (data object, bez ścieżki) oraz nowy port `WorkspaceTrust` + `TrustError` (enum) w kształcie z „Zmian API”? (Tak; zgodne z decyzją 2 AM-608 i opcją 2 z 2026-11-09. Alternatywa: port w `sessions:api` — odrzucona, bo `sessions:impl` musiałby edytować pliki Claude Code albo delegować do `agent-runtime`).
2. `sessions:api`: dodać `RuntimeProblem.WORKSPACE_NOT_TRUSTED`? Wartość trafi też do `SnapshotStatus.Stale` (listing jej nie zwraca, ale teksty `fresh.*` muszą istnieć, bo testy iterują `entries`). (Tak, jak w roadmapie).
3. Nowa krawędź zależności `mission-control:ui` → `agent-runtime:api` (dozwolona regułą 1 z docs/11 §3, ale nowa) i zmiana publicznego konstruktora `NewAgentController` na `NewAgentPorts`? (Tak).

Pytania niezablokowane (plan przyjmuje rekomendację): brak kopii zapasowej `~/.claude.json` (ADR 0031, punkt 7); ponowna serializacja zamiast edycji bajtowo-wiernej (punkt 5); status ADR 0031 do zmiany na „przyjęta” przez człowieka.

Ryzyka:

- Obejście zabezpieczenia Claude Code i zapisy równoległe do współdzielonego pliku: ADR 0031. Działająca sesja może cofnąć wpis — wtedy `TrustIneffective` z instrukcją ręczną, bez pętli.
- `CLAUDE_CONFIG_DIR` w powłoce logowania użytkownika: `claude` czyta inny plik niż `~/.claude.json`; skutek jak wyżej. Nie czytamy środowiska powłoki (wymagałoby `ProcessRunner` w porcie).
- Klucz `toRealPath` niepotwierdzony nagraniem dla katalogu z dowiązaniem (`/var` vs `/private/var`); wpis do ręcznego sprawdzenia w `docs/compat.md`.
- AM-308 (start w podfolderze) zmieni `cwd` startu; krok zgody musi brać ten sam katalog co `start`. Które zadanie wejdzie drugie, poprawia źródło `dir` w kontrolerze.
- Strażniki bez skutku w UI (`saving`, `Edit` w kroku zgody) mają testy kontrolera; test „pada po usunięciu linii” sprawdzić mutacją (Lekcje). `NewAgentController` blisko TooManyFunctions — krok zgody jako osobne funkcje rozszerzające albo plik pomocniczy.
