# AM-312 · Stare sesje z dysku na liście sesji projektu

Issue: #170 · Wymagania: FR-P9, FR-S9, NFR-6 · ENG-I1–I8, ENG-C2, ENG-C8, ENG-C10, ENG-T1–T6 · ADR 0024, 0029, nowy 0032 (szkic) · Zależy: AM-311 (scalone, PR #189) · Blokuje: AM-313, AM-314

Status: **zaimplementowane**; pytania blokujące 1–4 rozstrzygnął człowiek (odpowiedzi 1, 2, 3a, 4a z podziałem „podfolder: n” tylko dla projektu z podfolderami). Odstępstwa od planu w sekcji „Odstępstwa” na końcu.

## Zakres

Sesje Claude Code z plików `<claudeHome>/projects/*/<uuid>.jsonl`, których nie zna supervisor (interaktywne i stare), pojawiają się na liście sesji projektu jako zatrzymane (`SessionState.Stopped`), z plakietką „z dysku”. Jeden PR (decyzja człowieka: przekroczenie ENG-C10 bez pytania o podział).

1. **Port odczytu (wariant A z AM-311).** `SessionHistory` w `agent-runtime:api`; za nim `FileSessionHistory` w `agent-runtime:impl` na istniejącym `SessionFileReader`/`SessionFiles` (głowa i ogon po 64 KiB, nigdy całość). Filtr wieku po `mtime` przed odczytem (M6), wstępny odsiew katalogów przez `SessionFiles.candidates`, decyzja po `startCwd` w katalogu projektu (M4). Pamięć podręczna wyników po (ścieżka, rozmiar, `mtime`). Port tylko czyta: nie ma metody, która zapisuje lub usuwa.
2. **Scalanie w `sessions:impl`.** Czysta funkcja `DiskSessions.merge`: deduplikacja z listą supervisora (UUID = `RuntimeSession.conversationId` albo pierwsze 8 znaków UUID = `RuntimeSession.id`, M8), przypisanie projektu `SessionRules.projectFor(startCwd)` (najgłębszy projekt), ukryte sesje, limit liczby per projekt (najnowsze po `modifiedAt`), mapowanie na `Session` (`id` = UUID, `name` = tytuł albo 8 znaków UUID, `state = Stopped`, `summary = null`, `meta` puste, `origin = DISK`). Skan dysku: przy starcie, po zmianie katalogów projektów, po zmianie ustawień (od razu) i co 60 s (`HISTORY_INTERVAL`); między skanami deduplikacja liczy się przy każdym listowaniu. Sesje z dysku nie emitują `SessionEvent`, a reduktor dostaje poprzednią migawkę bez nich.
3. **Ustawienia** (globalne): wiek 7 / 30 / 90 dni / bez limitu (domyślnie 30), liczba na projekt 50 / 200 / 1000 (domyślnie 200). Plik `session-history.json` (ADR 0032), zapis tylko odstępstw (ADR 0024). Okno „Stare sesje z dysku…” (paleta i menu) oraz te same dwa wybory w oknie potwierdzenia dodania folderu. Zmiana działa od razu.
4. **UI listy** (`mission-control:ui`): plakietka „z dysku” (tekst i etykieta czytnika, nie sam kolor), plakietka miejsca jak dziś (AM-310). Sesja z dysku jest w filtrach „Wszystkie” i „Zakończone”, nigdy w „Aktywne”, w widokach Czeka/Pracuje/Gotowe/Błędy, w kafelkach `SessionStats` ani w licznikach panelu (wynika z `Stopped`, testy to przypinają). Akcje: tylko „Usuń” (pytanie 3); bez Attach, Odpowiedz, Respawn i Podglądu. Gdy limit ucina listę: ostatni wiersz „jeszcze N starszych · Zmień limit” (odmiana `PluralForm`), link otwiera okno ustawień; tylko na stronie projektu (grupy), nie podfolderu.
5. **Okno po dodaniu folderu** (`projects:ui`): po udanym `add` kontroler czeka (najdłużej 30 s) na migawkę z kluczem projektu w `SessionsSnapshot.history`; gdy `shown > 0`, jednorazowe okno „Znaleziono N starych sesji (podfolder: n, folder główny: m). Pokazać?” (pytanie 4). Inny dialog, usunięcie projektu albo upływ czasu porzuca oczekiwanie.

**Nie robimy:** „Wznów” (AM-313), ręcznego przypisania do podfolderu (AM-314), `customTitle` jako tytułu, gałęzi i modelu dla sesji z dysku, poprawki kodowania w `FileSessionMetaSource` (AM-818, osobny `/triage`), `CLAUDE_CONFIG_DIR` (dziś `claudeHome = ~/.claude`, jak AM-818).

## Zmiany API (pytania blokujące 1 i 2: nic z tego nie jest zatwierdzone)

```kotlin
// agent-runtime:api — SessionHistory.kt
/** Read-only access to Claude Code session files (ADR 0032). Any dispatcher; never blocks, never throws except
 *  cancellation; never writes, moves or deletes a file. */
public fun interface SessionHistory {
    /** Sessions whose start directory (first absolute `cwd`, docs/compat.md M1–M2) is one of [dirs] or below, from
     *  files modified at or after [since] (null = any age). Reads at most 64 KiB from the start and the end of a file.
     *  Files that are not listable sessions are skipped. Newest [PastConversation.modifiedAt] first. A missing
     *  `projects` directory is `Ok(empty)`. Errors: [HistoryError]. */
    public suspend fun list(dirs: List<Path>, since: Instant?): Outcome<List<PastConversation>, HistoryError>
}
/** One session file. [title] (first user message, ≤ 80 code points) is user data: `toString` hides it (ENG-C8). */
public data class PastConversation(
    val conversationId: ConversationId, val startCwd: Path, val startedAt: Instant?, val lastActivityAt: Instant?,
    val modifiedAt: Instant, val cwdChanged: Boolean, val title: String?,
)
/** Why the listing failed as a whole; a single bad file is skipped, not an error. Fixed categories, no paths. */
public enum class HistoryError { UNREADABLE }
```

public enum class HistoryAge(public val days: Int?) { DAYS_7(7), DAYS_30(30), DAYS_90(90), UNLIMITED(null) }

    /** Current settings; the defaults when nothing is stored or the file cannot be used. */
    public val settings: StateFlow<SessionHistorySettings>
    /** Saves `change(current)`, then publishes it; nothing is published when saving fails. */

        Outcome<SessionHistorySettings, HistorySettingsError>
}

## Ryzyka i pytania

**Pytania blokujące (decyzja człowieka przed startem):**

1. **Zmiana `agent-runtime:api`:** nowy port `SessionHistory`, `PastConversation`, `HistoryError` (sygnatury wyżej). Zgoda?
2. **Zmiana `sessions:api`:** `Session.origin` + `SessionOrigin` (UUID jako `Session.id` dla `DISK`), `SessionsSnapshot.history` + `ProjectHistory`, typy ustawień i `SessionHistorySettingsRepo`, zmiany KDoc `respawn`/`remove`/`stop`/`recentOutput` (bez nowego typu błędu: `UnknownSession`). Zgoda? Alternatywa dla `origin`: `fromDisk: Boolean` (prostsze, gorzej dla AM-313).
3. **Co robi „Usuń” przy sesji z dysku.** (a, rekomendacja) ukrywa na stałe: UUID w `hidden` w `session-history.json`, plik sesji zostaje; (b) ukrywa do restartu aplikacji (bez zapisu); (c) brak „Usuń” w AM-312.
4. **Okno „Znaleziono N starych sesji. Pokazać?”.** (a, rekomendacja) „Pokaż” zaznacza projekt i filtr „Zakończone”, „Nie teraz” zamyka; sesje są widoczne w „Zakończone” w obu przypadkach, bez zapisu per projekt; (b) „Nie” wyłącza stare sesje dla tego projektu na stałe (nowa flaga w pliku i w API). Do tego: świeżo dodany projekt nie ma podfolderów, więc „podfolder: n” wyjdzie 0 — pokazywać podział tylko, gdy projekt ma podfoldery (rekomendacja)?

**Pytania nieblokujące** (domyślnie w nawiasie): sesje z dysku także w filtrze „Wszystkie” (tak); `customTitle` jako tytuł (nie, osobne zadanie); ponowny skan co 60 s (tak); wiersz „jeszcze N starszych” na stronie podfolderu (nie).

**Ryzyka:**

- **Żywa sesja interaktywna jako „zatrzymana”.** Sesja otwarta teraz w terminalu, nieznana supervisorowi, ma świeży plik i pojawi się jako `Stopped`. Plakietka „z dysku” to łagodzi; AM-313 musi pamiętać o R4 (kopia z nowym UUID).
- **Dane użytkownika (ENG-C8).** Tytuł z pierwszej wiadomości trafia do `Session.name`; logi tylko liczby i kategorie, `PastConversation.toString` bez tytułu, test.
- **Koszt skanu bez limitu wieku:** tysiące plików po 1 ms (M6) co 60 s; pamięć podręczna po `mtime` sprowadza ponowny skan do `stat`. Zimny dysk niezmierzony.
- **Format nieudokumentowany:** zmiana w Claude Code daje pustą historię, nie błąd okna; `docs/compat.md` i `/compat-check`.
- **`stateIn` o krok w tyle (Lekcje):** oczekiwanie na `history` po `add` czyta `snapshot.value` przed `first {}`.
- **Rozmiar PR** ok. 4× limitu ENG-C10; kolejność commitów: 1) ADR, plan, `docs/11`; 2) `agent-runtime:api` + fake + kontrakt; 3) `FileSessionHistory`; 4) `sessions:api` + fake'i + kontrakty; 5) `DiskSessions`, `HistoryScan`, ustawienia, komendy; 6) `mission-control:ui`; 7) `projects:ui`; 8) `app`, testy okna, CHANGELOG, `docs/05`, `compat.md`.
