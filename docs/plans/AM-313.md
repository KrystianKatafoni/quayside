# AM-313 · Wznów starą sesję z dysku

Issue: #171 · Wymagania: FR-P9, FR-S4 · ENG-I1–I8, ENG-C2, ENG-C8, ENG-C10, ENG-T1–T6 · ADR 0002, 0032 (bez nowego ADR) · Zależy: AM-312 (scalone, PR #191) · Pomiar: `docs/compat.md` M9, R1–R5

Status: **w realizacji**; pytania blokujące 1–3 rozstrzygnięte przez człowieka (warianty a, a, b zgodnie z rekomendacją).

## Zakres

Sesja z dysku (`SessionOrigin.DISK`) dostaje akcję „Wznów”: `claude --bg --resume <uuid>` w katalogu startu sesji (`Session.cwd` = `startCwd`), bez promptu i bez flag (R5: flaga daje kopię; compat: „Wznów nie wymaga promptu”, sesja czeka na prompt jako `AwaitingInput`). Jeden PR (decyzja człowieka: przekroczenie ENG-C10 bez pytania o podział).

1. **Bez zmiany `api` się nie da.** `AgentRuntime` nie ma `--resume` (`StartSpec` wymaga promptu, `respawn` działa tylko na zadaniu supervisora). `SessionCommands.respawn` dla `DISK` daje dziś `UnknownSession` (KDoc), a wznowienie zmienia `Session.id` (UUID → 8 znaków albo id kopii), więc UI musi dostać nowe id. Alternatywa bez nowej metody w `sessions:api` (respawn dla `DISK` = wznowienie) też zmienia kontrakt `api` (KDoc, fake, kontrakt) i gubi zaznaczenie — pytanie 2.
2. **Respawn zostaje dla sesji supervisora** (compat: to samo zadanie, bez nowego UUID). „Wznów” jest tylko dla `DISK`; dla `SUPERVISOR` daje `UnknownSession` (lustro dzisiejszego `respawn` dla `DISK`).
3. **Sprawdzenia przed startem** (`sessions:impl`, bo nieistniejący UUID daje kod 0 i dopiero potem `failed`): świeże listowanie supervisora (jak każda komenda), sesja jest `DISK` i nieukryta, plik rozmowy nadal jest na dysku (`SessionHistory.list(listOf(cwd), since = null)` zawiera UUID z tym samym `startCwd`; pamięć podręczna po `mtime`, więc tanio), katalog startu istnieje (`StartDirs.isDirectory`). Każde niepowodzenie kończy się bez wołania `claude`.
4. **Po starcie:** efekt `Expected.Appears` (jak `start`) z `id` z linii `backgrounded · <id>`, fazą `BLOCKED`/`WaitingFor.Input`, `cwd` = katalog startu, nazwą wiersza z dysku i `conversationId` = UUID tylko wtedy, gdy `id` = pierwsze 8 znaków UUID. Deduplikacja z AM-312 (`DiskSessions.merge`) od razu ukrywa wiersz `DISK`; listowanie supervisora wygrywa z efektem (także stan `failed`, gdy plik zniknął między sprawdzeniem a startem).
5. **Kopia (R4: rozmowa otwarta w interaktywnym `claude`)** — `id` ≠ 8 znaków UUID: oryginał zostaje jako wiersz `DISK`, kopia pojawia się jako nowa sesja; `conversationId` w efekcie = `null` (nowy UUID nieznany). Sposób pokazania: pytanie 2.
6. **Pojedynczo, nigdy zbiorczo:** API przyjmuje jedno id; brak `resumeAll`, palety „wznów wszystkie” i akcji na wielu wierszach. UI blokuje inne akcje w trakcie (`ActionUi.busy`); drugie „Wznów” tej samej sesji po sukcesie trafia na brak wiersza `DISK` → `UnknownSession` (R5: nawet gdyby doszło do `claude`, budzi to samo zadanie).
7. **UI (`mission-control:ui`):** sesja `DISK` ma „Wznów” i „Usuń” (bez Respawn, Attach, Odpowiedz, Podglądu). Po sukcesie zaznaczenie przechodzi na nowe id z filtrem „Wszystkie” (wznowiona sesja nie jest w „Zakończone”), ale tylko gdy użytkownik nie zmienił zaznaczenia w trakcie. Błąd: stały tekst bez nazwy i ścieżki. Paleta (`app`): „Wznów sesję” tylko dla zaznaczonej sesji `DISK`.

**Nie robimy:** promptu przy wznowieniu, wznawiania z innego katalogu niż katalog startu, zaufania katalogu z poziomu „Wznów” (`WorkspaceNotTrusted` = komunikat jak przy starcie, bez dialogu AM-309), wznowienia na innym koncie (AM-1007, ADR 0029), ręcznego przypisania (AM-314), wykrywania rozmowy otwartej w terminalu przed startem (brak niezawodnego sygnału).

## Zmiany API (decyzje człowieka zatwierdzone: pytania 1–3 warianty a, a, b)

```kotlin
// agent-runtime:api — AgentRuntime.kt
/**
 * Resumes a conversation the supervisor does not know (`claude --bg --resume <uuid>`, no prompt, no flags) in
 * [ResumeSpec.cwd]; returns the id from `backgrounded · <id>`. The id is the first 8 characters of the UUID when the
 * same conversation woke; any other id is a copy with a new UUID (conversation open in another Claude Code process,
 * docs/compat.md R4). Does not check that the conversation exists: the CLI answers 0 for an unknown UUID and the job
 * turns [RuntimePhase.FAILED] later. Errors: [RuntimeError.WorkspaceNotTrusted], [RuntimeError.CommandFailed],
 * [RuntimeError.Unparseable], [RuntimeError.Timeout], [RuntimeError.NotInstalled].
 */
public suspend fun resume(spec: ResumeSpec): Outcome<SessionId, RuntimeError>

/** What to resume. A data class so that AM-1007 can add a prompt or an account without breaking callers. */
public data class ResumeSpec(val conversation: ConversationId, val cwd: Path)
```

```kotlin
// sessions:api — SessionCommands.kt
/**
 * Resumes one [SessionOrigin.DISK] session in its start directory ([Session.cwd], FR-P9); never several at once.
 * Before `resume` returns, the snapshot shows the live session under [ResumedSession.id] (waiting for a prompt) and no
 * longer the disk one, unless it is a copy. A [SessionOrigin.SUPERVISOR] session: [SessionError.UnknownSession],
 * use [respawn]. Checks before Claude Code is called: the session file is still on the disk, the start directory
 * exists. Errors: [SessionError.UnknownSession], [SessionError.ResumeUnavailable], [SessionError.Runtime].
 */
public suspend fun resume(id: SessionId): Outcome<ResumedSession, SessionError>

/** @property id the live session. @property copy true: the conversation was open elsewhere, a copy runs and the disk
 *  session stays on the list unchanged (docs/compat.md R4). */
public data class ResumedSession(val id: SessionId, val copy: Boolean)

// SessionError.kt (pytanie 3, wariant b)
/** The disk session [id] cannot be resumed; never carries a path (ENG-C8). */
public data class ResumeUnavailable(val id: SessionId, val problem: ResumeProblem) : SessionError
public enum class ResumeProblem { /** The session file is gone. */ FILE_MISSING, /** The start directory is gone. */ DIRECTORY_MISSING }
```

KDoc do zmiany (Lekcja o starych wyliczeniach): `SessionOrigin.DISK` („every command except remove and stop”), `SessionError.UnknownSession`, `SessionsApi.commands`, `SessionCommands.respawn`, `MissionControlController` („only the stop, respawn and remove commands”), `SessionControl.otherControls`, `SessionActionsState`. Błąd odczytu historii przy sprawdzaniu (`HistoryError.UNREADABLE`) = `Runtime(COMMAND_FAILED)`, jak nieudany zapis ukrycia w AM-312.

## Ryzyka i pytania

**Pytania blokujące (decyzja człowieka przed startem):**

1. **Zmiana `agent-runtime:api`:** `AgentRuntime.resume(spec: ResumeSpec)` + `ResumeSpec` (sygnatury wyżej). Alternatywa: (b) pole `resume: ConversationId?` w `StartSpec` z opcjonalnym promptem — łamie dzisiejszy niepusty `prompt` i miesza dwie komendy. Rekomendacja: (a).
2. **Zmiana `sessions:api`:** (a, rekomendacja) nowa metoda `SessionCommands.resume(id): Outcome<ResumedSession, SessionError>` + `ResumedSession(id, copy)`; łamie implementacje `SessionCommands` (`FakeSessions`, `PreviewSamples` w `app`, fake'i testów `mission-control:ui`). (b) zwrot `Outcome<SessionId, …>` bez `copy`: przy kopii (R4) użytkownik widzi nowy wiersz i stary „z dysku” bez wyjaśnienia. (c) bez nowej metody: `respawn` dla `DISK` wznawia (zmiana KDoc i zachowania); UI nie zna nowego id, zaznaczenie znika, kopii nie da się rozpoznać.
3. **Nowy typ błędu:** (b, rekomendacja) `SessionError.ResumeUnavailable(id, ResumeProblem)` — nowy wariant zapieczętowanego interfejsu wymaga gałęzi `when` w `projects:ui` (`SessionsView.kt`) i `mission-control:ui`; (a) bez nowego typu: brak pliku = `UnknownSession`, brak katalogu = `Runtime(COMMAND_FAILED)` (nieprecyzyjny komunikat), `projects:ui` bez zmian.

**Pytania nieblokujące** (domyślnie w nawiasie): wznowiona sesja czeka na prompt (`AwaitingInput`), więc reduktor wyśle `BecameBlocked` i powiadomienie „czeka” (tak, jak każda sesja czekająca); komenda palety „Wznów sesję” (tak); tekst przycisku „Wznów”, w trakcie „Wznawianie…” (tak; Respawn zostaje „Respawn”).

**ADR:** niepotrzebny — wznowienie to kolejna komenda CLI w ramach ADR 0002, zachowanie opisuje `docs/compat.md` (R1–R5); ADR 0013 odrzuca `--resume` tylko jako odpowiedź działającej sesji.

**Ryzyka:**

- **Kod 0 nie znaczy sukcesu.** Sprawdzenie pliku zawęża okno do czasu między sprawdzeniem a startem; wtedy listowanie pokaże `failed`, a wiersz `DISK` zniknie (deduplikacja po 8 znakach). Test to przypina.
- **Rozmowa otwarta w terminalu (R4)** — wykrywana dopiero po fakcie (id kopii); oryginał nietknięty. Komunikat kopii zależy od pytania 2.
- **Dane użytkownika (ENG-C8):** `name` wiersza (pierwsza wiadomość) przechodzi do efektu; logi tylko id, komenda i kategoria; stderr `note: …` nie trafia do logów ani błędów.
- **`stateIn` o krok w tyle (Lekcje):** kontroler wybiera nowe id z wyniku komendy, nie z migawki; filtr ustawia razem z zaznaczeniem jednym krokiem (jak `showFinished` w AM-312).
- **Zmiana formatu linii `backgrounded`** daje `Unparseable` — wiersz `DISK` zostaje, sesja mogła jednak ruszyć; `/compat-check`.
- **Kolejność commitów:** 1) plan, `docs/11`; 2) `agent-runtime:api` + fake + kontrakt; 3) adapter + `FakeClaude`; 4) `sessions:api` + `FakeSessions` (podział pliku) + `ResumeContract`; 5) `sessions:impl`; 6) `mission-control:ui`; 7) `projects:ui`, `app`, testy okna, CHANGELOG, `docs/05`, `compat.md`.

## Odstępstwa od planu

- **Ikona `RESUME` w `core:design-system`** (poza listą modułów planu): decyzja prowadzącego, bo ikona `RESPAWN` myliłaby dwie różne akcje. `IconKindTest` zmieniony z 22 na 23 ikony, `docs/08` poprawione.
- **`SessionActionRunner.run`** zachowuje sygnaturę `UiText?`; nowe id sesji przekazuje przez wywołanie zwrotne `onResumed` (testy runnera bez zmian).
- **Podział plików pod detekt:** `ResumeCommand`, `StopAll` (sessions:impl) i `BackgroundStart` (agent-runtime:impl); `MissionControlController` traci prywatną `confirmRemove` (wciągnięta do `onEvent`) i zyskuje `onNavigation`.
- **`SessionsState.stillOnDisk`** deleguje do `HistoryScan.stillOnDisk`, bo konstruktor `RuntimeSessionCommands` nie może się zmienić.
- **Teksty:** `action.respawn.failed` zmienione z „Nie udało się wznowić sesji” na „Nie udało się ponownie uruchomić sesji”, żeby nie mylić z „Wznów”.
- **Test poprawiony:** `SessionResumeControllerTest` oczekiwał wierszy od najstarszego, a lista sesji jest od najnowszego `startedAt` (`SessionScope.visible`); kolejność oczekiwana zamieniona w dwóch asercjach.
- **Test dopisany w `agent-runtime:impl`:** `ClaudeCliAdapterByIdFailureTest` (osobna klasa, bo `ClaudeCliAdapterTest` przekracza LargeClass) — `failed id command returns CommandFailed when the listing is not available`. `byId` nie ma już osobnej `isListed`; niedostępne listowanie daje `CommandFailed` komendy, nie `UnknownSession`, a test to przypina.
- **Brak `removeDirectory` w `ResumeContract`:** `sessionsModule` sprawdza katalog przez wstrzykiwane `StartDirs.isDirectory`, którego kontrakt nie umie skryptować (harness nie ma takiego wejścia). Katalog testują `RuntimeSessionResumeTest` (impl) i `FakeSessionsResumeTest` (fake). Ten test wykrył błąd fake'a: `missingDirs + dir` dodawało składniki ścieżki (`Path` jest `Iterable<Path>`), więc `removeDirectory` nic nie robiło; poprawione na `+ setOf(dir)`.
- **`FakeSessions.resume`** nie dopisuje już wpisu do `conversations` (zbędny: deduplikację robi prefiks 8 znaków, a po usunięciu żywej sesji wiersz z dysku ma wrócić jak w impl).
- **Test `the copy notice goes away…`** po zmianie zaznaczenia wybiera z powrotem kopię i sprawdza brak informacji (inaczej mutacja bez zerowania `copied` przeżywała).
- **Bez testu koloru informacji o kopii:** używa `mutedColor()` (ten sam token co tekst „Wznawianie…”, audyt kontrastu motywu liczy muted na panelu); osobny test pikselowy nie wnosi nic nad audyt.
- **Słowo kluczowe „wznów”** usunięte z komendy Respawn w palecie (zostaje przy „Wznów sesję”).
