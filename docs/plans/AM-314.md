# AM-314 · Ręczne przypisanie sesji do podfolderu

Issue: #172 · Wymagania: FR-P9 (też FR-P7, FR-P8, NFR-6) · ENG-I1–I8, ENG-C2, ENG-C8, ENG-C10, ENG-T1–T6 · ADR 0024, 0032, nowy 0033 (szkic) · Zależy: AM-312 (PR #191), AM-313 (PR #193, scalone)

Status: **plan zatwierdzony** (decyzja człowieka 2026-11-11: we wszystkich pytaniach 1–6 wariant a). Sygnatury i format opisują warianty zatwierdzone.

## Zakres

Gdy automat po `cwd` źle umieścił sesję w grupie (np. sesja z dysku zaczęła w `/p` i przeszła do `/p/soft`), użytkownik wybiera jej miejsce ręcznie: „Automatycznie (wg katalogu)”, „folder główny” albo jeden z podfolderów projektu. Jeden PR (decyzja człowieka: przekroczenie ENG-C10 bez pytania o podział).

1. **Komenda** `SessionCommands.assignPlace(id, place)` w `sessions:api`; `place = null` = „Automatycznie” (usuwa wpis). Sprawdza sesję w bieżącej migawce, nie woła Claude Code; zapis przez `SessionHistorySettingsRepo.update`, potem ponowna publikacja (jak `hide` w AM-312).
2. **Zapis** w `session-history.json` pod kluczem `places`, tylko odstępstwa, klucz = UUID rozmowy (albo krótkie id, gdy UUID nieznany), wpis `{project, subfolder?}` (ADR 0033).
3. **Odczyt przed `cwd`:** czysta funkcja `SessionPlaces.resolve` w `sessions:impl` wylicza `Session.assignedDir` przy każdej publikacji migawki i zdarzeń w `SessionsState.publish`. Wpis nieważny (inny projekt, podfolder spoza `Project.subfolders`, nie bezpośrednie dziecko `Project.dir`) jest pomijany. Projekt sesji się nie zmienia.
4. **UI:** każde wyliczenie miejsca przechodzi z `cwd` na `Session.placeDir` (`assignedDir ?: cwd`): `GlobalView.isIn`, `MissionControlReducer` (plakietka miejsca), `GroupOverview`, `SessionsView` i `PastSessionsFlow` w `projects:ui`. Akcja „Przypisz do podfolderu…” w menu wiersza (⋯, prawy klik) i w panelu szczegółów, tylko dla sesji projektu z podfolderami; okno z listą wyborów; panel szczegółów pokazuje „Miejsce: soft (ręcznie)”.

**Nie robimy:** zmiany projektu sesji przez przypisanie, przypisań zbiorczych, automatycznego czyszczenia wpisów, czytania środka pliku sesji, komendy palety (chyba że pytanie 3 = b), zmian w `projects:api`.

## Zmiany API (pytania 1 i 2: zatwierdzone 2026-11-11, wariant a)

```kotlin
// sessions:api — Session.kt: nowe pole na końcu z domyślną (zgodność źródłowa); toString pokazuje je jak cwd
/** @property assignedDir directory the user put the session in (FR-P9, AM-314, ADR 0033): the directory of its
 *  project or one of `Project.subfolders`; null = the place follows [cwd]. Never changes [project]. User data. */
val assignedDir: Path? = null,
/** Directory that decides the place of the session inside its project's group: [assignedDir], else [cwd]. */
val placeDir: Path get() = assignedDir ?: cwd

// SessionCommands.kt
/**
 * Puts session [id] in [place] inside its project, or back to the place by its directory when [place] is null
 * (FR-P9, ADR 0033). Any origin and state; never calls Claude Code; checks the session in the current snapshot. Saved
 * under the conversation, so it survives a [resume]; [Session.assignedDir] shows it before `assignPlace` returns.
 * Null without a saved place writes nothing. Errors: [SessionError.UnknownSession] (also a session outside every
 * project), [SessionError.SubfolderUnavailable] with [SubfolderProblem.NOT_IN_PROJECT] (not exactly one of
 * `Project.subfolders`, e.g. `Soft` for `soft` or `../x`), [SessionError.Runtime] with [RuntimeProblem.COMMAND_FAILED]
 * when saving failed (the place stays as it was).
 */
public suspend fun assignPlace(id: SessionId, place: PlaceAssignment?): Outcome<Unit, SessionError>

/** A place the user picks for a session inside its project (AM-314). */
public sealed interface PlaceAssignment {
    /** The project directory itself ("folder główny"). */
    public data object ProjectRoot : PlaceAssignment
    /** One of `Project.subfolders` by its exact name; not blank. `toString` hides [name] (ENG-C8).
     *  @throws IllegalArgumentException when [name] is blank (a programmer error, like [NewSessionSpec.subfolder]). */
    public data class Subfolder(val name: String) : PlaceAssignment
}

// SessionHistorySettings.kt — nowe pole z domyślną
/** @property places places picked by the user, by conversation UUID (short supervisor id when the UUID is unknown). */
val places: Map<SessionId, StoredPlace> = emptyMap(),
/** One saved place: [project] it was picked in, [place] inside it. `toString` hides the subfolder name. */
public data class StoredPlace(val project: ProjectId, val place: PlaceAssignment)
```

KDoc do zmiany (Lekcja o starych wyliczeniach): `SessionOrigin.DISK` („only remove and resume apply” → także `assignPlace`), `SessionsApi.commands`, `SessionError.UnknownSession`, `SessionError.SubfolderUnavailable` („of a start” → „of a start or a place”), `Session.project` (miejsce z `placeDir`). Fake i impl mapują nieudany zapis tą samą kategorią `Runtime(COMMAND_FAILED)` (Lekcja; kontrakt przypina).

## Ryzyka i pytania

**Pytania blokujące (rozstrzygnięte przez człowieka 2026-11-11: wszędzie wariant a; komendy palety nie robimy):**

1. **Zmiana `sessions:api`** (sygnatury wyżej). (a, rekomendacja) `assignPlace` + `PlaceAssignment` + `Session.assignedDir`/`placeDir` + `SessionHistorySettings.places`/`StoredPlace`; łamie implementacje `SessionCommands` (`FakeSessions`, `PreviewSamples` w `app`, fake'i testów UI). (b) `Session.place: PlaceAssignment?` bez ścieżki: UI liczy miejsce samo, ta sama reguła skopiowana do dwóch modułów `ui`. (c) bez nowej komendy: UI pisze przez `SessionHistorySettingsRepo.update`, walidacja w UI, fake i impl bez wspólnego kontraktu.
2. **Błędy.** (a, rekomendacja) bez nowego wariantu: `UnknownSession`, `SubfolderUnavailable(NOT_IN_PROJECT)`, `Runtime(COMMAND_FAILED)`. (b) nowy `SessionError.PlaceUnavailable(id, PlaceProblem { NO_PROJECT, NOT_IN_PROJECT })`: dokładniejszy tekst, gałąź `when` w `SessionsView` (`projects:ui`) i w `mission-control:ui`.
3. **Gdzie akcja.** (a, rekomendacja) menu wiersza i panel szczegółów, okno z listą; (b) jak (a) plus paleta „Przypisz sesję do podfolderu…” dla zaznaczonej sesji (`app`, ID komendy bez nazw); (c) tylko panel szczegółów.
4. **„Folder główny” jako wybór.** (a, rekomendacja) tak: „Automatycznie”, „folder główny”, podfoldery; (b) tylko „Automatycznie” i podfoldery (sesji z podfolderu nie da się przenieść do korzenia).
5. **Których sesji dotyczy.** (a, rekomendacja) każdej sesji projektu z podfolderami: żywej i z dysku, w każdym stanie; (b) tylko z dysku (FR-P9 dosłownie); (c) tylko nieaktywnych.
6. **ADR 0033** (szkic): (a, rekomendacja) klucz `places` w `session-history.json`, schemat 1; (b) osobny plik `session-places.json` z nowym repo w `api`; (c) `projects.json`. Do tego klucz wpisu: (a, rekomendacja) UUID, a bez niego krótkie id (przetrwa wznowienie); (b) zawsze `Session.id`. Wpis nieważny: (a, rekomendacja) pomijany i zostaje w pliku; (b) usuwany przy następnym zapisie.

**Pytania nieblokujące** (domyślnie w nawiasie): po przeniesieniu sesji poza bieżącą stronę podfolderu zaznaczenie znika, bez skoku na nową stronę (tak); znacznik „(ręcznie)” tylko w panelu szczegółów, plakietka wiersza bez zmian (tak); „Usuń” sesji nie kasuje wpisu (tak).
