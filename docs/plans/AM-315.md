# AM-315 · Nazwa i podsumowanie starej sesji oraz historia rozmowy bez ładowania całego pliku

Issue: #195 · Wymagania: FR-P9, NFR-6 · ENG-I1–I8, ENG-C2, ENG-C8, ENG-C10, ENG-T1–T6 · ADR 0032, nowy 0034 (szkic) · Zależy: AM-312, AM-313 (scalone)

Status: **plan zatwierdzony**; pytania blokujące 1–2 rozstrzygnięte przez człowieka 2026-11-11 (opcje a); pytania nieblokujące: odpowiedzi domyślne.

## Zakres

Ustalenia z kodu: (1) format 2.1.322 nie ma wpisów `summary` ani `ai-title` (`docs/compat.md` M7), ma `custom-title` (`customTitle`, 86/132 plików, pozycja 2) i `agent-name`; parser (`SessionEntries`) dziś ich nie czyta. (2) `SessionFileReader` czyta 64 KiB głowy i 64 KiB ogona naraz, bez czytania wstecz porcjami. (3) `Session.name` i `Session.summary` już istnieją i UI je rysuje (wiersz: nazwa i druga linia, panel: „PODSUMOWANIE”); `DiskSessions` daje `summary = null`. Podgląd (`SessionPreview.key`) pomija `DISK`, a `recentOutput` dla `DISK` daje `UnknownSession`.

1. **Nazwa i podsumowanie (bez nowych pól `sessions:api`).** `SessionFiles.parse` dokłada `customTitle` (ostatni wpis `custom-title`, ogon wygrywa) i `lastPrompt` (ostatnia prawdziwa wiadomość `user` w ogonie, reguła `titleOf`). `DiskSessions`: `name = customTitle ?: title ?: 8 znaków UUID`, `summary = DiskSessions.summaryOf(title, lastPrompt)` (tabela niżej).
2. **Historia od końca.** `SessionHistory.conversation` (ADR 0034): porcje 64 KiB wstecz, cięcie po `\n` na bajtach, kursor bajtowy, limity 1 MiB na linię i 8 MiB na wywołanie, tekst ≤ 4 000 code pointów. `sessions:impl`: `SessionMonitor.conversation(id, before)` dla `DISK` (20 wiadomości), `UnknownSession` dla `SUPERVISOR`.
3. **UI (`mission-control:ui`).** Nowy `ConversationState` czyta pierwszą porcję po zaznaczeniu sesji `DISK` (jedno źródło dla panelu i podglądu, `collectLatest`, bez odświeżania co 3 s — plik się nie zmienia, wznowienie zmienia `origin`). Panel szczegółów: podsumowanie albo wartość zastępcza „Brak wiadomości w pliku sesji”, sekcja „OSTATNIE WIADOMOŚCI” (3 ostatnie, po 3 linie) i przycisk „Pokaż historię” (= spacja). Podgląd (spacja) dla `DISK`: lista wiadomości (etykieta roli tekstem „Ty”/„Claude”, nie samym kolorem; zaznaczalny tekst), przycisk „Wczytaj starsze” u góry, informacja „(przycięte)”. `recentOutput` zostaje dla `SUPERVISOR` bez zmian.

**Nie robimy:** podsumowania modelem, wyszukiwania w historii, historii sesji supervisora (także zatrzymanych), pokazywania wywołań narzędzi, `agent-name` jako nazwy, odświeżania historii na żywo.

## Zmiany API (pytania blokujące 1 i 2: nic nie jest zatwierdzone)

```kotlin
// agent-runtime:api — SessionHistory.kt: `fun interface` → `interface` (implementują tylko FakeSessionHistory i FileSessionHistory)
public interface SessionHistory {
    public suspend fun list(dirs: List<Path>, since: Instant?): Outcome<List<PastConversation>, HistoryError> // bez zmian
    /**
     * Up to [limit] (coerced to 1..100) messages of [conversation] that lie before [before] (null = end of file),
     * oldest first; the file is `<dirNameOf(startCwd)>/<uuid>.jsonl`, read backwards in chunks, never whole (ADR 0034).
     * Only `text` parts of user and assistant messages. Errors: [ConversationError]; an id that is not a lowercase
     * UUID is [ConversationError.NOT_FOUND] without touching the disk.
     */
    public suspend fun conversation(conversation: ConversationId, startCwd: Path, before: HistoryCursor?, limit: Int):
        Outcome<ConversationPage, ConversationError>
}
// PastConversation: dwa nowe pola na końcu z domyślnymi null; toString ukrywa oba (ENG-C8)
//   val name: String? = null        // customTitle z ostatniego wpisu custom-title; ≤ 80 code pointów
//   val lastPrompt: String? = null  // ostatnia prawdziwa wiadomość user w ogonie; ≤ 80 code pointów
/** Start of the line of a message in the file (bytes); opaque for callers, valid while the file is only appended to. */
public data class HistoryCursor(val offset: Long)
/** @property older cursor for the previous page; null = the start of the file was reached. */
public data class ConversationPage(val messages: List<ConversationMessage>, val older: HistoryCursor?)
/** [text] is user data: `toString` hides it. [truncated]: cut to 4 000 code points. */
public data class ConversationMessage(val role: ConversationRole, val text: String, val at: Instant?, val truncated: Boolean)
public enum class ConversationRole { USER, ASSISTANT }
public enum class ConversationError { /** No such file or invalid id. */ NOT_FOUND, /** IO failure or cursor past the end. */ UNREADABLE }
```

## Odstępstwa od planu (po implementacji i review)

- **Podgląd zaczyna od góry** (najstarsza wiadomość załadowana), z „Wczytaj starsze” u góry; przewijanie na dół nie jest robione (testy wymuszają start od góry).
- **`canPreview` dla `DISK`:** `MissionControlController.actions.canPreview` jest prawdziwe także dla sesji z dysku (historia); `canAttach`/`canReply` nadal nie. Komenda palety nazywa się „Podgląd” (nie „Podgląd outputu”). Nie ma zmian w `MissionControlReducer.kt` ani `SessionActions.kt`; zakres wyliczają `SessionPreview.key` i `PreviewState.kt`.
- **Budżet 8 MiB także w `fill()`:** zgodnie z ADR 0034 pkt 3 czytnik sprawdza budżet przy każdej porcji, nie tylko na granicy linii; po wyczerpaniu budżetu w środku linii, którą i tak pomijamy (ponad 1 MiB albo częściowa pierwsza), zatrzymuje się na początku ostatniej porcji (`boundary`), a kursor strony może leżeć w środku takiej linii (następne wywołanie pomija jej częściową resztę). Budżet sprawdza `refill()` przy każdej porcji. Linia poniżej 1 MiB trwająca na granicy budżetu jest doczytywana do końca (wiadomość nie ginie), więc górna granica odczytu jednego wywołania to 8 MiB + 1 MiB + 64 KiB.
- **`ConversationState`:** pierwsza strona sprawdza `isActive` zamiast licznika wyborów (`collectLatest` czeka na zakończenie poprzedniego bloku, więc licznik w tym miejscu jest zawsze równy); licznik zostaje dla starszych stron (`loadOlder`).
- **Kontrakt `SessionHistory`:** `conversation` sprawdza UUID przed zbudowaniem ścieżki (id z NUL dawał `InvalidPathException`); `FakeSessionHistory` zwraca `NOT_FOUND` dla katalogu startu innego niż listowanej rozmowy, jak implementacja plikowa.
- **Test dostarczony pomocniczo:** `GatedConversation`, `DiskConversationKit`, `FakeConversations` (fixtures/testy), nie ujęte w pierwotnej liście modułów.

## Ryzyka i pytania

**Pytania blokujące (decyzja człowieka przed startem):**

1. **Zmiana `agent-runtime:api`:** (a, rekomendacja) `SessionHistory` z `fun interface` na `interface` z metodą `conversation`, pola `PastConversation.name`/`lastPrompt` z domyślnymi `null`, typy `HistoryCursor`, `ConversationPage`, `ConversationMessage`, `ConversationRole`, `ConversationError`; (b) osobny port `ConversationReader` (mniejszy interfejs, ale 14. parametr `sessionsModule` i druga fabryka w `app`). Zgoda na (a)?
2. **Zmiana `sessions:api`:** (a, rekomendacja) `SessionMonitor.conversation(id, before)` + `SessionMessages.kt` + KDoc `name`/`summary`/`recentOutput`; łamie 5 implementacji (lista wyżej, w tym test `projects:ui`); (b) osobny interfejs `SessionConversations` jako nowe pole `SessionsApi` (zmiana konstruktora data class). Nowych pól nazwy i podsumowania w `Session` nie trzeba — są `name` i `summary`. Bez nowego wariantu `SessionError`.

**Pytania nieblokujące** (domyślnie w nawiasie): nazwa z `customTitle` (tak; może być nadawana automatycznie przez Claude Code, nie przez użytkownika) czy też `agentName` (nie); format podsumowania „pierwsza → ostatnia” (tak); w panelu 3 ostatnie wiadomości (tak; alternatywa: tylko przycisk); historia tylko dla `DISK` (tak).

**Ryzyka:**

- **Dane użytkownika (ENG-C8):** treść w pamięci i UI; `toString` ukrywa tekst, logi tylko liczby i kategorie, test logów.
- **Ścieżka z `ConversationId`:** konstruktor publiczny bez walidacji — impl sprawdza UUID przed `resolve` (Lekcja o `SubfolderName`).
- **Ogon bez wiadomości użytkownika** (długie wyniki narzędzi > 64 KiB): `lastPrompt = null`, podsumowanie = pierwsza wiadomość; dolne ograniczenie jak `cwdChanged`.
- **Wiadomość `assistant` w kilku wpisach** (jedna część na wpis): pokazujemy każdy wpis z tekstem osobno; brak scalania po `message.id`.
- **Format nieudokumentowany:** zmiana daje brak nazwy lub pustą historię, nie błąd; `docs/compat.md` i `/compat-check`.
- **Spacja i Enter na przyciskach** „Wczytaj starsze”/„Pokaż historię”: niefokusowalne (`canFocus = false`), test Tabem.
- **Kolejność commitów:** 1) plan, ADR, `docs/11`; 2) `agent-runtime:api` + fake + kontrakt; 3) `SessionFiles`/`SessionEntries` (nazwa, `lastPrompt`); 4) `BackwardLines`, `ConversationEntries`, `ConversationFile`; 5) `sessions:api` + fake'i + `ConversationContract`; 6) `sessions:impl`; 7) `mission-control:ui`; 8) `app`, testy okna, CHANGELOG, `docs/05`, `compat.md`.
