# AM-405 · mission-control:ui: lista sesji, panel szczegółów, pasek trybu

Issue: #29 · Wymagania: FR-S1, FR-S8 (część), FR-S9 (część), FR-S2 (prezentacja), NFR-2, ENG-C6, ENG-C8, ENG-C10, ENG-T4 · docs/05, docs/11 §1 (MVI), §3, §7, §9 · Etap: M4

## Zakres

Nowy moduł `feature:mission-control:ui` (skill `/new-module mission-control`, tylko część `ui`) oraz podpięcie `sessions` w `app`. Środek ekranu i panel szczegółów z docs/05 dla **projektu zaznaczonego w sidebarze**:

- **Nagłówek projektu**: nazwa, ścieżka, liczba sesji (FR-S1). Bez gałęzi git (wymaga inspekcji, poza zakresem).
- **Filtr** Wszystkie / Aktywne / Zakończone (FR-S9, pierwsza połowa). Aktywne to `state.isActive`, Zakończone to reszta.
- **Lista sesji** (FR-S1): `glif · nazwa (mono) · podsumowanie · ostatnie zdarzenie · wiek`. Zaznaczenie kliknięciem (tło `sel`, pasek akcentu). Kolejność: najnowsze `startedAt` u góry. Wiek liczony od `lastActivityAt`, odświeżany co 1 s z wstrzykniętego `Clock`.
- **Panel szczegółów** (FR-S8, tylko dostępne pola): nazwa, stan (glif i tekst), podsumowanie, katalog roboczy (`cwd` jako „worktree”), ID, czas startu, ostatnia aktywność. Bez zaznaczenia: tekst „Wybierz sesję”.
- **Pasek trybu** (decyzja 3): `NORMAL`, nazwa projektu, liczniki czekających i pracujących ze wszystkich projektów, świeżość snapshotu.
- **Stan snapshotu** (docs/11 §7): `Loading` daje „Wczytywanie sesji…”. `Stale` zostawia listę i pokazuje baner „Nieaktualne od HH:mm:ss” ze stałym tekstem dla `RuntimeProblem`.
- **Stan pusty** (`MissionControlEmpty`) przenosimy z `app` do modułu: „Brak projektów” albo „Wybierz projekt”.

Nie robimy:

- widoków globalnych „czeka na mnie / pracuje / błędy” (FR-S9, druga połowa) → nowe zadanie **AM-407** (pytanie blokujące 2);
- pól FR-S8 bez danych w `sessions:api`: model, tryb, zdarzenia hooków, link do PR (pytanie 2 do człowieka);
- akcji panelu (Odpowiedz, Attach, Respawn, Zatrzymaj), linii skrótów, terminala, j/k (AM-406);
- głosu, popupu i wersji supervisora w pasku trybu (M7);
- `core:design-system` (AM-802): kolory jako stałe `internal`;
- zmian `sessions:api` i `projects:api`. W `feature/projects/ui` jedyna zmiana to addytywne `public val selection: StateFlow<ProjectId?>` w `ProjectsController` z testem (decyzja 6).

## Zmiany API

`sessions:api`, `projects:api`: brak. Publiczne typy `mission-control:ui` (KDoc po angielsku):

```kotlin
/**
 * State holder of Mission Control (MVI, docs/11 §1) for the project selected in the sidebar. Collects in
 * [scope] (the window scope, Main dispatcher; not thread-safe) and re-reads [clock] every [tick] for session
 * ages. Never throws, runs no commands and does no IO; shows only [SessionMonitor.snapshot].
 * @throws IllegalArgumentException if [tick] is not positive.
 */
public class MissionControlController(
    sessions: SessionMonitor, projects: ProjectsApi, selectedProject: StateFlow<ProjectId?>,
    clock: Clock, scope: CoroutineScope, tick: Duration = 1.seconds,
) {
    internal val state: StateFlow<MissionControlUiState>   // read by the composables only
    internal fun onEvent(event: MissionControlEvent)
}

/** The centre of the window: header, filter, session list, details panel and mode bar; stateless apart from [controller]. */
@Composable public fun MissionControl(controller: MissionControlController, modifier: Modifier = Modifier)
```

Wewnętrzne (`internal`): `enum SessionFilter(ALL, ACTIVE, FINISHED) { fun matches(s: SessionState): Boolean }`; `MissionControlEvent { SelectFilter(f); SelectSession(id) }`; `MissionControlUiState(screen: Screen, modeBar: ModeBar)`, gdzie `Screen = NoProjects | NoSelection | Project(header, filter, rows, details, banner)`; `SessionRow(id, glyph, name, summary, lastEvent: UiText, age: UiText, selected)`; `SessionDetails(...)`; `ModeBar(mode = "NORMAL", project: String?, waiting, working, freshness: UiText)`; `UiText(key, args)` i loader tekstów (świadomy duplikat z `projects:ui`, bo `ui` nie widzi `ui`).

Czyste funkcje (ENG-C9, `internal object`):

```kotlin
internal object MissionControlReducer {
    /** Whole screen from inputs; a selected session that is gone or filtered out is dropped. */
    fun reduce(snapshot: SessionsSnapshot, projects: List<Project>, selectedProject: ProjectId?,
               filter: SessionFilter, selectedSession: SessionId?, now: Instant): MissionControlUiState
}
internal object StateGlyph { fun of(s: SessionState): Glyph }           // symbol, tone, key (docs/05 tabela)
internal object LastEvent { fun of(s: SessionState): UiText }           // np. "prosi o zgodę: Bash"
internal object AgeText { fun of(from: Instant, now: Instant): UiText } // s / min / h / d
internal object Freshness { fun of(status: SnapshotStatus): UiText }    // Loading / Fresh / Stale(problem, HH:mm:ss)
```

### Decyzje

1. **Wybór projektu** przychodzi jako `StateFlow<ProjectId?>` z `app` (źródło: sidebar, pytanie blokujące 1). Zmiana projektu czyści zaznaczenie sesji i przywraca filtr `ALL`.
2. **Wiek**: kontroler trzyma `now` z `clock.now()`, w pętli `delay(tick)` w `scope`. Pętla działa tylko przy zaznaczonym projekcie. `AgeText` zaokrągla w dół; wiek ujemny (zegar przesunięty) daje „teraz”.
3. **Pasek trybu** (interpretacja docs/05): na razie jest jeden tryb `NORMAL`. To stała etykieta, którą AM-406 zamieni na stan klawiatury. Liczniki są globalne (suma `isWaiting` / `Working` ze wszystkich sesji), bo pasek ma odpowiadać na pytanie „czy coś na mnie czeka” niezależnie od zaznaczenia. Świeżość: „na żywo”, „wczytywanie” albo „nieaktualne od HH:mm:ss”.
4. **Dane wrażliwe** (ENG-C8): podsumowanie, nazwę, `cwd` i `question` UI wyświetla, ale nie loguje. Kontroler nie ma `Logger`, bo nie ma błędów do logowania.
5. **Sesje bez projektu** (`project == null`) nie trafiają do widoku projektu. Pokaże je AM-407.
6. **Zaznaczenie projektu z sidebaru**: AM-405 sam dodaje do `ProjectsController` publiczne `val selection: StateFlow<ProjectId?>` (wariant b z pytania 1, wybrany domyślnie, żeby nie czekać na AM-305). Konflikt z AM-305 rozwiązuje rebase.

## Ryzyka i pytania

Pytania blokujące (domyślnie przyjęto: 1 → wariant b, AM-405 dodaje `selection` sam; 2 → wydzielenie AM-407; człowiek może zmienić):

1. **Skąd Mission Control wie, który projekt jest zaznaczony.** Zaznaczenie istnieje tylko w `ProjectsController.state`, a to pole jest `internal` w `projects:ui`. Reguła 1 z docs/11 §3 zabrania zależności `mission-control:ui` → `projects:ui`, więc potrzebny jest publiczny strumień, który odczyta `app`.
   - a) **(rekomendacja)** Addytywna zmiana w `projects:ui`: `public val selection: StateFlow<ProjectId?>` w `ProjectsController` (ok. 3 linie i 1 test). Zrobić ją **w AM-305**, bo ten wątek i tak zmienia `projects:ui`. AM-405 startuje po scaleniu AM-305 albo robi rebase na nim. Wtedy AM-405 nie dotyka `feature/projects/**`.
   - b) AM-405 dopisuje te 3 linie sam. To grozi konfliktem z AM-305 i wychodzi poza moduły z roadmapy.
   - c) Zaznaczenie przenosimy do `app` (`MutableStateFlow` wstrzykiwany do obu kontrolerów). To zmienia konstruktor `ProjectsController` (7 parametrów, detekt) i jest większą zmianą `projects:ui`. Odradzam.
2. **ENG-C10 (≤ 400 linii kodu produkcyjnego na PR).** Szacunek pełnego zakresu z widokami globalnymi: ok. 520 linii. Rekomendacja: widoki globalne (FR-S9, druga połowa, w sidebarze według docs/05) idą do nowego zadania **AM-407** (`mission-control:ui`, `app`; zależy od AM-405). Wymagają też ustalenia, jak wybór widoku globalnego współgra z zaznaczeniem projektu w `projects:ui`. Po wydzieleniu AM-405 ma ok. 380 linii (kontroler ~60, reducer i funkcje czyste ~100, typy stanu ~40, composables ~150, teksty ~15, `app` ~20). Jeśli wyjdzie więcej, pasek trybu idzie do osobnego PR.

Pytania do człowieka (niczego nie blokują, plan przyjmuje rekomendację):

1. **Liczniki w pasku trybu** są globalne, nie dla projektu (decyzja 3). Alternatywa: liczniki tylko dla zaznaczonego projektu (`countsFor`).
2. **Brakujące pola FR-S8** (model, tryb, zdarzenia hooków, link do PR). `Session` ich nie ma. Model i tryb wymagają zmiany `sessions:api`, a być może także `agent-runtime:api` (czy `claude agents --json` je zwraca, trzeba sprawdzić w `docs/compat.md`). Hooki i PR przychodzą z M6 (AM-603, `PullRequestReady`). Rekomendacja: nowe zadanie po AM-603 „FR-S8: model, tryb, zdarzenia hooków, PR” (`sessions:api`, `sessions:impl`, `mission-control:ui`). FR-S8 zostaje w roadmapie oznaczone jako częściowe.
3. **Akcje panelu** (Zatrzymaj, Respawn) mają już komendy w `SessionCommands`, ale nie ma ich w FR-S8 ani w roadmapie. Rekomendacja: dopisać do AM-406 albo osobnego zadania, żeby AM-405 nie przekroczył 400 linii.

Ryzyka:

- **Konflikt z AM-305 w `app/Main.kt` i `app/build.gradle.kts`**: oba zadania podpinają `sessionsModule` (AM-305 dla `stopAllIn` i liczników). Kto scala drugi, ten robi rebase i używa już istniejącego `sessions`. `sessionsModule` dostaje `CoroutineScope(SupervisorJob() + core.dispatchers.io)` żyjący przez całą aplikację, nie scope okna.
- Pętla `tick` co 1 s przebudowuje stan także wtedy, gdy wiek się nie zmienia. Compose porównuje `data class`, więc rekompozycja jest tania. Na razie bez optymalizacji.
- `runComposeUiTest` z nieskończoną pętlą `tick`: testy UI używają `mainClock.autoAdvance = false` albo dużego `tick`, żeby `waitForIdle` się nie zawiesił.
- Lokalnie w chmurze Compose się nie zbuduje (`dl.google.com`); pełne `check` sprawdza CI na macOS.
