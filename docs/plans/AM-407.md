# AM-407 · Widoki globalne „Czeka na mnie”, „Pracuje”, „Błędy”

Issue: #83 · Wymagania: FR-S9 (druga połowa), FR-S1, FR-S4 (akcje w widoku), FR-K1 · ENG-C8, ENG-C9, ENG-C10, ENG-T4 · docs/05 „Układ” (sidebar: „widoki globalne”) · ADR 0011 (przyjęta) · Zależy: AM-405 (oraz AM-409, AM-410 w kodzie)

## Zakres

Widok globalny to lista sesji **ze wszystkich projektów** (także sesji bez projektu, AM-405 decyzja 5), wybranych według stanu. Widok globalny i zaznaczony projekt wykluczają się (decyzja 1). `sessions:api`, `command-palette:*` bez zmian.

1. **`mission-control:ui`**: `enum GlobalView { WAITING, WORKING, FAILED }`; publiczny composable `GlobalViews` (trzy pozycje z licznikami, zaznaczona pozycja na tle `sel`); ekran `Screen.Global`: nagłówek „Czeka na mnie” i „wszystkie projekty · sesje: N” (`header.global`), bez zakładek filtra, wiersz z dodatkową kolumną projektu; panel szczegółów i akcje z AM-410 bez zmian; intencja `ShowView`; strumień `view`.
2. **`app`**: `GlobalViews` pod `ProjectsSidebar` w lewej kolumnie (docs/05: pod „+ Dodaj projekt”); komendy palety „Widok: Czeka na mnie / Pracuje / Błędy”; ukrycie komend „Filtr: …” w widoku globalnym; wybranie widoku czyści zaznaczenie projektu w sidebarze.
3. **`projects:ui`** (poza roadmapą, pytanie blokujące 1): addytywne `ProjectsIntent.ClearSelection`.

Nie robimy: skrótów klawiszowych dla widoków (docs/05 ich nie ma; pytanie 2); pozycji w menu okna „Widok” (pytanie 3); pola „Projekt” w panelu szczegółów; liczników widoków w pasku trybu (pasek już liczy globalnie); akcji dla wielu sesji; zmian `sessions:*` i `command-palette:*`.

## Zmiany API

`sessions:api`, `projects:api`, `command-palette:*`: brak. Publiczne API `mission-control:ui` (woła tylko `app`):

```kotlin
/** Global views of Mission Control over the sessions of every project, also those without a project (FR-S9). */
public enum class GlobalView {
    /** Sessions that wait for the user: [SessionState.isWaiting]. */ WAITING,
    /** Sessions in [SessionState.Working]. */ WORKING,
    /** Sessions in [SessionState.Failed]. */ FAILED;
    internal fun matches(state: SessionState): Boolean
}

public sealed interface MissionControlIntent {
    // NextSession, PreviousSession, SelectFilter, StopSelected, RespawnSelected, RemoveSelected bez zmian;
    // SelectFilter: KDoc uzupełniony o „ignored while a global view is shown”.
    /** Sidebar entry and palette: shows [view] and clears the selected session; ignored while a dialog is open. */
    public data class ShowView(val view: GlobalView) : MissionControlIntent
}

public class MissionControlController(/* bez zmian */) {
    /** The shown global view, null on the project page. `app` hides filter commands and clears the sidebar by it. */
    public val view: StateFlow<GlobalView?>
}

/** Entries of the global views with their counts over every project; clicking one sends [MissionControlIntent.ShowView]. */
@Composable public fun GlobalViews(controller: MissionControlController, modifier: Modifier = Modifier)
```

`projects:ui` (addytywnie): `/** A global view of Mission Control is shown: no project is selected; ignored while a dialog is open. */ public data object ClearSelection : ProjectsIntent`.

Wewnętrzne:

- `Selection(project, view: GlobalView? = null, filter, session)`; `internal fun Selection.onProject(id: ProjectId?): Selection` (tabela 2) zastępuje lambdę w kolektorze `selectedProject`.
- `internal object SessionScope { fun visible(sessions: List<Session>, selection: Selection): List<Session> }`: w widoku globalnym `view.matches`, bez filtra i bez warunku projektu; inaczej sesje projektu z `filter.matches`. Zawsze najnowsze `startedAt` u góry. Używają go reduktor, `SessionActions.target` i `moveCursor` (decyzja 4).
- `Screen.Global(view, sessions: Int, rows, details, banner, loading)`; `SessionRow.project: UiText? = null` (`row.project` z nazwą albo `row.noProject`; `null` na stronie projektu); `MissionControlUiState.views: List<ViewEntry(view, count, selected)>`.
- KDoc do poprawy po rozszerzeniu zakresu: `MissionControlController` („for the project selected in the sidebar”), `SessionFilter` („of the project”), `SessionActions.target`, `ModeBar`.

### Decyzje

1. **Widok globalny albo projekt, nigdy oba** (wariant B z pytania blokującego 1). `ShowView(v)` ustawia `view = v`, `session = null`. `QuaysideApp` zbiera `missionControl.view.filterNotNull()` i wysyła `ProjectsIntent.ClearSelection`, więc sidebar traci podświetlenie, a ⌘⌫ i „Zmień nazwę” wyłączają się. Wybranie projektu (klik, „Przejdź do projektu”, `g p`) emituje nowe `id` i `onProject` wraca na stronę projektu z `ALL`. `null` z sidebaru przy aktywnym widoku zostawia widok (tabela 2).
2. **Filtr** Wszystkie/Aktywne/Zakończone dotyczy tylko strony projektu. W widoku globalnym zakładek nie ma, `app` nie oferuje komend „Filtr: …”, a `SelectFilter` kontroler ignoruje (czyta `selection.value`, nie `view`).
3. **Lista w widoku globalnym**: kolumny jak w AM-405 plus nazwa projektu (secondary) przed podsumowaniem; sesja bez projektu albo z projektem spoza listy ma „bez projektu”. Kolejność jak na stronie projektu (stabilna dla j/k). Pozycje `GlobalViews` liczą sesje ze wszystkich projektów; zaznaczona ma tło `sel`, licznik WAITING w tonie `WARN`, FAILED w `ERR`. Bez projektów (`NoProjects`) widok globalny i tak działa.
4. **j/k i akcje** (lekcja o `stateIn`): `moveCursor` liczy wiersze z `SessionScope.visible(monitor.snapshot.value.sessions, selection.value)`, nie ze `state.value`. Cel akcji AM-410 też z `SessionScope`, więc `x`, Respawn i Usuń działają na sesji dowolnego projektu. Sesja po akcji zwykle wypada z widoku (stop w „Pracuje”, respawn w „Błędy”): panel pokazuje „Wybierz sesję”; nieudana akcja zostawia sesję i jej `Failure`.
5. **Wiek** tyka, gdy `project != null || view != null` (dziś tylko przy projekcie; w wariancie B projekt jest wtedy `null`).
6. **Komendy palety** (grupa `SESSION`, bez skrótów): `sessions.view.waiting` „Widok: Czeka na mnie” (`keywords = [waiting, czeka]`), `sessions.view.working` „Widok: Pracuje” (`[working]`), `sessions.view.failed` „Widok: Błędy” (`[failed, errors, błąd]`). Oferowane bez dialogu, oprócz widoku już pokazanego. `sessionCommands(projects, menu, actions, view, onIntent, openPalette)`.
7. **Bez logów**: przełączanie widoku to nawigacja (jak filtr w AM-409).

## Ryzyka i pytania

Pytania blokujące:

1. **Zmiana `projects:ui` spoza roadmapy** (moduły zadania: `mission-control:ui`, `app`). Zaznaczenie projektu jest w `ProjectsController`; `app` nie ma jak go wyczyścić.
   - **B (rekomendacja)**: addytywne `ProjectsIntent.ClearSelection` (ok. 5 linii i 2 testy, jak `selection` w AM-405). Widok i projekt się wykluczają, klik w dowolny projekt wraca do projektu.
   - A: bez zmiany `projects:ui`. Sidebar dalej podświetla projekt X przy widoku globalnym, a ⌘⌫ usuwa X. Klik w już zaznaczony X nie emituje zmiany, więc nie wraca do projektu: trzeba dodać `MissionControlIntent.ShowProject` i komendę „Widok: projekt” (ok. +15 linii, gorsze UX). Przy A znika tabela 2 (wiersze z `null`) i powiązanie w `MainWindow`.

Pytania nieblokujące (plan przyjmuje rekomendację):

1. **Skróty widoków**: brak (docs/05 ich nie ma). Alternatywa: sekwencje `g w`, `g r`, `g e` w `AppShortcuts` (ok. +5 linii).
2. **Menu okna „Widok”**: bez pozycji widoków. Alternatywa: trzy pozycje z `AppMenuState` (ok. +15 linii).
3. **Kolejność w „Czeka na mnie”**: najnowsze `startedAt` u góry (stabilna dla j/k). Alternatywa: najdłużej czekające u góry (`lastActivityAt` rosnąco); kolejność zmieniałaby się przy każdej odpowiedzi.

Ryzyka:

- **Rozmiar w ENG-C10**: linie netto w `src/main` (bez importów, KDoc i pustych): `mission-control:ui` ~180 (reduktor 35, typy stanu 20, `GlobalView`/`SessionScope`/`onProject` 25, kontroler 17, `withActions` 8, composables 70 z czego ~15 to wydzielenie wspólnej strony listy, tagi i intencja 5); `app` ~36 (`sessionCommands` 20, `AppCommands` 5, lewa kolumna 6, `MainWindow` 5); `projects:ui` ~5. Razem ~221, z zapasem 30% **ok. 290**. Zasoby ~15 linii osobno. Bez nadwyżki.
- `view` to `stateIn` nad `selection`: komendy palety i `ClearSelection` są o krok w tyle. Kontroler sprawdza `selection.value` na świeżo (decyzja 2, 4), więc najgorszy skutek to komenda bez efektu.
- Kolejność `ShowView` i `ClearSelection`: `null` z sidebaru przychodzi po ustawieniu widoku i według tabeli 2 go nie kasuje. Test `a cleared project keeps the global view` to pilnuje.
- Wydzielenie wspólnej strony listy z `ProjectPage` dotyka istniejących testów ekranu AM-405/AM-410 tylko przez tagi; tagi zostają bez zmian.
- `GlobalViews` w lewej kolumnie ma własne kolory (`Colors.panel` = tło sidebaru 0xFF2C2C2E); ujednolicenie w AM-802.
