# AM-408 · Paleta ⌘K i „Zmień nazwę projektu…” w menu okna

Issue: #86 · Wymagania: FR-K1, FR-P6 · ENG-I2, ENG-C8, ENG-C10, ENG-T4 · docs/05 „Skróty”, docs/11 §1, §3 · ADR 0011 (przyjęta) · Zależy: AM-406

## Zakres

Drugi z trzech etapów palety (podział z AM-406):

1. **Nowy moduł `command-palette:ui`**: `CommandPaletteController` (stan palety, MVI) i composable `CommandPalette` (warstwa nad oknem jak `ProjectsDialog`, pole wyszukiwania, lista wyników, skrót obok tytułu).
2. **`projects:ui`**: publiczne intencje `Select(id)` i `RenameSelectedRequested`, pola `ProjectsMenuState.canRename` i `dialogOpen` (decyzje człowieka z AM-406).
3. **`app`**: `AppCommands` (komendy projektów w `CommandRegistry`), `commandPaletteModule` w `Main.kt`, menu okna z „Zmień nazwę projektu…” (bez skrótu) i „Paleta komend…” (⌘K), warstwa palety w `AgentManagerApp`.

Nie robimy: `j`/`k`, `g p`, mapowania `KeyEvent` → `KeyChord`, `Window.onKeyEvent` (AM-409); akcji sesji `x`, Zatrzymaj/Respawn/Usuń (AM-410); `⏎` (AM-505); `r`, `space` (AM-411); komend filtra Mission Control (wymagają publicznej intencji w `mission-control:ui`, poza modułami zadania); pola palety w nagłówku z docs/05 (nagłówka jeszcze nie ma); `core:design-system` (AM-802). Bez zmian `command-palette:{api,impl}`, `projects:api`, `sessions:*`, `mission-control:ui`.

## Zmiany API

`command-palette:api`, `projects:api`: brak. Publiczne API `projects:ui` (wywołuje tylko `app`):

```kotlin
/**
 * Which window-menu commands are enabled. All false while a dialog is open, so ⌘⌫ reaches text fields.
 * @property dialogOpen a dialog of the sidebar is open; `app` then offers no project commands in the palette.
 */
public data class ProjectsMenuState(val canAdd: Boolean, val canRemove: Boolean, val canRename: Boolean, val dialogOpen: Boolean)

public sealed interface ProjectsIntent {
    /** "Rename project…" in the window menu or the palette: opens the rename dialog; ignored without a selection. */
    public data object RenameSelectedRequested : ProjectsIntent
    /** "Go to project" in the palette: selects [id]; ignored for a project that is not listed. */
    public data class Select(val id: ProjectId) : ProjectsIntent
}
```

Publiczne API `command-palette:ui`:

```kotlin
/**
 * State holder of the ⌘K palette (FR-K1). Reads [registry] and runs the chosen command in [scope]
 * (the window scope, Main dispatcher; not thread-safe). Logs only command ids (ENG-C8), never titles or queries.
 */
public class CommandPaletteController(registry: CommandRegistry, scope: CoroutineScope, logger: Logger) {
    /** True while the palette is shown; `app` disables the window-menu project items then. */
    public val isOpen: StateFlow<Boolean>
    /** Opens with an empty query, limited to [group] when given (`g p` in AM-409); ignored when already open. */
    public fun open(group: CommandGroup? = null)
    /** Closes without running anything. */
    public fun close()
}

/** The palette over the whole window; shows nothing while closed. */
@Composable public fun CommandPalette(controller: CommandPaletteController)

/** The Compose menu binding of [shortcut]: only one chord with ⌘; null otherwise (shown in the palette only). */
public fun Shortcut.toKeyShortcut(): KeyShortcut?
```

Wewnętrzne: `internal data class PaletteState(open, query, group: CommandGroup?, highlighted: Int)`, `internal data class PaletteView(open, query, results: List<Command>, highlighted: Int)`, `internal sealed interface PaletteEvent { QueryChanged(text), MoveUp, MoveDown, Confirm, Pick(index), Dismiss }`, czyste `PaletteState.view(all: List<Command>): PaletteView` i `PaletteState.reduce(event, resultCount): PaletteState`, `internal object ShortcutLabel { fun of(shortcut: Shortcut): String }`.

W `app` (`internal`): `class AppCommands(projects: ProjectsApi, controller: ProjectsController, scope: CoroutineScope) : CommandProvider` oraz czyste `fun projectCommands(list: List<Project>, menu: ProjectsMenuState, onIntent: (ProjectsIntent) -> Unit): List<Command>`; `data class AppMenuState(add, remove, rename, palette)` z `fun of(menu: ProjectsMenuState, paletteOpen: Boolean)`; `object AppShortcuts { ADD_PROJECT (⌘⇧O), REMOVE_PROJECT (⌘⌫), PALETTE (⌘K) }`.

### Decyzje

1. **Komendy w tym etapie** (`projectCommands`, tytuły z `strings.properties`, te same co w menu okna):

   | Id | Tytuł | Grupa | Skrót | Warunek | Intencja |
   | --- | --- | --- | --- | --- | --- |
   | `projects.add` | Dodaj projekt… | `PROJECT` | ⌘⇧O | `canAdd` | `AddRequested` |
   | `projects.rename` | Zmień nazwę projektu… (`keywords = [rename, nazwa]`) | `PROJECT` | – | `canRename` | `RenameSelectedRequested` |
   | `projects.remove` | Usuń projekt (`keywords = [remove]`) | `PROJECT` | ⌘⌫ | `canRemove` | `RemoveSelectedRequested` |
   | `projects.goto.<id>` | Przejdź do projektu: <nazwa> | `GO_TO_PROJECT` | – | każdy projekt z listy | `Select(id)` |

   Niedostępna komenda znika z listy (`Command` nie ma pola `enabled`). Przy `menu.dialogOpen` lista jest pusta. `AppCommands.commands = combine(projects.projects, controller.menu).map(::projectCommands).stateIn(scope, Eagerly, …)`. Rejestracja w `DisposableEffect` okna, `close()` w `onDispose`.
2. **Menu okna** (`AppMenu.kt`, z `Main.kt` wyjęte `ProjectsMenu`). „Projekty”: Dodaj projekt… (⌘⇧O), Zmień nazwę projektu… (bez skrótu), Usuń projekt (⌘⌫). Nowe menu „Widok”: Paleta komend… (⌘K). Skróty pochodzą z `AppShortcuts.X.toKeyShortcut()`, czyli z tego samego źródła co w komendach. Włączenie liczy `AppMenuState.of`: przy otwartej palecie wszystkie pozycje projektów są wyłączone (⌘⌫ i ⌘⇧O trafiają do pola palety), a ⌘K działa tylko przy zamkniętej palecie i bez dialogu.
3. **Klawiatura w palecie** (`onPreviewKeyEvent` pola, jak `RenameField`). Po otwarciu pole dostaje fokus (`FocusRequester` w `LaunchedEffect`). ↑/↓ przesuwają podświetlenie bez zawijania, tak jak `j`/`k`. Enter działa jak `Confirm`. Esc i klik w tło działają jak `Dismiss`. Zmiana zapytania ustawia podświetlenie na 0. Kiedy lista się skurczy, podświetlenie przycina się do ostatniego wyniku. Podświetlony wiersz jest przewijany do widoku (`LazyColumn`, `scrollToItem`). Klik w wiersz działa jak `Pick(index)`. Gdy nic nie pasuje, paleta pokazuje „Brak pasujących komend”.
4. **Uruchamianie**: `Confirm` przy otwartej palecie z wynikiem najpierw zamyka paletę (synchronicznie, jak `begin` w `ProjectsController`), potem `scope.launch { command.run() }` i INFO `command run` z `commandId`. Drugi `Confirm` trafia już na zamkniętą paletę i jest ignorowany. Paleta nie łapie wyjątków z `run`, bo kontrakt `Command` ich zabrania.
5. **Wyniki**: `CommandMatcher.search(query, all)`, potem filtr `group`. Bez nagłówków grup, bo przy niepustym zapytaniu sortowanie po trafności miesza grupy. Wiersz pokazuje tytuł i `ShortcutLabel` (macOS: `⌃⌥⇧⌘` + klawisz, np. „⇧⌘O”, „⌘⌫”, „g p”).
6. **`projects:ui`**: `Select(id)` przechodzi przez `reduce(SidebarEvent.Select)` tylko dla id z listy. `RenameSelectedRequested` przechodzi przez `reduce(SidebarEvent.RenameRequested(selected))`. `menu()`: `canRename = canRemove = dialog == null && selected != null`, `dialogOpen = dialog != null`. Oba wejścia ignorują intencję przy otwartym dialogu (istniejący `return` w `onIntent`).

## Ryzyka i pytania

Pytania blokujące: brak (szczegóły w odpowiedzi do lead'a).

Ryzyka:

- **Rozmiar**: ok. 385 linii produkcyjnych: `command-palette:ui` ~250 (kontroler 60, stan i przejścia 40, composable 95, `ShortcutLabel` i `toKeyShortcut` 35, teksty i tagi 20), `projects:ui` ~30, `app` ~105 (`AppCommands` 50, `AppMenu` 40, `Main`/`AgentManagerApp`/teksty 15). Blisko limitu ENG-C10. Jeśli PR przekroczy 400 linii, wydzielamy `projects:ui` z pozycją menu „Zmień nazwę projektu…” jako osobny, pierwszy PR (~55 linii).
- `Key(nativeKeyCode)` dla liter w `toKeyShortcut` zakłada, że `VK_A..VK_Z` = `'A'..'Z'` i `VK_0..VK_9` = `'0'..'9'` (AWT). Test sprawdza to na przykładach z `Key.A`/`Key.O`/`Key.Z`/`Key.Zero`.
- Dwa `Popup` z `focusable = true` (paleta i dialog projektu) jednocześnie: wyklucza to `AppMenuState` (⌘K wyłączone przy dialogu) i zamknięcie palety przed `run`.
- `Command` z lambdą: `stateIn` w `AppCommands` emituje przy każdej zmianie `menu` (koszt pomijalny, jak w AM-406).
- `MenuBar` nie da się przetestować w `runComposeUiTest`. Logika włączania jest w czystym `AppMenuState`, a skróty sprawdza ręczny test na Macu.
