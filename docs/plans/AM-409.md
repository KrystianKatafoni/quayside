# AM-409 · Skróty j/k i g p

Issue: #87 · Wymagania: FR-K2 (część: j/k, g p), FR-K1, FR-S9 (komendy filtra, warunkowo) · ENG-I2, ENG-I8, ENG-C8, ENG-C10, ENG-T4 · docs/05 „Skróty klawiszowe” · ADR 0011 (przyjęta) · Zależy: AM-408

## Zakres

Trzeci z trzech etapów palety (podział z AM-406). Skróty bez ⌘ są zwykłymi komendami w `CommandRegistry` z polem `shortcut`, więc paleta pokazuje je w wierszach („j”, „k”, „g p”), a klawiatura i paleta uruchamiają ten sam `run`.

1. **`command-palette:ui`**: mapowanie `KeyEvent` → `KeyChord` (`KeyChords`), czysta reguła sekwencji `ShortcutMatcher`, publiczne `CommandPaletteController.onKeyEvent`.
2. **`mission-control:ui`**: publiczne `MissionControlIntent` (`NextSession`, `PreviousSession`, warunkowo `SelectFilter`), `MissionControlController.onIntent`, czysta reguła `SessionCursor`.
3. **`app`**: komendy „Następna sesja” (j), „Poprzednia sesja” (k), „Przełącz projekt…” (g p), warunkowo „Filtr: Wszystkie/Aktywne/Zakończone”; `WindowKeys` podpięte do `Window(onKeyEvent = …)`.

Nie robimy: `x` i akcji sesji w panelu i palecie (AM-410); `⏎` attach (AM-505); `r` i `space` (AM-411); ściągawki skrótów w sidebarze i linii skrótów pod listą (docs/05; osobne zadanie UI); wskaźnika prefiksu `g` w pasku trybu (decyzja z AM-406: niewidoczny); limitu czasu prefiksu. Bez zmian `command-palette:{api,impl}`, `projects:*`, `sessions:*`.

## Zmiany API

`command-palette:api`, `projects:*`: brak. Publiczne API `command-palette:ui` (dochodzi jedna metoda):

```kotlin
/**
 * A key of the main window (`Window.onKeyEvent`, ADR 0011). Runs the registered command whose shortcut has no ⌘
 * and matches this key, or this key after a pending first chord (`g p`). The first chord waits with no time limit;
 * Escape or any other key cancels it. Ignored while the palette is open. ⌘ shortcuts stay with `MenuBar`.
 * @return true when the key was used: a run, a pending first chord or a cancel.
 */
public fun onKeyEvent(event: KeyEvent): Boolean
```

Publiczne API `mission-control:ui` (wywołuje tylko `app`):

```kotlin
/** Intents of Mission Control from the palette and window keys (MVI, docs/11 §1; ADR 0011). */
public sealed interface MissionControlIntent {
    /** `j`: selects the next visible session; without a selection the first; stays on the last (no wrap). */
    public data object NextSession : MissionControlIntent
    /** `k`: selects the previous visible session; without a selection the last; stays on the first. */
    public data object PreviousSession : MissionControlIntent
    /** Palette "Filter: …": shows only sessions that [filter] matches (FR-S9). Conditional, question 1. */
    public data class SelectFilter(val filter: SessionFilter) : MissionControlIntent
}

/** In [MissionControlController]: handles [intent]; ignored without a shown project or without rows. */
public fun onIntent(intent: MissionControlIntent)

/** `SessionFilter` becomes `public` (entries ALL, ACTIVE, FINISHED); `matches` stays `internal`. */
```

Wewnętrzne:

- `command-palette:ui`: `internal object KeyChords { fun of(key: Key, modifiers: Set<KeyModifier>): KeyChord? }` i `internal fun KeyEvent.toChord(): KeyChord?` (tylko `KeyDown`; litery i cyfry przez `nativeKeyCode`, odwrotnie do `toKeyShortcut`; klawisze modyfikatorów i nieznane → `null`). `internal sealed interface ShortcutStep { Run(command), Wait(first: KeyChord), Cancelled, NoMatch }`, `internal object ShortcutMatcher { fun step(pending: KeyChord?, chord: KeyChord, commands: List<Command>): ShortcutStep }`. W kontrolerze `internal fun onChord(chord: KeyChord): Boolean` (testy bez Compose `KeyEvent`) i prywatne `pending: KeyChord?`, kasowane w `open()`, `close()` i po każdym kroku innym niż `Wait`.
- `mission-control:ui`: `internal object SessionCursor { fun next(rows: List<SessionId>, selected: SessionId?): SessionId?; fun previous(…): SessionId? }` (`null` = bez zmiany).
- `app`: `AppShortcuts.NEXT_SESSION` (j), `PREVIOUS_SESSION` (k), `SWITCH_PROJECT` (g p); `internal fun sessionCommands(projects: List<Project>, menu: ProjectsMenuState, onIntent: (MissionControlIntent) -> Unit, openPalette: (CommandGroup) -> Unit): List<Command>`; `AppCommands(projects, controller, missionControl, palette, scope)`; `internal class WindowKeys { fun attach(handler: (KeyEvent) -> Boolean): AutoCloseable; fun onKeyEvent(event: KeyEvent): Boolean }` (bez handlera zwraca `false`; `@Volatile`). `MainWindow` dostaje `AppModules(projects, sessions, inspector, registry)` i `keys`, bo detekt pozwala na 5 parametrów funkcji.

### Decyzje

1. **Komendy** (tytuły w `strings.properties`):

   | Id | Tytuł | Grupa | Skrót | Warunek | Akcja |
   | --- | --- | --- | --- | --- | --- |
   | `sessions.next` | Następna sesja | `SESSION` | j | brak dialogu | `NextSession` |
   | `sessions.previous` | Poprzednia sesja | `SESSION` | k | brak dialogu | `PreviousSession` |
   | `projects.switch` | Przełącz projekt… (`keywords = [switch, projekt]`) | `PROJECT` | g p | brak dialogu, ≥ 1 projekt | `palette.open(GO_TO_PROJECT)` |
   | `sessions.filter.{all,active,finished}` | Filtr: Wszystkie / Aktywne / Zakończone | `SESSION` | – | brak dialogu | `SelectFilter(…)` (pytanie 1) |

   „Przełącz projekt…” jest w `PROJECT`, a nie w `GO_TO_PROJECT`, bo inaczej `g p` pokazałoby samo siebie. j/k są dostępne zawsze poza dialogiem, a bez wierszy intencja nic nie robi (bez nowego stanu w API). Przy `menu.dialogOpen` `AppCommands` nie daje żadnej komendy, więc przy dialogu żadna litera nic nie uruchamia.
2. **`ShortcutMatcher`** bierze pod uwagę tylko skróty bez `META` w żadnym akordzie (⌘ obsługuje `MenuBar`, więc nie ma podwójnego uruchomienia). Bez `pending`: skrót jednoakordowy → `Run`; początek skrótu dwuakordowego → `Wait`; inaczej `NoMatch` (zdarzenie idzie dalej). Z `pending`: pełna para → `Run`; każdy inny akord, także Esc → `Cancelled` (akord jest pochłonięty i nie uruchamia własnej komendy, jak w vimie). Konflikt `g` i `g p`: wygrywa skrót jednoakordowy (bez limitu czasu nie ma innego deterministycznego wyboru). `Shift` jest modyfikatorem: `G` ≠ `g`. `KeyEvent` z samym modyfikatorem daje `null` i nie kasuje prefiksu.
3. **Kontroler palety**: `onChord` przy otwartej palecie zwraca `false` i nic nie robi. `Run` używa istniejącego `run(command)` (INFO `command run` z `commandId`, bez tytułu, ENG-C8). Przy otwartej palecie klawisze i tak trafiają do jej `Popup`.
4. **`WindowKeys`**: `Main.kt` tworzy jeden obiekt przed `application` i przekazuje `keys::onKeyEvent` do `Window`, a `MainWindow` w istniejącym `DisposableEffect` wywołuje `keys.attach(palette::onKeyEvent)`. Kontroler palety powstaje w treści okna, więc bez uchwytu `Window` go nie widzi.
5. **`SessionCursor`** liczy po wierszach z `state.value` (lista po filtrze), a zaznaczenie bierze z bieżącego `selection` w `update`. Ukryte albo zniknięte zaznaczenie liczy się jako brak zaznaczenia.

## Ryzyka i pytania

Pytania blokujące: komendy filtra (pytanie 1, w odpowiedzi do lead'a).

- **Rozmiar** (linie netto, bez importów, KDoc i pustych): `command-palette:ui` ~80 (`KeyChords` 30, `ShortcutMatcher` 30, kontroler 20); `mission-control:ui` ~35 (intencje i `onIntent` 18, `SessionCursor` 15, `public` 2); `app` ~85 (`sessionCommands` i skróty 40, `AppCommands` 8, `WindowKeys` 15, `Main`/`MainWindow`/`AppModules` 15, teksty 7). Razem ~200, z zapasem 30% ~260. Bez komend filtra ~230. Poniżej 300, więc bez podziału.
- `Window.onKeyEvent` dostaje zdarzenia także bez fokusu, ale `runComposeUiTest` nie ma `Window`. Harness kładzie `WindowKeys` na `Box` z fokusem; zachowanie bez fokusu sprawdza test ręczny.
- Otwarty `Popup` menu ⋯ w sidebarze nie ustawia `dialogOpen`. Ma `focusable = true`, więc klawisze powinny trafić do niego, a nie do okna; sprawdza to test ręczny.
- `KeyChords` zakłada `VK_A..VK_Z` = `'A'..'Z'` (jak `toKeyShortcut`); na układach innych niż QWERTY litera może wynikać z pozycji klawisza.
- `SessionCursor` czyta wiersze z `state.value`; dwa naciśnięcia w jednej klatce mogą liczyć po tej samej liście (zaznaczenie jest zawsze świeże).
