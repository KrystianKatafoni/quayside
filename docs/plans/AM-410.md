# AM-410 · Akcje sesji: x stop, Zatrzymaj/Respawn/Usuń w panelu i palecie

Issue: #88 · Wymagania: FR-K2 (część: x), FR-S4 (stop, respawn, usuń z listy), FR-K1 · ENG-I2, ENG-I4, ENG-C8, ENG-C10, ENG-T4 · docs/05 „Panel szczegółów”, „Skróty klawiszowe” · ADR 0011 (przyjęta) · Zależy: AM-409

## Zakres

`sessions:api` ma już wszystkie potrzebne operacje (`SessionCommands.stop`, `respawn`, `remove`; AM-404), więc zadanie nie zmienia `api` żadnego feature. Decyzja człowieka: jeden PR z pełnym zakresem (bez osobnego AM-412), z jawną nadwyżką ponad ENG-C10 (sekcja „Ryzyka”).

1. **`mission-control:ui`**: intencje `StopSelected`, `RespawnSelected`, `RemoveSelected`; publiczny stan `actions`; przyciski „Zatrzymaj”, „Respawn”, „Usuń z listy” w panelu szczegółów; tekst „w toku” i stały komunikat błędu w panelu; dialog potwierdzenia usunięcia (`Popup` na całe okno).
2. **`app`**: komendy palety „Zatrzymaj sesję” (skrót `x`), „Respawn sesji”, „Usuń sesję z listy”, oferowane według `actions`; przy otwartym dialogu Mission Control brak komend palety i wyłączone menu okna.

Nie robimy: `⏎` attach (AM-505); `r` i `space` (AM-411); potwierdzenia przed stopem i respawnem (decyzja 8); akcji dla wielu sesji naraz. Bez zmian `sessions:*`, `projects:*`, `command-palette:*`.

## Zmiany API

`sessions:api`, `command-palette:api`, `projects:*`: brak. Publiczne API `mission-control:ui` (wywołuje tylko `app`):

```kotlin
public sealed interface MissionControlIntent {
    // NextSession, PreviousSession, SelectFilter bez zmian
    /** `x` and the palette: stops the selected visible session when it is active; otherwise ignored (FR-S4). */
    public data object StopSelected : MissionControlIntent
    /** Palette and panel: respawns the selected visible session when it is not active; otherwise ignored. */
    public data object RespawnSelected : MissionControlIntent
    /** Palette and panel: asks to confirm removing the selected inactive session from the list; otherwise ignored. */
    public data object RemoveSelected : MissionControlIntent
}

/**
 * Which session actions apply to the selected visible session now; all false without one, while an action runs
 * and while a dialog of Mission Control is open. `app` offers palette commands by it; the controller checks again.
 * @property dialogOpen a dialog of Mission Control is open: `app` offers no palette commands and disables the menu.
 */
public data class SessionActionsState(
    val canStop: Boolean, val canRespawn: Boolean, val canRemove: Boolean = false, val dialogOpen: Boolean = false,
)

@Suppress("LongParameterList") // tick is a test seam; decided by a human (AM-410)
public class MissionControlController(
    sessions: SessionsApi, projects: ProjectsApi, selectedProject: StateFlow<ProjectId?>,
    clock: Clock, scope: CoroutineScope, logger: Logger, tick: Duration = 1.seconds,
) {
    /** Actions of the selected visible session, for the palette and the window menu (AM-410). */
    public val actions: StateFlow<SessionActionsState>
}
```

Wartości domyślne `canRemove` i `dialogOpen` utrzymują istniejące wywołania `SessionActionsState(canStop, canRespawn)` w testach.

Wewnętrzne:

- `internal enum class SessionAction { STOP, RESPAWN, REMOVE }`; `Failure(id, action, reason: UiText)`; `ActionUi(busy: Pair<SessionId, SessionAction>?, failure: Failure?, dialog: SessionDialog?)` jako piąty strumień `combine`.
- `internal sealed interface SessionDialog { data class ConfirmRemove(val id: SessionId, val name: String) }`; `MissionControlUiState.dialog: SessionDialog?`. Nazwa jest tylko wyświetlana w dialogu, nigdy logowana (ENG-C8).
- `MissionControlEvent.Run(action)` (klik w panelu), `ConfirmRemove`, `Dismiss` (Anuluj, Escape, klik w tło).
- `SessionActions { fun target(sessions, selection): Session?; fun available(state, busy): Set<SessionAction> }`; kontroler podaje `busy = busy != null || dialog != null`.
- `SessionActionRunner.run(action, id): UiText?` obsługuje też `REMOVE` (`commands.remove`). `SessionActionMessages` bez zmian (powtarza kategorie `StopMessages` z `projects:ui`; zaakceptowane).
- `app`: `sessionCommands(projects, menu, actions, onIntent, openPalette)` zwraca pustą listę przy `menu.dialogOpen` albo `actions.dialogOpen`; `AppMenuState.of(menu, paletteOpen, sessionDialogOpen: Boolean = false)`.

### Decyzje

1. **Dostępność akcji** (tabela 1): sesja aktywna (Pracuje, Czeka na odpowiedź, Prosi o zgodę) → „Zatrzymaj”; nieaktywna (Gotowe, Błąd, Zatrzymana) → „Respawn” i „Usuń z listy”. Przycisków niedostępnych akcji nie ma. Nieaktualny snapshot (`Stale`) nie blokuje akcji; błąd wraca jako komunikat.
2. **Cel akcji czytany na świeżo** (lekcja o `stateIn`): `onIntent` liczy cel z `sessions.monitor.snapshot.value` i bieżącego `selection.value` przez `SessionActions.target`, nigdy ze `state.value` ani z `actions`. `j`, a zaraz po nim `x`, zatrzymuje nową sesję.
3. **Współbieżność**: jedna akcja naraz. `busy` jest ustawiane w tym samym wywołaniu co `scope.launch` (jak `begin` w `ProjectsController`). W trakcie wszystkie przyciski są wyłączone, `actions` ma same `false`, a panel sesji pokazuje „Zatrzymywanie…”, „Respawn…” albo „Usuwanie…”. Zmiana zaznaczenia w trakcie jest dozwolona.
4. **Usuwanie**: `RemoveSelected` albo klik „Usuń z listy” otwiera `ConfirmRemove` dla celu z decyzji 2 (bez wywołania komendy). „Usuń z listy” w dialogu zamyka dialog, ustawia `busy = (id, REMOVE)` i wywołuje `remove(id)` dla id z dialogu, nie dla bieżącego zaznaczenia. „Anuluj”, Escape i klik w tło zamykają dialog bez wywołania. Po sukcesie sesja znika z listy, a panel pokazuje „Wybierz sesję”. Błąd (np. `SessionActive`, gdy sesję wznowiono gdzie indziej) trafia do `Failure` tak samo jak przy stopie; ponownego sprawdzenia aktywności przy potwierdzeniu celowo nie ma.
5. **Dialog Mission Control**: `Popup(focusable = true)` na całe okno, jak `ProjectsDialog`. Gdy jest otwarty, `actions.dialogOpen = true`, `sessionCommands` zwraca pustą listę (żaden skrót, także j/k i `x`), a `AppMenuState.of` wyłącza wszystkie pozycje menu okna, także ⌘K.
6. **Błędy**: bez dialogu. `Failure` pokazuje się w panelu tylko dla swojej sesji: tytuł `action.<akcja>.failed` i powód z tabeli 2. Stałe teksty bez id, nazwy i ścieżki. `Failure` znika przy następnej akcji i przy zmianie zaznaczonej sesji; otwarcie dialogu potwierdzenia też czyści poprzedni `Failure`.
7. **Logi**: INFO `session stopped` / `session respawned` / `session removed` z `sessionId`; WARN `session <stop|respawn|remove> failed` z `sessionId` i `reason` (kategoria z tabeli 2). Otwarcie i anulowanie dialogu bez logu.
8. **Bez potwierdzenia przed stopem i respawnem** (decyzja człowieka): respawn cofa stop, a docs/05 traktuje `x` jako akcję jednego klawisza.
9. **Komendy palety** (grupa `SESSION`):

   | Id | Tytuł | Skrót | Warunek | Akcja |
   | --- | --- | --- | --- | --- |
   | `sessions.stop` | Zatrzymaj sesję (`keywords = [stop]`) | x | brak dialogu, `canStop` | `StopSelected` |
   | `sessions.respawn` | Respawn sesji (`keywords = [respawn, wznów]`) | – | brak dialogu, `canRespawn` | `RespawnSelected` |
   | `sessions.remove` | Usuń sesję z listy (`keywords = [remove, rm, usuń]`) | – | brak dialogu, `canRemove` | `RemoveSelected` |

   „Brak dialogu” = ani `menu.dialogOpen`, ani `actions.dialogOpen`. Przy otwartej palecie `onChord` niczego nie uruchamia (AM-409).

## Ryzyka i pytania

Pytania blokujące: brak (podział, potwierdzenie stopu, `@Suppress`, warunkowe komendy, etykiety i powielone kategorie rozstrzygnął człowiek).

- **Rozmiar ponad ENG-C10, zaakceptowany przez człowieka.** Linie netto w `src/main` (bez importów, KDoc i pustych): `mission-control:ui` ~255 (kontroler 60, reguły 15, runner i komunikaty 55, typy stanu i reduktor 30, widok panelu 45, dialog 40, intencje i `SessionActionsState` 10); `app` ~60 (`sessionCommands` 30, `AppMenuState`/`AppMenu` 10, `AppCommands`/`MainWindow`/skrót 20). Razem ~315, z zapasem 30% **ok. 410**, czyli ok. 10 linii ponad limit 400. **Faktycznie: ok. 362 netto** (dodane ok. 418, z czego ~35 to przeniesione `Label` i `Colors`). Zasoby osobno ~25 linii. Opis PR musi wymienić tę nadwyżkę i decyzję człowieka.
- `actions` to `stateIn` nad `stateIn`, a lista komend idzie jeszcze przez rejestr na `Default`. Komenda może pojawić się kilka milisekund po zaznaczeniu; kontroler i tak sprawdza cel na świeżo, więc najgorszy skutek to klawisz bez efektu.
- Dialog `Popup(focusable = true)` powinien zabrać klawisze oknu; blokada przez `actions.dialogOpen` jest drugą warstwą. Zachowanie w prawdziwym oknie sprawdza test ręczny.
- `FakeSessions` kończy komendy od razu; stan „w toku” daje tylko `GatedCommands`.
