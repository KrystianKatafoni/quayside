# AM-411 · sessions:api: recentOutput i podgląd space

Issue: #89 · Wymagania: FR-K2 (część: space), FR-K1 · ENG-I1, ENG-I2, ENG-I4–I7, ENG-C8, ENG-C10, ENG-T2, ENG-T4 · docs/05 „Skróty klawiszowe”, „Układ” · ADR 0011 (przyjęta) · Zależy: AM-410

## Zakres

Decyzja człowieka: zadanie jest **podzielone**. AM-411 robi tylko odczyt ogona wyjścia sesji i podgląd pod `space`. **Reply (`SessionCommands.reply`) i skrót `r` są poza zakresem.** Przechodzą do nowego zadania AM-506 po AM-502 (PTY), bo strategia odpowiedzi z docs/09 jest nadal otwarta.

1. **`sessions:api`**: `SessionMonitor.recentOutput(id)` (odczyt, więc strona read, ENG-I2) i typ `RecentOutput` z ukrytym `toString`. `FakeSessions` i kontrakt dostają odczyt wyjścia.
2. **`sessions:impl`**: `RecentOutputReader` nad istniejącym `AgentRuntime.recentOutput`. `ClaudeCliAdapter` już go implementuje (`claude logs`, `OutputTail`: bez ANSI, ≤ 200 linii i 16 KiB), więc `agent-runtime:*` się nie zmienia.
3. **`mission-control:ui`**: intencja `TogglePreview`, panel podglądu („peek”) pod listą sesji w środkowej kolumnie (tam, gdzie docs/05 przewiduje panel terminala), przycisk „Podgląd” w panelu szczegółów, `SessionActionsState.canPreview`/`previewOpen`.
4. **`app`**: komenda palety „Podgląd outputu” / „Zamknij podgląd” ze skrótem `space`.

Nie robimy: `reply`, `r`, pola odpowiedzi (AM-506); `⏎` attach (AM-505); strumienia wyjścia (`logs -f`); Escape zamykającego podgląd (Escape kasuje prefiks `g` w `ShortcutMatcher`); zmian w `agent-runtime:*`, `projects:*`, `command-palette:*`.

## Zmiany API

`sessions:api` (zmiana łamiąca dla implementacji `SessionMonitor`, ENG-I6; wywołań nie łamie):

```kotlin
public interface SessionMonitor {
    // snapshot, events bez zmian
    /**
     * Tail of the output of session [id] (`claude logs`), already cleaned and truncated by the runtime
     * (no ANSI, at most about 200 lines). Reads on demand: never changes [snapshot], emits no [events].
     * Any dispatcher; never blocks, never throws except CancellationException (ENG-I4, ENG-I5).
     * Errors: [SessionError.UnknownSession], [SessionError.Runtime].
     */
    public suspend fun recentOutput(id: SessionId): Outcome<RecentOutput, SessionError>
}

/** Output tail of a session. [text] is user data (ENG-C8): never log it; `toString` shows it as `***`. */
public data class RecentOutput(val text: String) {
    /** True when the session printed nothing yet (blank text). */
    val isEmpty: Boolean get() = text.isBlank()
    override fun toString(): String = "RecentOutput(text=$HIDDEN)"
}
```

`SessionError`: KDoc „Why a [SessionCommands] operation or [SessionMonitor.recentOutput] failed”. `FakeSessions` (testFixtures): wyjście z `SessionsWorld.outputs: Map<SessionId, String> = emptyMap()`, `setOutput(id, text)`, `failNextOutput(error)`, `outputReads: List<SessionId>` (odczyty nie trafiają do `calls`, więc istniejące asercje na komendach zostają). Fake: nieznane id → `UnknownSession`, runtime niedostępny → `Runtime(NOT_INSTALLED)`.

`sessions:impl` (internal): `RecentOutputReader(runtime, logger).read(id)` woła `runtime.recentOutput(id)` bez listowania i mapuje błąd przez `toSessionError()` (`UnknownSession(id)` zachowuje id, reszta → `Runtime(toProblem())`). WARN `Session output failed` z `session` i `problem`; sukces bez logu. `PollingSessionMonitor` dostaje `reader` w konstruktorze; sygnatura `sessionsModule` bez zmian.

Publiczne API `mission-control:ui` (wywołuje tylko `app`):

```kotlin
public sealed interface MissionControlIntent {
    /** `space` and the palette: opens the output preview of the selected visible session, or closes it. */
    public data object TogglePreview : MissionControlIntent
}

public data class SessionActionsState(
    val canStop: Boolean, val canRespawn: Boolean, val canRemove: Boolean = false, val dialogOpen: Boolean = false,
    /** A visible session is selected and no dialog is open; also while an action runs. */
    val canPreview: Boolean = false,
    /** The preview is open: the palette offers "Zamknij podgląd". */
    val previewOpen: Boolean = false,
)
```

Wewnętrzne: `PreviewContent { Loading; Text(text) /* toString *** */; Empty; Failed(reason: UiText) }`, `PreviewUi(id, name, content)` w `MissionControlUiState.preview: PreviewUi? = null`, `MissionControlEvent.TogglePreview` (przycisk i „Zamknij”). Czyste `SessionPreview`: `key(open, sessions, selection): SessionId?` (id celu z `SessionActions.target`, `null` przy zamkniętym), `content(outcome)`. Podgląd składa się w `combine` stanu przez `.copy(preview = shown)`; stan otwarcia i pętlę odczytu trzyma `PreviewState`.

### Decyzje

1. **Panel, nie dialog.** Podgląd jest nie-modalny: dolna część środkowej kolumny (`weight` 0.4, nad nim lista), nagłówek „Podgląd · <nazwa>” i „Zamknij  space”, tekst mono w `SelectionContainer`, przewinięty na dół po każdym wczytaniu. j/k działają dalej, a podgląd idzie za zaznaczeniem. Tak działa „peek” w Agent View (docs/00), a miejsce zgadza się z docs/05 (panel terminala pod listą).
2. **Przełączanie z danych na świeżo** (lekcja o `stateIn`): `TogglePreview` przy zamkniętym podglądzie czyta cel z `monitor.snapshot.value` i `selection.value`; bez celu nic nie robi. Przy otwartym zamyka zawsze. Przy otwartym dialogu intencja jest ignorowana, jak inne intencje sesji.
3. **Wczytywanie**: jeden kolektor `combine(open, selection, snapshot) → SessionPreview.key` (id celu albo `null`) z `distinctUntilChanged` i `collectLatest`. Nowe id → `Loading`, odczyt, potem pętla „`delay(PREVIEW_REFRESH = 3.seconds)`, odczyt” do zmiany klucza. Ponowny odczyt zachowuje poprzedni tekst (bez migania), a błąd zastępuje go `Failed`. `lastActivityAt` zmienia się tylko przy zmianie stanu (reducer), więc bez pętli podgląd pracującej sesji by stał. Zmiana zaznaczenia przerywa poprzedni odczyt. Zgubiony cel (filtr, inny projekt lub widok, usunięcie) zamyka podgląd. Stała zamiast parametru kontrolera (detekt LongParameterList); testy przesuwają czas wirtualny.
4. **Treść** (tabela 1): pusty tekst → „Brak outputu”; błąd → „Nie udało się wczytać outputu” i powód z `SessionActionMessages.reason` (te same klucze `action.reason.*`). Podgląd nie blokuje akcji i akcje nie blokują podglądu.
5. **Dane wrażliwe**: treść wyjścia nie trafia do logów, tagów testowych ani `toString` (`RecentOutput`, `PreviewContent.Text`). `mission-control:ui` niczego przy podglądzie nie loguje; błąd loguje `sessions:impl` (WARN, tylko kategoria).
6. **Komenda palety** (grupa `SESSION`): `sessions.preview`, tytuł `command.previewSession` = „Podgląd outputu” (albo `command.closePreview` = „Zamknij podgląd” przy `previewOpen`), `keywords = [preview, logs, podgląd]`, skrót `space` (`ChordKey.Named.SPACE`, w palecie „␣”). Komenda jest dostępna przy `canPreview || previewOpen` i bez dialogu.
7. **Teksty**: `preview.title=Podgląd · {0}` (nazwa sesji jest wyświetlana, nigdy logowana), `preview.loading=Wczytywanie outputu…`, `preview.empty=Brak outputu`, `preview.failed=Nie udało się wczytać outputu`, `preview.close=Zamknij  space`, `action.preview=Podgląd  space`. Tagi: `PREVIEW`, `PREVIEW_TEXT`, `PREVIEW_CLOSE`, `DETAILS_PREVIEW`.

## Ryzyka i pytania

Pytania blokujące: brak (podział zakresu rozstrzygnął człowiek; zmiany tylko w `api` własnego feature).

- **Miejsce `recentOutput`.** `SessionMonitor`, a nie nowe `SessionOutput` w `SessionsApi`: trzecie pole `SessionsApi` bez sensownej wartości domyślnej złamałoby `projects:ui` (`ControllerWorld`: `SessionsApi(sessions, sessions)`), a ten moduł był poza listą (teraz jest w niej tylko z powodu fokusu wiersza). ENG-I2 wprost przypisuje odczyt do `SessionMonitor`. Gdyby człowiek wolał osobny interfejs, trzeba dopisać `projects:ui` (tylko test) do modułów.
- **Rozmiar** (linie netto w `src/main`, bez importów, KDoc i pustych): `sessions:api` ~10, `sessions:impl` ~27, `mission-control:ui` ~155 (reguły i typy 35, kontroler 40, `PreviewState` 40, panel 50, przycisk 8, intencje i stan 7), `app` ~20. Razem ~212, z zapasem 30% **ok. 275**, poniżej 400, więc bez podziału. Zasoby ~10 linii, testFixtures ~70 osobno.
- `combine` w kontrolerze ma już 5 strumieni: podgląd idzie jako `combine(ui, preview, ::Pair)` w piątym miejscu, bez przechodzenia na wersję z tablicą.
- `clickable` z fokusem może sam obsłużyć Spacebar jako klik, zanim zdarzenie dojdzie do `Window.onKeyEvent`. Sprawdza to test ręczny. W razie problemu: `focusProperties { canFocus = false }` na wierszach (w zakresie `mission-control:ui`).
- `ProcessRunner` trzyma początek wyjścia (AM-203, ryzyko): przy `logs` > 4 MiB ogon jest zły. Poza zakresem.
- Otwarty podgląd uruchamia `claude logs` co 3 s (obok `agents --json` co 2 s). Tylko jeden podgląd naraz, a zamknięcie kończy pętlę; przy kosztownym `logs` wystarczy zmienić stałą.
- **Fokus wierszy.** Wiersze nawigacji (sesje, zakładki filtrów, widoki globalne, wiersz projektu w `projects:ui`) mają `focusProperties { canFocus = false }`, bo sfokusowany `clickable`/`selectable` obsługuje `space` i Enter jako klik i nie oddaje ich skrótom okna (`space`, później `⏎` z AM-505). Klik żąda fokusu także od niefokusowalnego węzła, a ten przekazuje go pierwszemu fokusowalnemu dziecku, więc dzieci wierszy też są niefokusowalne (przycisk menu `⋯` w wierszu projektu: parametr `focusable = false` w `TextButton`; wiersze sesji, filtry i widoki globalne mają tylko teksty). Pozostałe przyciski tekstowe biorą fokus: znany kompromis (`space` po kliknięciu przycisku kliknie go ponownie).
- `SessionPreview.key` liczy cel z `snapshot` i `selection` w `combine`, więc może być o krok w tyle za `j`. Skutek: krótko widać poprzednią sesję, a `collectLatest` przerywa jej odczyt.
