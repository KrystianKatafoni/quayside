# AM-502 · terminal:api/impl: shell i attach w PTY

Issue: #32 · Wymagania: FR-T1 · ENG-M4, ENG-I1–I8, ENG-C6, ENG-T2, ENG-T3 · docs/06, docs/11 §3–4 · ADR 0012 (przyjęta) · Zależy: AM-501

## Zakres

1. **`feature:terminal:api`** (nowy moduł): kontrakt `TerminalApi` / `TerminalSession`, `TerminalId`, `TerminalError`; w `testFixtures` fake i abstrakcyjny kontrakt.
2. **`feature:terminal:impl`**: produkcyjna implementacja za fabryką `terminalModule(...)`. Przejmuje ze spike'a `PtyTtyConnector` (bez zmian) i `TerminalWidgetSettings` (plus odpięcie ⌘K, ADR 0012 decyzja 3). Usuwa `openSpikeTerminal` i `TerminalSpikeErrors`.
3. **Shell**: login shell (`<shell> -l`) w podanym katalogu. **Komenda** (np. `AgentRuntime.attachCommand(id)`): przez login shell z `exec "$@"`, tak jak `LoginShellProcessRunner`. Wtedy `claude` z `~/.zprofile` jest widoczny także po starcie z Findera.
4. **`tests:architecture`**: reguła „importy `com.jediterm.` i `com.pty4j.` tylko w `feature/terminal/impl/src/main`” (przeniesiona z AM-501).
5. **`app`, tylko zbiór `terminalSpike`** (pytanie blokujące 1): okno spike'a przechodzi na `terminalModule` i kompiluje się dalej, aż AM-503 je usunie. Produkcyjny `app/src/main` się nie zmienia.

## Zmiany API

```kotlin
/** Opaque id of an open terminal, unique within one [TerminalApi]; safe to log. */
@JvmInline public value class TerminalId(public val value: String)

/** Why a terminal did not open or did not take input. Never carries exception text (ENG-C8). */
public sealed interface TerminalError {
    /** The working directory does not exist or is not a directory. */
    public data object WorkDirMissing : TerminalError
    /** The PTY or the widget did not start (pty4j, missing shell binary, native library). */
    public data object StartFailed : TerminalError
    /** The session or the whole [TerminalApi] was closed. */
    public data object Closed : TerminalError
}

/**
 * Opens terminals backed by a PTY (FR-T1). Open functions are safe on any dispatcher: the process starts
 * on IO, the widget is built on the Swing event thread. [close] closes every open session and makes later
 * opens fail with [TerminalError.Closed]; `app` calls it on exit (also from a shutdown hook). Idempotent.
 */
public interface TerminalApi : AutoCloseable {
    /** Starts the user's login shell (`<shell> -l`) in [dir], e.g. the project or its worktree. */
    public suspend fun openShell(dir: Path): Outcome<TerminalSession, TerminalError>

    /**
     * Runs [command] in a PTY through the login shell (`exec`, so the program replaces the shell and its exit
     * code is the session's). Meant for `AgentRuntime.attachCommand(id)` and `claude logs`. A program that is
     * not found is not an error here: the shell prints its message and the session exits with 127.
     */
    public suspend fun openCommand(command: ShellCommand): Outcome<TerminalSession, TerminalError>
}

/**
 * One open terminal: a process in a PTY and its widget. The process lives until it exits or [close];
 * an exited session keeps its screen until [close].
 */
public interface TerminalSession : AutoCloseable {
    public val id: TerminalId
    /** Null while the process runs; its exit code afterwards. Updated from a background thread. */
    public val exitCode: StateFlow<Int?>
    /** The same widget on every call, embedded by `terminal:ui` via `SwingPanel`. Swing event thread only. */
    public fun component(): JComponent
    /**
     * Types [text] into the PTY as if from the keyboard (UTF-8, no newline added; `"\r"` is Enter).
     * Any dispatcher; does not block the caller. Err([TerminalError.Closed]) after [close] or process exit.
     */
    public suspend fun send(text: String): Outcome<Unit, TerminalError>
    /** Kills the process and all its descendants, then disposes the widget. Any thread, idempotent. */
    override fun close()
}
```

Fabryka (jedyny publiczny element `impl`, ENG-M4):

```kotlin
/**
 * PTY terminals with JediTerm widgets. [shell]: usually `LoginShellProcessRunner.defaultShell()`.
 * [scope] lives as long as the app; it disposes widgets on [AppDispatchers.main]. [logger] gets ids,
 * kinds and fixed categories only, never arguments or environment (ENG-C8).
 */
public fun terminalModule(
    dispatchers: AppDispatchers, scope: CoroutineScope, logger: Logger, shell: Path,
    baseEnvironment: Map<String, String> = System.getenv(),
): TerminalApi
```

Odstępstwa od szkicu z docs/11 §4 (poprawiamy docs/11 w tym PR): `suspend` + `Outcome` przy otwieraniu (start PTY to IO, ENG-I4/I5); bez `profile`, `settings`, `find` (AM-504, dodanie to nowe parametry i metody); bez `title` (etykietę karty zna `terminal:ui`); `send` jest `suspend` z `Outcome` i zostaje teraz (decyzja 5).

### Decyzje

1. **Shell:** `ShellLaunch.shell(shell) = [shell, "-l"]`. **Komenda:** `ShellLaunch.command(shell, argv) = [shell, "-l", "-c", "exec \"$@\"", "quayside"] + argv`. Argumenty są parametrami pozycyjnymi, shell ich nie parsuje. Bez `-i` dla komendy.
2. **Środowisko** (`ShellLaunch.environment(base, extra)`): `base + extra`, potem zawsze `TERM=xterm-256color`. Gdy brak `LC_ALL`, `LC_CTYPE` i `LANG`, dochodzi `LC_CTYPE=UTF-8` (start z Findera nie ma locale, a zsh psuje wtedy polskie znaki). Wymiary startowe 80×24, potem resize z widżetu.
3. **Wątki:** sprawdzenie katalogu i `PtyProcessBuilder.start()` na `io`. `JediTermWidget(settings)`, `setTtyConnector`, `start()` na `main`. Gdy widżet się nie zbuduje, proces jest zabijany, a wynik to `StartFailed`. `send` → `connector.write` na `io`. `close()`: `PtyTtyConnector.close()` od razu w wątku wołającym (zabija drzewo, bez czekania), `widget.close()` przez `scope.launch(dispatchers.main)`.
4. **Cykl życia:** `exitCode` ustawia `process.onExit()` (bez korutyny). `JediTermTerminalApi` trzyma otwarte sesje (`ConcurrentHashMap`) i flagę `closed`. Sesja wypada ze zbioru przy `close()`. Jeśli `close()` API trafi w trwający `open`, `open` po zbudowaniu sesji widzi flagę, zamyka sesję i zwraca `Closed`. Zakończenie procesu nie zamyka sesji (ekran zostaje).
5. **`send` już teraz:** AM-506 (moduły `sessions:*`, `mission-control:ui`, `app`) nie zmienia `terminal:api`, więc zapis tekstu musi być w kontrakcie od razu (szkic docs/11 też go ma). Bez bracketed paste i bez dopisywania Enter: to decyzja AM-506.
6. **Logi:** INFO `terminal opened` (`terminalId`, `kind=shell|command`), INFO `terminal exited` (`terminalId`, `exitCode`), DEBUG `program` (= `argv.first()`), `workDir`. WARN `terminal open failed` (`reason` = `workDirMissing|startFailed`). Nigdy argumentów ani środowiska.
7. **Sieroty:** `PtyTtyConnector.close()` zabija najpierw potomków, potem shell (Z1 ze spike'a). JVM shutdown hook rejestruje `app` w AM-503 (`terminal.close()`); `impl` nie rejestruje hooków (brak stanu globalnego).

## Ryzyka i pytania

**Pytania blokujące:** 1 (zakres `app`), szczegóły w odpowiedzi dla lead'a. Plan zakłada rekomendację.

- **Szacunek** (linie netto w `src/main` i Gradle, bez importów, KDoc i pustych): `terminal:api` ~30 + Gradle 10; `impl`: fabryka 10, `JediTermTerminalApi` 55, `JediTermSession` 45, `PtyLauncher` 30, `ShellLaunch` 25, ustawienia 3, Gradle 3; `app` (spike) ~15; `settings` 1. Razem ~227, z zapasem 30% **ok. 295 dodanych**. Usunięte: `TerminalSpike.kt` ~55. Fixtures i testy (poza ENG-C10) ~350. Bez podziału.
- `JediTermWidget` może wymagać wyświetlacza. Kontrakt na prawdziwej impl i `JediTermSessionTest` są pomijane w trybie headless. Kover ≥ 80% dla `impl` zależy od CI macOS. Jeśli pokrycie spadnie, `PtyLauncherTest` pokrywa start bez widżetu.
- `/bin/sh -l` na macOS uruchamia `path_helper` z `/etc/profile`, a ten przestawia `PATH`. Fałszywy `claude` trafia więc na PATH przez `$HOME/.profile` (jak `.zprofile` u użytkownika), nie przez bazowe `PATH`.
- `exitCode` po `close()` to kod sygnału z pty4j (np. 137 albo ujemny). Kontrakt go nie sprawdza.
- AM-506: jeśli strategia reply wybierze attach w ukrytym PTY bez widżetu, potrzebny będzie wariant `open` bez `component()`. To byłaby zmiana `terminal:api` w AM-506. `send` tej drogi nie zamyka.
