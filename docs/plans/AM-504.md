# AM-504 · Szukanie w scrollbacku (⌘F, wielkość liter, regex)

Issue: #34 · Wymagania: FR-T3 · ENG-I1–I8, ENG-C2, ENG-C8, ENG-T2 · docs/06 (Szukanie), docs/11 §3–4 · ADR 0012 (warunki 2 i 3) · Zależy: AM-503

## Zakres

1. **`terminal:api`:** mały interfejs `TerminalSearch` dostępny jako `TerminalSession.search` (ENG-I2). Do tego czysta reguła `ScrollbackMatcher` współdzielona przez `impl` i fake (wzór: `CommandMatcher`, ADR 0011) oraz fake i zestaw kontraktowy w `testFixtures`.
2. **`terminal:impl`:** szukanie na migawce tekstu z `TerminalTextBuffer` (historia i ekran). Wszystkie trafienia są podświetlone, bieżące mocniej i przewinięte do widoku. Wbudowane szukanie JediTerm bez skrótu (⌘F zostaje dla aplikacji).
3. **`terminal:ui`:** pasek szukania w Compose w prawym górnym rogu aktywnego panelu, nad widżetem (blending jest już włączony). Pasek ma pole, licznik `3/12`, przełączniki *Aa* i `.*`, ↑/↓ i ×. ⌘F z fokusem w terminalu otwiera pasek, a gdy pasek jest już otwarty, przenosi fokus do pola i zaznacza tekst. Esc zamyka pasek, czyści podświetlenia i oddaje fokus widżetowi.

**Dlaczego własny pasek, a nie komponent JediTerm** (sprawdzone w źródłach JediTerm, `master`):

- `JediTermWidget.findText` przez pakietowe `TerminalSearchUtil` szuka tylko podciągu z `ignoreCase`, bez regexu;
- `FindItem` ma prywatny konstruktor, więc trafień regexu nie da się przekazać do `TerminalPanel.setFindResult`;
- komponent Swing nie pasowałby do UI aplikacji i nie dałby się przetestować testami Compose.

Podświetlenie rysuje podklasa `TerminalPanel`: po `super.paintComponent` maluje prostokąty. Korzysta z chronionych pól `myCharSize`, `myClientScrollOrigin` i z `getInsetX()`, a jej instancję zwraca `createTerminalPanel` podklasy `JediTermWidget`. Przewijanie działa tak samo jak w JediTerm: `getVerticalScrollModel().setValue(…)`.

**Bez zmian w `app`.** ⌘F przechwytuje `TerminalKeyDispatcher` w `terminal:ui` (działa, gdy fokus jest w widżecie). Gdy fokus jest w polu paska, klawisze obsługuje samo pole. Pozycja w menu i komenda palety nie są potrzebne. Bez akceleratora w menu nie grozi też podwójna obsługa skrótu (ryzyko z AM-503).

**Nie robimy:** ustawień terminala i Option jako Meta (AM-508), dzwonka (AM-509), ⌘G/⌘⇧G, szukania przez zawinięte wiersze, historii zapytań, szukania we wszystkich kartach naraz, znaczników na pasku przewijania.

## Zmiany API

```kotlin
// terminal:api — TerminalSession dostaje:
/** Search in this terminal's scrollback and screen (FR-T3); works after the process exited, until [close]. */
public val search: TerminalSearch

/** What to look for. [text] empty = no search. [regex]: Java regex syntax; [matchCase] applies to both modes. */
public data class SearchQuery(val text: String, val matchCase: Boolean = false, val regex: Boolean = false)
/** A hit in row [row] (0 = oldest scrollback line of the searched snapshot), columns [start] until [end] (exclusive). */
public data class SearchMatch(val row: Int, val start: Int, val end: Int)
/** Hits found: [count]; [current] is the 0-based index of the selected hit in reading order, null when none. [limited]: stopped at [ScrollbackMatcher.MAX_MATCHES]. */
public data class SearchResult(val count: Int, val current: Int?, val limited: Boolean) { public companion object { public val NONE: SearchResult } }
/** [UP]: towards older output; [DOWN]: towards newer output. Both wrap around. */
public enum class SearchDirection { UP, DOWN }
/** Why a search did not run. Never carries the pattern or exception text (ENG-C8). */
public sealed interface SearchError {
    /** [SearchQuery.regex] is set and [SearchQuery.text] is not a valid pattern. */
    public data object InvalidPattern : SearchError
    /** The session was closed. */
    public data object Closed : SearchError
}

/**
 * Find in one terminal (FR-T3). [find] highlights every hit, selects the newest one (closest to the bottom) and
 * scrolls it into view. Any dispatcher; matching runs off the Swing thread, highlights are drawn on it.
 * The hits are a snapshot: new output does not update them until the next [find].
 */
public interface TerminalSearch {
    /** Replaces the previous search. Empty text clears and returns [SearchResult.NONE]. */
    public suspend fun find(query: SearchQuery): Outcome<SearchResult, SearchError>
    /** Selects the next hit in [direction] and scrolls to it; [SearchResult.NONE] without hits. */
    public suspend fun step(direction: SearchDirection): Outcome<SearchResult, SearchError>
    /** Removes highlights and forgets the hits. Idempotent; harmless after close. */
    public suspend fun clear()
}

/** Pure matching shared by `impl` and fakes: per row, left to right, non-overlapping, empty hits skipped. */
public object ScrollbackMatcher {
    public const val MAX_MATCHES: Int = 10_000
    public fun find(rows: List<String>, query: SearchQuery): Outcome<List<SearchMatch>, SearchError>
}
```

Typy `terminal:ui` (internal): `SearchBarState(tab: TabId, query: SearchQuery, result: SearchResult, invalid: Boolean, focusRequest: Int)`. `TerminalSearchController(scope, logger, activeTab: () -> TerminalTab?)` ma operacje `open()`, `close()`, `type(text)`, `toggleCase()`, `toggleRegex()`, `step(dir)`, `onActiveTabChanged(tab)` oraz `state: StateFlow<SearchBarState?>`.

### Decyzje

1. **Migawka:** pod blokadą `TerminalTextBuffer` (`lock`/`unlock` w `finally`) kopiowany jest tekst wierszy `-historyLinesCount until height`. Dopasowania liczy `Dispatchers.Default` z `AppDispatchers`, a podświetlenie i przewijanie są ustawiane na `main`. Wiersze trafień są bezwzględne (`historia + wiersz ekranu`), dlatego zostają na miejscu, gdy przybywa wyjścia (do obcięcia historii).
2. **Dopasowanie per wiersz fizyczny:** regex jest kompilowany raz (`IGNORE_CASE` + `UNICODE_CASE`, gdy brak `matchCase`), a `PatternSyntaxException` daje `InvalidPattern`. Tryb dosłowny używa `Regex.escape`. Trafienia puste (`x*`, `^`) są pomijane.
3. **Wybór startowy i kierunek:** po `find` bieżące jest najnowsze trafienie. ⏎ i przycisk ↑ = `UP`, ⇧⏎ i ↓ = `DOWN` (jak iTerm2). Licznik pokazuje `current + 1` / `count` (`10000+` przy `limited`).
4. **Pasek:** jeden naraz, przypięty do karty aktywnej w chwili ⌘F. Zmiana aktywnej karty albo jej zamknięcie zamyka pasek i woła `clear()`. Każda zmiana tekstu lub przełącznika anuluje poprzednie `find` (job) i uruchamia nowe. Pusty tekst wywołuje `clear()` i ukrywa licznik. `InvalidPattern` daje czerwoną ramkę, tekst „Błędny wzorzec” i czyści podświetlenia.
5. **Fokus:** otwarcie paska zwiększa `focusRequest`, a `SearchBar` wtedy woła `FocusRequester.requestFocus()` i zaznacza tekst. Esc → `close()`, potem `requestFocusInWindow()` na widżecie karty (jak `FocusActivePane`).
6. **Logi (ENG-C8):** DEBUG `terminal search` z `tabId`, `regex`, `count`; nigdy tekst zapytania. `InvalidPattern` nie jest logowany.
7. **Rysowanie:** wszystkie trafienia mają półprzezroczyste tło akcentu, bieżące mocniejsze tło i obrys. Kolor jest stałą w `impl`; schemat kolorów dojdzie w AM-8xx.

## Ryzyka i pytania

**Decyzje człowieka (2026-10-20):**

1. **Rozmiar:** szacunek ok. 475 linii netto (`api` 120, `impl` 145, `ui` 210), ok. 620 z zapasem. Człowiek wybrał jeden PR z całym szukaniem, bez podziału na AM-510.
2. **Kierunek:** ⏎ = starsze, ⇧⏎ = nowsze (jak iTerm2), zgodnie z decyzją 3.

**Ryzyka i decyzje nieblokujące:**

- **Wewnętrzne pola JediTerm:** `myCharSize`, `myClientScrollOrigin`, `getInsetX()` i `createTerminalPanel` są chronione, a nie publiczne, więc aktualizacja JediTerm może to zepsuć. Zabezpieczenia: test `JediTermSearchTest` i punkt w ręcznej liście. Przed kodem sprawdzić sygnatury w źródłach 3.76 (`TerminalTextBuffer.getLine(i)` dla ujemnych `i`, `lock`). `createTerminalPanel` jest wołane z konstruktora `JediTermWidget`, więc stan podświetleń trzyma panel, a nie pola podklasy widżetu.
- **Zawinięte wiersze:** trafienie nie przechodzi przez granicę zawinięcia (decyzja 2). Szerokie znaki: zakładamy indeks tekstu = kolumna (JediTerm wstawia znacznik DWC), do sprawdzenia ręcznie z CJK/emoji.
- **Ekran alternatywny** (`vim`, `less`): szukamy w buforze, który jest pokazany. Po obcięciu historii (limit wierszy) podświetlenia mogą się przesunąć do następnego `find`.
- **ReDoS:** wzorzec pochodzi od użytkownika, a dopasowanie per wiersz ogranicza długość wejścia. Anulowanie joba nie przerywa `Regex` w trakcie, więc limit `MAX_MATCHES` chroni tylko przed liczbą trafień.
- **Compose nad `SwingPanel`:** pasek wymaga blendingu (włączony w AM-503) i oddania fokusu AWT z widżetu do okna Compose. Paleta ⌘K robi to już poprawnie (F4/F6), sprawdzić ręcznie.
- Composable paska rozbite od razu (`SearchField`, `SearchToggle`, `SearchCounter`, `SearchBar`) z powodu LongMethod ≤ 30 i ≤ 5 parametrów. `TerminalController` dostaje tylko pole `search`, bez nowych funkcji (TooManyFunctions).
