# AM-505 · Skrót ⏎: attach wybranej sesji w karcie terminala

Issue: #90 · Wymagania: FR-K2 (część: ⏎), FR-T1, FR-K1 · ENG-I1, ENG-I2, ENG-C2, ENG-C8 · docs/05 „Skróty klawiszowe” (⏎ Attach w terminalu), docs/06 (karta `attach · <sesja>`) · ADR 0011 (przyjęta) · Zależy: AM-503, AM-409 (scalone)

## Zakres

Wszystkie potrzebne klocki już są: `AgentRuntime.attachCommand(id)` (czysta funkcja, `agent-runtime:api`), `TerminalController.openCommand(project, label, command)` (`terminal:ui`, przygotowane w AM-503 „dla AM-505”) i `FocusActivePane`, który daje fokus widżetowi nowej karty. Zadanie nie zmienia `api` żadnego feature ani `terminal:ui`.

1. **`mission-control:ui`**: publiczny `AttachTarget` i zapytanie `MissionControlController.attachTarget()`, które czyta cel na świeżo; flaga `SessionActionsState.canAttach`. Przyciski panelu („Zatrzymaj”, „Respawn”, „Usuń z listy”, „Podgląd”, „Zamknij” podglądu) przestają przyjmować fokus, bo inaczej zjadałyby ⏎ (Lekcje).
2. **`app`**: komenda palety „Attach sesji w terminalu” ze skrótem ⏎. Uruchamia ją `SessionAttacher`, który składa `attachTarget()`, `attachCommand` i `TerminalController.openCommand`. Za to odpowiada osobny `CommandProvider` (`AttachCommands`), żeby `sessionCommands` i `AppCommands` nie przekroczyły limitów detektu.

**Nie robimy:** `r` (AM-506), przycisku „Attach” w panelu szczegółów z docs/05 (pytanie 3), kropki stanu przy karcie attach (docs/06, wymaga `terminal:ui`; pytanie 2), fokusu istniejącej karty attach zamiast nowej (wymaga `terminal:ui`; pytanie 1), pozycji w menu okna, kart `logs`.

## Zmiany API

`sessions:api`, `agent-runtime:api`, `terminal:*`, `command-palette:*`, `projects:*`: brak. Publiczne API `mission-control:ui` (woła je tylko `app`):

```kotlin
/**
 * The selected session to attach to (AM-505): its [session] id, display [name] for the tab label and the registered
 * [project] whose tab group gets the tab. [name] and [project] are user data: log [session] only (ENG-C8).
 */
public data class AttachTarget(val session: SessionId, val name: String, val project: Project)

// SessionActionsState: nowe pole na końcu, z wartością domyślną (istniejące wywołania bez zmian)
/** @property canAttach a visible session of a registered project is selected and no dialog is open; also while an action runs. */
val canAttach: Boolean = false

// MissionControlController
/**
 * The session `⏎` attaches to, read now from the snapshot, the selection and the project list (not from [actions],
 * which may lag one step); null without a selected visible session, for a session outside the registered projects
 * and while a dialog of Mission Control is open. Pure query: no state change, no log.
 */
public fun attachTarget(): AttachTarget?
```

Wewnętrzne: `internal object SessionAttach { fun targetOf(session: Session?, projects: List<Project>, dialogOpen: Boolean): AttachTarget? }`. Używają go `attachTarget()` i `actionsOf` (`canAttach = targetOf(...) != null`). `actionsOf` dostaje `projects.projects` jako piąty strumień `combine` (5 parametrów, ENG-C2).

`app`:

```kotlin
internal class TerminalDeps(val api: TerminalApi, val shellLabel: String, val attachCommand: (SessionId) -> ShellCommand)
// AppModules(projects, sessions, inspector, registry, terminal: TerminalDeps): 5 zamiast 6 pól, limit konstruktora to 6
internal fun attachCommands(dialogOpen: Boolean, actions: SessionActionsState, attach: () -> Unit): List<Command>
internal class SessionAttacher(missionControl, terminal: TerminalController, attachCommand: (SessionId) -> ShellCommand, logger) {
    /** Opens `claude attach` of [MissionControlController.attachTarget] in a new tab of its project; no-op without one. */
    fun attachSelected()
}
internal class AttachCommands(controller: ProjectsController, missionControl, attacher: SessionAttacher, scope) : CommandProvider
```

### Decyzje

1. **Cel czytany na świeżo** (lekcja o `stateIn`): komenda woła `attacher.attachSelected()`, a ta czyta `attachTarget()`, nigdy `actions` ani `state`. `j`, a zaraz po nim ⏎, podłącza nową sesję.
2. **Kiedy attach jest dostępny** (tabela 1): zaznaczona widoczna sesja w **każdym** stanie, jeśli jej `project` jest na liście projektów i nie ma otwartego dialogu Mission Control. Działająca akcja (stop, respawn) attachu nie blokuje, tak samo jak podglądu. Przy sesji `Stopped` albo `Failed` wynik zależy od CLI: komunikat i `exit N` zostają w karcie (punkt ręczny).
3. **Nic nie zaznaczono, sesja bez projektu albo otwarty dialog**: komendy nie ma, a ⏎ nic nie robi. `onChord` zwraca `false`, więc klawisz nie jest zużyty. Bez komunikatu. Sesja bez projektu zdarza się tylko w widokach globalnych, a karta wymaga `ProjectId` grupy.
4. **Zawsze nowa karta**: każde ⏎ otwiera nową kartę `attach · <nazwa>` w aktywnym panelu, w grupie projektu sesji (`TerminalTabs.open`). Fokusu istniejącej karty nie robimy, bo `TabId` i lista kart są `internal` w `terminal:ui` (pytanie 1).
5. **Po attach**: panel terminala pod Mission Control pojawia się (jeśli nie było kart) z nową kartą, a `FocusActivePane` daje fokus jej widżetowi. Kolejne klawisze, także ⏎, trafiają do TUI Claude Code. Osobnego „widoku terminala” w aplikacji nie ma. Powrót do listy to klik w Mission Control, bez zmian.
6. **Droga klawisza ⏎**: ⏎ obsługuje tylko `Window.onKeyEvent` → `palette.onKeyEvent`. Gdy fokus jest w widżecie terminala, ⏎ idzie do PTY (`TerminalKeys` mostkuje tylko akordy z ⌘). Pole szukania i paleta zjadają ⏎ w `onPreviewKeyEvent`, a dialogi to `Popup(focusable = true)` i wtedy lista komend jest pusta. Przyciski panelu Mission Control dostają `canFocus = false`, bo po kliknięciu „Podgląd” ⏎ kliknęłoby go ponownie. Wiersze i filtry są już niefokusowalne.
7. **Komenda**: id `sessions.attach`, tytuł `command.attachSession=Attach sesji w terminalu`, `keywords = [attach, terminal, podłącz]`, grupa `SESSION`, skrót `AppShortcuts.ATTACH_SESSION = Shortcut.of(KeyChord(ChordKey.Named.ENTER))` (różny od ⌘⇧⏎ maksymalizacji). Jest oferowana przy `actions.canAttach` i bez `menu.dialogOpen`/`actions.dialogOpen`.
8. **Etykieta karty**: `terminal.attachTab=attach · {0}` z `AttachTarget.name` (docs/06, AM-503). `TerminalProject` buduje wspólny `terminalProjectOf(project)` (`id`, `displayName`, `dir`). Katalog roboczy daje `attachCommand` (`homeDir`).
9. **Logi**: INFO `session attach` z `sessionId`, bez nazwy i ścieżki. Otwarcie karty loguje już `TerminalController` (`tabId`, `kind`). Brak celu nie jest logowany.

## Ryzyka i pytania

**Pytania blokujące: brak.** Pytania nieblokujące (zostaje domyślna decyzja, jeśli człowiek nie zdecyduje inaczej):

1. **Istniejąca karta attach tej sesji**: domyślnie każde ⏎ otwiera nową kartę (decyzja 4), więc do sesji podłączają się dwaj klienci `claude attach`. Fokus istniejącej karty wymaga nowego publicznego API w `terminal:ui` (np. `openCommand` z kluczem karty), czyli osobnego zadania. Do potwierdzenia ręcznie: czy CLI pozwala na dwa attach naraz.
2. **Kropka stanu przy karcie attach** (docs/06; AM-503 przypisał ją do AM-505): wymaga `terminal:ui`, więc proponuję osobny wpis w roadmapie.
3. **Przycisk „Attach” w panelu szczegółów** (docs/05): klik musi dojść do `app`, czyli potrzebny callback albo strumień zdarzeń z kontrolera. Proponuję zrobić to razem z „Odpowiedz” w AM-506.
4. **Przyciski `projects:ui` („Dodaj projekt”, „Zamknij” banera) przyjmują fokus po kliknięciu** i wtedy ⏎ (a dziś też `space`) kliknie je ponownie. Poprawka to 2 linie poza modułami zadania, więc proponuję osobny `fix/`.

**Rozmiar:** netto w `src/main` (bez importów, KDoc i pustych linii): `mission-control:ui` ok. 30 (reguła 15, kontroler 12, fokus przycisków 2, pole 1), `app` ok. 65 (`SessionAttach.kt` 45, `TerminalDeps`/`Main`/`WindowControllers` 12, skrót i teksty 8). Razem ok. 95, z zapasem 30% **ok. 125**, czyli dużo poniżej limitu ENG-C10. Testy ok. 300 linii.

**Ryzyka:**

- Szybkie podwójne ⏎ przed otwarciem karty da dwie karty: `openCommand` działa asynchronicznie, a fokus przechodzi do widżetu dopiero po otwarciu. Akceptujemy to, bo ten sam skutek daje decyzja 4.
- `MissionControlController` ma po zmianie 10 funkcji (detekt TooManyFunctions zgłasza od 11). Kolejna funkcja (AM-506) wymusi podział albo `@Suppress`.
- `AttachTarget.toString` zawiera nazwę i `Project` (ścieżkę), więc KDoc zakazuje logowania całości (ENG-C8).
- Zaznaczalny tekst podglądu (`SelectionContainer`) może przyjąć fokus. Sprawdzić ręcznie, czy ⏎ dalej dochodzi do okna.
- Lekcja o KDoc z wyliczeniami: zaktualizować KDoc `actions`, `SessionActionsState` i nagłówek `MissionControlController` („runs only the stop, respawn and remove…”: attach nie jest komendą `sessions`, ale `actions` wylicza flagi).
