# AM-507 · Spike: odpowiedź przez ukryty attach w PTY (pytanie tekstowe, opcje, zgoda)

Issue: #101 · Wymagania: FR-S5, FR-K2 (`r`) · ENG-C8, ENG-C10, ENG-T3 · docs/09 (ryzyko „brak `reply`”), docs/11 §3 · ADR 0013 (przyjęta, część druga), ADR 0012 · Zależy: AM-502 (scalone)

## Zakres

Spike odpowiada na pytanie, czy aplikacja może odpowiedzieć sesji w tle, sama otwierając ukryty `claude attach <id>` w PTY. Wpisuje odpowiedź, sprawdza, czy TUI ją przyjął, i się odłącza. Niezawodność mierzymy osobno dla pytania tekstowego, pytania z opcjami i prośby o zgodę (ADR 0013). Prace dzielą się na trzy części:

- **(a) W repo, testowane bez prawdziwego Claude Code (ten PR, decyzja Krystiana: jeden PR ok. 550 linii):**
  - sterownik ukrytej odpowiedzi;
  - ekran bez widżetu (emulator jediterm-core, bez Swinga);
  - klasyfikator pytania;
  - runner scenariuszy T/O/Z z prawdziwym `claude` (przez `ProcessRunner`) i raport;
  - szkic ADR 0014 z protokołem pomiaru.

  Całość leży w osobnym zbiorze źródeł `replySpike` modułu `terminal:impl`. Testy używają fałszywego TUI `claude` na `PATH` i `FakeProcessRunner`.
- **(b) Ręcznie na macOS (Krystian):** protokół niżej, task `runReplySpike`.
- **(c) Wynik:** ADR 0014 „Odpowiedź przez ukryty attach” uzupełnia drugą część ADR 0013, którego nie edytujemy. Szkic ze statusem „proponowana” trafia do tego PR i zawiera kontekst, warianty, protokół, kryteria i pustą sekcję „Wyniki”. Wyniki i decyzję dla każdego rodzaju pytania wpisuje osobny PR `docs/AM-507-wyniki` (Closes #101) po pomiarze. Status zmienia człowiek.

**Gdzie kod:** `feature/terminal/impl/src/replySpike/kotlin/dev/quayside/terminal/impl/replyspike/`.

- Zbiór jest skojarzony z `main` (`associateWith`), więc widzi `internal` `PtyLauncher`, `ShellLaunch` i `PtyTtyConnector`.
- Nie trafia do jara ani do `.dmg`. `src/main` się nie zmienia.
- Nie w `app` jak w AM-501, bo `app` nie widzi `internal` z `impl`, a publiczny uchwyt w `impl` łamie regułę Konsist.
- Nie w `main`, bo przed wynikiem nie ma decyzji o API. Wariant `open` bez widżetu w `terminal:api` i `SessionReplies` w `sessions:api` wdroży zadanie po ADR 0014.

**Nie robimy:** zmian `api` żadnego feature, zmian `sessions:impl`, pola odpowiedzi w panelu ani w popupie (AM-702), wpisu w CHANGELOG (nic widocznego), Agent SDK ani `stream-json` (przy złym wyniku osobny spike i ADR 0015).

## Zmiany API

Feature `api`: **brak**. Typy spike'a są `internal` w zbiorze `replySpike`:

```kotlin
/** What the user answers. [Text.value] is user data (ENG-C8): never logged. */
internal sealed interface Reply {
    data class Text(val value: String) : Reply
    /** 1-based, as numbered by the TUI. */ data class Option(val index: Int) : Reply
    data class Permission(val allow: Boolean) : Reply
}
internal data class KeyVariant(val text: TextKeys = TextKeys.PASTE, val choice: ChoiceKeys = ChoiceKeys.DIGIT)
internal enum class TextKeys { PASTE, TYPE }      // bracketed paste + CR / plain chars + CR
internal enum class ChoiceKeys { DIGIT, ARROWS }  // "n" / ↓×(n-1) + CR
/** Pure: keystroke chunks for [reply]. Strips C0 controls and ESC from text, so an answer cannot inject keys. */
internal object ReplyKeys { fun keys(reply: Reply, variant: KeyVariant): List<String> }

/** What the screen asks for. Markers live in [PromptMarkers], calibrated on recorded frames. */
internal sealed interface Prompt {
    data object None : Prompt; data object Text : Prompt; data object Unknown : Prompt
    data class Options(val count: Int) : Prompt
    data class Permission(val tool: String?) : Prompt
}
internal object ScreenClassifier { fun classify(rows: List<String>): Prompt }

/** jediterm-core emulator (no Swing) over a PTY; rows are read under the buffer lock. */
internal class HeadlessScreen(connector: PtyTtyConnector, columns: Int = 120, rows: Int = 40) : AutoCloseable {
    fun rows(): List<String>
    /** Real time; true when [predicate] held before [timeout]. */
    suspend fun await(timeout: Duration, predicate: (List<String>) -> Boolean): Boolean
}
internal enum class Detach { KEY, HANGUP }        // detach key of `claude attach` / SIGHUP to the client only
internal data class ReplyLimits(val ready: Duration = 5.seconds, val ack: Duration = 5.seconds, val keyGap: Duration = 30.milliseconds)
/** Result of one hidden reply; no screen text, no answer (ENG-C8). */
internal sealed interface ReplyOutcome {
    data class Acknowledged(val ready: Duration, val ack: Duration) : ReplyOutcome
    data class NotReady(val seen: Prompt) : ReplyOutcome      // nothing typed
    data class KindMismatch(val seen: Prompt) : ReplyOutcome  // nothing typed
    data object NotAcknowledged : ReplyOutcome                // typed, prompt still shown after ack
    data object StartFailed : ReplyOutcome
}
internal class HiddenReply(shell: Path, baseEnvironment: Map<String, String>, logger: Logger, time: TimeSource = TimeSource.Monotonic) {
    /** Opens [attach] hidden, waits for a prompt matching [reply], types it, waits for the prompt to go, detaches. */
    suspend fun reply(attach: ShellCommand, reply: Reply, variant: KeyVariant, detach: Detach, limits: ReplyLimits = ReplyLimits()): ReplyOutcome
}

/** `claude` CLI for the runner over [ProcessRunner]; errors are fixed categories, never output text (ENG-C8). */
internal class SpikeClaude(runner: ProcessRunner, executable: String = "claude") {
    suspend fun start(name: String, prompt: String, dir: Path, model: String = "haiku"): Outcome<Unit, SpikeError>
    suspend fun find(name: String): Outcome<SpikeSession?, SpikeError>   // id, phase, waitingFor from `agents --json --all`
    suspend fun stopAndRemove(id: String): Outcome<Unit, SpikeError>
}
internal enum class Kind { TEXT, OPTIONS, PERMISSION }
/** Pure: [TrialVerdict.Success], [TrialVerdict.Failure] (category) or [TrialVerdict.Harmful] (category) of one trial. */
internal object Verdicts { fun of(trial: TrialFacts): TrialVerdict }
/** Pure: per kind successes, harmful count, p50/p95, race typings and the [Rating] from the table below. */
internal object ReplyReport { fun summarize(trials: List<TrialRecord>): Map<Kind, KindSummary> }
```

Decyzje:

1. Sterownik niczego nie wpisze, dopóki klasyfikator nie pokaże pasującego rodzaju pytania. Chroni to przed wyścigiem.
2. `HANGUP` zabija tylko klienta `attach`, bez potomków.
3. Logi i raport (JSONL + podsumowanie w `build/reply-spike/`) zawierają rodzaj, wynik, czasy i wersję `claude`. Nigdy tekstu ekranu ani odpowiedzi. Zrzuty ekranu powstają tylko w trybie `record`.
4. Runner sprząta każdą sesję (`stop` i `rm`), także po porażce.

## Testy

Testy z PTY: `@Timeout(10, threadMode = SEPARATE_THREAD)`, `/bin/sh`, `HOME` jako katalog tymczasowy, fałszywy TUI dopisany do `PATH` przez `.profile` (wzór `PtyLauncherTest`). Jak działa `fake-claude-tui.sh attach <id>`:

- `stty raw -echo`;
- ramka z `$FAKE_TUI_FRAME` po `$FAKE_TUI_DELAY`;
- odebrane bajty zapisuje do `$FAKE_TUI_LOG`;
- czyści pytanie po Enter, cyfrze albo Esc (nie czyści przy `FAKE_TUI_STUCK=1`).

- [ ] jednostkowe:
  - `ReplyKeysTest` (tabela 1), `ScreenClassifierTest` (tabela 2), `VerdictsTest` (tabela 3), `ReplyReportTest` (tabela 4);
  - `SpikeClaudeTest` (`FakeProcessRunner`): `start runs claude bg with name model and prompt in the dir`, `find reads id phase and waitingFor by name`, `find returns null for an unknown name`, `unparseable listing is an error category without its text`, `stop and remove runs both commands`, `a failing command is its category`.
- [ ] integracyjne `HeadlessScreenTest`: `cursor moves and line clears give the final screen`, `polish text renders unchanged`, `alternate screen is shown and restored`, `await returns false after the timeout`.
- [ ] integracyjne `HiddenReplyTest`:
  - wysyłka: `text reply pastes the answer and enter once the prompt shows`, `option reply sends the digit`, `option reply with arrows moves down and confirms`, `permission allow and deny send their keys`;
  - nic nie wpisane: `nothing is typed before the prompt appears`, `a prompt that never shows is NotReady and types nothing`, `a permission prompt for a text reply is KindMismatch and types nothing`, `option beyond the shown count is KindMismatch`;
  - potwierdzenie i odłączenie: `a prompt that stays is NotAcknowledged`, `hangup detach leaves a process outside the client alive`, `key detach sends the key`;
  - logi: `logs carry kind and outcome only`.
- [ ] kontraktowe, funkcjonalne: brak (nie ma `api` ani UI). Konsist skanuje tylko `src/main`, więc reguły architektury się nie zmieniają.

Ocena każdego rodzaju według tabeli 4. **Dobry:** pole odpowiedzi bez terminala. **Graniczny:** pole odpowiedzi plus akcja „Odpowiedz w terminalu” przy `NotReady`. **Zły:** ten rodzaj zostaje w terminalu (AM-506). Gdy złe są wszystkie trzy, osobny spike Agent SDK/`stream-json` (ADR 0015).

**Uwaga statystyczna:** 10/10 nie gwarantuje niezawodności ≥ 95%. Jednostronny 95% przedział ufności (Clopper–Pearson) daje dolną granicę ok. 74%, więc wynik „dobry” znaczy tylko „brak sygnału awarii”. Ocenę graniczną albo złą bez szkodliwego wyniku można doprecyzować 10 dodatkowymi próbami. Przy 20 próbach progi to: dobry ≥ 19/20, graniczny 17–18/20, zły < 17/20. ADR 0014 zapisuje liczbę prób i przypiętą wersję. Ponowny pomiar następuje po aktualizacji Claude Code.

## Ryzyka i pytania

**Pytania blokujące: brak.** Decyzje Krystiana: jeden PR (bez AM-511), tylko `terminal:impl`, 10 prób na rodzaj. Pytania nieblokujące (jeśli nikt nie zdecyduje inaczej, zostaje domyślna decyzja):

2. **Koszt tokenów**, ok. 63 sesje `haiku`. Uruchamia je tylko Krystian, ręcznie (`runReplySpike`). CI i testy nie wołają prawdziwego `claude`.

- wyścig „widoczna karta attach” tylko ręcznie;

**Ryzyka:**

- jediterm-core bez widżetu (`JediTerminal` + `JediEmulator` + własny `TerminalDisplay`) nie jest udokumentowaną drogą. Plan B: ukryty `JediTermWidget` (tylko Mac, testy z `assumeFalse(isHeadless)`). Wynik trafia do ADR 0014.
- Markery TUI w ręcznie zrobionych ramkach są przybliżeniem. Krok 1 je weryfikuje. Poprawka markerów i ramek (zanonimizowanych) to commit w tym PR przed pomiarem.
- Klawisz odłączenia `claude attach` jest nieznany. Jeśli `attach` sam startuje supervisor, `HANGUP` może dotknąć sesji. Werdykt `Harmful` to wyłapie.
- Format `agents --json` w `SpikeClaude` to duplikat parsera z `agent-runtime:impl`. W kodzie spike'a jest to akceptowalne, a fixtures `agents-*.json` są kopią nagranych przykładów.
- `associateWith` dla `test` → `replySpike` i task `detektReplySpike`: jeśli Gradle albo detekt ich nie obsłużą, klasy spike'a stają się publiczne w pakiecie `replyspike`, a detekt dla zbioru dopisujemy ręcznie. Każde takie odstępstwo implementer zapisuje w planie.
