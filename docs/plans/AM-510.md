# AM-510 · Karty attach: fokus istniejącej karty sesji i kropka stanu

Issue: #109 · Wymagania: FR-T2, FR-K2 (część: ⏎ i `r` przy istniejącej karcie) · ENG-I1, ENG-I2, ENG-C2, ENG-C8 · docs/06 „Karty per projekt” (kropka stanu przy karcie `attach`) · ADR 0011, 0012, 0013 (przyjęte) · Zależy: AM-503, AM-505, AM-506 (scalone)

## Zakres

1. **Fokus istniejącej karty** (`terminal:ui`, `app`): karta dostaje opcjonalny klucz `TabKey` nadany przez wołającego. `TerminalController.focusOrOpen` szuka karty o tym kluczu i aktywuje ją zamiast otwierać nowy proces. `SessionAttacher` (⏎, `r` i komendy palety) woła `focusOrOpen` z kluczem `attach:<sessionId>`, więc ⏎ i `r` dzielą jedną kartę sesji (AM-506, decyzja 5).
2. **Kropka stanu** (`terminal:ui`, `app`): `terminal:ui` dostaje własny, niezależny od sesji `TabStatus` i rysuje kropkę przy karcie, której klucz ma status. `app` mapuje `SessionsSnapshot` z `sessions:api` na `Map<TabKey, TabStatus>` i przekazuje mapę przez `TerminalController.showStatuses`. `terminal:ui` nie zależy od `sessions`.

**Nie robimy:** kropki przy kartach `zsh`, kart `logs`, przycisku „Attach” w panelu szczegółów, zmian `terminal:api`, `sessions:api`, `mission-control:ui`, kolorów ze schematu (AM-802), usuwania `openCommand`.

## Zmiany API

`terminal:api`, `sessions:api`, `mission-control:ui`, `command-palette:*`: brak. Publiczne API `terminal:ui` (woła je tylko `app`):

```kotlin
/** Identity of a tab chosen by the caller (e.g. `attach:<sessionId>`), so a later request finds the same tab (AM-510). Not logged. */
@JvmInline public value class TabKey(public val value: String)

/** The state shown as a dot next to a keyed tab; `app` maps its domain state to it (AM-510). */
public enum class TabStatus { WAITING, WORKING, DONE, FAILED, STOPPED }

// TerminalController
/**
 * Activates the tab opened with [key] and gives its widget the focus; starts no process. Without such a tab,
 * runs [command] in a new tab labelled [label] in [project]'s group, shown in the active pane. A tab of [key] whose
 * process exited is replaced in place by a new one. Ignored while a tab of [key] is still opening.
 */
public fun focusOrOpen(project: TerminalProject, key: TabKey, label: String, command: ShellCommand)

/** Shows a dot next to every tab whose key is in [statuses]; other tabs show none. Replaces the previous map. */
public fun showStatuses(statuses: Map<TabKey, TabStatus>)
```

Wewnętrzne: `TerminalTab.key: TabKey? = null`; `internal val statuses: StateFlow<Map<TabKey, TabStatus>>` (osobny `MutableStateFlow`, nie przez reduktor, bo snapshot przychodzi co cykl pollingu); `internal val focusRequests: StateFlow<Int>`; `TabReuse { Focus(tab), Replace(tab), Open }` i czyste `TerminalTabs.reuseOf(tabs, key)`; `TerminalEvent.Replaced(old: TabId, tab: TerminalTab) : OfTab`; `TabSpec(project, label, kind, key)` i `Placement { Active, Split(axis), Replace(old) }`, żeby `open(spec, placement, start)` i `newTab(spec, session)` miały ≤ 5 parametrów (ENG-C2). Composable: `TerminalTabBar`, `TabGroupChip`, `TabChip` dostają po jednym parametrze (`statuses` albo `status: TabStatus?`), najwyżej 4.

`app`:

```kotlin
internal fun attachTabKey(id: SessionId): TabKey                       // TabKey("attach:${id.value}")
internal fun tabStatusOf(state: SessionState): TabStatus                // tabela 3
internal fun attachTabStatuses(snapshot: SessionsSnapshot): Map<TabKey, TabStatus>
```

### Decyzje

1. **Wybór karty** (tabela 1): klucz jest globalny, nie per grupa. Istnieje najwyżej jedna karta o danym kluczu (zastępowanie w miejscu i blokada w trakcie otwierania), ale `reuseOf` i tak preferuje kartę żywą.
2. **Żywa karta**: `dispatch(Select(id))` (pokazuje ją w jej panelu albo w aktywnym, gdy ukryta; przy maksymalizacji pokazuje jej panel) i `focusRequests++`. `FocusActivePane` ma `focusRequests` w kluczach `LaunchedEffect`, więc fokus wraca do widżetu także wtedy, gdy karta już jest aktywna, a fokus jest w liście Mission Control. Log INFO `terminal tab focused` z `tabId`.
3. **Martwa karta (proces zakończony, np. detach albo błąd CLI): zastąpienie w miejscu.** Nowy proces dostaje nowy `TabId` (bo `PaneFrame` ma `key(tab.id)` i `SwingPanel` nie podmieniłby widżetu) na tej samej pozycji w liście i w tym samym liściu układu (tabela 2). Stara sesja dostaje `close()`. Gdy start zawiedzie, martwa karta zostaje, a pasek błędu pokazuje kategorię. Odrzucone: nowa karta obok martwej (bałagan przy ⏎ na sesji `Stopped`) i zostawienie martwej karty bez akcji (⏎ nic by nie robiło).
4. **Wyścig podwójnego ⏎** (ryzyko z AM-505): klucz trafia do `opening: MutableSet<TabKey>` przed `launch` i wychodzi w `finally`. Drugie wywołanie z tym kluczem w tym czasie nic nie robi.
5. **`r` też używa `focusOrOpen`**: ADR 0013 kieruje do TUI, a istniejąca karta attach pokazuje to samo pytanie. Strażnik `waiting` w `replySelected` zostaje bez zmian.
6. **Kropka**: `TabStatus.WAITING` łączy AwaitingInput i AwaitingPermission, tekst „Czeka na użytkownika”. Przed etykietą karty, koło 8 dp w kolorze `TerminalColors.of(status)`: kopia wartości z `Colors.of(Tone)` Mission Control (WAITING `FFD60A`, WORKING `64D2FF`, DONE `30D158`, FAILED `FF453A`, STOPPED secondary). Nie jest klikalna, więc nie przyjmuje fokusu. Semantyka: tag `terminal.tab.<id>.status` i `stateDescription` z `tab.status.<nazwa>` (teksty jak `state.*` w MC). `TabChip` jest blisko limitu LongMethod (30): `exit N` przechodzi do `TabExitMarker`, kropka do `TabStatusDot`.
7. **Przepływ stanu**: `WindowControllers.init` uruchamia w `scope` okna `snapshot.collect { terminal.showStatuses(attachTabStatuses(it)) }`. Bez `stateIn` (lekcja). `Stale` zostawia ostatnie kropki, `Loading` (pusta lista) nie daje kropek, a sesja usunięta z listy traci kropkę (karta zostaje). Zbieranie snapshotu siedzi w `followSessions` (`app/src/main/kotlin/dev/agentmanager/app/AttachTabs.kt`), wołanym z `WindowControllers.init` i z testowego `WindowWorld`; sama linia w `WindowControllers.init` nie ma testu, bo testy okna nie tworzą `WindowControllers`.
8. **Droga klawisza**: bez zmian względem AM-505/506. ⏎ i `r` działają przez `Window.onKeyEvent`. Gdy fokus jest w widżecie, idą do PTY (`TerminalKeyDispatcher` mostkuje tylko ⌘). Nie dochodzi żaden fokusowalny element.

## Ryzyka i pytania

**Pytania blokujące: brak.** Pytania nieblokujące (zostaje domyślna decyzja, jeśli człowiek nie zdecyduje inaczej):

1. **Martwa karta**: domyślnie zastąpienie w miejscu (decyzja 3). Inna możliwość to nowa karta obok martwej.
2. **`openCommand`** zostaje publiczne, choć po zmianie woła je tylko test. Usunięcie to osobna decyzja (np. przy kartach `logs`).
3. **Kolory** są skopiowane z Mission Control do AM-802. Zmiana jednego miejsca nie zmieni drugiego.

**Rozmiar:** netto w `src/main` (bez importów, KDoc i pustych linii): `terminal:ui` ok. 95 (kontroler z `Placement`/`TabSpec` 37, reduktor `replace`/`reuseOf` 22, typy 10, kropka, kolory, tagi, teksty i przekazanie `statuses` 26), `app` ok. 22 (`AttachTabs.kt` 15, `WindowControllers` 5, `SessionAttacher` 2). Razem ok. 117, z zapasem 30% **ok. 150**, więc jeden PR (limit ENG-C10 ok. 400). Testy ok. 450 linii. Gdyby implementacja przekroczyła 300, podział: część 1 fokus (`focusOrOpen`, zastępowanie), część 2 kropka (`TabStatus`, `showStatuses`, `AttachTabs.kt`).

**Ryzyka:**

- `focusRequests` to strażnik bez skutku widocznego w testach Compose (fake `JPanel` nie jest w oknie). Test jednostkowy sprawdza licznik, a KDoc opisuje powód (lekcja o strażnikach).
- Lekcja o KDoc z wyliczeniami: poprawić „in a new tab” w KDoc `SessionAttacher`, `attachSelected`, `replySelected` i „The 11 operations” w `TerminalController`.
- `TabChip` i `TerminalArea` blisko LongMethod: zmierzyć ciała funkcji przed oddaniem (lekcja).
- Zastąpienie zamyka starą sesję. Jeśli `close()` martwej sesji pty4j rzuca, zachowanie jak przy × (już obsłużone w `close`).
- `TabKey` zawiera id sesji. Id nie jest daną użytkownika (ENG-C8), ale kontroler i tak nie loguje klucza.
