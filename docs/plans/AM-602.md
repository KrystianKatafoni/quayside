# AM-602 · HookInstaller z backupem i odinstalowaniem

Issue: #5 · Wymagania: NFR-5, ENG-C8, ENG-I1, ENG-T2 · docs/03 „Hooki”, docs/11 §4, ADR 0010, ADR 0017 · Etap: M6 · Zależy: AM-601

## Zakres

Implementacja `HookInstaller` z `agent-runtime:api` na prawdziwych plikach: `~/.claude/settings.json` (`HookScope.Global`) i `<projekt>/.claude/settings.local.json` (`HookScope.Project`). `install` robi kopię zapasową i dopisuje nasze handlery HTTP dla pięciu zdarzeń, `uninstall` usuwa tylko nasze handlery albo przywraca kopię, `status` pokazuje, które zdarzenia mają nasz handler. Kształt handlera jest z docs/03, rozpoznawanie z ADR 0010.

Nie robimy: okna zgody i wywołania instalatora z UI (NFR-5 „za zgodą” spełnia wywołujący; UI to osobne zadanie), przekazania tokenu do procesu `claude` (patrz ryzyka), wpięcia w `app`, zmian `api`.

## Moduły

- `feature:agent-runtime:impl`: `HookSettingsJson` (czyste edycje JSON), `OurHandlers` (rozpoznawanie, ADR 0010), `SettingsFiles` (ścieżki, odczyt, zapis atomowy), `HookBackups`, `SettingsJsonHookInstaller`, fabryka `hookInstallerModule`, testy.
- `feature:agent-runtime:api`: bez zmian; `HookInstallerContract` z `testFixtures` działa teraz także na prawdziwych plikach.
- `docs/ROADMAP.md`, `CHANGELOG.md`.

## Zmiany API

Brak w `api`. Publiczna jest tylko fabryka:

```kotlin
public fun hookInstallerModule(homeDir: Path, backupDir: Path, clock: Clock, io: CoroutineDispatcher,
                               logger: Logger, port: Int = 47321): HookInstaller
```

### Reguły

1. **Dopisywane są tylko nasze handlery.** Dla każdego z pięciu zdarzeń, które nie ma jeszcze naszego handlera, do tablicy zdarzenia dochodzi grupa `{"hooks": [handler]}`. Reszta pliku (inne klucze, obce hooki, kolejność kluczy) zostaje; plik jest zapisany od nowa z wcięciem, a oryginał leży w kopii.
2. **Handler** (docs/03): `{"type":"http","url":"http://127.0.0.1:<port>/hooks","headers":{"X-AM-Token":"$AM_HOOK_TOKEN"},"allowedEnvVars":["AM_HOOK_TOKEN"]}`. Token nie trafia do pliku.
3. **Idempotencja.** Gdy wszystkie pięć zdarzeń ma nasz handler (dowolny port), plik nie jest zapisywany; `install` i tak zwraca świeżą kopię.
4. **Kopia przed każdym `install`.** Plik w `backupDir`: `<epoch ms>-<numer>-<zakres>.json` z oryginalnym tekstem (prawa `rw-------`); dla brakującego pliku pusty `….absent`. `BackupRef` to nazwa pliku; ref z innego zakresu (projekt bywa rozróżniany po haszu katalogu), z separatorem ścieżki albo nieistniejący → `BackupNotFound`.
5. **`uninstall(scope, null)`** usuwa tylko nasze handlery; puste grupy, zdarzenia i klucz `hooks` znikają. Brak pliku to `Ok`. **`uninstall(scope, ref)`** przywraca kopię co do bajtu (dla `.absent` usuwa plik) i nie dotyka niczego innego.
6. **Plik nie do użycia** (niepoprawny JSON, korzeń nie jest obiektem, `hooks` nie jest obiektem, nasze zdarzenie nie jest tablicą, błąd odczytu) → `status` = `Unreadable(kategoria)`, `install`/`uninstall` = `SettingsUnreadable(plik, kategoria)`; plik zostaje nietknięty, kopii nie ma, treść pliku nigdzie nie wraca (ENG-C8). Błąd zapisu kopii lub pliku → `WriteFailed(plik, "io")`.
7. **Zapis atomowy** (plik tymczasowy w tym samym katalogu + `move`), wszystko na wstrzykniętym `io` pod jednym `Mutex`.

## Ryzyka i pytania

- **Token musi dotrzeć do procesu `claude`.** Nagłówek ma wartość `$AM_HOOK_TOKEN`, którą Claude Code rozwija ze swojego środowiska (`allowedEnvVars`). Dopóki procesy `claude` nie dostaną `AM_HOOK_TOKEN` w środowisku, serwer odpowie 401 na każdy hook, a polling nadal działa. Do rozstrzygnięcia osobno (nie zweryfikowałem na prawdziwym `claude`): `ClaudeCliAdapter.start` dokłada `AM_HOOK_TOKEN` do środowiska polecenia (nie pokryje sesji uruchomionych poza Quayside ani demona działającego już bez zmiennej), albo token zapisany wprost w nagłówku (łamie „token tylko w Keychain”, ADR 0017). Rekomendacja: wariant ze środowiskiem w osobnym zadaniu.
- Plik jest zapisywany z domyślnym wcięciem; użytkownik, który formatował go inaczej, zobaczy zmianę whitespace (oryginał w kopii).
- Zdarzenie naszego typu będące nie-tablicą w pliku użytkownika blokuje instalację (`SettingsUnreadable`), zamiast je nadpisać.
