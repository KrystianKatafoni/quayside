# AM-604 · Summarizer (last_assistant_message, opcjonalnie Haiku)

Issue: #7 · Wymagania: FR-S7, FR-S1, ENG-C8, ENG-I1–I8 · docs/03 „Hooki”, docs/00 „Podsumowanie sesji”, docs/11 §2, §4, §8, §9, ADR 0002, ADR 0004, ADR 0019 · Etap: M6 · Zależy: AM-603

## Zakres

Decyzje człowieka (2026-11-02): zakres obejmuje `sessions:impl` i `app`; Haiku wchodzi do AM-604; model woła port `OneShotPrompt` w `agent-runtime:api`; streszczenia modelem są domyślnie wyłączone; przełącznik jest w nowym pliku `summaries.json`. Szczegóły i uzasadnienie: ADR 0019 („proponowana”, przyjęcie przy scaleniu).

Dwa PR-y, każdy na własnej gałęzi:

- **Część A** (`feat/AM-604-summarizer`, `Refs: #7`): feature `summaries` (`api` + `impl`, bez `ui`) z podsumowaniem bez modelu i spięcie z `sessions:impl` i `app`. Po hooku `Stop` sesja od razu ma podsumowanie (najwyżej 2 zdania, ≤ 160 znaków, jedna linia, bez Markdown) w `Session.summary`. Wiersz, panel szczegółów (AM-405) i zmienna głosu `{podsumowanie}` (AM-703) już je pokazują.
- **Część B** (nowa gałąź `feat/AM-604-haiku` z `main` **po scaleniu A**, `Closes #7`): port `OneShotPrompt`, adapter `claude -p`, `summaries.json` i streszczenie Haiku, które w tle zastępuje podsumowanie z części A.

Nie robimy: ekranu ani przełącznika w UI (FR-S7 go nie wymaga; użytkownik edytuje `summaries.json`, zmiana działa po restarcie; ekran to osobne zadanie w roadmapie), zapisu podsumowań na dysk, historii z transkryptu, podsumowań z `NeedsInput` i `claude logs`.

### API A (`summaries:api`)

```kotlin
/**
 * Turns the last message of an agent's turn (`last_assistant_message` of the `Stop` hook) into a short
 * summary at once, without IO (FR-S7). An [Outcome.Ok] summary is one line, not blank and at most
 * [MAX_LENGTH] code points. Pure and thread-safe; never throws. The message and the summary are user data
 * (ENG-C8): never logged.
 */
public fun interface Summarizer {
    public fun summarize(lastMessage: String): Outcome<String, SummaryError>
    public companion object { public const val MAX_LENGTH: Int = 160 }
}

/** Why there is no summary. Holds no part of the message (ENG-C8). Every error keeps the previous summary. */
public sealed interface SummaryError {
    /** Blank, or only code blocks, tables or markup. */
    public data object Empty : SummaryError
}

/** What `summariesModule` gives the composition root. */
public data class SummariesApi(val summarizer: Summarizer)
```

Fabryka A: `public fun summariesModule(): SummariesApi`. `sessionsModule` dostaje ostatni parametr `summaries: SummariesApi? = null` (null = bez podsumowań; dotychczasowe testy bez zmian). `reduce` ma już 5 parametrów (ENG-C2), więc `details` zastępuje obiekt `internal data class HookData(val details: Map<SessionId, HookDetail> = emptyMap(), val summaries: Map<SessionId, String> = emptyMap())`. Reguła: `summary = summaries[id] ?: before?.summary`. Wywołania w `SessionStateReducerHooksTest` zmieniają się na `hooks = HookData(details = …)`.

### Reguły A

`LastMessageSummary.of(message): String?`:

1. Bloki kodu w płotach (trzy odwrócone apostrofy albo `~~~`) znikają; niezamknięty płot usuwa resztę tekstu.
2. Znikają linie nagłówków (`#`), wiersze tabel (`|…`) i linie poziome (`---`, `***`). Z początku linii znikają `>`, znaczniki list (`-`, `*`, `+`, `1.`, `1)`) i `[ ]`/`[x]`.
3. `[tekst](url)` → `tekst`; znikają `**`, `__` i odwrócone apostrofy (pojedyncze `*`, `_` zostają).
4. Pierwszy akapit; linie łączone spacją; `\r` i znaki Cc → spacja; spacje zwinięte, brzegi przycięte.
5. Najwyżej 2 zdania (koniec: `.`, `!`, `?`, `…` i biały znak), o ile mieszczą się w 160; dłuższe pierwsze zdanie ucięte na ostatniej spacji przed 159 code pointem (bez spacji w drugiej połowie: twarde cięcie) + `…`; pary surogatów nie są rozcinane.
6. Pusty wynik → `null` (`Err(Empty)`).

`SessionsState.onHook(TurnEnded)` z niepustym `lastMessage`, pod mutexem: rozmowy spoza ostatniej listy są pomijane (chroni też przed pętlą z `claude -p` w części B); `Ok` → wpis `summaries[conversationId]` i jedna publikacja razem z notatką, więc `TurnFinished` niesie nowe podsumowanie; `Err` i brak wiadomości → bez zmiany. `publish` mapuje `ConversationId` → `SessionId` przez bieżącą listę; udane `refresh` usuwa rozmowy spoza listy. Podsumowanie przeżywa wygaśnięcie notatki hooka. Zero logów z treścią.

### API B

```kotlin
// agent-runtime:api
/**
 * Asks a model one question through Claude Code in print mode, outside any session and without hooks
 * (ADR 0019). Never throws except CancellationException; any dispatcher. Errors: NotInstalled, Timeout,
 * CommandFailed (stderr redacted, never the prompt), Unparseable (fixed category). Costs tokens: call only
 * after the user opted in.
 */
public fun interface OneShotPrompt {
    public suspend fun ask(request: PromptRequest): Outcome<String, RuntimeError>
}

/** One question; `toString` hides [prompt] (ENG-C8). @throws IllegalArgumentException blank or > MAX_PROMPT. */
public data class PromptRequest(val prompt: String, val model: String, val timeout: Duration) {
    public companion object { public const val MAX_PROMPT: Int = 16_000 }
}

// summaries:api
/** A better summary that may take seconds and cost tokens; same guarantees as [Summarizer]. */
public fun interface SummaryRefiner {
    public suspend fun refine(lastMessage: String): Outcome<String, SummaryError>
}
public data class SummariesApi(val summarizer: Summarizer, val refiner: SummaryRefiner? = null) // null = model off
// SummaryError: + Unavailable (no claude, timeout), + Failed (model or output error); fixed categories only
```

Fabryki: `public fun oneShotPromptModule(process: ProcessRunner, homeDir: Path, executable: String = "claude"): OneShotPrompt`; `public suspend fun summariesModule(storage: JsonStorage, prompt: OneShotPrompt, logger: Logger): SummariesApi` (czyta `summaries.json` raz).

### Reguły B

1. argv: `[exe, -p, --model, <model>, --output-format, json, --settings, {"disableAllHooks":true}, --no-session-persistence, --, <prompt>]`, katalog `homeDir`. Wyłączone hooki zapobiegają pętli `Stop` → streszczenie → `Stop`. Wynik: pole `result` (string) z JSON; `is_error: true` → `CommandFailed(kod, "")`; brak JSON/pola → `Unparseable("print result")`; kod ≠ 0 → `CommandFailed` z `StderrTail.of(stderr, secrets = listOf(prompt))`. Adapter nie loguje `ShellCommand` (jego `toString` pokazuje argv).
2. `summaries.json`: `{"schemaVersion":1,"data":{"useModel":false}}`; brak pliku i `.broken` = wyłączone. `HaikuSummaryRefiner`: model `haiku`, timeout 30 s, prompt = stała instrukcja + ostatnie 8 000 znaków wiadomości; odpowiedź przez `LastMessageSummary.of` (gwarancje kontraktu); `NotInstalled`/`Timeout` → `Unavailable`, reszta → `Failed`.
3. `sessions:impl`: po publikacji z części A, gdy `refiner != null`, `SummaryRefinement` startuje zadanie w zakresie monitora: najwyżej jedno wywołanie modelu naraz (`Semaphore(1)`), nowy `Stop` tej rozmowy anuluje poprzednie, wynik trafia do mapy tylko przy zgodnym numerze tury (lekcja o pokoleniach). Wynik publikowany bez zdarzenia. `Err` → `warn` ze stałą kategorią, podsumowanie z A zostaje.

## Ryzyka i pytania

Pytania blokujące:

1. **Rozmiar B ≈ 490 linii.** Rekomendacja: B dzielimy na B1 (`agent-runtime`: port, adapter, kontrakt; ≈ 200) i B2 (`summaries`, `sessions`, `app`; ≈ 290), oba `Refs: #7`, `Closes #7` w B2. Alternatywa: jeden PR B ponad limitem (jak AM-703). Którą wybierasz?

Pytania niezablokowane (plan przyjmuje rekomendację):

1. Prompt idzie w argv, bo `ProcessRunner` nie ma stdin (rozszerzenie to zmiana `core:process`). Treść jest widoczna w `ps` dla tego samego użytkownika, jak prompt w `claude --bg`.
2. Długość 2 zdania / 160 znaków; podsumowania tylko w pamięci; w języku agenta.

Ryzyka:

- Flagi `-p --output-format json`, `--settings` z `disableAllHooks` i `--no-session-persistence` trzeba potwierdzić na `claude` 2.1.139+ (`/compat-check`, `docs/compat.md`); bez `disableAllHooks` strażnik „tylko rozmowy z listy” w A i tak zatrzymuje pętlę, ale hooki trafią do serwera.
- Koszt: jedno wywołanie Haiku na turę każdej sesji; ograniczone przez `Semaphore(1)` i anulowanie starszych tur.
- Treść wiadomości trafia do modelu drugi raz (tylko po `useModel: true`); nigdy do logów.
- Heurystyka zdań jest prosta („e.g.” utnie zdanie).
