# AM-605 · Wstrzyknięcie AM_HOOK_TOKEN do procesów claude

**Uzasadnienie zmiany roadmapy:** hooki z AM-602 wysyłają nagłówek `X-AM-Token: $AM_HOOK_TOKEN`. Bez tej zmiennej w środowisku procesu `claude` serwer hooków (AM-601) odpowiada 401 i działa tylko polling.

## Zakres

- `agentRuntimeModule(injectHookToken = true)` buduje `KeychainHookTokenStore`; `ClaudeCliAdapter.start` i `respawn` przekazują token w `ShellCommand.env` jako `AM_HOOK_TOKEN` (jedyne miejsca startujące `claude --bg`; `attach` działa w istniejącej sesji).
- Token nigdy nie trafia do pliku ani do logów (`ShellCommand.toString` maskuje env).
- Błąd Keychain nie blokuje startu sesji: ostrzeżenie w logu i start bez tokena (polling pozostaje źródłem prawdy).
- `app/Main.kt` włącza wstrzykiwanie.

## Moduły

`agent-runtime:impl` (`ClaudeCliAdapter`, `AgentRuntimeModule`, `HookEnv`), `app` (`Main`).

## Testy

`HookTokenEnvTest`: start i respawn z tokenem, brak tokena dla `stop`/`logs`, brak magazynu, awaria Keychain, przełącznik w fabryce.
