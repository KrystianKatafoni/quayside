# AM-606 · Ekran ustawień podsumowań

Issue: #67 · Wymagania: FR-S7, NFR-6, NFR-10, ENG-C2, ENG-C8, ENG-I4 · docs/11 §4, §8, ADR 0019 · Etap: M6 · Zależy: AM-604

## Zakres

Okno „Ustawienia podsumowań” (dialog `Popup` nad oknem, jak ustawienia powiadomień) z jednym przełącznikiem „Streszczaj modelem (Haiku)”, zapisywanym w `summaries.json`. Dwie drogi do okna: pozycja menu „Widok → Ustawienia podsumowań…” i komenda palety `summaries.settings`. Okno tłumaczy koszt (ostatnia wiadomość trafia drugi raz do modelu przez `claude -p`, zużywa tokeny) i domyślne „wyłączone”.

Decyzje:

1. Zmiana działa **od następnego uruchomienia**. `summariesModule` czyta plik raz i na tej podstawie buduje `SummariesApi.refiner`; podmiana refinera na żywo wymagałaby zmian w `sessions:impl` (poza zakresem). Okno pokazuje notatkę „Zmiana zadziała po ponownym uruchomieniu aplikacji”, gdy szkic różni się od wartości, z jaką wystartowała aplikacja (`startedWithModel`).
2. Port `SummarySettingsRepo` w `summaries:api` (nowy typ, bez zmian istniejących) zamiast czytania pliku w `ui`: `ui` nie widzi `impl`, a `app` nie powinien znać formatu pliku.
3. Format pliku bez zmian (`{"useModel": bool}`, schemat 1, ADR 0019): nowy ADR niepotrzebny.

Nie robimy: przełączania refinera na żywo, wyboru modelu innego niż Haiku, limitu kosztu, ekranu historii streszczeń.

- `summaries:ui` (nowy moduł, `settings.gradle.kts`): `SummarySettingsController`, `SummarySettingsDialog`, `SummaryStrings`, `SummaryTags`, `i18n/summary-settings.properties`; testy kontrolera, tekstów i ekranu (`AmTestTheme`).
- `app`: `SummarySettingsCommands.kt`; zmiany w `AppModules.kt` (`summarySettings`), `Main.kt` (`StoredSettings`), `WindowControllers.kt`, `MainWindow.kt`, `AppMenu.kt`, `i18n/strings.properties`; testy: komenda, okno w `WindowWorld`, `CompositionRootTest` (klucze tekstów).

## Zmiany API

`summaries:api` (nowe, bez zmian istniejących):

```kotlin
public interface SummarySettingsRepo {
    public val useModel: StateFlow<Boolean>
    public val startedWithModel: Boolean
    public suspend fun setUseModel(on: Boolean): Outcome<Unit, SummarySettingsError>
}
public enum class SummarySettingsError { WRITE_FAILED, NEWER_SCHEMA }
```

## Testy

- Kontrakt `SummarySettingsRepoContract` na fake i na `JsonStorage` (pusty katalog, zmiana, powrót, `startedWithModel` nie zmienia się).
- `JsonSummarySettingsRepo`: wartość z pliku, plik uszkodzony (domyślnie wyłączone + ostrzeżenie), nowszy schemat (odmowa, brak zapisu), nieczytelny plik, nieudany zapis (bez publikacji, log bez szczegółów), kolejna próba po błędzie, otwarcie niczego nie zapisuje.
- Kontroler: szkic z zapisanej wartości, notatka restartu tylko gdy szkic ≠ `startedWithModel`, edycja nie zapisuje, jeden zapis naraz, wynik po anulowaniu odrzucony (także po ponownym otwarciu), błąd zostaje do następnej edycji.
- Ekran: fokus na przełączniku, klik pokazuje notatkę, Zapisz zapisuje, Esc i Anuluj nie zapisują, błąd zapisu widoczny.
- Okno: komenda palety otwiera dialog; zmiana + zapis dociera do repo (scenariusz użytkownika).

Ręcznie na macOS (nie sprawdzone w chmurze, bo `app` się tu nie kompiluje): Widok → Ustawienia podsumowań…, włączyć, zapisać, `cat ~/Library/Application Support/Quayside/summaries.json`, uruchomić ponownie i zobaczyć streszczenia modelem.
