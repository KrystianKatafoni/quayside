# AM-607 · Podpięcie HookInstaller: propozycja instalacji hooków, zgoda, backup, odinstalowanie, status

Issue: #60 · Wymagania: NFR-5, NFR-4, NFR-6, ENG-C2, ENG-C8, ENG-I4 · docs/03 „Hooki”, docs/09 „Otwarte kwestie”, docs/11 §3, §8, §9, ADR 0004, ADR 0010, ADR 0011, ADR 0017, ADR 0020 (proponowana) · Zależy: AM-602, AM-405

## Zakres

Decyzje człowieka (2026-11-02):

1. Hooki tylko globalnie (`HookScope.Global`, `~/.claude/settings.json`); hooki per projekt to osobne zadanie.
2. „Pomiń” zapamiętuje nowy plik `hook-offer.json`, właściciel `app` (ADR 0020, „proponowana”, przyjęcie przy scaleniu; wiersz w docs/11 §8).
3. Jeden PR na gałęzi `feat/AM-607-hook-installer`, `Closes #60`, ok. 565 linii: świadomy wyjątek od ENG-C10 (jak AM-703).

`hookInstallerModule` (AM-602) powstaje w `app` i dostaje okno „Hooki Claude Code”. Bez tego hooki (stany AM-603, podsumowania AM-604, powiadomienia AM-702) nie działają end-to-end. Zakres PR:

- komenda palety i pozycja menu „Hooki Claude Code…”: okno ze statusem, „Zainstaluj”, „Odinstaluj”, „Zamknij”;
- propozycja przy pierwszym uruchomieniu (to samo okno z przyciskiem „Pomiń”), odmowa zapamiętana w `hook-offer.json`.

Nie robimy: hooków per projekt (`.claude/settings.local.json`, `HookScope.Project`), przywracania kopii z UI (`uninstall(…, backup)`), zmian w `agent-runtime` i `projects:ui` (inspektor już pokazuje hooki projektu, FR-P2), okna startu agenta (AM-608), ekranu podsumowań (AM-606).

## Zmiany API

Brak zmian w `api`. Typy wewnętrzne `app`:

```kotlin
/** Hooks setup of the window (AM-607): the installer, the folder of its backups (shown in the dialog), the offer file. */
internal class HookDeps(val installer: HookInstaller, val backupDir: Path, val offer: HookOfferStore)

/** The open "Hooki Claude Code" dialog. [status] is null while it is read; [busy] while install or uninstall runs. */
internal data class HookDialogState(
    val status: HookStatus?,
    val busy: Boolean = false,
    val notice: HookNotice? = null,
    val firstRun: Boolean = false, // the close button is "Pomiń" and remembers the choice
)

/** What the last action did. Shows the file path and a fixed text per error type, never file content (ENG-C8). */
internal sealed interface HookNotice {
    data object Installed : HookNotice
    data object Uninstalled : HookNotice
    data class Failed(val error: HookError) : HookNotice
}

/**
 * Logic of the dialog, scope [HookScope.Global] only. Methods run on Main; IO runs in [scope] (the window scope),
 * one action at a time; a result that arrives after [close] is dropped. Logs only the error type, no paths above DEBUG.
 */
internal class HookSetupController(installer: HookInstaller, offer: HookOfferStore, scope: CoroutineScope, logger: Logger) {
    val state: StateFlow<HookDialogState?>
    fun open()          // reads the status
    fun install()       // install(Global), then status again; Ok -> Installed notice with backupDir
    fun uninstall()     // uninstall(Global, backup = null): removes only our hooks; then offer.dismiss()
    fun close()         // with firstRun = true also offer.dismiss()
    fun offerAtStart()  // opens with firstRun = true when HookOffer.shouldOffer(status, offer.dismissed())
}

/** Pure rule of the start offer. */
internal object HookOffer { fun shouldOffer(status: HookStatus, dismissed: Boolean): Boolean }

/** `hook-offer.json` (ADR 0020); missing or broken file = not dismissed. */
internal class HookOfferStore(storage: JsonStorage) {
    suspend fun dismissed(): Boolean
    suspend fun dismiss(): Outcome<Unit, StorageError>
}
```

## Reguły

1. **Port.** W `Main.kt` stała `HOOK_PORT = 47321` (docs/11 §9) idzie jawnie do `hookEventSourceModule(…, port = HOOK_PORT)` i `hookInstallerModule(…, port = HOOK_PORT)`, więc URL w pliku i serwer zawsze się zgadzają. `backupDir = appSupportDir(homeDir).resolve("hooks-backup")`.
2. **Zgoda.** Plik użytkownika zmienia się tylko po kliknięciu „Zainstaluj” albo „Odinstaluj”. Otwarcie okna, „Zamknij”, „Pomiń” i Escape wołają tylko `status`. Okno mówi przed instalacją: plik `~/.claude/settings.json`, 5 zdarzeń (`Notification`, `Stop`, `StopFailure`, `SessionStart`, `SessionEnd`), adres `http://127.0.0.1:47321/hooks`, kopia zapasowa w `~/Library/Application Support/Quayside/hooks-backup/` oraz to, że sesje uruchomione poza Quayside nie wyślą zdarzeń (brak `AM_HOOK_TOKEN`, AM-605).
3. **Status i przyciski.** `NotInstalled` i `Partial` (z listą brakujących): aktywne „Zainstaluj” (dopisuje tylko brakujące). `Installed` i `Partial`: aktywne „Odinstaluj”. `Unreadable`: oba wyłączone, komunikat „nie można odczytać pliku”. W trakcie akcji (`busy`) oba wyłączone; drugie kliknięcie nic nie robi.
4. **Błędy.** `HookError` → komunikat po typie (`SettingsUnreadable`, `WriteFailed`, `BackupNotFound`) ze ścieżką pliku; `reason` z `impl` nie trafia do UI ani do logu na poziomie wyższym niż DEBUG. Okno zostaje otwarte. Po błędzie kontroler czyta status ponownie (plik mógł się zmienić poza oknem), a komunikat `Failed` zostaje.
5. **Odinstalowanie** zawsze z `backup = null` (usuwa tylko nasze hooki); przywrócenie kopii cofnęłoby późniejsze zmiany użytkownika.
6. **Komenda** `hooks.setup` (`CommandGroup.APP`, słowo kluczowe `hooks`), ukryta, gdy otwarty jest dialog projektów, sesji, ustawień terminala, powiadomień albo hooków (wzór `NotificationSettingsCommands`, ADR 0011). Pozycja menu w „Widok” pod „Ustawienia powiadomień”; `AppMenu` dolicza okno hooków do `dialogOpen`. `MainWindow` dostaje 4. parametr `HookDeps` (`AppModules` ma już 6 pól, ENG-C2), `WindowControllers` 5. parametr.
7. **Okno** jak `TerminalSettingsDialog`: fokusowalny `Popup` na całe okno, Escape = „Zamknij” (przy propozycji startowej „Pomiń”). Zgoda z klawiatury: fokus startowy jest zawsze na „Zamknij”/„Pomiń” (przed i po wczytaniu statusu, także przy propozycji startowej) i wraca na nie po starcie i końcu akcji; żaden przycisk zapisujący ustawienia nie dostaje fokusu automatycznie, więc Enter albo Space zaraz po pokazaniu okna zamyka je jak „Pomiń” i nie woła `install`. Kolejność Tab: Zamknij, Zainstaluj, Odinstaluj (Shift+Tab odwrotnie), wyłączony przycisk jest pomijany. Fokus widać po ramce w `HookColors.focusBorder` (kontrast ≥ 3:1). Kolory tekstu z kontrastem ≥ 4.5:1 (NFR-6; przy kopiowaniu z innego `ui` sprawdzić kontrast). Tekst zgody podaje port (`HOOK_PORT`) i folder kopii (`HookDeps.backupDir`) jako parametry, nie literały.
8. **Start.** `MainWindow` woła `offerAtStart()` raz w `LaunchedEffect(Unit)`. Propozycja tylko, gdy `shouldOffer`. „Pomiń” i udane „Odinstaluj” zapisują `dismissed = true`; „Zamknij” z palety nie zapisuje. Błąd zapisu zamyka okno i loguje stałą kategorię. `offerAtStart` po odczycie statusu sprawdza licznik `life`: jeśli użytkownik w międzyczasie otworzył lub zamknął okno, propozycji nie pokazuje. Aktywna akcja (`acting`) liczy się niezależnie od okna: ponowne `open()` w jej trakcie ma `busy = true`, `install`/`uninstall` są wtedy ignorowane, a po jej końcu nowe okno czyta status od nowa.

## Ryzyka i pytania

Pytania blokujące: brak (pytania o zakres globalny, `hook-offer.json` i jeden PR rozstrzygnął człowiek 2026-11-02, patrz „Zakres”).

Pytania niezablokowane (plan przyjmuje rekomendację):

1. Odinstalowanie nie robi kopii pliku (`removeOurs` w AM-602 jej nie robi; usuwa tylko nasze wpisy). Zmiana wymagałaby `agent-runtime:impl`; NFR-5 spełnia możliwość cofnięcia przez „Odinstaluj”.
2. Propozycja pojawia się także wtedy, gdy Claude Code nie jest zainstalowany (instalacja utworzy `~/.claude/settings.json`).

Follow-up (propozycja wpisu do roadmapy, do dodania przez lead'a):

- `AM-6xx · Hooki per projekt: instalacja w .claude/settings.local.json dodanych projektów (HookScope.Project), status w oknie „Hooki Claude Code” · moduły: app, projects:ui (opcjonalnie) · zależy: AM-607 · wymagania: NFR-5`.

Ryzyka:

- Globalne hooki dotyczą wszystkich sesji `claude` użytkownika. Sesje bez `AM_HOOK_TOKEN` (z terminala) i sesje przy zamkniętej aplikacji wyślą żądanie, które dostanie 401 albo odmowę połączenia; trzeba sprawdzić na `claude` 2.1.139+, czy Claude Code pokazuje wtedy błąd hooka w sesji (`/compat-check`, `docs/compat.md`). Okno uprzedza o tym przed instalacją.
- Treść `settings.json` nie trafia do UI ani logów: kontroler widzi tylko `HookStatus` i `HookError` ze stałymi kategoriami.
- Fokusowalny `Popup` blokuje skróty okna; strażniki komend sprawdzają testy jednostkowe (lekcja o Popup).
- Duży PR (≈ 565 linii): recenzja trudniejsza; commity dzielić logicznie (spięcie, kontroler, okno, propozycja startowa).
