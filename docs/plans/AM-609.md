# AM-609 · Hooki per projekt: instalacja w `.claude/settings.local.json` dodanych projektów, status w oknie „Hooki Claude Code”

Issue: #68 · Wymagania: NFR-5, NFR-6, ENG-C2, ENG-C8 · docs/03 „Hooki”, docs/09 „Otwarte kwestie”, docs/11 §3, §9, ADR 0010, ADR 0011 · Zależy: AM-607

## Zakres

Okno „Hooki Claude Code” (AM-607) dostaje listę zakresów: „Globalnie” (`~/.claude/settings.json`) i pod nim każdy projekt dodany w Quayside (`<dir>/.claude/settings.local.json`, `HookScope.Project(project.dir)`), każdy wiersz ze statusem. „Zainstaluj” i „Odinstaluj” działają na zaznaczonym wierszu, z tymi samymi zasadami zgody, kopii i błędów co w AM-607. `SettingsJsonHookInstaller` (AM-602) obsługuje już `HookScope.Project` (plik, kopia z etykietą `project<hash>`), więc zmiana dotyczy tylko `app`.

Nie robimy: zmian w `agent-runtime` (`api`, `impl`) ani w `projects:ui` (inspektor przy dodawaniu już pokazuje hooki projektu, FR-P2); propozycji startowej per projekt (start dalej proponuje tylko zakres globalny); edycji `.gitignore` projektu; sprzątania hooków przy usuwaniu projektu z Quayside (patrz „Ryzyka”); przywracania kopii z UI.

## Moduły

- `app` (jedyny moduł kodu): `HookSetup.kt` (stan, kontroler), nowy `HookTargets.kt` (cele i ich źródło), `HookSetupDialog.kt`, nowy `HookTargetList.kt` (lista wierszy oraz `statusText`, `rowStatus`, `eventName` przeniesione z okna; osobny plik, bo `HookSetupDialog.kt` ma już 12 funkcji — TooManyFunctions), `HookTags.kt`, `Main.kt` (`hookDeps`), `WindowControllers.kt`, `i18n/strings.properties`; testy, w tym `WindowWorld.kt`.
- Dokumenty: `docs/09` (zamknięta kwestia „gdzie instalować hooki”: dopisek „per projekt: AM-609”), `docs/11` §9 (jedno zdanie: okno hooków obejmuje projekty), `docs/ROADMAP.md`, `CHANGELOG.md` `[Unreleased]`.

## Zmiany API

Brak zmian w `api`. Typy wewnętrzne `app`:

```kotlin
/** A settings file the hooks dialog can change. Names and paths are user data: log only [kind] (ENG-C8). */
internal sealed interface HookTarget {
    val scope: HookScope
    val kind: String // "global" or "project", the only log field

    data object Global : HookTarget

    /** [present] is false when [dir] is no longer a directory: no status read, no install (it would recreate it). */
    data class Project(val id: ProjectId, val name: String, val dir: Path, val present: Boolean) : HookTarget
}

/** The targets of the dialog: [HookTarget.Global] first, then the projects in the sidebar order. */
internal fun interface HookTargetSource {
    suspend fun targets(): List<HookTarget>
}

/** [HookTargetSource] over the live project list; checks the folders on [io]. */
internal class ProjectHookTargets(
    projects: StateFlow<List<Project>>,
    io: CoroutineDispatcher,
    isDirectory: (Path) -> Boolean = Files::isDirectory,
) : HookTargetSource

/** One row of the dialog. [status] is null while it is read or when the project folder is missing. */
internal data class HookRow(val target: HookTarget, val status: HookStatus?)

/** The open dialog; [selected] indexes [rows]. Buttons act on the selected row (AM-609). */
internal data class HookDialogState(
    val rows: List<HookRow>,
    val selected: Int = 0,
    val busy: Boolean = false,
    val notice: HookNotice? = null,
    val firstRun: Boolean = false,
) {
    val current: HookRow // rows[selected]
    val canInstall: Boolean // !busy, target present, status NotInstalled or Partial
    val canUninstall: Boolean // !busy, target present, status Installed or Partial
}

internal class HookDeps(val installer: HookInstaller, val backupDir: Path, val offer: HookOfferStore, val targets: HookTargetSource)

internal class HookSetupController(
    installer: HookInstaller,
    offer: HookOfferStore,
    targets: HookTargetSource,
    scope: CoroutineScope,
    logger: Logger,
) {
    fun open()             // rows from targets(), Global selected, reads every present row's status
    fun select(index: Int) // ignored while busy or out of range; clears the notice
    fun install()          // install(current.target.scope)
    fun uninstall()        // uninstall(current.target.scope, backup = null)
    fun close()
    fun offerAtStart()     // unchanged: Global only, rows = [Global]
}
```

## Reguły

1. **Wiersze.** `open()` buduje wiersze z `targets()` raz na życie okna (lista projektów nie zmienia się, gdy fokusowalny `Popup` jest otwarty). Status czyta po kolei dla każdego obecnego celu; do odczytu wiersz ma `status = null` („Odczyt…”). Projekt bez folderu: tekst „Folder projektu nie istnieje”, oba przyciski wyłączone, `installer` nie jest wołany. Propozycja startowa (`firstRun`) ma tylko wiersz „Globalnie”.
2. **Cel akcji.** `install`/`uninstall` biorą cel z bieżącego `mutable.value` w chwili kliknięcia (lekcja o `stateIn`). Wynik i ponowny odczyt statusu trafiają do wiersza tego celu (szukanego po `target`, nie po indeksie) i tylko w tym samym życiu okna (licznik `life` jak w AM-607). Flaga `fetched` mówi, czy cele bieżącego życia okna są już pobrane; gdy akcja z wcześniejszego życia kończy się przed pobraniem celów, kontroler pobiera je ponownie, a nie tylko czyta statusy (pusta lista projektów to też „pobrane”). W trakcie akcji `select` nic nie robi.
3. **Zgoda (NFR-5).** Bez zmian: plik zmienia tylko klik „Zainstaluj”/„Odinstaluj”. Wybór wiersza (klik, Space, Enter) niczego nie zapisuje. Fokus startowy na „Zamknij”/„Pomiń” przed i po wczytaniu statusu oraz po każdej akcji; żaden wiersz ani przycisk zapisujący nie dostaje fokusu automatycznie.
4. **Tekst informacji** zależy od zaznaczonego wiersza: „Globalnie” — tekst AM-607; projekt — plik `<dir>/.claude/settings.local.json` (ścieżka jako parametr `{0}`), port (`{1}`, `HOOK_PORT` jako String), folder kopii (`{2}`), zdanie, że hooki projektu działają tylko w sesjach uruchomionych w tym folderze, że przy hookach globalnych nie są potrzebne (Claude Code uruchamia ten sam hook raz), i że Quayside nie dopisuje pliku do `.gitignore`.
5. **Pamięć propozycji.** Udane „Odinstaluj” zapisuje `hook-offer.json` tylko dla celu `Global`; odinstalowanie w projekcie nie zmienia propozycji startowej.
6. **Logi.** Tylko typ błędu i `kind`; nigdy ścieżka ani nazwa projektu (ENG-C8).
7. **Lista** (`HookTargetList`): wiersze `AmListRow` w `Modifier.selectableGroup()`, przewijana (`verticalScroll`, maks. ok. 240 dp), nazwa projektu i status w wierszu; wiersz „Globalnie” ma etykietę `~/.claude/settings.json`. Kolejność Tab: Zamknij, Zainstaluj, Odinstaluj, wiersze (od „Globalnie”); wyłączony przycisk pominięty. Kolory z `HookColors` (NFR-6; nowych par kolorów nie dodajemy).
8. **ENG-C2.** Kontroler ma 5 parametrów, `HookDeps` 4 pola, `MainWindow`/`WindowControllers` bez nowych parametrów. Composable nowej listy i zmienione `HookPanel`/`HookButtons` ≤ 30 linii treści (zmierzyć ręcznie, lekcja o LongMethod).

## Ryzyka i pytania

Pytania blokujące: brak (zakres i moduły zgodne z roadmapą; bez zmian `api`, bez nowego formatu pliku, bez ADR).

Pytania niezablokowane (plan przyjmuje rekomendację):

1. Projekt z usuniętym folderem: rekomendacja — sprawdzenie `isDirectory` w `app` i wyłączone przyciski, bo `SettingsFiles.write` robi `createDirectories` i odtworzyłby folder. Alternatywa (strażnik w `agent-runtime:impl`) wymaga modułu spoza roadmapy.
2. `.gitignore`: Claude Code dopisuje `settings.local.json` do ignorowanych tylko, gdy sam zapisuje ustawienie. Rekomendacja — okno uprzedza, Quayside nie zmienia `.gitignore` (NFR-5: zgoda dotyczy plików ustawień).
3. Hooki w projekcie, który użytkownik potem usunie z Quayside, zostają w pliku. Rekomendacja: follow-up „ostrzeżenie w dialogu usuwania projektu, gdy ma hooki Quayside” (`projects:ui`, `ProjectInspector` już to wie), do dodania przez lead'a.
4. Propozycja startowa pojawia się dalej, gdy brak hooków globalnych, nawet jeśli wszystkie projekty mają hooki lokalne; „Pomiń” to zapamiętuje.

Ryzyka:

- Podwójne zdarzenia przy hookach globalnych i projektu: wg dokumentacji Claude Code ten sam handler z kilku plików ustawień uruchamia się raz; nasze wpisy są identyczne (ten sam port). Sprawdzić na `claude` 2.1.139+ (`/compat-check`, `docs/compat.md`).
- Odczyt statusu N projektów przy otwarciu: jeden mutex instalatora, odczyty po kolei; przy dziesiątkach projektów wiersze pokazują „Odczyt…” przez chwilę. Akceptowalne.
- Ścieżki i nazwy projektów to dane użytkownika: tylko w UI, nigdy w logach powyżej DEBUG.
- Fokusowalny `Popup` blokuje skróty okna; strażniki kontrolera (`select` przy `busy`) sprawdzają testy jednostkowe (lekcja o kontrolkach wyłączonych w UI).
