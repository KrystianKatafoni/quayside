# AM-703 · MacSayAdapter, szablony, grupowanie

Issue: #11 · Wymagania: FR-N4, FR-N5 · docs/07 §Głos, docs/11 §4, docs/12 §1, §3 · Etap: M7 · Zależy: AM-701

## Zakres

Kanał VOICE zaczyna mówić: każde dostarczenie na kanale głosu (FR-N1) daje tekst z szablonu rodzaju, który `say` wypowiada wybranym głosem, tempem i głośnością. Najwyżej 1 komunikat na 20 s, kolejne łączone („3 agenty czekają”). Głos milknie, gdy okno aplikacji jest aktywne albo mikrofon jest w użyciu (każde osobnym przełącznikiem, domyślnie włączone).

Nie robimy: ekranu ustawień głosu ani listy zainstalowanych głosów (`say -v ?`, AM-704), ciszy nocnej, trybu Skupienia, głosu per projekt (AM-705), podpisu „co powiedział głos” pod popupem, dźwięku i badge (AM-903), prawdziwego wykrywania mikrofonu (port z implementacją „nigdy aktywny”; adapter CoreAudio po decyzji o ADR 0018).

Uzupełniamy odstępstwo z AM-701: `decide()` dostaje `DeliveryContext` (docs/11 §4) z polami „okno aktywne” i „mikrofon aktywny”; cisza nocna dojdzie w AM-705.

### Jeden PR

Decyzja człowieka: całość w jednym PR (`Closes #11`), mimo szacunku ok. 450 linii (limit 400 z ENG-C10). Kolejność pracy wewnątrz PR: ustawienia, serializer, czyste rdzenie i `DeliveryContext`, potem adapter, notifier i spięcie w `app`. Wpis w `CHANGELOG.md` `[Unreleased]` razem z kodem. Mikrofon: tylko port z `NoMicrophone`; adapter CoreAudio to osobne zadanie po przyjęciu ADR 0018 (do dopisania w roadmapie).

## Zmiany API (`notifications:api`)

```kotlin
/** A macOS voice by the name `say -v` accepts, e.g. `Zosia`. Not checked against the installed voices. */
@JvmInline
public value class VoiceId(public val name: String) { init { require(name.isNotBlank()) { "blank voice" } } }

/**
 * How spoken messages sound and when they are silenced (FR-N4, FR-N5, docs/07 defaults).
 * A kind missing from [templates] uses [defaultTemplate], so "restore default" (AM-704) is a removal.
 *
 * @property voice the macOS voice; null means the system voice. An uninstalled voice falls back to it.
 * @property rate words per minute, [MIN_RATE]..[MAX_RATE].
 * @property volume percent, 0..100.
 * @property templates message per kind with `{sesja}`, `{projekt}`, `{pytanie}`, `{narzędzie}`, `{podsumowanie}`.
 * @property readQuestion after a [NotificationKind.NEEDS_INPUT] message, also read the question when the
 *   template does not contain `{pytanie}`.
 * @property onlyInBackground silent while a window of the app is active.
 * @property muteWhenMicrophoneActive silent while any app records from the microphone.
 */
public data class SpeechSettings(
    val voice: VoiceId? = DEFAULT_VOICE,
    val rate: Int = DEFAULT_RATE,
    val volume: Int = DEFAULT_VOLUME,
    val templates: Map<NotificationKind, String> = emptyMap(),
    val readQuestion: Boolean = true,
    val onlyInBackground: Boolean = true,
    val muteWhenMicrophoneActive: Boolean = true,
) {
    init { /* require rate in MIN_RATE..MAX_RATE, volume in 0..100 */ }

    /** The template of [kind]: the entry in [templates] or [defaultTemplate]. */
    public fun templateFor(kind: NotificationKind): String

    public companion object {
        public val DEFAULT_VOICE: VoiceId = VoiceId("Zosia")
        public const val DEFAULT_RATE: Int = 190
        public const val MIN_RATE: Int = 90
        public const val MAX_RATE: Int = 360
        public const val DEFAULT_VOLUME: Int = 70
        /** The default message of [kind] (docs/07; kinds docs/07 does not name: see the table below). */
        public fun defaultTemplate(kind: NotificationKind): String
    }
}

// NotificationSettings: new last parameter
val speech: SpeechSettings = SpeechSettings(),
```

Domyślne szablony: `NEEDS_INPUT` „Agent {sesja} w projekcie {projekt} czeka na odpowiedź”, `PERMISSION` „{sesja} prosi o zgodę na {narzędzie}”, `FAILED` „Uwaga, {sesja} zatrzymał się z błędem” (docs/07); propozycja dla reszty: `TURN_ENDED` „{sesja} skończył turę”, `PULL_REQUEST` „{sesja} ma pull request do przeglądu”, `RUNNING_LONG` „{sesja} pracuje już długo”, `TERMINAL_BELL` „Dzwonek w terminalu”.

Plik `notifications.json`: nowa opcjonalna sekcja `"speech": {"voice": "Zosia" | null, "rate", "volume", "templates": {"needsInput": "…"}, "readQuestion", "onlyInBackground", "muteWhenMicrophoneActive"}`. Brak klucza = domyślne, `rate`/`volume` poza zakresem przycinane, pusty `voice` lub pusty szablon = domyślne, zły typ → `.broken`. Bez zmiany wersji schematu (dodane pole jest opcjonalne, starszy czytnik je pomija).

## Zasady i typy w `impl` (wszystko `internal`)

- `DeliveryContext(appActive: Boolean, microphoneActive: Boolean)`; `decide(event, settings, context)` i `decideTerminalBell(settings, context)`. Wspólna czysta funkcja `voiceAllowed(speech, context)`: VOICE odpada, gdy `onlyInBackground && appActive` albo `muteWhenMicrophoneActive && microphoneActive`. Inne kanały bez zmian.
- `VoiceTemplates.render(template, kind, session, project): String?` — podstawia zmienne; `{sesja}` z `-` i `_` zamienionymi na spacje; brak wartości = pusty tekst; nieznane `{x}` zostają; wartości bez `[[`/`]]` (komendy osadzone `say`), bez nowych linii, ucięte do 200 znaków; spacje zwinięte; pusty wynik = null (nic nie mówimy). `readQuestion` dopisuje „. <pytanie>”.
- `VoiceGrouping` (czysty reduktor bez czasu): stan `cooling: Boolean`, `pending: List<VoiceMessage>`. `offer`: bez chłodzenia → `Speak(text)` + start chłodzenia; w chłodzeniu → do `pending` (ta sama sesja i rodzaj zastępuje starszy). `cooldownEnded`: pusto → koniec chłodzenia; 1 wiadomość → jej tekst; kilka sesji → `groupedText(n)` („2 agenty czekają”, „5 agentów czeka”, „22 agenty czekają”); kilka wiadomości jednej sesji → najnowsza. Każde `Speak` startuje nowe 20 s.
- `SpeechPort.speak(utterance): Outcome<Unit, SpeechError>`; `Utterance(text, voice, rate, volume)` z `toString` bez tekstu (ENG-C8). `SpeechError`: `Unavailable` (brak `say`), `Failed(exitCode)`, `TimedOut`.
- `MacSayAdapter(runner: ProcessRunner, workDir: Path, program: String = "/usr/bin/say")`: argv `[program, -v, <głos>, -r, <tempo>, "[[volm 0.70]] <tekst>"]` (prefiks głośności chroni też przed tekstem zaczynającym się od `-`); timeout 60 s; kod ≠ 0 przy podanym głosie → jedna próba bez `-v`. Pełna ścieżka zamiast `PATH`.
- `MicrophoneMonitor { val active: StateFlow<Boolean> }`, w tym zadaniu tylko `NoMicrophone` (zawsze `false`).
- `VoiceNotifier(speech: SpeechPort, settings, scope, context: () -> DeliveryContext, logger)`: przyjmuje dostarczenia VOICE od centrum, stan `VoiceGrouping` pod blokadą, timer chłodzenia `delay(20.s)` w `scope`, jeden konsument mówi po kolei. Przed mówieniem zebranej grupy ponownie sprawdza `voice` i `voiceAllowed`. Błąd `say`: `warn` ze stałą kategorią, bez tekstu.
- Fabryka: `notificationCenterModule(…, process: ProcessRunner? = null, appActive: StateFlow<Boolean> = MutableStateFlow(false), logger: Logger = NoOpLogger)`; `null` = brak głosu (dotychczasowe testy bez zmian). 9 parametrów (logger trafia do `VoiceNotifier`; `app` podaje `core.logger`) pod istniejącym `@Suppress("LongParameterList")` (patrz pytania).

## Ryzyka i pytania

Pytania do człowieka (żadne nie blokuje startu PR 1; plan przyjmuje wariant rekomendowany):

1. **Mikrofon (FR-N5)**: wykrycie wymaga CoreAudio przez JNA (bezpośrednia zależność, dziś tylko przechodnio z pty4j) — szkic `docs/adr/0018-wykrywanie-mikrofonu-coreaudio-jna.md` („proponowana”). Rekomendacja: AM-703 daje port i przełącznik z `NoMicrophone`; adapter `CoreAudioMicrophoneAdapter` jako nowe zadanie w roadmapie po przyjęciu ADR. Do tego czasu przełącznik „wycisz przy mikrofonie” nie ma skutku.
2. **Moduły spoza roadmapy**: roadmapa podaje tylko `notifications:impl`; plan zmienia też własne `notifications:api` (ustawienia głosu) i `app` (spięcie). Bez `app` głos nie zadziała u użytkownika. Akceptujesz?
3. **Szablony domyślne dla rodzajów spoza docs/07** (`TURN_ENDED`, `PULL_REQUEST`, `RUNNING_LONG`, `TERMINAL_BELL`) — zaproponowane wyżej; trzeba je zatwierdzić. Są polskimi stałymi w `api`, nie w zasobach (NFR-10), bo AM-704 pokaże „przywróć domyślne”; tłumaczenie de/en wymaga potem decyzji, czy szablon zależy od języka głosu.
4. **Tekst grupy**: docs/07 podaje „3 agenty czekają”, ale w grupie może być błąd albo PR. Rekomendacja: zostaje „N agenty czekają/agentów czeka” dla każdej mieszanki.
5. **Lista głosów** do wyboru (FR-N4) potrzebuje portu w `api` (`say -v ?`); rekomendacja: dodać w AM-704 razem z ekranem.
6. **Fabryka z 9 parametrami**: `impl` może wystawiać tylko fabryki (Konsist), więc obiekt parametrów musiałby trafić do `api`. Rekomendacja: zostaje `@Suppress` jak w AM-702.

Ryzyka:

- `[[volm 0.7]]` działa nie dla każdego głosu (głosy neural/premium mogą go ignorować); wtedy głośność = systemowa. Sprawdzić ręcznie z Zosią na Macu.
- `say` z nieznanym głosem: zakładamy kod ≠ 0 (stąd ponowna próba bez `-v`); potwierdzić na Macu.
- „Okno aktywne” liczy każde okno aplikacji z fokusem; okno popupów ma `focusable = false`, więc go nie liczy. Działanie `AppForeground` sprawdzamy ręcznie (AWT bez wyświetlacza w CI).
- Login shell na każde `say` dodaje ok. 0,1–0,3 s; mieści się w 2 s z docs/01.
- Treść pytania i nazwy trafiają do argv procesu (widoczne w `ps` dla tego samego użytkownika); nie logujemy ich (ENG-C8), `ProcessRunner` loguje tylko nazwę programu.
