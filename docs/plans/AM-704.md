# AM-704 · Ekran ustawień powiadomień

Issue: #12 · Wymagania: FR-N1–FR-N4, NFR-6, NFR-10 · docs/07, docs/11 §4, ENG-I1–I8, ENG-C2, ENG-C8, ENG-C10 · Zależy: AM-702, AM-703 (scalone) · Wzór: AM-508 część B

## Zakres

Dialog „Ustawienia powiadomień” nad oknem (jak `TerminalSettingsDialog`: `Popup` na całe okno, Escape = Anuluj, Tab po kontrolkach, przewijanie w pionie), otwierany z palety (`notifications.settings`) i z menu „Widok”. Zmienia `NotificationSettings` przez `NotificationSettingsRepo.update`; nowe wartości działają od razu (centrum czyta ustawienia przy każdym zdarzeniu).

**Podział na dwie części (dwa PR do #12, `[x]` w roadmapie dopiero po B).** Szacunek całości to ok. 700 linii netto `src/main` (z zapasem 30%), więc jeden PR łamie ENG-C10 (≤ 400):

- **Część A (`feat/AM-704-notification-settings-screen`): dialog i kanały.** Kontroler, dialog, wspólne kontrolki, sekcja „Zdarzenia i kanały” (macierz 7 rodzajów × 4 kanały), przełączniki globalne „Popupy” i „Głos”, próg N minut dla `RUNNING_LONG`, komenda palety i pozycja menu w `app`. **Ok. 390 linii** (zmierzone po implementacji: netto ok. 596 z importami, ok. 480 bez importów, brutto ok. 715).
- **Część B1 (`feat/AM-704-popup-settings`): popup.** Sekcja „Popup” (pozycja z 6, czas wyświetlania, maks. naraz, styl), `ChoiceField`, walidacja maks. naraz. Tylko `notifications:ui` (+ test w `app`). **Ok. 235 linii** (szczegóły: sekcja „Część B1”).
- **Część B2: głos**, dwa PR (pomiar w sekcji „Część B2”): **B2a** (`feat/AM-704-voice-model`, `Refs: #12`): port `VoiceCatalog` + adapter `say -v ?`, reguła szablonów w `api`, szkic mowy i walidacja w `ui`; bez zmian `app` i bez zmian widocznych dla użytkownika, **ok. 250 linii**. **B2b** (`feat/AM-704-voice-settings`, `Closes #12`): sekcja „Głos” w dialogu, ładowanie listy głosów w kontrolerze, spięcie w `app`, roadmapa `[x]`, **ok. 310 linii**.

Zasady:

- Zapis zaczyna od **bieżących** ustawień (`update { current -> … }`), więc pola spoza szkicu (AM-705) zostają z bieżących ustawień; pola szkicu nadpisują zmiany zrobione po `open()` (jedynym zapisującym jest dialog).
- Macierz i szablony zapisujemy **tylko jako odstępstwa**: rodzaj z kanałami równymi `defaultChannels(kind)` i szablon równy `defaultTemplate(kind)` albo pusty są usuwane z mapy. Dlatego „Przywróć domyślny” to zwykła edycja szkicu (tekst = domyślny), a po zapisie wpis znika z `templates`.
- Liczby (N minut, maks. naraz, tempo, głośność) są w szkicu tekstem (jak AM-508), sprawdzane przy zapisie; `require` w `api` nigdy nie rzuca z dialogu.
- Szablon wpisany w UI z `[[` lub `]]` (komendy osadzone `say`) albo dłuższy niż 200 znaków jest odrzucany przy zapisie z komunikatem pod polem.
- „Wycisz przy aktywnym mikrofonie” jest widoczny i zapisywany, z adnotacją „Jeszcze nie działa: wykrywanie mikrofonu czeka na ADR 0018” (tekst w zasobach; usuwa go zadanie adaptera CoreAudio).
- Lista głosów ładuje się w tle przy pierwszym `open()` (po błędzie: przy następnym); do tego czasu i po błędzie wybór ma tylko „Głos systemowy” i zapisany głos. Zapisany głos spoza wczytanej listy ma etykietę „(niezainstalowany)”.
- Wszystkie teksty w `i18n/notification-settings.properties` (NFR-10); checkboxy macierzy mają etykiety dostępności „<rodzaj> – <kanał>” (NFR-6).

**Nie robimy:** ciszy nocnej, trybu Skupienia, wyjątków per projekt, języka głosu wg projektu (AM-705), przycisku „Testuj głos” (wymaga portu mowy w `api`, pytanie 3), popupu systemowego macOS i „wszystkich monitorów” (brak modelu; natywny most, docs/07 dopuszcza na MVP tylko własny popup), przełączników akcji w popupie i grupowania (stałe zachowanie), podglądu popupu, wspólnego modułu `core:design-system`.

/** An installed macOS voice as `say -v ?` lists it; [locale] such as `pl_PL` or `es_419`. Immutable. */
public data class VoiceOption(val id: VoiceId, val locale: String)
/** Why [VoiceCatalog.voices] gave no list: [UNAVAILABLE] the program cannot start, [FAILED] it ran and failed. */
public enum class VoiceCatalogError { UNAVAILABLE, FAILED }
/** The voices installed on this Mac (FR-N4). Safe on any dispatcher, never throws, no cache: asks the system each call. */
public interface VoiceCatalog {
    /** Voices sorted by name ignoring case, one per name (the first listed wins); errors carry no process output. */
    public suspend fun voices(): Outcome<List<VoiceOption>, VoiceCatalogError>
}
// SpeechSettings.kt
/** Why a template typed by the user cannot be saved. */
public enum class TemplateProblem { EMBEDDED_COMMAND, TOO_LONG }
// SpeechSettings.Companion; MAX_VOLUME was private, `init` uses MIN_VOLUME..MAX_VOLUME
public const val MIN_VOLUME: Int = 0
public const val MAX_VOLUME: Int = 100
public const val MAX_TEMPLATE_LENGTH: Int = 200
/** [TemplateProblem.EMBEDDED_COMMAND] for `[[` or `]]` (embedded `say` commands), checked first;
 *  [TemplateProblem.TOO_LONG] above [MAX_TEMPLATE_LENGTH] characters; else null. Placeholders are not checked. */
public fun templateProblem(template: String): TemplateProblem?
// PopupSettings.Companion (S6): `init`, the draft range and the message use it
public const val MIN_VISIBLE: Int = 1

// notifications:impl, VoiceCatalogModule.kt (B2a)

// Timeout, IoFailed, exit ≠ 0 → FAILED; exit 0 → Ok(parseSayVoices(stdout)) (also when cut at maxOutputBytes).
/** Lines `<name, may have spaces and brackets>  <locale>  # <sample>`; regex
 *  `^(.+?)\s+([a-z]{2,3}_[A-Z0-9]{2,3})\s+#` (locale like `pl_PL`, `zh_CN`, `es_419`); a line without a match or with a

// notifications:ui, NotificationDraft.kt (B2a); NotificationDraft gets `val speech: SpeechDraft` after `popup`

// SettingsStrings.of(InvalidField): exhaustive `when`; RATE → range(MIN_RATE, MAX_RATE), VOLUME → range(MIN_VOLUME,
