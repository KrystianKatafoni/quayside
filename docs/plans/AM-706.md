# AM-706 · Cisza nocna i wyjątki projektów w oknie ustawień powiadomień

Issue: #69 · Wymagania: FR-N6, FR-N7, NFR-6, NFR-10 · docs/07 (przełączniki globalne, „Wyjątki per projekt”), docs/11 §3 reguła 1, ENG-I1–I8, ENG-C2, ENG-C10 · Zależy: AM-705 (scalone) · Wzór: AM-704 B1/B2b, AM-813

## Zakres

Dwie nowe sekcje dialogu „Ustawienia powiadomień”, wstawione po sekcji „Głos”, przed stopką. Kolejność Tab: … głos → **Nie przeszkadzać** → **Wyjątki projektów** → Zapisz. Logika ciszy i profili istnieje od AM-705 (`QuietHours`, `ProjectNotifications`, `NotificationSettings.projects`); to zadanie tylko je pokazuje i zapisuje.

- **„Nie przeszkadzać” (FR-N6):** przełącznik „Wycisz głos i dźwięk w godzinach” (`enabled`), pola tekstowe „Od” i „Do” (`GG:MM`), stały podpis o skutku ciszy i o przejściu przez północ, przełącznik „Respektuj tryb Skupienia macOS” (`respectFocus`), pod nim podpis „Jeszcze nie działa: wykrywanie Skupienia macOS czeka na osobne zadanie” (jak `settings.micNote`).
- **„Wyjątki projektów” (FR-N7):** jeden blok na każdy zarejestrowany projekt: nazwa, a pod nią w jednym wierszu `Dropdown` profilu (Domyślny / Tylko błędy / Wyciszony) i `Dropdown` głosu („Głos globalny” + `voiceChoices` z AM-704). Bez projektów: podpis „Brak projektów. Dodaj projekt w pasku bocznym.” Podpis sekcji wyjaśnia profile.

Zasady:

- Godziny są w szkicu tekstem i są sprawdzane przy zapisie (jak liczby w AM-704). Wzorzec po `trim()`: `^([01]?\d|2[0-3]):([0-5]\d)$` (cyfry ASCII). Pole w szkicu ma zawsze format `HH:MM`.
- Pola godzin i Skupienia są **zawsze edytowalne**, także przy wyłączonej ciszy (jak sekcja Popup). Nie ma więc wyłączonych kontrolek ani strażnika w kontrolerze.
- `od == do` jest odrzucane (`QUIET_TO`) **tylko przy `enabled`**. Plik z równymi godzinami i wyłączoną ciszą nie blokuje zapisu innych pól.
- Szkic wyjątków zawiera tylko projekty z listy `ProjectsApi`, posortowane po nazwie bez wielkości liter. Zapis: `current.projects` bez id z listy + wiersze różne od `ProjectNotifications()`. Wpisy projektów spoza listy (usunięte, UUID nie wraca) zostają bez zmian.
- Lista projektów jest czytana przy każdym `open()` (`projects.value`), nie śledzona w trakcie otwartego dialogu.
- Głos projektu: zapisany głos zostaje na liście (`remember` per projekt, jak `VoiceRow`); głos spoza wczytanej listy dostaje etykietę „(niezainstalowany)”.
- UI nie czyta zegara ani strefy: godzinę lokalną liczy `impl` przy każdym zdarzeniu (`zone: () -> ZoneId`, AM-705, testy dwóch stref w `DeliveryContextTest`).
- Kolory: tylko istniejące `mutedColor()`/`errColor()` z `AmTheme` (audyt NFR-6 w `core:design-tokens`); bez własnej palety.
- Nowe popupy: brak. Listy `AmDropdown` zgłaszają się do `AmModalGate` (AM-817), więc działają nad `SwingPanel`.

**Nie robimy:** adaptera Skupienia, dni tygodnia, wyboru godzin z listy, skoku literą w głosie projektu, śledzenia listy projektów przy otwartym dialogu, sprzątania wpisów usuniętych projektów, zmian `api`/`impl`.

## Zmiany API

Inne feature: bez zmian (`ui` → `api` dowolnego feature, docs/11 §3 reguła 1; precedens `mission-control:ui` → `projects:api`). Publiczne API `notifications:ui`:

```kotlin
/** The do-not-disturb part of [NotificationDraft] (FR-N6); [from] and [to] stay text (`HH:MM`) until save. */
public data class QuietDraft(val enabled: Boolean, val from: String, val to: String, val respectFocus: Boolean)

/** The exception of one registered project as the dialog shows it (FR-N7); [voice] null = the global voice. */
public data class ProjectDraft(val id: ProjectId, val name: String, val profile: ProjectProfile, val voice: VoiceId?)

// NotificationDraft gets, after `speech`:
val quiet: QuietDraft,
/** Registered projects sorted by name ignoring case; projects outside the list keep their stored exception. */
val projects: List<ProjectDraft>,

/** The fields of the dialog that a save can refuse: threshold, popup, speech and quiet hours. */
public enum class NotificationField { RUNNING_LONG_MINUTES, MAX_VISIBLE, RATE, VOLUME, TEMPLATE, QUIET_FROM, QUIET_TO }

/**
 * … (FR-N1, FR-N2, FR-N4, FR-N6, FR-N7). [projects]: the registered projects, read at every [open]; the
 * exceptions of other projects are kept as stored.
 */
public class NotificationSettingsController(
    repo: NotificationSettingsRepo, voices: VoiceCatalog, preview: VoicePreview,
    projects: StateFlow<List<Project>>, scope: CoroutineScope,
)   // 5 parameters (ENG-C2)
```

Composable (`internal`, ≤ 5 parametrów, LongMethod ≤ 30): `QuietSection(state, controller)` = nagłówek, przełącznik, `TimeRow` ×2 (prywatny), podpis, przełącznik Skupienia, podpis. `ProjectsSection(state, controller)` = nagłówek, podpis, `ProjectBlock` ×N albo podpis pustej listy. `ProjectBlock(row, voices, controller)` = nazwa + `Row` z 2 × `Dropdown` (po 260 dp; panel 640 dp). Etykiety dostępności: „Profil: <projekt>”, „Głos: <projekt>”.

## Ryzyka i pytania

**Pytania blokujące: brak** (bez zmian `api`, formatu pliku i granic modułów; bez ADR). Decyzje przyjęte za człowieka (nieblokujące):

1. `notifications:ui` dostaje zależność od `projects:api` (reguła 1 docs/11), a kontroler bierze `StateFlow<List<Project>>`. Szkic z AM-705 przewidywał własny typ `ProjectChoice` w `ui`. Ten wariant jest prostszy i nie tworzy nowego publicznego typu.
2. Godziny są polami tekstowymi `GG:MM`. Wariant odrzucony: lista co 15 min (96 pozycji) albo dwie listy (godzina i minuta).
3. Sekcje stoją po „Głosie”, nie przy przełącznikach globalnych (docs/07). Dzięki temu zmienia się tylko jeden istniejący test kolejności Tab: `NotificationSettingsVoiceScreenTest.tab moves through the voice section in order` (po `MUTE_MICROPHONE` idą `QUIET_ENABLED`, `QUIET_FROM`, `QUIET_TO`, `RESPECT_FOCUS`, potem Zapisz).
4. Podpis profilu „Wyciszony” mówi, że badge jeszcze nie działa (AM-903). AM-903 musi usunąć tę uwagę z `settings.projectsHint`.
5. Projekty są sortowane po nazwie bez wielkości liter, nie w kolejności paska bocznego.
