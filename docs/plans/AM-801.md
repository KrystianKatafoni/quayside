## Zmiany API

```kotlin
// core:design-tokens — wszystkie typy niemutowalne, bez IO; wołane z dowolnego wątku
/** sRGB colour with alpha, packed as 0xAARRGGBB. */
@JvmInline public value class Rgba(public val argb: Long) {   // init: argb in 0..0xFFFF_FFFF
    public val alpha: Int; public val red: Int; public val green: Int; public val blue: Int; public val isOpaque: Boolean
    public fun withAlpha(percent: Int): Rgba                 // 0..100
    public companion object {
        public val BLACK: Rgba; public val WHITE: Rgba
        /** `#RRGGBB` (any case) → opaque colour; anything else → null, never throws. */
        public fun parse(hex: String): Rgba?
    }
}
/** Channel-wise sRGB mix: [percent] of [other] (0..100), rounded; alpha of the receiver. */
public fun Rgba.mix(other: Rgba, percent: Int): Rgba
/** Alpha compositing of the receiver over an opaque [background]; result is opaque. */
public fun Rgba.over(background: Rgba): Rgba
/** HSL hue in [0, 360), or null for greys (red == green == blue). */
public fun Rgba.hue(): Double?
/** Shortest distance between hues in [0, 180]; null when either colour is grey. */
public fun hueDistance(a: Rgba, b: Rgba): Double?
/** WCAG 2.x relative luminance and contrast; a translucent foreground is composited over the opaque background. */
public object Wcag {
    public const val TEXT_MIN: Double = 4.5; public const val NON_TEXT_MIN: Double = 3.0
    public fun luminance(color: Rgba): Double                 // require opaque
    public fun contrast(foreground: Rgba, background: Rgba): Double   // 1.0..21.0, symmetric for opaque colours
    public fun inkFor(background: Rgba): Rgba                 // BLACK or WHITE, whichever contrasts more
}

/** All colour tokens of a theme (docs/08), grouped to keep constructors ≤ 6 (ENG-C2). */
public data class ColorTokens(val surfaces: SurfaceColors, val content: ContentColors,
                              val status: StatusColors, val terminal: TerminalColors)
public data class SurfaceColors(val bg: Rgba, val panel: Rgba, val raised: Rgba, val sel: Rgba, val border: Rgba, val border2: Rgba)
public data class ContentColors(val text: Rgba, val muted: Rgba, val dim: Rgba, val accent: Rgba, val accentInk: Rgba)
/** warn = agent waits for you, work = working, ok = done, err = failed (docs/08 „Semantyka”). */
public data class StatusColors(val warn: Rgba, val warnInk: Rgba, val warnBg: Rgba, val ok: Rgba, val err: Rgba, val work: Rgba)
public data class TerminalColors(val termBg: Rgba, val termText: Rgba)
// KDoc: bg is opaque; panel may be translucent (Backdrop.TRANSLUCENT) and is drawn on bg.

/** Shape tokens in dp (FR-A7). init: radius ≥ 0, borderWidth ≥ 0. */
public data class ShapeTokens(val radius: Int, val borderWidth: Int, val shadow: ShadowSpec?, val backdrop: Backdrop)
/** Panel shadow; horizontal offset is always 0. init: blur ≥ 0 (spread may be negative). */
public data class ShadowSpec(val offsetY: Int, val blur: Int, val spread: Int, val color: Rgba)
/** OPAQUE panel, or TRANSLUCENT: panel colour with alpha over bg, no blur (Compose Desktop cannot blur). */
public enum class Backdrop { OPAQUE, TRANSLUCENT }

/** Key of a typography as stored in theme.json, e.g. `plex`. init: matches [a-z0-9-]+. */
@JvmInline public value class TypographyId(public val value: String)
/** Pair of font families: [uiFont] for the interface, [terminalFont] for terminals; resolved by name in AM-802. */
public data class TypographySpec(val id: TypographyId, val name: String, val uiFont: String, val terminalFont: String)
```

```kotlin
// appearance:api
/** Key of a theme as stored in theme.json (`scheme`, `dayScheme`, `nightScheme`). init: [a-z0-9-]+. */
@JvmInline public value class SchemeId(public val value: String)
public enum class ThemeMode { LIGHT, DARK, LIGHT_HIGH_CONTRAST, DARK_HIGH_CONTRAST; public val isDark: Boolean; public val isHighContrast: Boolean }
/** One built-in or custom theme; [defaultTypography] is only suggested by the Appearance screen, null = none. */
public data class ThemeSpec(val id: SchemeId, val name: String, val mode: ThemeMode, val colors: ColorTokens,
                            val shape: ShapeTokens, val defaultTypography: TypographyId?)
/** Themes and typographies in display order. init: non-empty, unique ids, defaults present, every defaultTypography present. */
public data class ThemeCatalog(val themes: List<ThemeSpec>, val typographies: List<TypographySpec>) {
    public fun theme(id: SchemeId): ThemeSpec?; public fun typography(id: TypographyId): TypographySpec?
    public companion object { public val DEFAULT_SCHEME: SchemeId /* plex */; public val DEFAULT_TYPOGRAPHY: TypographyId /* plex */ }
}
/** Appearance feature contract; AM-804 adds theme, select and update. Thread-safe, never blocks. */
public interface AppearanceApi { public val catalog: ThemeCatalog }   // same instance on every read
// appearance:impl — jedyna publiczna fabryka: public fun appearanceModule(): AppearanceApi
```

## Ryzyka i pytania

**Pytania blokujące: brak** (decyzje 2026-11-03 w sekcji „Zakres”: jeden PR ponad ENG-C10, 4 korekty kolorów, `deriveTokens` z regułami ★, fonty 8 podstawowych w AM-802, bez ADR).

**Pytania nieblokujące (plan przyjmuje rekomendację):**

1. `ColorTokens` w 4 grupach (ENG-C2) zamiast płaskich 19 pól (precedens `RuntimeSession` 8 pól; detekt domyślnie pomija klasy danych). Koszt: `colors.content.muted` zamiast `colors.muted`.
2. Test obejmuje też `text/raised`, `text/sel`, `termText/termBg` ≥ 4.5 (tekst na zaznaczeniu i w terminalu; NFR-6); commit 4 dopisuje je w docs/12 §1.
3. `ThemeSpec`, `SchemeId`, `ThemeCatalog` w `appearance:api`; w `core:design-tokens` tylko to, czego potrzebuje `core:design-system` (AM-802).
4. Szary kolor (np. `accent` `#FFFFFF` w `minimal-black`) nie ma odcienia, więc nie ma konfliktu odcieni; dotyczy AM-805.

**Ryzyka:**

- PR ok. 680 linii (zgoda człowieka) jest trudniejszy w review: commity w kolejności z „Zakres”, każdy z zielonym `./gradlew check`.

- `synth` (29,8°) i `paper` po korekcie (`warn/bg` 4.55) są blisko progów; obliczenia ręczne ±0,5°/±0,05 — rozstrzyga test; przy porażce implementer zatrzymuje się i zgłasza wartość człowiekowi, nie dobiera jej sam.
- `muted` 70 % `text` jest jasny w ciemnych schematach (ok. 8:1 w `plex`) — słabo „przygaszony”; ocena wzrokowa w AM-803.
- `AppearanceApi` dostanie członków w AM-804: zmiana łamiąca tylko dla `FakeAppearanceApi` (ENG-I6, ten sam feature).
- `appearanceModule()` nieużywane do AM-803 — Kover liczy je przez test kontraktowy.
- Detekt: gdy MagicNumber, TooManyFunctions lub LongMethod (tabele `@MethodSource` > 30 linii) wymusi pliki spoza listy, dopisać je do „Moduły” w tym samym PR (lekcja).
