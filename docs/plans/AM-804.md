# AM-804 · Dzień/noc z macOS, zapis i import/eksport `theme.json`

Issue: #18 · Wymagania: FR-A5, FR-A6 (też FR-A4, NFR-6, NFR-1) · docs/08 „`theme.json`”, docs/11 §3–§4, ADR 0016 (wzorzec pliku), ADR 0022 · Zależy: AM-803 (scalone) · ADR 0023 (proponowana, szkic w tym PR)

**Decyzje 1–4 z sekcji „Ryzyka i pytania” zapadły zgodnie z rekomendacją** (moduły dopisane, własne schematy poza zakresem, brak sekcji `terminal`, wykrywanie przez `defaults` co 5 s).

## Zakres

**Robimy:** (1) `theme.json` w `~/Library/Application Support/Quayside` przez `JsonStore` (koperta `schemaVersion: 1`): motyw, typografia, skala, gęstość, dzień/noc; wybór z ekranu Wygląd przeżywa restart. Odczyt łagodny jak ADR 0016: brak klucza, zły typ, nieznana nazwa enuma albo id spoza katalogu daje wartość domyślną pola; plik, który nie jest obiektem, idzie do `theme.json.broken`; nowszy schemat = wartości domyślne i brak zapisu. (2) Dzień/noc (FR-A5): pola `followSystem`, `dayScheme`, `nightScheme`; tryb macOS z `defaults read -g AppleInterfaceStyle` przez `ProcessRunner`, odpytywany co 5 s tylko przy włączonym `followSystem`; pierwszy odczyt w `main` przed oknem (bez mignięcia złego motywu). (3) Nowy strumień `applied` = ustawienia z motywem w użyciu teraz; `app` buduje z niego wygląd okien i kolory nowych kart terminala. (4) Import/eksport (FR-A6, część „import i eksport”): przyciski „Importuj…” i „Eksportuj…” w oknie Wygląd, systemowy wybór pliku z `app`. Eksport zapisuje **szkic** (to, co widać w podglądzie) w formacie `theme.json`. Import czyta plik ściśle (zła wartość = błąd, brak pola = domyślna), wkłada wynik do szkicu i nic nie zapisuje — zapis dopiero przez „Zastosuj”, „Anuluj” odrzuca. (5) UI dzień/noc: przełącznik „Dzień i noc z macOS”; gdy włączony, nad listą motywów segment „Dzień | Noc”, a klik w motyw ustawia motyw wybranego segmentu; podgląd pokazuje motyw edytowanego segmentu.

**Nie robimy:** własnych schematów kolorów (`customSchemes`, edytor, walidacja kontrastu importowanych kolorów) — decyzja 2; sekcji `terminal` w `theme.json` (font i rozmiar terminala zostają w `terminal.json`, ADR 0016) — decyzja 3; komunikatu w UI o uszkodzonym lub nowszym pliku (tylko log, jak `notifications.json`); zmiany wyglądu otwartych kart JediTerm (AM-807, ADR 0016 pkt 3); obserwacji zdarzeń systemu (`AppleInterfaceThemeChangedNotification`).

**Etapy (jeden PR, każdy commit z zielonym `./gradlew check`):** (1) `appearance:api`: nowe typy, `applied`, `ThemeFiles`, fake'i i kontrakty; (2) `appearance:impl`: `decodeSettings`, serializer, `JsonThemeStore`; (3) `appearance:impl`: tryb macOS i `SystemModeWatcher`; (4) `appearance:impl`: `FileThemeFiles`; (5) `appearance:ui`: szkic dzień/noc, kontroler, kontrolki, import/eksport; (6) `app`: fabryka w `main`, `applied` w `AppTheme`, `AwtThemeFilePicker`; (7) dokumentacja, ADR 0023, CHANGELOG. **Rozmiar:** plan szacował ok. 820 linii `src/main` (impl ~420, ui ~240, api ~80, app ~80), z zapasem 30% ok. 1050; wykonanie: +1185/−107 w `src/main` — ponad ENG-C10, jeden PR (decyzja człowieka z pamięci projektu).

## Zmiany API

`appearance:api` (bez zmian w `api` innych feature):

```kotlin
/** Day and night themes picked by the macOS mode (FR-A5); [enabled] false = always AppearanceSettings.scheme. */
public data class DayNight(
    val enabled: Boolean = false,
    val day: SchemeId = DEFAULT_DAY,      // `paper`
    val night: SchemeId = ThemeCatalog.DEFAULT_SCHEME,
) { public companion object { public val DEFAULT_DAY: SchemeId = SchemeId("paper") } }

public data class AppearanceSettings(/* scheme, typography, uiScale, density as in AM-803 */ val dayNight: DayNight = DayNight())

/**
 * The settings in effect: [this] with `scheme` set to the day or night theme when day/night is on and
 * [systemDark] is known; otherwise [this] unchanged. Pure.
 */
public fun AppearanceSettings.appliedFor(systemDark: Boolean?): AppearanceSettings

public sealed interface AppearanceError { /* UnknownScheme (also day/night ids), UnknownTypography */
    /** theme.json could not be written, or was unreadable/newer at start and is never overwritten. Settings unchanged. */
    public data object StorageFailed : AppearanceError
}

public interface AppearanceApi {
    public val catalog: ThemeCatalog
    /** The saved choice (theme.json); what the Appearance dialog edits. */
    public val settings: StateFlow<AppearanceSettings>
    /** What the app draws now: `settings.appliedFor(macOS is dark)`; follows macOS within ~5 s. */
    public val applied: StateFlow<AppearanceSettings>
    /** Validates (all ids incl. day/night), saves theme.json, then publishes; Err leaves settings unchanged. */
    public suspend fun update(change: (AppearanceSettings) -> AppearanceSettings): Outcome<AppearanceSettings, AppearanceError>
}

/** theme.json files the user picks (FR-A6). Never throws; IO on its own dispatcher; never applies anything. */
public interface ThemeFiles {
    /** Reads [source] strictly: a present but invalid field (unknown id, bad enum) is Err; a missing one is the default. */
    public suspend fun read(source: Path): Outcome<AppearanceSettings, ThemeFileError>
    /** Writes [settings] to [target] as theme.json v1, replacing an existing file atomically. */
    public suspend fun write(settings: AppearanceSettings, target: Path): Outcome<Unit, ThemeFileError>
}

/** Why a theme file failed; fixed categories, never file contents or paths in texts (ENG-C8). */
public sealed interface ThemeFileError {
    public data object ReadFailed : ThemeFileError      // missing, no permission, larger than 64 KiB
    public data object NotThemeFile : ThemeFileError    // not UTF-8 JSON object, no schemaVersion or data object
    public data class NewerVersion(val found: Int) : ThemeFileError
    public data object InvalidValue : ThemeFileError
    public data object WriteFailed : ThemeFileError
}
```

## Ryzyka i pytania

**Pytania blokujące (rekomendacja w nawiasie):**

1. **Moduły poza roadmapą.** Roadmapa wymienia tylko `appearance:impl`. FR-A5 i FR-A6 wymagają też: `appearance:api` (pola dzień/noc, `applied`, `ThemeFiles`, błąd zapisu), `appearance:ui` (przełącznik, segment, przyciski, port wyboru pliku), `app` (fabryka w `main`, `applied` w wyglądzie, okno wyboru pliku AWT). Czy dopisać je do AM-804? (**Tak** — bez nich użytkownik nie może włączyć dzień/noc ani zaimportować pliku; `api` jest własnym `api` feature, inne `api` bez zmian.)
2. **Zakres FR-A6.** FR-A6 to „własny schemat, import i eksport `theme.json`” (priorytet C), a docs/08 ma `customSchemes`. Własne schematy oznaczają: katalog zmienny w czasie (`catalog: ThemeCatalog` → `StateFlow`, zmiana łamiąca w `api`, `ui` i `app`), walidację kontrastu NFR-6 importowanych kolorów (`ContrastAudit` jest dziś tylko w testFixtures `core:design-tokens` — trzeba go przenieść do `main`), wyprowadzenie brakujących tokenów i decyzję o edytorze. Czy AM-804 robi tylko import/eksport ustawień, a własne schematy idą do nowego zadania (np. AM-814)? (**Tak, wydzielić** — plan ma już ok. 1050 linii.)
3. **Sekcja `terminal` w `theme.json`.** docs/08 pokazuje `"terminal": {"font", "size"}`, ale te wartości mają właściciela w `terminal.json` (ADR 0016, `terminal:impl`). Czy usuwamy `terminal` z formatu i z docs/08, a eksport nie zawiera fontu ani rozmiaru terminala? (**Tak** — jedno źródło prawdy; inaczej `appearance:impl` musiałby pisać przez `TerminalSettingsRepo` i dwa pliki mogłyby się rozjechać.)
4. **Wykrywanie trybu macOS** (szczegóły w ADR 0023). A: `defaults read -g AppleInterfaceStyle` przez istniejący `ProcessRunner` co 5 s, tylko przy włączonym dzień/noc — bez nowej biblioteki, testowalne `FakeProcessRunner`, ale każde odpytanie uruchamia powłokę logowania (przy ciężkim profilu ok. 0,1–0,5 s CPU co 5 s) i zmiana dochodzi z opóźnieniem do 5 s. B: JNA + `CFPreferencesCopyAppValue` co 1 s — tani odczyt, ale nowa bezpośrednia zależność (ADR 0018 wciąż „proponowana”, JNA nie ma w `libs.versions.toml`) i kod natywny. C: obserwacja `AppleInterfaceThemeChangedNotification` przez JNA i runtime Objective-C — natychmiast, najwięcej kodu natywnego. (**A**; B jako zadanie następcze, jeśli człowiek zgłosi opóźnienie lub koszt.)

**Ryzyka:**

- Tryb „Automatycznie” w macOS: zakładamy, że system zapisuje `AppleInterfaceStyle=Dark` także przy przełączeniu automatycznym. Do sprawdzenia ręcznie w `:app:run` (Ustawienia systemowe → Wygląd → Automatycznie); jeśli nie, decyzja 4 wraca na stół.
- Wyjście `defaults` idzie przez powłokę logowania: profil może coś wypisać (stąd „ostatnia niepusta linia”); `NotFound`/`Timeout` (2 s) nie zmieniają ostatniego trybu.
- `apple.awt.fileDialogForDirectories=true` jest ustawione globalnie w `main` (`AwtDirectoryPicker`), więc `FileDialog` wybierałby katalogi. `AwtThemeFilePicker` przełącza właściwość na `false` na czas okna i przywraca ją w `finally` na wątku AWT (oba pickery działają tylko tam, więc bez wyścigu). Weryfikacja ręczna: dodanie projektu nadal wybiera folder po imporcie.
- Nowszy lub nieczytelny `theme.json` przy starcie: `update` zwraca `StorageFailed` i nic nie zmienia (jak `terminal.json`), więc okno Wygląd pokaże błąd zapisu przy każdym „Zastosuj” — świadome, rzadkie; komunikat o pliku to osobne zadanie.
- Zmiana kolejności w `main`: `appearanceModule` jest teraz `suspend` (pierwszy odczyt trybu przed oknem) i potrzebuje `appScope`; `runBlocking` tylko w `main` (ENG-C3).
- `AppearanceController` jest blisko TooManyFunctions — import/eksport w osobnym `ThemeFileActions`; `AppearanceDialog` i `ThemeList` blisko LongMethod (30) i ENG-C2 (≤ 5 parametrów) — mierzyć ręcznie (lekcje).
- Fokus startowy dialogu zostaje na zaznaczonym motywie; „Importuj…”/„Eksportuj…” są SECONDARY i nigdy nie dostają fokusu startowego (lekcja o dialogu zgody). Kolory nowych kontrolek wyłącznie z `AmTheme` (bez kopiowania palet — lekcja NFR-6).
- Komunikaty kotlinx.serialization cytują plik: `decodeSettings` i `FileThemeFiles` łapią wyjątki i zwracają stałe kategorie; logi z kluczem pola, nigdy z wartością ani ścieżką użytkownika.
- Import nie stosuje niczego do „Zastosuj”: test `apply after import saves the imported settings` przypina tę ścieżkę; podgląd pokazuje importowany motyw od razu.
- Przed pushem `npx --yes markdownlint-cli2@0.18.1` (plan, ADR, docs/08, docs/11).
