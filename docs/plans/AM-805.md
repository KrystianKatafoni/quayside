# AM-805 · Katalog 20 motywów z kształtem i 14 dodatkowych typografii

Issue: #70 · Wymagania: FR-A1, FR-A2, FR-A7, NFR-6 · docs/08 („Motywy z kształtem”, „Typografie”, „Luki 1–2”), docs/12 §1, ADR 0021, ENG-I1–I8, ENG-C2, ENG-C10 · Zależy: AM-801, AM-802 (scalone)

## Zakres

Decyzje człowieka (2026-11-03): katalog 9 + 20 = 29 motywów; typografia niezależna od motywu, motyw tylko podpowiada swoją parę; bez rozmycia tła; Ubuntu Mono zamienione (`glass-light` → DM Mono, `deep-abyss` → JetBrains Mono); **jeden PR** ok. 565 linii `src/main` (świadomy wyjątek od ENG-C10, opis PR to wymienia). Bez nowego ADR: fonty idą drogą ADR 0021, który wymienia AM-805. Korekty zmieniające charakter (decyzja człowieka): `dracula` — `muted` rozjaśniony regułą do ok. `#ACB4CF`, `panel` `#44475A` bez zmian; `solarized-dark` — wiersz ma wprost `text` `#EEE8D5` (base2) i `muted` `#93A1A1` (base1), `withContrast` ich nie zmienia. Cień w `AmPanel` robimy teraz, pod warunkiem że `dropShadow` istnieje w Compose MP 1.12.2 i nie jest przestarzałe (inaczej cień przechodzi do AM-803, a commit 4 odpada).

**Robimy:** (1) 20 motywów w `appearance:impl` (8 kolorów i kształt z tabeli docs/08, domyślna typografia); (2) 14 typografii i 8 nowych rodzin fontów w `core:design-system` (`AmFonts`, `resources/fonts`, `OFL.txt`, `SOURCES.md`); (3) korekta `muted` (i `work`) przez czystą funkcję `withContrast`: ten sam odcień, tylko jaśniej albo ciemniej; (4) wyprowadzenie `warn`/`ok`/`err` z regułą konfliktu odcieni; (5) rysowanie `shadow` w `AmPanel` (KDoc `AmShape` z AM-802 obiecuje „drawn from AM-805”; FR-A7). `Backdrop.TRANSLUCENT` już działa przez kanał alfa `panel`.

**Nie robimy:** ekranu Wygląd, grup „Podstawowe”/„Z motywów” (AM-803), `theme.json` (AM-804), zrzutów ekranu (luka 3), rejestracji fontów w AWT dla JediTerm, wpięcia w `app`, CHANGELOG (nic widocznego do AM-803). `core:design-tokens` **bez zmian**: `ContrastAudit` już składa półprzezroczysty `panel` na `bg`; roadmapa dostaje `core:design-system` zamiast `core:design-tokens`.

**Wyprowadzenie (motywy z kształtem).** Wiersz podaje 6 kolorów (`bg panel text muted accent border`, `#RRGGBB` albo `#RRGGBB/NN` = krycie NN %). `panel` z alfą → `Backdrop.TRANSLUCENT`. Dla jasności powierzchni bierzemy `panelSolid = panel.over(bg)`.

## Zmiany API

Brak zmian w `appearance:api` i `core:design-tokens` (`ThemeSpec.shape`/`defaultTypography` i `ShapeTokens` wystarczają). Publiczne API `core:design-system` bez zmian sygnatur; zmienia się zachowanie i KDoc:

```kotlin
/** Bundled OFL fonts (ADR 0021): the 22 families of docs/08 typographies except macOS system fonts (SF Pro, Menlo). */
public object AmFonts { public val families: Set<String>; public fun family(name: String): FontFamily? }
/** … [shadow] is drawn by AmPanel outside its corner shape; TRANSLUCENT backdrop = panel colour alpha over the parent (no blur). */
public data class AmShape(…)
// AmPanel: when AmTheme.shape.shadow != null, Modifier.dropShadow(corner, Shadow(blur.dp, spread.dp, color, DpOffset(0, offsetY.dp))) before clip
```

**`impl` (internal):** `ShapedRow(key, name, mode, colors: String, shape: String, typography: String)` (6 pól, ENG-C2; `shape` = `"<ramka> <promień> <cień>"`, cień `none` albo `y/rozmycie/rozrzut/#RRGGBB/NN`; `require` przy złym formacie); `fun deriveShapedTokens(row: ShapedRow): ColorTokens`; `data class StatusTriple(warn, ok, err)`; `fun deriveStatus(dark: Boolean, accent: Rgba): StatusTriple`; `fun Rgba.withContrast(backgrounds: List<Rgba>, minimum: Double, toward: Rgba): Rgba` — najmniejsze całkowite `p` w 0..100, dla którego `mix(toward, p)` ma ≥ `minimum` z każdym tłem (tła nieprzezroczyste); `p = 0` zwraca kolor bez zmian, brak `p` zwraca `toward`. Przed `dropShadow` implementer sprawdza w źródłach Compose MP 1.12.2 (`*-desktop` na repo1.maven.org), że API istnieje i nie jest `@Deprecated`/eksperymentalne bez OptIn; jeśli nie — stop i zgłoszenie (cień przechodzi do AM-803).

## Ryzyka i pytania

**Pytania blokujące: brak** (decyzje człowieka 2026-11-03 w sekcji „Zakres”: `dracula` opcja (a), `solarized-dark` opcja (a), cień w `AmPanel` teraz z warunkiem API).

**Pytania nieblokujące (plan przyjmuje rekomendację):**

1. Korekta przez funkcję (`withContrast`) zamiast wpisanych wartości: wiersz zostaje wierny CSS, wynik jest deterministyczny; docs/08 dostaje wartości końcowe z testu.
2. Statusy z list kandydatów (nie per motyw): `gruvbox` dostaje turkusowy `warn` i różowy `err`, `monokai` żółty `warn` i pomarańczowo-czerwony `err` — statusów motywy nie definiują, więc to nie zmiana charakteru.
3. Uwagi docs/08 bez zmian: `cyberpunk` `muted` magenta, `minimal-black` `accent` = `text`, `emerald-light` `muted` po korekcie ciemniejszy od `accent` — ocena wzrokowa w AM-803.

**Ryzyka:**

- PR ok. 435 → 565 linii `src/main` (z KDoc, Gradle, `SOURCES.md`; 20 wierszy po ok. 8 linii po ktlint); testy ok. 450 linii; pliki fontów poza liczeniem. Commity w kolejności z „Zakres”.
- Wartości policzone ręcznie (±0,05 kontrastu, ±0,5°); przy porażce audytu implementer nie dobiera kolorów sam, tylko zgłasza wiersz i wartość lead'owi.
- `#0F766E` vs `#15803D` (32,9°) i `dracula` 34,5° blisko progu 30°.
- `appearance:impl` w testach ładuje `AmFonts` z modułu Compose: tylko `families` (bez renderu); gdy brak klas Compose w runtime testu → dopisać `compose.desktop.currentOs` do `testImplementation` i odnotować w planie.
- `Outfit`, `Courier Prime`, `PT Mono` mogą nie przejść testu polskich znaków lub `0O1lI` (`latin-ext` potwierdzone dla Outfit i Roboto Mono) — wtedy stop i pytanie do człowieka (inny font pary).
- `FontFamily.Monospace` na macOS może nie być Menlo — ocena w AM-803.
- KDoc z wyliczeniami do przejrzenia (lekcja): `AmFonts` („14”), `BuiltInSchemes`/`BuiltInTypographies` („nine”, „eight”), `BundledFontsTest`, `AmShape` („drawn from AM-805”), nagłówek `SOURCES.md`.
- Detekt: `ShapedThemes.rows()` (LongMethod), testy z tabelami > 30 linii (`@Suppress("LongMethod")`), TooManyFunctions w testach katalogu — pliki spoza listy dopisać do „Moduły” w tym samym PR.
