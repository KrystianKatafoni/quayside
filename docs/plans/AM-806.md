# AM-806 · Ekrany na AmTheme: usunięcie 8 lokalnych palet i kopii kontrolek

Issue: #74 · Wymagania: FR-A1, NFR-6 · docs/08 (`plex`, „Wyprowadzenie tokenów”), docs/11 §3 (reguły 1 i 5), docs/12 §1, ENG-I1–I8, ENG-C2, ENG-C10 · Zależy: AM-802, AM-805 (scalone)

## Zakres

Decyzje człowieka (2026-11-03): **jeden PR** ok. 850 linii `src/main` (z zapasem 30 %), świadomy wyjątek od ENG-C10, opis PR to wymienia; bez pytania o podział.

**Robimy:** (1) `app` opakowuje oba okna (`MainWindow`, `PopupWindow`) w `AmTheme` z domyślnym motywem i typografią katalogu (`plex` + `plex`); (2) każdy ekran pięciu modułów `ui` i dialog hooków w `app` czyta kolory, kształt i typografię z `AmTheme`; usuwamy 8 palet (`Colors` MC, `NewAgentColors`, `SidebarColors`, `TerminalColors` ui, `PopupColors`, `SettingsColors`, `PaletteColors`, `HookColors`) i kopie kontrolek: 3× `Label`, `HookText`, `PopupText`, `Wrapped` → `AmText`; 2× `focusFrame()` i ramka `HookButton` → `amFocusFrame`; fokusowalne przyciski dialogów → `AmButton`; ciała dialogów, karta popupu, pasek szukania → `AmPanel`; pasek trybu MC → `AmModeBar` + `AmModeBadge`; (3) reguła Konsist i test kontrastu par ekranów na `plex`.

**Nie robimy:** wyboru motywu i typografii (AM-803/804), `theme.json`; kolorów i fontu JediTerm (`TerminalWidgetSettings` w `terminal:impl`, poza modułami zadania; pytanie nieblokujące 1); `AmListRow` na ekranach (fokusowalny `selectable` z rolą RadioButton zmieniłby semantykę i zjadał Space/Enter w MC); wspólnego pola tekstowego i przełącznika (pytanie 2). Przyciski z `canFocus = false` (MC, sidebar, pasek kart, `GlyphButton`, przełącznik w `SearchBar`) **zostają lokalne**, tylko kolory z tokenów — `AmButton` jest fokusowalny (lekcja Space/Enter).

## Zmiany API

Brak zmian w `api` jakiegokolwiek feature. `core:design-system` (publiczne, explicit API):

```kotlin
/** One block of text in [role]; [color] null = the colour of the container (content.text by default).
 *  [maxLines] 1 = one line with ellipsis (default); more lines wrap and end with an ellipsis. 5 params (ENG-C2). */
@Composable public fun AmText(text: String, modifier: Modifier = Modifier, role: TextRole = TextRole.BODY,
    color: Color? = null, maxLines: Int = 1)
/** Dims everything behind a modal layer: black at 60 % alpha in every theme (the scrim of today's dialogs). */
public fun Modifier.amScrim(): Modifier
// testFixtures: the plex tokens (SampleTokens.colors(), SampleTokens.shape()) and the plex typography.
@Composable public fun AmTestTheme(content: @Composable () -> Unit)
```

`app` (`internal`):

```kotlin
/** Colours, shape and typography the windows are drawn with; AM-804 replaces the source with the user's choice. */
internal data class AppLook(val colors: ColorTokens, val shape: ShapeTokens, val typography: TypographySpec)
/** Default scheme and typography (plex); ThemeCatalog guarantees both, so a miss is a programmer error.
 *  @throws IllegalStateException never for the built-in catalog. */
internal fun ThemeCatalog.defaultLook(): AppLook
/** AmTheme over [content] with [look]; wraps both windows inside `application {}` in Main. */
@Composable internal fun AppTheme(look: AppLook, content: @Composable () -> Unit)
```

`main`: `val look = appearanceModule().catalog.defaultLook()`; `application { AppTheme(look) { Window(…) { MainWindow(…) }; PopupWindow(…) } }`. Implementer sprawdza w źródłach Compose MP 1.12 (`Window` w `ui-desktop`, `rememberCompositionContext`), że `CompositionLocal` przechodzą do treści `Window`; jeśli nie — `AppTheme` idzie do środka każdego `Window`, a `PopupWindow` (notifications:ui) czyta `AmTheme` przed `Window` i podaje je dalej w środku.

**`internal` w `ui`:** czyste funkcje mapujące: `Tone.color(tokens): Rgba` (MC), `TabStatus.color(tokens): Rgba` (terminal), `NotificationKind.barColor(tokens): Rgba` (notifications). `BasicTextField` zostają lokalne: `textStyle = AmTheme.typography.style(BODY).copy(color = text)`, `cursorBrush = SolidColor(text)`.

## Ryzyka i pytania

**Pytania blokujące: brak** (żadne `api` feature się nie zmienia, reguły 1 i 5 docs/11 dopuszczają `ui`/`app` → `core:design-system` i `app` → `appearance:*`; bez ADR; zakres w roadmapie).

**Pytania nieblokujące (plan przyjmuje rekomendację):**

1. Kolory i font JediTerm (`termBg`/`termText`, IBM Plex Mono w AWT) wymagają `terminal:impl` (i parametru fabryki z `app`) — poza modułami zadania. Rekomendacja: osobna linia roadmapy przed AM-803 (dopisuje lead/człowiek). W AM-806 tylko tło obszaru terminala = `termBg`, więc widżet i jego okolica mogą się różnić odcieniem.
2. Pola tekstowe (6 kopii) i przełączniki (3) zostają lokalne na tokenach; `AmTextField`/`AmToggle` przy pierwszym ekranie, który ich potrzebuje (AM-803).
3. Kontrast par ekranów na całym katalogu (29 motywów) sprawdza dopiero AM-803, gdy wybór motywu staje się możliwy. Znany problem: `oatmeal-light` ma `work` skorygowane tylko do 3:1 (AM-805), więc licznik „pracuje” jako tekst da tam < 4,5:1 — AM-803 musi zmienić licznik (np. kropka + `text`) albo korektę.

**Ryzyka regresji wizualnych:**

- Cała aplikacja zmienia charakter: szarości macOS i niebieski akcent (`#1C1C1E`, `#0A84FF`) → Plex Violet (`#0B0A10`, fiolet `#A78BFA`); ciemniejsze tła, zaznaczenie fioletowe. Zamierzone (FR-A1: `plex` domyślny); wpis w CHANGELOG.
- `work` (`#C4B5FD`) i `accent` (`#A78BFA`) są w `plex` blisko siebie: kropka „pracuje” i znacznik wybranego wiersza oraz paski popupu PR/„długo działa” trudniej odróżnić. Rodzaj zawsze mówi też tekst; ocena wzrokowa człowieka przy `:app:run`.
- `NEEDS_INPUT` i `PERMISSION` tracą różnicę bursztyn/pomarańcz (oba `warn`, semantyka docs/08 „czeka na Ciebie”).
- Fonty: systemowy SF → IBM Plex Sans/Mono; inne szerokości: ucięcia nazw w sidebarze, kartach terminala, pasku trybu; tekst 12 sp → 11 sp (`CAPTION`). Testy z rozmiarami węzłów mogą paść — poprawka asercji, nie układu, gdy tekst nadal mieści się w oknie 1280×800.
- `amFocusFrame` rezerwuje 4 dp wokół każdego fokusowalnego elementu: dialogi (Nowy agent, hooki, ustawienia, projekty) rosną o ok. 8 dp na kontrolkę; promień 8 dp i ramka 1 px `AmPanel` zamiast 4/6/10 dp bez ramki.
- Baner ostrzeżenia ciemnieje (`#5C4400` → `#332919`); błędy są różowe (`#FCA5A5`).
- `PopupWindow` to osobne okno: gdy `CompositionLocal` nie przechodzą do `Window`, pierwszy popup rzuci „AmTheme is missing” w runtime (testy `runComposeUiTest` nie mają `Window`). Wariant zapasowy w „Zmiany API”; człowiek sprawdza popup przy `:app:run`.
- JediTerm bez zmian (domyślne kolory widżetu) obok tła `termBg` — możliwy widoczny szew.
- Rozmiar ok. 650 → 850 linii `src/main` (ktlint rozbija `AmTheme.colors.content.text.toColor()`), testy ok. 350 linii (23 pliki × opakowanie, nowe ok. 200, usunięte ok. 70). Composable blisko LongMethod (30) po zamianie na nazwane argumenty — mierzyć ręcznie (`ModeBarView`, `HookPanel`, `NewAgentDialog`); pliki wymuszone przez detekt dopisać do „Moduły”.
- Obejście `semantics(mergeDescendants = true)` w `DialogButton` jest na wywołaniu w `terminal:ui` i `mission-control:ui`; do przeniesienia do `AmButton` przy AM-803.
- `work` vs `accent` w `plex` ma kontrast 1,47:1 — odróżnienie ocenia człowiek wzrokowo.
- Reguła Konsist `HEX_COLOR` łapie literały heksadecymalne, ale nie `Color(red = …)` ani `Color.Black`; ten zakres opisuje plan, KDoc reguły (test w `tests/architecture`) zostaje bez zmian w tym PR.
