# AM-807 · Kolory i font terminala z AmTheme

Issue: #78 · Wymagania: FR-A1, FR-A2, NFR-6 · docs/08 (tokeny `termBg`/`termText`, „Font terminala: z typografii albo własny”), docs/11 §3 (reguły 2 i 5), ADR 0016 (ustawienia czytane przy otwarciu karty), ADR 0021 („rejestracja w AWT to osobne zadanie”), ENG-C2, ENG-I1–I8 · Zależy: AM-806 (scalone)

## Zakres

Dziś widżet JediTerm rysuje domyślny styl `UserSettingsProvider.getDefaultStyle()`: czarny tekst na białym tle, font z `TerminalSettings.fontFamily` albo domyślny JediTerm. Wokół niego `TerminalArea` ma tło `termBg` (AM-806), a `SwingPanel` domyślne tło `Color.White`. To jest „szew”.

**Robimy:** (1) `terminal:impl`: nowy parametr fabryki `colors: StateFlow<TerminalColors>`, czytany przy każdym otwarciu karty (jak `settings`, ADR 0016); `TerminalWidgetSettings` nadpisuje `getDefaultForeground()` = `termText` i `getDefaultBackground()` = `termBg`; (2) `app`: rejestruje w AWT pliki fontu terminala bieżącej typografii (dołączone w `core:design-system`) i podaje terminalowi ustawienia, w których `fontFamily == null` znaczy „font terminala typografii”; (3) `terminal:ui`: tło `SwingPanel` ustawiane w `factory` na `termBg` i etykieta pola fontu „Font (puste = z typografii)”.

**Nie robimy:** zmiany kolorów i fontu w już otwartych kartach (ADR 0016; podgląd na żywo to AM-803/804); palety ANSI (16 kolorów xterm), koloru zaznaczenia, kolorów trafień wyszukiwania (`HighlightingPanel.HIT_FILL` itd.), wyglądu paska przewijania JediTerm (pytanie nieblokujące 3); wyboru typografii (AM-803/804); zmian w `terminal:api`, `core:design-system`, `appearance:*`.

**Kolejność commitów** (każdy z zielonym `./gradlew check`): (1) `terminal:impl` (kolory, fabryka) + wywołanie w `app/Main.kt`; (2) `app`: fonty w AWT i mapowanie ustawień; (3) `terminal:ui`; (4) dokumentacja: `docs/ROADMAP.md` (AM-807 `[x]`), `docs/08-wyglad.md` (zdanie w wierszu 11: terminal JediTerm czyta `termBg`/`termText` i font typografii od AM-807), `CHANGELOG.md` `[Unreleased]` („Terminal w kolorach i foncie motywu”).

## Zmiany API

Brak zmian w `api` jakiegokolwiek feature. Zmienia się publiczna fabryka `terminal:impl` (używa jej tylko `app`):

```kotlin
/**
 * PTY terminals with JediTerm widgets. [shell] is the login shell (usually `LoginShellProcessRunner.defaultShell()`).
 * [settings] and [colors] are read at every open, so a change applies to tabs opened later and never to open ones
 * (ADR 0016); [colors] gives the default text (`termText`) and background (`termBg`) of the widget, alpha ignored.
 * The module owns an app-long scope on [AppDispatchers.default] that disposes widgets on [AppDispatchers.main].
 * [logger] gets ids, kinds and fixed categories only (ENG-C8).
 */
public fun terminalModule(
    dispatchers: AppDispatchers,
    logger: Logger,
    shell: Path,
    settings: StateFlow<TerminalSettings>,
    colors: StateFlow<TerminalColors>,
): TerminalApi
```

Parametr `scope` znika z publicznej fabryki: moduł tworzy `CoroutineScope(SupervisorJob() + dispatchers.default)` sam — dokładnie to, co dziś robi `app` — żeby zostać przy 5 parametrach (ENG-C2; obiekt parametrów musiałby być publiczną klasą w `impl`, czego zabrania reguła Konsist `impl exposes only its module factory`). Wewnętrzna fabryka (testy) zostaje z `scope` i `TerminalLaunch`.

`terminal:impl` (`internal`):

```kotlin
internal class TerminalLaunch(val shell: Path, val settings: StateFlow<TerminalSettings>,
    val colors: StateFlow<TerminalColors>, val baseEnvironment: Map<String, String> = System.getenv())
/** Snapshot of [settings] and [colors] taken when the widget is built (ADR 0016). 3 params. */
internal class TerminalWidgetSettings(settings: TerminalSettings, colors: TerminalColors,
    fontAvailable: (String) -> Boolean) : DefaultSettingsProvider()
/** Opaque JediTerm colour with the red, green and blue of this token; alpha is dropped (termBg is opaque in docs/08). */
internal fun Rgba.toTerminalColor(): TerminalColor
```

`app` (`internal`):

```kotlin
/**
 * Registers the bundled files of font family [family] (the ones AmFonts gives Compose: `ResourceFont.name` of
 * `AmFonts.family(family)`) with [register], so JediTerm finds the family by name. Returns how many files were
 * registered: 0 for a system family (Menlo, SF Pro), an unknown one or unreadable files (logged with a fixed
 * category, never the path). Never throws.
 */
internal fun registerTerminalFont(family: String, logger: Logger,
    register: (java.awt.Font) -> Boolean = GraphicsEnvironment.getLocalGraphicsEnvironment()::registerFont): Int
/** [this] with the typography's [terminalFont] when the user chose no own font (`fontFamily == null`, docs/08). */
internal fun TerminalSettings.withTypographyFont(terminalFont: String): TerminalSettings
/** [settings] mapped by [withTypographyFont] in [scope] (Eagerly); the value is current before the first read. */
internal fun typographySettings(settings: StateFlow<TerminalSettings>, terminalFont: String,
    scope: CoroutineScope): StateFlow<TerminalSettings>
```

`Main.kt`: `val look = appearanceModule().catalog.defaultLook()` przenosi się przed `appModules`; potem `registerTerminalFont(look.typography.terminalFont, core.logger)` — przed pierwszym otwarciem karty, bo `JediTermTerminalApi.installedFonts` jest `lazy`. `startTerminals` podaje `typographySettings(stored.settings, …)` i `MutableStateFlow(look.colors.terminal)`. `forwardBells` dalej czyta `stored.settings` (bez mapowania).

`terminal:ui`: tło ustawiane w `factory`: `SwingPanel(factory = { component.background = java.awt.Color(termBg.toArgb()); component }, modifier = …)`. Przeciążenie `SwingPanel(background = …)` jest w Compose MP 1.12 `@Deprecated` („Set the background manually in the factory method”), a `allWarningsAsErrors` blokuje jego użycie; efekt ten sam. Etykieta: `settings.fontFamily=Font (puste = z typografii)`.

Decyzje z implementacji:

- `terminalDeps` w `Main.kt` jest bez parametru `shell` (ENG-C2, limit 5 parametrów); `appModules` dostaje `look`.
- `ResourceFont` z właściwością `.name` to `androidx.compose.ui.text.platform.ResourceFont`.
- `TerminalWidgetSettings` ma `@Suppress("TooManyFunctions")` (12 funkcji, próg detekt 11).

## Ryzyka i pytania

**Pytania blokujące: brak** (żadne `api` feature się nie zmienia; reguła 2 docs/11 dopuszcza `impl` → `core:*`, reguła 5 `app` → wszystko; bez ADR; moduły jak w roadmapie).

**Pytania nieblokujące (plan przyjmuje rekomendację):**

1. Publiczna fabryka `terminalModule` traci parametr `scope` (moduł tworzy go sam), żeby po dodaniu `colors` zostać przy 5 parametrach (ENG-C2). Alternatywa: obiekt parametrów w `terminal:api` — poza modułami zadania. Rekomendacja: jak w planie.
2. KDoc `TerminalSettings.fontFamily` w `terminal:api` („null: the terminal's default monospace font”) zostaje bez zmian; od AM-807 „domyślny font terminala” = font terminala typografii. Rekomendacja: doprecyzować przy najbliższej zmianie `terminal:api` (np. AM-803/804).
3. Pasek przewijania JediTerm (Swing, wygląd Aqua), paleta ANSI xterm, kolor zaznaczenia (`rgb(82,109,165)`) i stałe kolory trafień wyszukiwania zostają; pasek przewijania może nadal odcinać się od `termBg`. Rekomendacja: osobna linia roadmapy, jeśli człowiek oceni szew przy `:app:run` jako widoczny.
4. Rejestracja fontu raz przy starcie i `lazy installedFonts` w `JediTermTerminalApi` nie zobaczą typografii zmienionej w trakcie działania — AM-804 musi rejestrować font przy zmianie i odświeżać zbiór zainstalowanych rodzin.

**Ryzyka:**

- Ścieżki plików fontu `app` czyta z publicznego API Compose: `AmFonts.family(…)` → `FontListFontFamily.fonts` → `ResourceFont.name` (publiczne w Compose MP 1.12, zweryfikowane w źródłach `DesktopFont.desktop.kt`). Zmiana sposobu ładowania w `AmFonts` łamie to po cichu — chroni test `plex terminal font registers both IBM Plex Mono files`. Plik zasobu czytać class loaderem `AmFonts::class.java`.
- AWT nie stosuje osi `wght` plików zmiennych: `Font.createFont` bierze instancję domyślną pliku, która w części rodzin Google Fonts bywa cienka. `plex` (IBM Plex Mono) ma pliki statyczne, więc AM-807 tego nie dotyka; AM-803 musi sprawdzić wzrokowo fonty terminala pozostałych 21 typografii.
- `registerFont` zwraca `false`, gdy rodzina o tej nazwie już jest (użytkownik ma zainstalowany IBM Plex Mono) — wtedy JediTerm użyje fontu systemowego; licznik 0 nie jest błędem, log tylko informacyjny.
- `getDefaultForeground/Background` sprawdzić w JediTerm 3.76 (w `master` są w `UserSettingsProvider`, `getDefaultStyle()` jest przestarzałe — nie nadpisywać go, `allWarningsAsErrors`).
- Kolory ANSI xterm (np. ciemnoniebieski) na ciemnym `termBg` mogą mieć słaby kontrast — wcześniej rysowane na białym tle też były częściowo nieczytelne; poza NFR-6 dla tokenów, ocena człowieka.
- `typographySettings` przez `stateIn` może być o jeden dispatch w tyle za zapisem ustawień (lekcja o `stateIn`); karta otwarta w tej samej chwili dostanie poprzedni font. Akceptowalne (ADR 0016 dotyczy kart otwieranych później); scope z `SupervisorJob` na `dispatchers.default`, żyje jak aplikacja.
- Rozmiar: `src/main` ok. 130 linii (`impl` ok. 45, `app` ok. 75, `ui` ok. 5) z zapasem 30 % na ktlint → ok. 170; testy ok. 220. Poniżej limitu ENG-C10, jeden PR.
