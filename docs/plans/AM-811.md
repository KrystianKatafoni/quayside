# AM-811 · Jasny terminal w jasnych motywach

Issue: #92 · Wymagania: FR-A1, FR-A2, NFR-6 · Zależy: AM-803 (scalone) · Decyzja człowieka 2026-11-05 („opcja b”, Uwagi do M8) · ADR: [0027](../adr/0027-kolory-terminala-z-motywu-i-paleta-ansi.md) (przyjęta 2026-11-08), [0016](../adr/0016-format-terminal-json.md) decyzja 3 · Lekcje: jedna reguła `readableOn`, ścieżka błędu funkcji wyprowadzającej, każde pole przekazane do JediTerm przypięte testem, dane o różnych kolorach źródłowych.

**Pytania 1–6 rozstrzygnął człowiek 2026-11-08** (sekcja „Ryzyka i pytania”); plan jest zgodny z decyzjami.

## Zakres

Dziś: `SchemeRow.terminal` i `deriveShapedTokens` dają ciemnym motywom (`bg`, `text`), a jasnym stałą parę `LIGHT_TERM_BG` `#1E242C` / `LIGHT_TERM_TEXT` `#E2E8F0`. `TerminalWidgetSettings` nadpisuje tylko domyślny tekst i tło; 16 kolorów ANSI to `ColorPaletteImpl.XTERM_PALETTE` z `DefaultSettingsProvider` (stała, nie z motywu). Zaznaczenie JediTerm jest odwrócone (`useInverseSelectionColor() = true`), kursor też rysuje parę odwróconą. Pasek przewijania (AM-810) i ramka panelu (AM-816) czytają `termBg`/`termText`/`accent`.

**Robimy:**

1. `core:design-tokens`: typ `AnsiColors` (16 kolorów, kolejność xterm) i pole `TerminalColors.ansi`.
2. `appearance:impl`: jedna funkcja `deriveTerminal(bg, text, dark)` dla obu rodzajów motywów: `termBg` = `bg`, `termText` = `text` w każdym trybie; `ansi` = baza xterm (16 stałych przepisanych z JediTerm 3.76 z komentarzem źródła) poprawiona `readableOn(listOf(termBg), dark)` do 4,5:1; wyjątek: kolor tła trybu (indeks 0 w ciemnym, 15 w jasnym) bez zmian. Usuwa `LIGHT_TERM_BG`, `LIGHT_TERM_TEXT`.
3. `terminal:impl`: `ThemePalette` (podklasa `ColorPalette`) z `ansi`; `TerminalWidgetSettings.getTerminalColorPalette()` ją zwraca.
4. Audyt kontrastu na 29 motywach (tekst, ANSI, ramka panelu) i dokumentacja.

**Nie robimy:** przemalowania otwartych kart po „Zastosuj” (ADR 0016, decyzja 3); kolorów trafień wyszukiwania (`SearchableWidget.HIT_FILL` itd.), koloru linków i `getFoundPatternColor` (żółte tło, czarny tekst — czytelne w obu trybach); kontrastu `termText` na kolorach ANSI jako tle (`ESC[41m`); zmian w `terminal:ui` i `terminal:api` (tło `SwingPanel`, `TerminalArea` i podgląd w `appearance:ui` czytają `termBg` już dziś, więc same stają się jasne); opcji „ciemny terminal w jasnym motywie” (pytanie 6).

**Commity** (każdy z zielonym `./gradlew check`): (1) `core:design-tokens` + dostosowanie konstruktorów w testach i fixture'ach; (2) `appearance:impl` (reguła); (3) `terminal:impl` (paleta); (4) `app` (audyt); (5) docs: `docs/08-wyglad.md` (wiersze 11, 27, 37, 96, 166 + nowa podsekcja „Paleta ANSI terminala (AM-811)” z bazą, regułą i wyjątkiem, rada o motywie `light`/`light-ansi` Claude Code), `docs/11-koncepcja-techniczna.md` §4 (linia `core:design-tokens`), ADR 0027, `CHANGELOG.md` `[Unreleased]` („Jasny terminal w jasnych motywach, kolory ANSI czytelne w każdym motywie”), `docs/ROADMAP.md` (tylko wiersz AM-811 → `[x]`; nie ruszać niezacommitowanych zmian AM-307/AM-821).

## Zmiany API

`core:design-tokens` (publiczne; zmiana łamiąca konstruktor `TerminalColors`, zatwierdzona przez człowieka 2026-11-08):

```kotlin
/**
 * The 16 ANSI colours of a terminal in xterm order: 0–7 black, red, green, yellow, blue, magenta, cyan, white;
 * 8–15 their bright variants. Immutable.
 *
 * @throws IllegalArgumentException when [colors] does not hold exactly [SIZE] colours (programmer error: only
 * catalog constants build it; data from users will go through a `parse(): AnsiColors?`, AM-814).
 */
public class AnsiColors(colors: List<Rgba>) {
    /** A copy of the given colours; later changes of the source list do not reach it. */
    public val colors: List<Rgba> = colors.toList()

    /** The colour of xterm index [index] (0–15). @throws IndexOutOfBoundsException outside 0–15. */
    public operator fun get(index: Int): Rgba

    /** Equal when all 16 colours are equal; [hashCode] and [toString] follow [colors]. */
    override fun equals(other: Any?): Boolean

    public companion object { public const val SIZE: Int = 16 }
}

/** Terminal colours: default text on default background, and the ANSI palette drawn on [termBg]. */
public data class TerminalColors(val termBg: Rgba, val termText: Rgba, val ansi: AnsiColors)
```

Zwykła klasa zamiast `data class`, bo pole główne `data class` nie może trzymać kopii listy (ENG-I: typ niemutowalny). `appearance:impl` (`internal`):

```kotlin
/**
 * Terminal colours of a theme (AM-811, ADR 0027): [bg] and [text] as they are, the xterm palette corrected by
 * [readableOn] to 4.5:1 on [bg] toward white ([dark]) or black, except the background colour of the mode
 * (index 0 when [dark], 15 otherwise), which stays as given.
 *
 * @throws IllegalArgumentException when [bg] is not opaque (from `Wcag.contrast`); catalog rows only, a theme file
 * would get an `Outcome` (AM-814).
 */
internal fun deriveTerminal(bg: Rgba, text: Rgba, dark: Boolean): TerminalColors
```

`terminal:impl` (`internal`): `class ThemePalette(ansi: AnsiColors) : ColorPalette()` — `getForegroundByColorIndex(i)` i `getBackgroundByColorIndex(i)` = `ansi[i]` bez alfy; `TerminalWidgetSettings.getTerminalColorPalette(): ColorPalette` = `ThemePalette(colors.ansi)` (jedna instancja na widżet). Typ koloru zwracanego przez `ColorPalette` (`java.awt.Color` czy `com.jediterm.core.Color`) i nazwy metod implementer sprawdza w źródłach JediTerm 3.76, nie w `master`. Bez nowych parametrów fabryki (ENG-C2 bez zmian).

## Ryzyka i pytania

**Pytania blokujące: brak.**

**Rozstrzygnięte (decyzja człowieka 2026-11-08, wszędzie wariant a):**

1. **ADR:** nowy ADR 0027 (przyjęta) z odwołaniem do decyzji 3 ADR 0016; ADR 0016 bez zmian. Numer 0026 jest zajęty dwukrotnie (`format-projects-json-v2`, `sandbox-docker`), więc 0027.
2. **Źródło palety ANSI:** baza xterm z JediTerm + `readableOn` względem `termBg`, jedna reguła dla obu trybów; człowiek akceptuje zmianę kolorów poniżej 4,5:1 także w ciemnych motywach (np. czerwony, magenta, jasna czerń).
3. **Publiczne API `core:design-tokens`:** `AnsiColors` i `TerminalColors.ansi` zatwierdzone; moduł dopisany do listy.
4. **Próg ANSI:** 4,5:1 dla 15 kolorów; kolor tła trybu (0 w ciemnym, 15 w jasnym) bez korekty.
5. **Pasek przewijania (AM-810) i ramka panelu (AM-816):** bez zmian kodu, tylko testy jasnych danych i audyt ramki (`accent` ≥ 3:1 na `termBg`); ramka nieaktywna (`border`) bez progu, jak dziś.
6. **Programy z kolorami 24-bit dla ciemnego tła** (motyw `dark` Claude Code): tylko rada w docs/08 (`/theme light` albo `light-ansi`); osobne zadanie, jeśli przeszkadza.

Odrzucone warianty: ręcznie dobrana baza jasna i domyślna paleta JediTerm (2), paleta liczona w `terminal:impl` (3), progi 3:1 lub 4,5:1 dla wszystkich 16 (4), osobne tokeny paska i ramki (5) oraz ustawienie „ciemny terminal w jasnych motywach” w `terminal.json` (6).

**Pytania nieblokujące:** `nordic-light` ma w pliku źródłowym `--bg-terminal: #1e242c`; plan stosuje „opcję b” także do niego (wiersz 96 docs/08 dostaje zdanie o odstępstwie). Gdyby po AM-811 karty otwarte przed zmianą motywu (ciemne) obok nowych (jasnych) raziły — to ograniczenie ADR 0016, osobne zadanie.

**Ryzyka:**

- API `ColorPalette` w JediTerm 3.76 może różnić się od `master` (typ koloru, nazwy metod) — sprawdzić w źródłach jar przed testami.
- Kolory zwykłe i jasne po korekcie mogą być do siebie bardzo podobne (np. czerwony i jasny czerwony na białym) — ocena wzrokowa człowieka; wariant 2(b) to poprawia.
- Jasne tło + odwrócone zaznaczenie daje ciemny pasek zaznaczenia — czytelny, ale inny niż dziś.
- Zmiana konstruktora `TerminalColors` dotyka ok. 12 miejsc w testach 4 modułów; `SampleTokens.colors()` dostaje paletę bazową xterm (stałą, bez korekty).
- Detekt: `TerminalWidgetSettings` ma już `@Suppress("TooManyFunctions")`; tabela 16 wierszy `@MethodSource` > 30 linii — wydzielić funkcję źródła (lekcja).
- Rozmiar: `src/main` ok. 110 linii (+30 % na ktlint ≈ 145), testy i fixture'y ok. 330, docs ok. 120 (bez planu i ADR). Razem ok. 600 — powyżej limitu ENG-C10, jeden PR (decyzja człowieka). Przed pushem `npx --yes markdownlint-cli2@0.18.1`.

## Odstępstwa i decyzje przy implementacji

- `SampleTokens.ansi()` (fixture) to paleta skorygowana pod `#0B0A10`, nie surowa baza xterm (plan: „baza bez korekty”); fixture ma przechodzić audyt kontrastu bez wywołania `deriveTerminal`.
- `TerminalContrastTest` w `app` powiela regułę uchwytu paska przewijania, bo `scrollbarColors` jest `internal` w `terminal:impl`; ryzyko rozjazdu reguły, pokrycie reguły zostaje w `ScrollbarColorsTest`.
- Test pikselowy `red output is painted in the theme red` pominięty (niestabilny bez okna); zostaje test ustawień (`palette comes from the theme ansi colours`) i `JediTermAnsiPaletteTest`.
- Szary w teście kierunku to `#767676` (4,5:1 na bieli i czerni), nie `#777777`.
- `ThemePalette` zwraca `com.jediterm.core.Color` (JediTerm 3.76); pomocnik `Rgba.toJediColor()` w `TerminalWidgetSettings.kt`.
- Reguła korekty to jedna: `readableOn(listOf(termBg), dark)`; `LIGHT_TERM_BG` i `LIGHT_TERM_TEXT` usunięte.
- Interakcja z AM-814 (rebase na `main` po PR #130): własne schematy dostają terminal tą samą regułą co katalog, bo `SchemeRow.terminal` woła `deriveTerminal(bg, text, dark)` (`termBg` = `bg`, `termText` = `text`, paleta ANSI skorygowana `readableOn`); schemat z pliku nie przenosi własnej palety. `ContrastAudit` jest już w `main` core:design-tokens (AM-814) i zawiera pary `ansiN/termBg` z AM-811, więc walidacja importowanych kolorów je obejmuje. Tryb w audycie to jasność `termBg`, a `deriveTerminal` używa `theme.mode` z pliku; przy rozbieżności (np. jasne tło z trybem „ciemny”) indeks pominięty w audycie może nie być ten, który zostawiła korekta, i schemat zostanie odrzucony jako `LowContrast` zamiast zaakceptowany. Dodano testy `CustomSchemesTest` dla jasnego schematu własnego.
