# AM-813 · Lista głosów z językiem, przykładem i odsłuchem próbki

Issue: #94 · Wymagania: FR-N4 · Etap: M7 · Zależy: AM-704, AM-817 · Gałąź: `feat/AM-813-voice-dropdown`

## Zakres

Stan po AM-704 i AM-817: pole „Głos lektora” w sekcji „Głos” to już `AmDropdown` z listą z `VoiceCatalog` (`say -v ?` przez `ProcessRunner`), kolejność: głos systemowy, zapisany niezainstalowany, `pl_*`, reszta; etykieta `{name} ({locale})`. Strzałki na zamkniętym polu nie zmieniają wartości, w liście nie zawijają, więc zasada z Lekcji o wartości groźnej już jest spełniona (bez nowej pracy). AM-813 dokłada:

1. **Język czytelny**: etykieta `Zosia — polski (Polska)` zamiast `Zosia (pl_PL)`; kod nieznany lub błędny zostaje surowy.
2. **Przykład**: parser zachowuje tekst po `#` z `say -v ?`; pod polem podpis „Przykład: …” dla wybranego głosu (nie w wierszach listy: przy ok. 150 głosach wiersze byłyby za długie).
3. **Odsłuch próbki**: przycisk „Odsłuchaj”/„Zatrzymaj” w wierszu głosu; mówi przykład wybranego głosu (głos systemowy, brak przykładu lub `[[`/`]]` w przykładzie → stały tekst „Tak brzmi głos powiadomień.”) z tempem i głośnością szkicu (gdy pole jest niepoprawne — z zapisanych ustawień). Bez ponowienia głosem systemowym: brak głosu = podpis błędu. Zamknięcie dialogu, zapis i drugi klik zatrzymują próbkę.
4. **Podpowiedź o polskich głosach** (po wczytaniu listy): 0 głosów `pl_*` → „Brak polskiego głosu…”, 1 głos → „Jedyny polski głos to {name}…”; obie z drogą: Ustawienia systemowe → Dostępność → Treść mówiona → Głos systemowy → Zarządzaj głosami. Przy ≥ 2 brak podpowiedzi. Aplikacja niczego nie instaluje.

**Nie robimy**: filtra „Polski” (polskie są już na górze; filtr w liście wyłączył AM-817), wyszukiwania w liście, otwierania Ustawień systemowych przyciskiem (URL `x-apple.systempreferences:` niestabilny między wersjami macOS), cache listy na dysku, chipa głosu w górnym pasku (AM-816), zmian `core:design-system`.

Jeden PR (decyzja człowieka z 2026-11-03: bez podziału ponad limitem). Kolejność commitów: (1) `api` + `testFixtures` + kontrakty, (2) `impl`: parser, `SayVoicePreview`, fabryka, (3) `ui`: czyste funkcje, kontroler, sekcja, teksty, (4) `app`, docs/11, CHANGELOG `[Unreleased]`.

## Zmiany API

```kotlin
// notifications:api, VoiceCatalog.kt — pole dochodzi na końcu z domyślną wartością (źródłowo zgodne)
/** An installed macOS voice as `say -v ?` lists it; [locale] such as `pl_PL` or `es_419`; [sample] the text after
 *  `#` (trimmed, may be empty), in the voice's language. Immutable. */
public data class VoiceOption(val id: VoiceId, val locale: String, val sample: String = "")

// notifications:api, VoicePreview.kt (nowy)
/** One sample to say: [text] in [voice] (null = system voice) at [rate] words per minute and [volume] percent.
 *  `toString` hides [text]. @throws IllegalArgumentException when [rate] or [volume] is outside the ranges of
 *  [SpeechSettings] (a programmer error; values typed by the user are checked by the caller first). */
public data class VoiceSample(val voice: VoiceId?, val text: String, val rate: Int, val volume: Int)

/** Why [VoicePreview.play] said nothing: [UNAVAILABLE] the program cannot start; [FAILED] it ran and failed, timed
 *  out, the voice is not installed, or [VoiceSample.text] holds `[[` or `]]` (refused without starting). */
public enum class VoicePreviewError { UNAVAILABLE, FAILED }

/** Plays a voice sample in the settings dialog (FR-N4). Safe on any dispatcher; suspends until the sample ends;
 *  cancelling the caller stops it. Never falls back to the system voice. Errors carry no process output. */
public interface VoicePreview {
    public suspend fun play(sample: VoiceSample): Outcome<Unit, VoicePreviewError>
}

// notifications:impl, VoiceCatalogModule.kt
/** [VoicePreview] on `/usr/bin/say` run through [process] in [workDir] (the home directory); timeout 60 s (as
 *  `MacSayAdapter`), no system-voice retry. */
public fun voicePreviewModule(process: ProcessRunner, workDir: Path): VoicePreview
// internal: SayVoicePreview(runner, workDir, program) nad MacSayAdapter(runner, workDir, program,
// fallbackToSystemVoice = false) — 4 parametry, domyślnie true (VoiceNotifier bez zmian);
// SpeechError.Unavailable → UNAVAILABLE, Failed/TimedOut → FAILED;
// SpeechSettings.templateProblem(text) == EMBEDDED_COMMAND → FAILED bez procesu. TOO_LONG (> 200 znaków) NIE odrzuca:
// przykład obcego głosu bywa dłuższy niż szablon.

// notifications:ui (public, zmiana konstruktora — 4 parametry; preview przed scope)
public class NotificationSettingsController(repo, voices: VoiceCatalog, preview: VoicePreview, scope)
// NotificationDialogState += previewing: Boolean = false, previewFailed: Boolean = false
/** Starts the sample of the drafted voice, or stops the one that plays. One sample at a time; open, cancel and
 *  a successful save stop it; a result after a stop is dropped (generation). */
public fun togglePreview()
// edit() czyści previewFailed. Czyste funkcje internal (VoiceChoices.kt):
// languageName(locale: String): String              — Locale z polskimi nazwami; zły kod → surowy kod
// polishHint(voices: List<VoiceOption>?): PolishHint? — sealed: None, Only(name); null przy null lub ≥ 2
// previewSample(draft: SpeechDraft, saved: SpeechSettings, voices: List<VoiceOption>?): VoiceSample
```

## Ryzyka i pytania

Pytania blokujące: brak.

**Rozstrzygnięte (2026-11-06, człowiek): zmiana `notifications:api` — wariant A.** Pole `VoiceOption.sample: String = ""` i nowy port `VoicePreview` (`VoiceSample`, `VoicePreviewError { UNAVAILABLE, FAILED }`) w `notifications:api`, fake i kontrakt w `testFixtures` (jak w „Zmiany API”). Powód: `ui` widzi tylko `api`, a `SpeechPort` w `impl` jest `internal`; osobny port zachowuje ENG-I2. Odrzucono wariant bez przykładu i odsłuchu, typ funkcyjny z `impl` podawany przez `app` (obejście docs/11) oraz metodę `preview` w `VoiceCatalog` (ENG-I2).

Ryzyka (bez decyzji):

- Próbka i komunikat `VoiceNotifier` mogą mówić naraz (dwa procesy `say`) — akceptowane, odsłuch trwa kilka sekund.
- Nazwy języków z JDK (CLDR) mogą zmienić się między wersjami JDK — test na JDK 21 z toolchaina; przy rozjeździe surowy kod nadal jest poprawny.
- Format `say -v ?` nie jest dokumentowany; przykład obcego głosu bywa długi — podpis zawija się, bez obcinania.
- Tekst przykładu pochodzi z systemu, nie od użytkownika, ale `VoiceSample.toString` i tak go ukrywa; kontroler niczego nie loguje (ENG-C8).
- Zapisany głos w innej wielkości liter (`zosia`) dalej pokazuje się jako niezainstalowany (jak w AM-704); odsłuch zgłosi błąd zamiast mówić głosem systemowym — świadomie, by użytkownik widział, że głosu nie ma.
