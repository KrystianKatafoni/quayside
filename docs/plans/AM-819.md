# AM-819 · Zmiana wysokości panelu terminala w trybie listy

Issue: #116 · Wymagania: FR-T2 · docs/06, docs/11 §8, ENG-I1–I8, ENG-C2, ENG-C10 · Zależy: AM-816 (scalone) · Gałąź: `feat/AM-819-resizable-terminal-pane` · ADR: [0025](../adr/0025-format-window-json.md) (przyjęta 2026-11-07)

## Zakres

1. **Uchwyt podziału** w trybie listy między Mission Control a panelem terminala (dziś stałe `TERMINAL_HEIGHT = 320.dp` w `QuaysideApp`). Pasek 6 dp na pełną szerokość prawej kolumny, przezroczysty (krawędź wyznacza ramka panelu z AM-816), z kursorem `PointerIcon(Cursor(Cursor.N_RESIZE_CURSOR))` (`pointerHoverIcon`). Przeciąganie przez `Modifier.draggable(Orientation.Vertical)`: w górę terminal rośnie, w dół maleje.
2. **Uchwyt leży poza `SwingPanel`**: to osobne dziecko układu nad ramką panelu, więc jego obszar trafień nie nachodzi na widget Swing (lekcja: `SwingPanel` zjada zdarzenia myszy). Przeciąganie, które zjedzie kursorem nad terminal, trwa dalej, bo AWT wysyła `mouseDragged` do komponentu, w którym wciśnięto przycisk (canvas Compose).
3. **Uchwyt niefokusowalny**: bez `clickable`; `focusProperties { canFocus = false }` plus `focusable()` (sam węzeł z właściwością `Focused`, której wymaga `assertIsNotFocused`; Tab go omija), więc Space i Enter zostają przy klawiszach okna. Test okna `Tab never moves the focus to the handle` zabija mutację bez `canFocus = false`, a `Enter after a drag…` mutację z `clickable`.
4. **Granice** (czysta funkcja `paneHeight`): terminal ≥ `MIN_TERMINAL_HEIGHT` = 120 dp, Mission Control ≥ `MIN_MISSION_HEIGHT` = 160 dp. Gdy okno nie mieści obu minimów, wygrywa minimum terminala, ale nigdy ponad dostępne miejsce. Granice liczy pomiar układu przy każdym rozmiarze okna. Uchwyt nie wlicza się do Mission Control ani do terminala: `available` to wysokość kolumny minus uchwyt, więc Mission Control ma dokładnie `available − paneHeight` ≥ 160 dp. Zmniejszenie okna nie zmienia zapamiętanej wysokości: po powiększeniu okna panel wraca do niej. Przeciąganie startuje od wysokości pokazanej, nie zapamiętanej.
5. **Uchwyt tylko przy widocznym panelu**: `TerminalArea` nic nie rysuje bez kart i błędu (AM-503). Układ wielotreściowy (`Layout(contents = listOf(mission, handle, panel))`) nie stawia uchwytu, gdy panel nie ma elementów do pomiaru; pomiar zapisuje to w stanie `Measured.panelShown` i dopiero wtedy komponuje się uchwyt (niezmierzony węzeł i tak byłby w drzewie semantyki); Mission Control dostaje wtedy całą wysokość, jak dziś.
6. **Zapamiętanie**: plik `window.json` (ADR 0025, właściciel `app`), `{"terminalHeight": <dp>}`, tylko odstępstwo od domyślnej 320. Odczyt raz w `main` przed oknem (jak `storedSettings`), więc panel nie skacze po starcie. Zapis po `onDragStopped`, nie przy każdym ruchu: stan „do zapisu” to `StateFlow`, jeden kolektor w zakresie okna zapisuje ostatnią wartość (wolny zapis pomija pośrednie). Bez debounce, więc bez zegara; testy na `runTest`. Zapis atomowy daje `JsonStore`. Błąd zapisu: WARN ze stałą kategorią (bez treści pliku), wysokość w oknie zostaje.
7. Tryb terminala (AM-809) bez zmian: panel wypełnia okno; po powrocie do listy panel ma wysokość przeciągniętą.

**Nie robimy:** obsługi klawiaturą (komenda palety „Terminal wyżej/niżej” może przyjść osobnym zadaniem), widocznego uchwytu z kolorem (bez nowych par kontrastu), zapisu rozmiaru i położenia okna, zmian w `terminal:ui`/`terminal:api`, podwójnego kliknięcia przywracającego domyślną.

**Rozmiar:** `src/main` ok. 295 linii (`TerminalSplit.kt` 90, wykonano 120, `TerminalPaneHeight.kt` 80, `WindowLayoutStore.kt` 75, zmiany w istniejących plikach 50); z zapasem 30 % (lekcja) ok. 380, w granicy ENG-C10. Testy ok. 450.

## Zmiany API

Brak zmian w `api` feature. Nowe typy `internal` w `app`:

```kotlin
/** Default, minimum terminal and minimum Mission Control height of the list mode, in layout dp (after the UI scale). */
internal val DEFAULT_TERMINAL_HEIGHT: Dp = 320.dp
internal val MIN_TERMINAL_HEIGHT: Dp = 120.dp
internal val MIN_MISSION_HEIGHT: Dp = 160.dp

/**
 * The terminal height shown for the remembered [preferred] height when [available] dp are left under the top bar,
 * without the handle: at least [MIN_TERMINAL_HEIGHT], leaving at least [MIN_MISSION_HEIGHT] to Mission Control; when
 * both minimums do not fit, the terminal minimum wins, but never more than [available] (and never below 0).
 */
internal fun paneHeight(preferred: Dp, available: Dp): Dp

/** The new remembered height after a drag by [delta] (positive = down) from the [shown] height: [paneHeight] of it. */
internal fun afterDrag(shown: Dp, delta: Dp, available: Dp): Dp

/**
 * The terminal height of one window. [preferred] is the remembered height; drags change it at once, [dragStopped]
 * hands the latest value to [store]. One collector in [scope] saves, so a slow save skips the values in between;
 * nothing is saved before the first drag. A failed save is logged (fixed category) and the height stays.
 */
internal class TerminalPaneHeight(
    initial: Dp,
    private val store: WindowLayoutStore,
    scope: CoroutineScope,
    private val logger: Logger,
) {
    val preferred: StateFlow<Dp>
    fun drag(delta: Dp, available: Dp)
    fun dragStopped()
}

/** `data` of `window.json` (ADR 0025): the terminal height of the list mode in dp. */
internal data class WindowLayout(val terminalHeight: Float = DEFAULT_TERMINAL_HEIGHT.value)

/** `window.json` (ADR 0025): lenient read, only deviations from [WindowLayout] defaults are written. */
internal class WindowLayoutStore(storage: JsonStorage, logger: Logger) {
    /** The stored layout; any read problem (broken file, newer schema, IO) gives the defaults and one WARN. */
    suspend fun load(): WindowLayout
    suspend fun save(layout: WindowLayout): Outcome<Unit, StorageError>
}

/** The layout store and what [WindowLayoutStore.load] gave in `main`, before the window opened. */
internal class WindowLayoutDeps(val store: WindowLayoutStore, val initial: WindowLayout)

// SettingsDeps(notifications, summaries, layout: WindowLayoutDeps)   — 3 of 6 constructor parameters
// TerminalSlot(..., pane: TerminalPaneHeight? = null)                — null: fixed DEFAULT_TERMINAL_HEIGHT, no handle
```

`TerminalSplit(missionControl: @Composable (Modifier) -> Unit, panel: (@Composable (Modifier) -> Unit)?, pane: TerminalPaneHeight?, modifier: Modifier)` — 4 parametry. Pomiar zapisuje ostatnie `available` w zwykłym polu (nie stan snapshotu), z którego czyta `drag`. Serializer: `terminalHeight` czytany przez `JsonPrimitive` z `!isString` (lekcja o `booleanOrNull`; `floatOrNull` też przyjmuje `"412"`), wartość skończona i > 0, inaczej domyślna.

## Ryzyka i pytania

**Pytania blokujące: brak.**

**Pytanie 1 — rozstrzygnięte (człowiek, 2026-11-07):** wariant A, nowy plik `window.json` w `app` wg [ADR 0025](../adr/0025-format-window-json.md) (przyjęta); odrzucone: pole w `terminal.json` (zmiana `terminal:api`), pole w `hook-offer.json` (plik o innym znaczeniu) i brak zapisu (sprzeczny z decyzją z 2026-11-06).

**Decyzje potwierdzone przez człowieka (2026-11-07):**

1. Wysokość w dp układu (po skali UI), nie ułamek wysokości okna: przy zmianie rozmiaru okna terminal zachowuje liczbę wierszy; ułamek wymagałby `schemaVersion = 2`.
2. Minima: terminal 120 dp (pasek kart i kilka wierszy), Mission Control 160 dp (nagłówek i ok. 2 wiersze); gdy oba się nie mieszczą, wygrywa terminal.
3. Zapis po zakończeniu przeciągania zamiast debounce (brak zegara w logice).

**Decyzje przyjęte za człowieka (do potwierdzenia w review):**

1. Uchwyt przezroczysty, 6 dp, tylko kursor (bez koloru i nowych par kontrastu NFR-6).
2. Zmniejszenie okna nie nadpisuje zapamiętanej wysokości; nadpisuje ją dopiero przeciągnięcie.

**Ryzyka:**

- `Layout(contents = …)` z treścią z `movableContentOf` (panel): przenoszenie w obrębie tej samej kompozycji jest wspierane; nie używać `BoxWithConstraints` (subkompozycja może zgubić stan widgetu przy przełączaniu trybów — AM-809).
- Zapis w zakresie okna: zamknięcie okna tuż po przeciągnięciu może zgubić zapis (zakres anulowany). Akceptowalne; najgorzej wraca poprzednia wysokość.
- Pole `available` przed pierwszym pomiarem: `drag` przed pomiarem jest niemożliwy (uchwyt jeszcze nie istnieje), więc pole może startować od 0 bez skutków.
- Limity detekt: `ListLayout` i `TerminalSplit` ≤ 30 linii, ≤ 5 parametrów — mierzyć ręcznie (lekcja); `QuaysideApp.kt` traci `TERMINAL_HEIGHT` i nie dostaje nowych funkcji (TooManyFunctions). Tabela `@MethodSource` > 30 linii: `@Suppress("LongMethod")`.
- `WindowWorld.kt` ma już 657 linii; detekt obejmuje testy (lekcja), więc nowe części (`paneStore`, kontener z `windowHeight`) trafiają do nowego pliku testowego `PaneWiring.kt`, a `WindowWorld.kt` dostaje tylko wywołanie. Gdy detekt wymusi inne pliki, dopisać je do „Moduły” w tym samym PR.
