# AM-821 · Wspólna polska odmiana liczebników

Issue: #128 · Wymagania: FR-P6, FR-P8 · Etap: M8 · Zależy: AM-307 · Decyzja człowieka 2026-11-08

## Zakres

1. **Jedna czysta funkcja formy** `PluralForm.of(count)` w `core:domain`: `ONE` (1), `FEW` (końcówka 2–4 poza 12–14), `MANY` (reszta, w tym 0, 5+, 12–14, 21, 112). Zastępuje trzy kopie: `countText` w `StatusBar.kt`, prywatne `countText` w `ProjectTone.kt` i regułę w `MissionControlStrings.plural`.
2. **Naprawa paska stanu**: liczniki używają `MissionControlStrings.plural`, więc „5 czeka”, „5 pracuje”, „12 czeka”, „0 czeka” (dziś „5 czekają”, „0 czekają”). Klucze `modeBar.waiting`/`modeBar.working` (+ `.one`) zastępują trójki `.one`/`.few`/`.many`, jak `overview.*` i `rail.*`.
3. **Pasek boczny** (`railLabel`) i **przegląd grupy** (`overview.*`) liczą formę przez `PluralForm`; teksty bez zmian.

Miejsce funkcji: `core:domain`. Reguła jest czystym Kotlinem bez Compose, a `core:domain` widzą oba moduły `ui` (już mają `implementation(project(":core:domain"))`) i każdy `impl` (reguła 1 i 2 dokumentu 11). `core:design-system` odpada: to Compose, a reguła językowa nie dotyczy wyglądu; `ui` nie mogą zależeć od siebie nawzajem, więc wspólny kod nie może leżeć w żadnym z nich. Klucze tekstów i pliki `.properties` zostają w modułach `ui` (NFR-10); `core:domain` daje tylko formę i przyrostek klucza.

Nie robimy: odmiany rzeczownika „agent/agenty/agentów” w `notifications:impl` (`VoiceGrouping`, inny wzorzec i moduł spoza zadania; kandydat na osobne zadanie), zmian `row.waiting`/`row.working` w `projects.properties` (format „czeka: N” nie wymaga odmiany), innych języków niż polski.

## Zmiany API (core:domain)

```kotlin
package dev.quayside.core.domain

/**
 * Grammatical number of a Polish noun or verb after a count, e.g. "1 czeka", "2 czekają", "5 czeka".
 * UI modules pick the text by [key] (e.g. `overview.waiting.few`) and fill in the count themselves.
 */
public enum class PluralForm(
    /** Suffix of the text key in `i18n/*.properties`: `one`, `few` or `many`. */
    public val key: String,
) {
    /** Exactly 1. */
    ONE("one"),

    /** Last digit 2-4, except 12-14 (2, 3, 4, 22, 24, 102). */
    FEW("few"),

    /** Everything else: 0, 5-21, 25-31, 112-114 and every negative count. */
    MANY("many"),
    ;

    public companion object {
        /** Polish form for [count]; pure, never throws. Negative counts (not produced by counters) are [MANY]. */
        public fun of(count: Int): PluralForm =
            when {
                count == 1 -> ONE
                count % 10 in 2..4 && count % 100 !in 12..14 -> FEW
                else -> MANY
            }
    }
}
```

Użycie w `ui` (bez nowego publicznego API):

```kotlin
// MissionControlStrings
fun plural(key: String, count: Int): String = formatted("$key.${PluralForm.of(count).key}", count)
// ProjectTone.kt
private fun countText(key: String, count: Int): String =
    ProjectsStrings.format(UiText("$key.${PluralForm.of(count).key}", listOf("$count")))
```

Pliki `.properties` (`missioncontrol`): zamiast `modeBar.waiting`, `modeBar.working`, `modeBar.waiting.one`, `modeBar.working.one` sześć kluczy `modeBar.waiting.{one,few,many}={0} czeka|{0} czekają|{0} czeka` i `modeBar.working.{one,few,many}={0} pracuje|{0} pracują|{0} pracuje`.

## Ryzyka i pytania

Pytania blokujące: brak. Zmiana nie dotyka `api` żadnego feature; nowy typ w `core:domain` jest zgodny z regułą 3 i 4 dokumentu 11.

Pytania nieblokujące (domyślna odpowiedź w nawiasie):

- Pasek stanu dla zera pokaże „0 czeka” / „0 pracuje” zamiast „0 czekają” — zgodnie z regułą `many` z decyzji 2026-11-08 (przyjmujemy; ukrywanie zerowych liczników to osobna decyzja UX).
- Reguła językowa w `core:domain` poszerza opis modułu („typy bazowe”) — dopisujemy `PluralForm` do tabeli w docs/11 zamiast tworzyć moduł `core:i18n` (przyjmujemy; nowy moduł byłby zmianą granic i wymagał ADR).

Ryzyka:

- `mission-control:ui` i `projects:ui` nie kompilują się w chmurze (Compose); weryfikacją jest CI. `core:domain` i jego test kompilują się lokalnie.
- Usunięcie kluczy `modeBar.waiting`/`modeBar.working` może zostawić odwołania w testach poza listą (`argumentTexts`, `fixedTexts`) — wyszukać `modeBar.` w całym repo, także w `app`.
- Odmiana „agenty czekają” w `notifications:impl` zostaje osobną regułą (rzeczownik ma inne formy niż czasownik); ujednolicenie na `PluralForm` — osobne zadanie, jeśli człowiek zechce.
- Tabela `RailLabelTest` i nowe przypadki w `StatusBarScreenTest` mogą przekroczyć LongMethod (30) — wydzielić źródło danych od razu.
